## Overview

Build a mobile-first voice memo tool at `tools/v0/v0.1/v0.1.23/en-gb/voice-memo/` that records audio in segments (zero data loss), transcribes locally in real time using a WASM speech model, and drives a 4-stage progressive enhancement pipeline: capture → transcribe → document → visuals.

All storage uses the existing VFS stack (IndexedDB provider). All UI layout uses sg-layout. All LLM calls reuse existing `sg-llm-*` components. No new frameworks.

## Stage 1: WASM Setup (mirrors video tool pattern)

### Setup Button Flow

Identical pattern to `tools/v0/v0.1/v0.1.5/en-gb/video-tools/index.html` → `runHealthCheck()`.

**Health checks (in order):**

| # | Check | Detail |
|---|-------|--------|
| 1 | WebAssembly support | `typeof WebAssembly === 'object'` |
| 2 | Web Worker support | `typeof Worker !== 'undefined'` |
| 3 | AudioContext support | `typeof AudioContext !== 'undefined' \|\| AudioWorklet` |
| 4 | MediaRecorder support | `typeof MediaRecorder !== 'undefined'` + supported MIME types |
| 5 | Microphone permission | `navigator.permissions.query({ name: 'microphone' })` |
| 6 | Load model: **whisper-tiny.en** (~39 MB) | Download + initialise via transformers.js. Cached in browser. |
| 7 | Transcription test (tiny.en) | Encode 2-second silence + speech blob → run inference → report latency |
| 8 | Load model: **whisper-base.en** (~74 MB) | Download + initialise |
| 9 | Transcription test (base.en) | Same test → report latency + WER comparison |
| 10 | WebGPU acceleration | Detect WebGPU, report if available (used to prefer GPU inference) |

**Result stored in sessionStorage** — skip re-download on page reload.

### WASM Model Strategy: transformers.js

Use `@xenova/transformers` (HuggingFace) via CDN import map or dynamic import. Runs Whisper via ONNX Runtime Web. Works on iOS Safari, Android Chrome, desktop.

```javascript
// core/sg-whisper/v0/v0.1/v0.1.0/sg-whisper.js

export async function loadWhisperModel(modelId = 'Xenova/whisper-tiny.en', onProgress) { ... }
export async function transcribeBuffer(model, audioBuffer, opts = {}) { ... }
export async function runHealthCheck(onStep) { ... }
// Returns: { passed, results: [{ label, status, detail, latencyMs }] }
```

### Two-Model Strategy

| Model | Use case | Size | Latency target |
|-------|----------|------|----------------|
| `whisper-tiny.en` | Real-time captions (every segment) | ~39 MB | < 2× segment duration |
| `whisper-base.en` | Better quality local transcript (post-record) | ~74 MB | Run after recording stops |

The tiny model provides immediate visual feedback during recording. The base model does a cleanup pass on the full audio once stopped. This gives the user two local transcripts before Stage 2 runs.

## Stage 2: Recording Architecture

### Segment-based MediaRecorder

```javascript
// core/sg-audio/v0/v0.1/v0.1.0/sg-audio.js

export async function startRecording(opts = {}) { ... }
// opts: { segmentDurationMs = 30_000, mimeType = 'audio/webm;codecs=opus',
//         onSegment, onError }
// onSegment({ index, blob, durationMs, startTimeMs }) called for each completed segment

export async function stopRecording(session) { ... }
export function isMediaRecorderSupported() { ... }
export async function runHealthCheck(onStep) { ... }
```

**Segment flow:**
1. `MediaRecorder` runs continuously
2. Every N seconds (default 30s), `requestData()` fires → `ondataavailable` yields a Blob
3. Blob is immediately written to VFS: `/voice-memos/{date}/{sessionId}/segment-{003}.webm`
4. Blob is also queued for tiny.en transcription (async, non-blocking)
5. Transcription result appended to `/voice-memos/{date}/{sessionId}/transcript-live.md`

**Phone loss protection:** VFS uses IndexedDB provider. Each segment write is committed before the next segment starts. Only the current in-flight segment (≤30s of audio) is at risk if the device loses power.

### VFS Vault Layout

```
/voice-memos/
  {date}-{sessionId}/                  ← e.g. 2026-04-08-a3f9b2c1/
    segment-001.webm                   ← written at end of segment 1
    segment-002.webm
    segment-003.webm                   ← ...
    transcript-live.md                 ← Stage 1: tiny.en output, appended per segment
    transcript-local.md                ← Stage 1b: base.en cleanup (post-stop)
    transcript-enhanced.md             ← Stage 2: OpenRouter
    brief.md                           ← Stage 3: LLM document
    infographic.md                     ← Stage 4: visual prompt / output
    .manifest.json                     ← session metadata (start time, segment count, status)
```

All paths go through `sg-vfs-bus` with IndexedDB provider. The vault (real SG/Send vault) sync is optional and deferred — the VFS is the immediate persistence layer.

## Stage 2: Enhanced Transcription (OpenRouter)

Reuse existing `sg-llm-request` component. Send: `audio segments` (as base64 data URL attachments) OR the `transcript-live.md` text to an audio-capable model.

**Model options to surface in UI (user picks):**
- `openai/whisper-large-v3` (via OpenRouter audio endpoint)
- `openai/gpt-4o-audio-preview` (audio input LLM)
- Cleanup mode: send rough transcript + ask LLM to fix

This uses the existing `sg-llm-attachment-manager` pattern from the chat tool (audio attachments already work per the existing reality doc).

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| transformers.js (not whisper.cpp WASM) | Better browser compatibility, simpler integration, HuggingFace model hub, no SharedArrayBuffer requirement on iOS |
| Segment duration: 30s default (configurable 10s–60s) | Balances loss risk vs transcription frequency |
| tiny.en for real-time, base.en for post-processing | Different latency requirements; tiny gives instant feedback |
| VFS IndexedDB as primary persistence (not vault) | Vault sync is async/optional; IndexedDB is immediate and offline-capable |
| Reuse sg-llm-* for Stages 2-3 | Existing components handle API key, model picker, streaming — no duplication |
| No Stage 4 implementation yet | Infographic tool exists separately; stub the button |
