# agent-with-tools — Tool Execution Pipeline
**v0.2.58 · architect document**

## Problem

Plain chat works. Tool calls are never executed because:
1. `sg-llm-chat-history` fires `llm:send` with no `tools:[]` array — Ollama never enters function-calling mode.
2. JSON-in-content fallback (inline shim) has no observability.
3. No loop coordinator — results never feed back to the LLM.

---

## Pipeline Stages

```
User message
     │
     ▼
[sg-llm-chat-history]  assembles messages[]
     │  llm:send  (bubble)
     │
 ─── CAPTURE LISTENER (api.js) ──────────────────────────────────
 │   stopImmediatePropagation()                                  │
 │   inject tools:[] from sg-tool-definition                     │
 │   re-fire llm:send{..., tools, tool_choice}                   │
 ─────────────────────────────────────────────────────────────────
     │
     ▼
[sg-llm-request]  sends to Ollama / OpenRouter
     │
     ├─ native tool_calls ──► llm:tool-calls ──────────────────┐
     │                                                          │
     └─ content only ──► llm:request-complete                  │
                              │                                 │
                    [aw-tool-extractor]                         │
                    JSON / codeblock parse                      │
                    llm:tool-calls-extracted (visibility)       │
                    llm:tool-calls ────────────────────────────►│
                                                                │
                                                          [aw-execution-inspector]
                                                          auto / manual approve
                                                                │  llm:tool-calls (pass-through)
                                                                ▼
                                                        [sg-tool-runner]
                                                        executes lb_* fns
                                                        llm:tool-results-complete
                                                                │
                                                      [aw-loop-coordinator]
                                                      iter < max → llm:send{messages}
                                                      iter ≥ max → llm:loop-limit-reached
                                                                │
                                                    ┌───────────┘
                                                    ▼
                                              (back to top)
```

## Event Map

| Event | Producer | Consumer(s) |
|-------|----------|-------------|
| `llm:send` | sg-llm-chat-history | **api.js capture** → sg-llm-request |
| `llm:request-complete` | sg-llm-request | aw-tool-extractor, aw-step-tracer |
| `llm:tool-calls` | sg-llm-request (native) / aw-tool-extractor (text) | aw-execution-inspector → sg-tool-runner |
| `llm:tool-calls-extracted` | aw-tool-extractor | aw-step-tracer, aw-pipeline-view |
| `sg-local-bridge:tool-call` | sg-local-bridge | aw-execution-inspector (card status), aw-step-tracer, aw-pipeline-view |
| `llm:tool-results-complete` | sg-tool-runner | aw-loop-coordinator |
| `llm:loop-limit-reached` | aw-loop-coordinator | aw-step-tracer (visible) |
| `sg-local-bridge:status` | sg-local-bridge | api.js (register LB schemas once) |

## Implementation Order

1. **P1** — api.js: LB_TOOL_SCHEMAS, sg-tool-definition registration, capture middleware, remove old shim
2. **P2** — aw-tool-extractor.js: headless, text-extraction fallback
3. **P3** — aw-execution-inspector.js: visual queue with auto/manual approval
4. **P4** — aw-step-tracer.js: event audit log
5. **P5** — aw-pipeline-view.js: stage indicator strip
6. **P6** — aw-loop-coordinator.js: iteration limit + loop wiring
7. manifest.json: add 5 new phase-2 entries
8. aw-layout.js: add Pipeline / Queue / Tracer panels to right column
9. index.html: add headless `<aw-tool-extractor>` + `<aw-loop-coordinator>`
