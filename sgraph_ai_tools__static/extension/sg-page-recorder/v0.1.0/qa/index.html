SG Page Recorder — QA target

A page built to make every rule the recorder claims to follow visible. Arm this tab from the extension, tick the feeds you are testing, then work down the page. Each block says what you should see in the side panel.

1 · Mouse

Move slowly across the box, then click the button in the corner.
Expect: move count climbing (~30/s, not 60), then one click naming click me last — not just coordinates.

2 · Keyboard — the part that must be right

Expect in which keys mode: five · entries, and ctrl+s recorded literally. A shortcut is an action, not typed content.
Expect: zero characters recorded, in every mode, including “literal text”. The side panel should show the redaction counter going up.
Expect: nothing recorded — any page can opt a region out.

3 · Console

Expect: each appears in the live feed; errors in red. The huge object must be truncated, not inlined — and the page must keep working.

4 · Network

Expect: method, status and duration for each. The token request must appear as …?… with no SECRET anywhere, and no headers or bodies at all.

5 · Probes

Rows: 3 ·

In the side panel, run document.getElementById('rows').textContent — once, then on every click.
Expect: the value recorded each time, changing as you add rows. A probe that throws (window.__nope.boom) records the error and keeps recording.

6 · Volume & stopping

Expect: counts rise, the feed stays responsive, nothing is lost silently — if the cap is hit, dropped appears. Then Stop in the popup and confirm the counts freeze.

7 · The bundle

Take a 📸 screenshot, then Export bundle.
Expect a zip with report.md, session.json, events.json and images/shot-01.png. The report should lead with the console errors and failed requests, and list the clicks by name.
