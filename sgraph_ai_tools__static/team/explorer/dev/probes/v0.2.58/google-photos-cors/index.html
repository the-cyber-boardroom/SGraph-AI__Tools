BLOCKED — what the user must do first

This probe cannot run end-to-end until a Google OAuth client ID exists. Per plan §11, the user (Dinis) must complete the Google Cloud setup:

  1. Cloud Console → APIs & Services → Library → enable "Photos Picker API". Do NOT enable the legacy "Photos Library API" — it no longer grants library read access.
  2. Create an OAuth client of type Web application, dedicated to this tool (distinct from the YouTube one).
  3. Add Authorised JavaScript origins: the tool's hosting origin and the local-dev origin (e.g. http://localhost:8000) — whatever origin this probe page is served from. No redirect URI is needed (GIS token-client implicit flow).
  4. OAuth consent screen: External user type; add the scope https://www.googleapis.com/auth/photospicker.mediaitems.readonly; while unverified, add the user's Google account as a test user.
  5. Paste the resulting client ID into the field above and click Connect.

Note: serve this page over http://localhost or HTTPS — GIS and the Picker API will not work from file://.

What this probe gates

  • OAuth path is low-risk — reuses the proven requestAccess token-client pattern from core/youtube-upload.
  • The unknown is CORS on baseUrl downloads (step 5). If it PASSES, core/sg-google-photos can download media bytes directly in the browser (plan Phase 4). If it FAILS, the connector needs a proxy and the architecture changes.
  • Session-flow scaffolding here (createPickerSession, pollSession, listPickedItems, downloadMediaBytes) is the structural template for the future core/sg-google-photos module.
