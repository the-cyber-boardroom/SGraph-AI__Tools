## How to Read This Document

- **Layer** = core / component / tool (tool = user-facing page)
- **IFD versions** = count of patch versions shipped via IFD overlay methodology
- **Latest** = highest version number found in the directory tree
- **Status** = active (multiple IFD versions, clearly used) / stable (v1.0.0, no overlays) / experimental (v0.1.0 only, no overlays)
- **Manifest** = whether a `manifest.json` exists (✅ / ❌)

## 5. Findings & Recommendations

### 5.1 Missing Manifests (HIGH PRIORITY)

**26 modules/components lack `manifest.json` files** (was 23 in v0.1.64, +3 new components arrived without manifests).

| Group | Count | Items |

| VFS | 3 | All 3 |
| Agentic | 6 | All 6 |
| LLM | 1 | bundle-viewer |

### 5.2 Potential Duplications / Retirements

| Items | Issue | Recommendation |
|-------|-------|----------------|
| `sg-header`/`sg-footer` (F-03/F-04) | Confirmed superseded by `sg-site-header`/`sg-site-footer` per reality doc | **Deprecate** — verify no tool pages still import them, then mark deprecated |
| `sg-llm-attachments` (L-15) vs `sg-llm-attachment-manager` (L-14) | L-14 has 4 IFD versions, PDF/audio/video support; L-15 has 1 | **Clarify** — are they used in different contexts (one-shot vs chat)? If not, deprecate L-15 |
| `sg-llm-output` (L-06) vs `sg-llm-chat-history` (L-04) | Output is used by one-shot tools; chat-history by chat tools | **Keep both** — distinct use cases confirmed by tool page analysis |
| Vault Browser T-07 vs Vault T-17 | T-07 has 12+ inline JS modules not in components tree; T-17 uses proper components | **Assess retirement of T-07** — its inline vault-manager.js, vault-mermaid.js etc. are not reusable |
| `sg-openrouter-balance` (O-02) vs `sg-openrouter-key-stats` (O-08) | Key-stats is a richer replacement for balance (same API endpoint, more data) | **Assess** — balance may still be useful as compact badge; key-stats for detail view |

### 5.3 Non-Standard Directory Structure

| Module | Issue | Recommendation |
|--------|-------|----------------|
| `core/sg-layout/v0.1.0/` | Flat path, not IFD `v0/v0.1/v0.1.0/` | Low priority — well documented, version tracked in file header |
| `core/sg-tree` v0.1.1+ | Filename-versioned (`sg-tree--v0.1.1.js`) instead of directory-versioned | By design — IFD surgical override pattern using import chains |

### 5.4 High-Churn Components (Refactoring Candidates)

| Component | IFD Versions | Recommendation |
|-----------|-------------|----------------|
| `sg-llm-chat-history` | **11** | Extract markdown renderer, scroll manager, and image bubble handler into sub-modules |
| `sg-llm-bundle` | **8** | Storage backend stabilising — consider abstracting storage layer |
| `sg-llm-chat-input` | **6** | Attachment handling evolved significantly — consider splitting attachment logic from input UX |
| `sg-llm-request` | **5** | Provider-specific translation logic growing — consider per-provider adapters |
| `sg-llm-connection` | **5** | Stable surface but tracks provider API changes |

### 5.5 Dependency Graph

```
Foundation:  sg-component → sg-tokens
Crypto:      sg-crypto, sg-pbkdf2, sg-wordlist, sg-ssh
             sg-send-crypto → (sg-crypto patterns)
Vault:       sg-vault-client → sg-vault-write
             sg-vault-connect → (vault-client + vault-write)
             sg-vault-tree    → vault-client v1.1
             sg-vault-viewer  → (vault-client v1.1 + vault-write)
Simulator:   sg-send-sim → (sg-vfs + crypto derivation)
LLM:         sg-llm-events (shared bus — all LLM components)
             sg-llm-request (sole external API caller)
             sg-llm-chat-history ↔ sg-llm-chat-input (bidirectional)
             sg-llm-bundle ← sg-llm-bundle-list ← sg-llm-bundle-viewer
             sg-llm-infographic → sg-llm-events
VFS:         sg-vfs-core ← sg-vfs-bus ← (sg-vfs-event-viewer, sg-vfs-seeder)
Agentic:     sg-agentic-loop → (sg-llm-request + sg-tool-runner)
             sg-tool-runner → (sg-sandbox v0.2 + sg-vfs-bus)
             sg-tool-definition → sg-tool-runner (imports BUILTIN_TOOL_DEFS)
```
