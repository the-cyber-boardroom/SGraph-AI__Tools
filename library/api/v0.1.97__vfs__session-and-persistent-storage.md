# Capability Briefing — Virtual File System (VFS): session-only vs persistent local storage

**From:** SGraph-AI__Tools — `core/sg-vfs` + `components/vfs`
**Date:** 13 Aug 2026 · code-verified against the tools repo (`core/sg-vfs/v0/v0.1/v0.1.0/`, `components/vfs/**/v0.1.0/`)
**Answers:** the two storage modes you asked about —
**(a)** non-persistent, current-browser-session-only, and **(b)** persistent "local storage."

---

## TL;DR

There is a **deployed, importable, browser-only Virtual File System** with a **single unified API** (`VirtualFileSystem`) sitting over **pluggable storage providers**. You pick the storage mode by picking the provider — the file API above it never changes:

| You asked for | Use this provider | Survives reload? | Backing store |
|---|---|---|---|
| **(a) session-only** (current browser session) | **`MemoryProvider`** | ❌ no — gone on reload/tab-close | JS `Map` in RAM |
| **(b) persistent "local"** | **`IndexedDbProvider`** | ✅ yes | **IndexedDB** (browser-local, per-origin) |
| both (fast RAM cache over durable local) | **`LayeredProvider`** | ✅ yes (lower tier) | Memory tier + IndexedDB tier |

```js
import { VirtualFileSystem }  from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-core.js';
import { MemoryProvider }     from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-provider-memory.js';
import { IndexedDbProvider }  from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-provider-indexeddb.js';

// (a) session-only — lost on reload
const vfs = new VirtualFileSystem(new MemoryProvider());
await vfs.init();
await vfs.writeFile('/notes/hello.txt', 'hi');
await vfs.readFile('/notes/hello.txt');          // → 'hi'

// (b) persistent — survives reload, stored in IndexedDB
const pvfs = new VirtualFileSystem(new IndexedDbProvider({ dbName: 'my-app' }));
await pvfs.init();
await pvfs.writeFile('/notes/hello.txt', 'still here tomorrow');
```

**The same eleven methods work against every provider.** Swapping session ↔ persistent is a one-line change of which provider you construct.

## 1. Important clarification: "local storage" here means **IndexedDB**, not the `localStorage` API

You asked for "local storage." For a **file system**, the correct browser-local backend is **IndexedDB**, and that is what `IndexedDbProvider` uses — **not** the `window.localStorage` key/value API. This is deliberate:

| | `window.localStorage` | **IndexedDB** (what the VFS uses) |
|---|---|---|
| API | synchronous, blocks the main thread | asynchronous, off-thread |
| Capacity | ~5 MB per origin (small) | hundreds of MB → GB (quota-based) |
| Value types | **strings only** | strings **and binary** (Blob/ArrayBuffer), structured objects |
| Fit for files | poor (a real tree of files blows the 5 MB cap and stalls the UI) | designed for exactly this |

So: **both modes are "local"** (nothing ever leaves the browser — no server, no upload). The persistent one is local-and-durable via **IndexedDB**; the session one is local-and-ephemeral via **RAM**.

> For the record, the repo *does* use `window.localStorage` — but only for **small config** (the OpenRouter key, LLM connection bundles, spend caches, vault-connect key). It is never used to store a file tree. That's what the VFS + IndexedDB is for.

## 2. The unified API (`VirtualFileSystem`)

`core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-core.js` — `class VirtualFileSystem`.

```js
const vfs = new VirtualFileSystem(provider, { bus /* optional DOM element */ });
await vfs.init();          // MUST be called before any op (opens the provider)
vfs.providerName;          // 'memory' | 'indexeddb' | 'layered'
```

Eleven async operations, identical across all providers:

| Method | Returns | Notes |
|---|---|---|
| `readFile(path)` | `Promise<string>` | file content as a string |
| `writeFile(path, content)` | `Promise<void>` | create/overwrite; **auto-creates parent folders** (`mkdir -p`) |
| `deleteFile(path)` | `Promise<void>` | |
| `listFolder(path)` | `Promise<Array>` | direct children: `{ name, path, type, size, modified }`, folders first |
| `stat(path)` | `Promise<object>` | `{ path, type, size, created, modified }` |
| `createFolder(path)` | `Promise<void>` | and parents |
| `copyFile(src, dst)` | `Promise<void>` | |
| `rename(src, dst)` | `Promise<void>` | move/rename |
| `exists(path)` | `Promise<boolean>` | |

Paths are **POSIX-style, absolute** (`/a/b/c.txt`), validated on every call. `size` is the **byte length** (`TextEncoder`), not string length. Errors carry POSIX-ish codes: `ENOENT` (not found), `EISDIR` (is a folder), `ENOTDIR` (not a folder).

**Content model:** files store **string** content. To keep **binary** (images, audio, PDFs) you store it as a string — the production `folder-editor` tool does this by base64-encoding binary into a `data:` URL string and decoding on read. (A future provider revision may store Blobs natively in IndexedDB; today, strings/base64 is the contract.)

## 3. (a) Session-only — `MemoryProvider`

`sg-vfs-provider-memory.js` — a plain in-memory `Map`. **Data lives only for the current page session and is lost on reload or tab close.** Zero latency, no persistence, no quota. Ideal for scratch workspaces, tests, previews, and as the fast tier of a layered stack.

```js
import { VirtualFileSystem } from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-core.js';
import { MemoryProvider }    from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-provider-memory.js';

const vfs = new VirtualFileSystem(new MemoryProvider());
await vfs.init();

await vfs.createFolder('/project/src');
await vfs.writeFile('/project/src/app.js', 'console.log(1)');
await vfs.listFolder('/project/src');   // [{ name:'app.js', type:'file', size:14, ... }]
// reload the page → everything above is gone.
```

Extras: `provider.clear()` resets to an empty root; `provider.size` returns the entry count.

## 4. (b) Persistent local — `IndexedDbProvider`

`sg-vfs-provider-indexeddb.js` — one IndexedDB object store (`entries`) keyed by path. **Survives reloads, tab closes, and browser restarts**, scoped to the page's origin. Same API as above.

```js
import { VirtualFileSystem }  from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-core.js';
import { IndexedDbProvider }  from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-provider-indexeddb.js';

const vfs = new VirtualFileSystem(new IndexedDbProvider({
  dbName:    'my-app-vfs',   // optional, default 'sg-vfs' — use your own to isolate apps
  namespace: '/project',     // optional path prefix
}));
await vfs.init();

await vfs.writeFile('/project/README.md', '# persists across reloads');
// close the tab, come back tomorrow, same origin:
await vfs.readFile('/project/README.md');   // → '# persists across reloads'
```

- **`dbName`** picks the IndexedDB database — give each app its own so they don't collide.
- **`clear()`** wipes the store (keeps an empty root).
- Because it's IndexedDB, it comfortably holds far more than `localStorage` and never blocks the UI thread.

**Reference in production:** the `folder-editor` tool uses exactly this — an IndexedDB VFS (`db: sg-folder-editor-v1`), drag a real OS folder in, stores text as strings + binary as base64 data URLs, writes a manifest at `/fe/current/.manifest.json`, and **restores the whole tree on reload.**

## 5. Both at once — `LayeredProvider`

`sg-vfs-provider-layered.js` — tiered storage. Register providers with a **priority** (lower = faster/checked first). The canonical stack is **Memory (0) over IndexedDB (1)**: reads hit RAM first and fall through to IndexedDB (back-filling RAM on the way up); writes go **write-through** to every tier.

```js
import { VirtualFileSystem } from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-core.js';
import { LayeredProvider }   from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-provider-layered.js';
import { MemoryProvider }    from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-provider-memory.js';
import { IndexedDbProvider } from 'https://tools.sgraph.ai/core/sg-vfs/v0/v0.1/v0.1.0/sg-vfs-provider-indexeddb.js';

const layered = new LayeredProvider();
layered.addProvider(new MemoryProvider(),    0);  // fast, ephemeral
layered.addProvider(new IndexedDbProvider(), 1);  // durable, local
const vfs = new VirtualFileSystem(layered);
await vfs.init();   // inits all layers
// writes land in RAM *and* IndexedDB; reads are RAM-fast but survive reload via the IDB tier.
```

The priority model is designed to extend to a third tier — a **remote `VaultProvider`** (authoritative, 50–500 ms) — so the same file API can later span RAM → local IndexedDB → encrypted remote vault with no call-site changes. The event vocabulary already reserves `PROVIDER_HIT` / `PROVIDER_MISS`, write-queue drain, and vault-commit events for this.

## 6. Components (drop-in UI, no wiring)

`components/vfs/**/v0/v0.1/v0.1.0/` — three Web Components that talk to the VFS purely through DOM events on a `[data-vfs-bus]` ancestor, so they need **no JS references** to the VFS instance:

| Element | Role |
|---|---|
| **`<sg-vfs-bus>`** | Headless. Owns a `VirtualFileSystem`, mounts it on the nearest `[data-vfs-bus]`, and routes `vfs:*-request` events to operations. **Pick the mode via the `provider` attribute.** Exposes `.vfs` for direct calls. |
| **`<sg-vfs-event-viewer>`** | Live observability: Timeline / Operations / Providers / Latency tabs — every request/response with `wallTime` and which provider served it. |
| **`<sg-vfs-seeder>`** | One-click seeding of sample trees for demos/tests. |

```html
<div data-vfs-bus>
  <!-- (a) session-only: -->      <sg-vfs-bus provider="memory"></sg-vfs-bus>
  <!-- (b) persistent local: -->  <!-- <sg-vfs-bus provider="indexeddb" db-name="my-app"></sg-vfs-bus> -->
  <!-- both (layered): -->        <!-- <sg-vfs-bus provider="layered"></sg-vfs-bus> -->

  <sg-vfs-event-viewer></sg-vfs-event-viewer>
</div>
<script type="module">
  import 'https://tools.sgraph.ai/components/vfs/sg-vfs-bus/v0/v0.1/v0.1.0/sg-vfs-bus.js';
  import 'https://tools.sgraph.ai/components/vfs/sg-vfs-event-viewer/v0/v0.1/v0.1.0/sg-vfs-event-viewer.js';
</script>
```

The `provider` attribute is the single switch between your two requested modes: `"memory"` (default) = session-only; `"indexeddb"` (with optional `db-name`) = persistent local; `"layered"` = Memory@0 + IndexedDB@1.

**Event bridge, briefly:** children dispatch `vfs:read-request` / `vfs:write-request` / … (with a `requestId`); `sg-vfs-bus` executes them and `VirtualFileSystem` dispatches `vfs:*-response` (or `vfs:error`) back on the same bus, carrying `{ requestId, path, result, provider, wallTime, timestamp }`. All event-name constants live in `sg-vfs-events.js` (`SGL_VFS.*`). This is what lets the event-viewer observe everything and lets components stay decoupled.

## 8. Import / CORS / hosting

- **All of the above is importable cross-origin from `tools.sgraph.ai`**, which serves `Access-Control-Allow-Origin: *` (confirmed live). ESM `import` straight from the pinned URLs — **no build step, no bundler, no server**.
- **100% client-side.** Nothing is uploaded; both modes keep every byte in the user's browser (RAM for session, IndexedDB for persistent).
- **Versioning:** pin to `…/v0/v0.1/v0.1.0/…` for immutability in production; the component `<sg-vfs-bus>` uses root-relative imports (`/core/sg-vfs/…`) so it resolves against whatever origin serves it.

## 9. Choosing — quick guide

- **Scratch space that must vanish when the tab closes** → `MemoryProvider` (a).
- **Keep the user's files between visits, no account, no server** → `IndexedDbProvider` (b).
- **Fast interaction now + durable local later, one API** → `LayeredProvider` (memory@0 + indexeddb@1).
- **Later, sync to an encrypted remote** → add a `VaultProvider` tier; call sites don't change.
