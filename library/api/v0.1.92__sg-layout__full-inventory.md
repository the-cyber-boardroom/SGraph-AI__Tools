## 2. Element registration and attributes

- **Tag:** `<sg-layout>`
- **Shadow DOM:** open mode; styles embedded as a `<style>` tag inside the shadow root.
- **`observedAttributes`:** `['layout']`
  - The `layout` attribute accepts a JSON string. When set or changed on a connected element, it triggers `setLayout(JSON.parse(value))`.
  - In most code, prefer the `setLayout()` method directly over setting the attribute as a string.

## 5. Events (`SGL_EVENTS`)

All event names are frozen string constants. Apart from `REGISTER`, events flow on the **internal event bus** accessed via `layout.events`, **not** as DOM CustomEvents. `addEventListener` on `<sg-layout>` will silently miss them.

```javascript
import { SGL_EVENTS } from 'https://tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout-events.js';
```

### 5.1 Layout signals (internal bus)

| Constant              | String value         | When                                       | `detail`                |
|-----------------------|----------------------|--------------------------------------------|-------------------------|
| `LAYOUT_READY`        | `'layout:ready'`     | First successful mount complete            | `{}`                    |
| `LAYOUT_CHANGED`      | `'layout:changed'`   | Any mutation: resize, dock, add/remove/focus | `{ tree }` (full JSON)  |

### 5.2 Panel lifecycle (internal bus)

| Constant         | String value      | When                                       | `detail`                       |
|------------------|-------------------|--------------------------------------------|--------------------------------|
| `PANEL_RESIZED`  | `'panel:resized'` | Panel size changed (debounced)             | `{ id, width, height }`        |
| `PANEL_FOCUSED`  | `'panel:focused'` | **Defined but not emitted in v0.1.0**      | `{ id }` (planned)             |
| `PANEL_HIDDEN`   | `'panel:hidden'`  | Tab is no longer the active tab in its stack | `{ id }`                     |
| `PANEL_SHOWN`    | `'panel:shown'`   | Tab became the active tab in its stack     | `{ id }`                       |
| `PANEL_CLOSED`   | `'panel:closed'`  | Tab closed via × button or `removePanel`   | `{ id }`                       |

### 5.3 Tabs (internal bus)

| Constant       | String value     | When                                       | `detail`                |
|----------------|------------------|--------------------------------------------|-------------------------|
| `TAB_CHANGED`  | `'tab:changed'`  | Active tab changed in a stack              | `{ stackId, tabId }`    |

### 5.4 Drag & dock (internal bus)

| Constant     | String value             | When                                  | `detail`                                  |
|--------------|--------------------------|---------------------------------------|-------------------------------------------|
| `DRAG_START` | `'sg-layout:drag-start'` | Drag threshold (5px) crossed on a tab | `{ panelId, sourceLayoutId }`             |
| `DRAG_END`   | `'sg-layout:drag-end'`   | Drag ends (drop or cancel)            | `{ panelId, accepted: boolean }`          |

### 5.5 Register (DOM CustomEvent)

| Constant   | String value          | Where dispatched                              | `detail`            | Bubbles / Composed |
|------------|-----------------------|-----------------------------------------------|---------------------|--------------------|
| `REGISTER` | `'sg-layout:register'`| Dispatched **by hosted custom elements** that want to be parented by an `<sg-layout>` ancestor (this is the fractal-nesting hook) | `{ respond }`       | yes / yes          |

The parent layout listens for this event, calls `detail.respond({ layout, depth })`, and the child stores the parent reference. Use this only if you are implementing a custom element that needs to know which `<sg-layout>` it lives inside.

### 5.6 Commands (incoming — consumers dispatch these)

| Constant            | String value                 | What it does                                   | `detail`         |
|---------------------|------------------------------|------------------------------------------------|------------------|
| `CMD_FOCUS_PANEL`   | `'sg-layout:focus-panel'`    | Listened for: focuses a panel by id            | `{ id }`         |

In practice, prefer the public methods (`focusPanel`, `addPanel`, etc.) over dispatching command events.

## 6. Layout JSON schema

The tree passed to `setLayout()` (and returned by `getLayout()`) is a recursive structure with three node kinds and one leaf kind.

```typescript
type Tree = Row | Column | Stack;

interface Row {
  type:      'row';
  id?:       string;        // auto-assigned if omitted
  sizes?:    number[];      // fractions of 1.0, one per child; defaults to equal
  children:  Tree[];
}

interface Column {
  type:      'column';
  id?:       string;
  sizes?:    number[];
  children:  Tree[];
}

interface Stack {
  type:       'stack';
  id?:        string;
  activeTab?: number;       // zero-based index into tabs; default 0
  tabs:       Tab[];
}

interface Tab {
  type?:   'tab';            // optional discriminator (defaults to 'tab')
  id?:     string;
  tag:     string;           // custom element tag to instantiate
  title?:  string;
  state?:  Record<string, any>; // any JSON; rehydratable
  locked?: boolean;
}
```

**Tab `state` behaviour:** the layout does not modify `state`; it is preserved verbatim across `getLayout()` / `setLayout()` round-trips. Use it for whatever your hosted custom element needs to rehydrate. The element can read it from properties the layout copies onto it, or you can read it from the tree returned by `getLayout()`.

**Nested layout:** to embed an `<sg-layout>` inside a tab, set `tag: 'sg-layout'`. The serialization helper captures the nested layout's tree under `state.layout` (in `getLayout()` output). When restoring, the layout passes `state.layout` as the `layout` attribute on the nested element before connecting.

## 7. Hosted-element contract — registration and metadata

When the layout instantiates a tab, it:

1. Creates an element of `tag` via `document.createElement(tag)`.
2. Appends it to the layout's light DOM (`<sg-layout>.appendChild(el)`).
3. Sets `el.slot = "p-<tabId>"` so the browser projects it into the shadow DOM slot.
4. Sets metadata on the element:
   - `el._sgLayoutRef` — back-reference to the parent `<sg-layout>` instance.
   - `el.dataset.panelId` — the tab id.
   - `el.dataset.layoutDepth` — the nesting depth.
   - `el.dataset.panelTitle` — the tab title (if set).

If the tab `tag` is itself `sg-layout`:

5. The nested element's `connectedCallback` dispatches a `sg-layout:register` CustomEvent (`bubbles: true, composed: true`).
6. The parent catches it via its document-level listener, calls `respond({ layout: parent, depth: parent.depth + 1 })`, and adds the child to its `_childLayouts` map.
7. The child's `dataset.depth` is set so depth-aware CSS rules apply.

Hosted elements **do not need to implement REGISTER themselves** unless they want a back-reference. The metadata via `el.dataset.*` is enough for most consumers.

## 8. Drag-to-dock

- **Threshold:** 5 pixels of pointer movement on a tab before drag starts (`SgLayout.DRAG_THRESHOLD = 5`).
- **Drag affordance:** the dragged tab follows the pointer as a ghost element. The layout shows a 5-zone overlay on the panel under the pointer.
- **Zones:**

  ```
  +-----------+-----------+
  |           |           |
  |   top    [           |
  |           |           |
  +-----[ center ]--------+
  |           |           |
  |           |  right    |
  |           |           |
  +-----------+-----------+
              bottom
  ```

  - `center` — add as a new tab to the target stack
  - `top` / `bottom` — split the target into a column; new tab becomes a sibling above or below
  - `left` / `right` — split into a row; new tab becomes a sibling left or right

- **Locked panels** never accept drops and their tabs cannot be dragged.
- Drag emits `DRAG_START` then `DRAG_END { accepted }` where `accepted` is `true` if the drop landed in a zone.

## 9. Resize handles

- Automatically inserted between adjacent children of `row` and `column` nodes.
- Width/height controlled by `--sgl-handle-size` (default 4px).
- Use pointer-capture for smooth resizing.
- Respect a `fixedSize` flag on tree nodes (set programmatically) — a fixed-size child does not get resize handles on its locked edges.
- Enforce `--sgl-min-panel-size` (default 80px) as the minimum size for any panel during resize.
- Emit `PANEL_RESIZED { id, width, height }` and `LAYOUT_CHANGED { tree }` on completion.

## 10. Locked panels

- `lockPanel(id)` / `unlockPanel(id)` / `isPanelLocked(id)` on the layout instance.
- A tab declared with `locked: true` in the tree starts locked.
- A locked tab:
  - cannot be dragged
  - cannot be the target of a drop
  - has no close (×) button
  - is not removed by `removePanel()` calls (silently ignored — call `unlockPanel` first if needed)

Use this for fixed UI chrome (file trees, persistent toolbars).
