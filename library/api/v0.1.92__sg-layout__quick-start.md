# sg-layout — Quick Start for Consumer Agents

**Version:** v0.1.92
**Audience:** AI agents and developers building tools on top of `<sg-layout>` — the fractal window/panel custom element used by every tool on tools.sgraph.ai.
**Companion doc:** `v0.1.92__sg-layout__full-inventory.md` — every method, event, attribute, and CSS variable.

This document covers the **common patterns** you need to build a typical tool layout: declare panels, host custom elements inside them, react to lifecycle events, and theme it. It is modelled on the actual usage in `vault-peek/ui/ui-layout.js` and `tests/sg-layout/v0.1.0.test.html`.

---

## 1. What `<sg-layout>` is (30 seconds)

A single custom element that renders a **tree of resizable, tabbed, draggable panels**. Each leaf in the tree (a "tab") hosts one custom element of your choosing.

- **Rows and columns** with drag-to-resize splitters
- **Tab stacks** — multiple tabs in one panel; click to switch
- **Drag-to-dock** — tear a tab off and drop it on top / left / center / right / bottom of any panel
- **Fractal nesting** — a tab can itself contain a nested `<sg-layout>` and recurse
- **Lockable panels** — disable drag/drop/close for fixed UI chrome
- **Serializable** — `getLayout()` → JSON, `setLayout(json)` → restore

Build your tool by composing your own custom elements (e.g. `<my-tree>`, `<my-viewer>`) and letting `<sg-layout>` host them.

---

## 2. The five things you actually need

```javascript
import 'https://tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout.js';
import { SGL_EVENTS } from 'https://tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout-events.js';
```

1. **A `<sg-layout>` element in the DOM** with a size.
2. **A layout tree as JSON**, passed via `setLayout()`.
3. **Custom elements registered as tab tags** (`my-tree`, `my-viewer`, etc).
4. **A few event listeners** on `layout.events` for `LAYOUT_READY`, `LAYOUT_CHANGED`, `PANEL_CLOSED`.
5. **Optional:** override CSS custom properties for theming.

Everything else (resize handles, tab bars, drag-to-dock, slot wiring) is automatic.

## 3. Minimum working example

```html
<!doctype html>
<html lang="en-gb">
<head>
  <meta charset="utf-8">
  <title>sg-layout quick start</title>
  <script type="module" src="https://tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout.js"></script>
  <style>
    html, body { height: 100%; margin: 0; }
    sg-layout { display: block; width: 100%; height: 100%; }
  </style>
</head>
<body>
  <sg-layout id="root"></sg-layout>

  <script type="module">
    import { SGL_EVENTS } from 'https://tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout-events.js';

    const LAYOUT = {
      type: 'row',
      sizes: [0.30, 0.70],
      children: [
        {
          type: 'stack',
          tabs: [
            { tag: 'div', title: 'Files', locked: true, state: { text: 'tree goes here' } },
          ],
        },
        {
          type: 'stack',
          tabs: [
            { tag: 'div', title: 'Welcome', state: { text: 'hello' } },
          ],
        },
      ],
    };

    customElements.whenDefined('sg-layout').then(() => {
      const root = document.getElementById('root');
      root.setLayout(LAYOUT);

      root.events.on(SGL_EVENTS.LAYOUT_READY,  () => console.log('layout ready'));
      root.events.on(SGL_EVENTS.PANEL_CLOSED,  ({ id }) => console.log('closed', id));
      root.events.on(SGL_EVENTS.LAYOUT_CHANGED,({ tree }) => localStorage.setItem('lo', JSON.stringify(tree)));
    });
  </script>
</body>
</html>
```

That's a complete two-column layout with a locked file-tree panel on the left and a single welcome tab on the right. Resize the splitter, drag the right tab, etc — it all works.

## 4. The layout JSON tree

The tree is a recursive structure with three node types:

```
row    → { type: 'row',    sizes?: [0.3, 0.7],   children: [...nodes] }
column → { type: 'column', sizes?: [0.5, 0.5],   children: [...nodes] }
stack  → { type: 'stack',  activeTab?: 0,        tabs: [...tabs] }

tab    → { tag: 'my-element', title?: 'Files',
           state?: { …any json }, locked?: false }
```

Rules:

- **Root** must be a `row`, `column`, or `stack`.
- **Stacks are the leaves of the tree** and contain one or more tabs.
- **Tab order** in the array is the visible tab order; `activeTab` is the zero-based index of the open tab.
- **`sizes`** is optional. If omitted, children are sized equally. Values are fractions of 1.0.
- **`tag`** is the custom element to mount in that tab (e.g. `'my-tree'`, `'div'` for an empty container).
- **`state`** is JSON your custom element can read from `this.dataset` or from properties the layout copies onto it. Use it for initial config.
- **`locked: true`** prevents the tab from being dragged, dropped onto, or closed.

To nest `<sg-layout>` inside a tab (fractal), set `tag: 'sg-layout'` and pass a child tree in `state.layout`. The full nesting model is covered in the full inventory doc.

## 5. How content gets into a panel — the REGISTER protocol

You do **not** assign hosted elements via `slot="…"`. Instead, when `<sg-layout>` mounts a tab it creates an element of `tag`, appends it to the layout's light DOM, sets `element.slot = "p-<tabId>"`, and projects it into a named slot in the shadow DOM.

For your custom element this means:

- It is created by the layout — you don't `document.createElement` it yourself.
- It receives metadata via standard browser hooks:
  - `el._sgLayoutRef` — the parent `<sg-layout>` instance
  - `el.dataset.panelId` — the tab id (use this to call `layout.focusPanel(panelId)` etc)
  - `el.dataset.layoutDepth` — nesting depth (0 = top level)
  - `el.dataset.panelTitle` — title string

If you want to **nest another `<sg-layout>` inside a tab**, the child element dispatches a `sg-layout:register` CustomEvent in its `connectedCallback`. The parent layout catches it (it bubbles + composed) and wires up the parent/child relationship automatically. You don't need to do anything else — just use `tag: 'sg-layout'`.

A custom element that wants to participate as a fractal child looks like:

```javascript
class MyNestedThing extends HTMLElement {
  connectedCallback() {
    this.dispatchEvent(new CustomEvent('sg-layout:register', {
      bubbles: true,
      composed: true,
      detail: {
        respond: ({ layout, depth }) => {
          this._parentLayout = layout;
          this._depth = depth;
        },
      },
    }));
  }
}
```

Most consumers will never write this — they just use `<sg-layout>` itself as the tag.

## 6. The 5 methods you'll actually use

```javascript
// Replace the entire layout
layout.setLayout(LAYOUT_JSON);

// Add a new tab to an existing stack (the common pattern: "open file in viewer")
const stackId = /* a stack id, see below */;
const tabId = layout.addTabToStack(stackId, {
  tag: 'my-viewer',
  title: 'README.md',
  state: { path: '/README.md' },
});

// Add a brand-new panel (creates a stack at the root)
const id = layout.addPanel({ tag: 'my-help', title: 'Help' });

// Close a tab
layout.removePanel(tabId);

// Switch to a tab
layout.focusPanel(tabId);
```

Finding a stack id: stacks generated from `setLayout()` get auto-assigned ids. Either set `id: 's1'` explicitly on stack nodes in your tree, or read the current tree with `layout.getLayout()` and pick one.

The full method list (15 methods including `getLayout`, `lockPanel`, `walkLayouts`, etc) is in the inventory doc.

## 7. Events — `layout.events`, not `addEventListener`

**This trips people up.** Apart from the bubble-up `sg-layout:register` event, `<sg-layout>` does **not** dispatch DOM CustomEvents. It uses an internal event bus exposed as the `.events` property.

```javascript
//  WRONG — silent no-op
layout.addEventListener('layout:changed', handler);

//  RIGHT
layout.events.on(SGL_EVENTS.LAYOUT_CHANGED, handler);
```

The events you'll want most often:

| Event                       | When                                                                 | `event.detail`               |
|-----------------------------|----------------------------------------------------------------------|------------------------------|
| `SGL_EVENTS.LAYOUT_READY`   | First successful `setLayout()` finished mounting                     | `{}`                         |
| `SGL_EVENTS.LAYOUT_CHANGED` | Any tree mutation (resize, dock, add/remove/focus tab)               | `{ tree }` — full JSON       |
| `SGL_EVENTS.PANEL_CLOSED`   | A tab was closed (× button or `removePanel`)                         | `{ id }`                     |
| `SGL_EVENTS.TAB_CHANGED`    | Active tab changed in a stack                                        | `{ stackId, tabId }`         |
| `SGL_EVENTS.PANEL_RESIZED`  | A panel changed size (debounced)                                     | `{ id, width, height }`      |

`LAYOUT_CHANGED` is what you want for persisting state — save `event.detail.tree` to `localStorage` and restore via `setLayout()` on next load.

The full event list (10 events) and the small set of incoming command events the layout listens for are in the inventory doc.

## 8. Theming

The shadow DOM uses CSS custom properties for all colours and sizes. Override them on `<sg-layout>` (or any ancestor) to retheme without forking:

```css
sg-layout {
  --sgl-bg:             #ffffff;
  --sgl-surface:        #f4f5f7;
  --sgl-surface-hover:  #e9ecef;
  --sgl-border:         #d0d4dc;
  --sgl-accent:         #2563eb;
  --sgl-text:           #1f2937;
  --sgl-text-muted:     #6b7280;
  --sgl-handle-size:    4px;
  --sgl-panel-header-height: 32px;
  --sgl-min-panel-size: 80px;
}
```

The default theme is dark. The component embeds its own `<style>` tag inside its shadow DOM, so you do **not** need to import `sg-layout.css` separately — that file exists only for sites that want the default custom-property values applied document-wide.

## 9. Persisting layout state

```javascript
// Save on every change
layout.events.on(SGL_EVENTS.LAYOUT_CHANGED, ({ tree }) => {
  localStorage.setItem('my-tool.layout', JSON.stringify(tree));
});

// Restore on load
const saved = localStorage.getItem('my-tool.layout');
layout.setLayout(saved ? JSON.parse(saved) : DEFAULT_LAYOUT);
```

The tree returned by `getLayout()` (and emitted in `LAYOUT_CHANGED.detail.tree`) is a pure-JSON serialisation — no element references, safe to stringify. Tab `state` is preserved verbatim, so your custom elements can rehydrate from it.

## 10. CORS, hostnames, version pinning

- **CDN:** `https://tools.sgraph.ai/core/sg-layout/v0.1.0/` — served with permissive CORS for cross-origin ESM imports.
- **Three files:**
  - `sg-layout.js` — the element (registers `<sg-layout>` on import as a side effect)
  - `sg-layout-events.js` — the `SGL_EVENTS` frozen constants
  - `sg-layout.css` — optional, defines default values for the CSS custom properties on `:root`
- **Pin to v0.1.0.** This is the only published version. The internal implementation has iterated to v0.1.4 but the public API (events, methods, JSON schema) is frozen at v0.1.0. New features arrive under new minor versions.
- **Flat path.** Note the path is `core/sg-layout/v0.1.0/` — not the triple-nested `v0/v0.1/v0.1.0/` pattern used by some other modules. This is intentional; it's the one core module on a flat layout (see `library/catalogue/v0.1.91__catalogue__core.md` for the exception note).

## 11. End-to-end example: a small tool

```html
<!doctype html>
<html lang="en-gb">
<head>
  <meta charset="utf-8">
  <title>My tool</title>
  <script type="module" src="https://tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout.js"></script>
  <style>
    html, body { height: 100%; margin: 0; background: #1A1A2E; }
    sg-layout  { display: block; width: 100%; height: 100%; }
  </style>
</head>
<body>
  <sg-layout id="app"></sg-layout>

  <script type="module">
    import { SGL_EVENTS } from 'https://tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout-events.js';

    class MyTree extends HTMLElement {
      connectedCallback() {
        this.innerHTML = '<ul><li>file-a.md</li><li>file-b.md</li></ul>';
        this.addEventListener('click', (e) => {
          const name = e.target.textContent;
          this.dispatchEvent(new CustomEvent('open-file', {
            bubbles: true, composed: true, detail: { name },
          }));
        });
      }
    }
    customElements.define('my-tree', MyTree);

    class MyViewer extends HTMLElement {
      connectedCallback() {
        const title = this.dataset.panelTitle || 'untitled';
        this.innerHTML = `<h2>${title}</h2><p>content of ${title}</p>`;
      }
    }
    customElements.define('my-viewer', MyViewer);

    const LAYOUT = {
      type: 'row',
      sizes: [0.25, 0.75],
      children: [
        { type: 'stack', id: 'left',  tabs: [{ tag: 'my-tree', title: 'Files', locked: true }] },
        { type: 'stack', id: 'right', tabs: [{ tag: 'div',     title: 'Welcome' }] },
      ],
    };

    customElements.whenDefined('sg-layout').then(() => {
      const app = document.getElementById('app');
      app.setLayout(LAYOUT);

      app.events.on(SGL_EVENTS.LAYOUT_CHANGED, ({ tree }) => {
        localStorage.setItem('my-tool.layout', JSON.stringify(tree));
      });

      document.addEventListener('open-file', ({ detail: { name } }) => {
        app.addTabToStack('right', { tag: 'my-viewer', title: name });
      });
    });
  </script>
</body>
</html>
```

That's a fully-functional file-tree-and-viewer tool: click a file name in the left panel and it opens as a new tab on the right. Drag tabs around, resize the splitter, close tabs with × — all free.
