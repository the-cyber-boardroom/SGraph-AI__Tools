## Architect Notes

**Why this matters:** Once a tool has the API, it can be:
- Driven by Playwright for CI smoke tests with zero UI dependencies
- Called by other tools (e.g. agentic loop driving infographic-gen headlessly)
- Scripted from the browser console during development
- Documented via auto-discovered SKILL files that LLM agents can read

**The pattern scales.** Every tool gets the dev panel (console/explorer/manifest) for free
the moment it calls `activate()`. No per-tool UI work needed.

**Key invariant:** The UI must never be the only path to tool functionality. If something
can only be done through clicking the UI, it is not yet part of the API.

## Dev Notes

**Effort per tool:** ~1–3 hours to add the API layer to an existing tool.
- The implementation functions already exist — `register()` wraps them.
- The hard part is writing complete SKILL files (especially SKILL-api.md).

**Recommended approach:** Add API to one tool per sprint alongside normal IFD work.
Do not retrofit all tools at once — the infographic pattern will evolve slightly
as more tools adopt it.

**Next candidate:** `chat` — highest traffic, methods are obvious from existing UI.
