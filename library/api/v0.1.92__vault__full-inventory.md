# Vault Components — Full Inventory for Consumer Agents

**Version:** v0.1.92
**Audience:** AI agents and developers who need the complete list of vault-related modules, components, and tools available at `https://tools.sgraph.ai`, with import URLs and capability summaries.
**Companion doc:** `v0.1.92__vault__quick-start.md` — the small, common subset for read-only embedding.

This document is a code-verified catalogue. Every entry has been confirmed against the repository as of project version v0.1.92. For prose explanations of the embed flow, manifest schema, and CORS expectations, read the quick-start guide first.

---

## Layers at a glance

```
core/                            # Pure JS modules — crypto, fetch, mutations, sessions, tree
  vault-client          read APIs
  vault-write           write APIs (build commits, encrypt blobs, derive write keys)
  vault-cache           Cache API wrapper for immutable objects
  vault-tree-model      In-memory tree with STUB/LOADED node states
  vault-session         Two-branch session orchestrator
  vault-mutations       High-level add/update/remove/rename/move/copy file/folder
  vault-init            Bootstrap a brand-new vault from a friendly token

components/vault-embed/           # Read-only custom elements (no globals, no localStorage)
  sg-vault-key, sg-vault-fetch, sg-vault-content, sg-vault-manifest, sg-vault-trace

components/content/               # Content renderers consumed by sg-vault-fetch
  sg-content-markdown, sg-content-image, sg-content-json

components/vault/                 # Interactive read/write custom elements (use [data-vault-bus])
  sg-vault-connect, sg-vault-tree, sg-vault-viewer, sg-vault-file-preview,
  sg-vault-file-ops, sg-vault-commit-log, sg-vault-sync-status,
  sg-vault-create, sg-vault-manager, sg-vault-picker

tools/                            # Standalone vault pages on tools.sgraph.ai
  vault, vault-mgr, vault-browser, vault-pyodide, vault-embed-demo, vault-peek
```

**CDN:** All paths below are mounted under `https://tools.sgraph.ai/`. The default vault API endpoint used by every read/write component is `https://send.sgraph.ai` and can be overridden per element or per session.

**Version pinning:** Every URL in this doc is pinned (`v0/v0.MAJOR/v0.MAJOR.MINOR/`). Pinned content is immutable. Production consumers should not use rolling paths.

## 1. Core modules (`core/`)

All core modules are framework-free ES modules with named exports. They are the same building blocks used by every vault component and tool.

### 1.1 `vault-client` — read operations

- **Path:** `core/vault-client/v1/v1.2/v1.2.2/sg-vault-client.js`
- **Import:** `https://tools.sgraph.ai/core/vault-client/v1/v1.2/v1.2.2/sg-vault-client.js`
- **Purpose:** Read-side crypto, key derivation, vault open, file read, tree walking.
- **Key exports:** `importReadKey(readKeyBase64Url)`, `parseVaultKey(fullKey)`, `deriveVaultKeys(passphrase, vaultId)`, `openVault(keys, options)`, `readFile(vault, filePath)`, `readFileAsJson(vault, filePath)`, `fetchSubTree(vault, treeId)`, `encryptMetadata(plainObj, key)`, `decryptMetadata(encryptedBase64, key)`, `computeObjectId(ciphertext)`, `fileIdToPath(objectId)`, `formatFileId(path)`, `parseFileId(fileId)`, `decryptField(encField, key)`, `walkTree(entries)`.

### 1.2 `vault-write` — write operations

- **Path:** `core/vault-write/v1/v1.1/v1.1.1/sg-vault-write.js`
- **Import:** `https://tools.sgraph.ai/core/vault-write/v1/v1.1/v1.1.1/sg-vault-write.js`
- **Purpose:** Encrypt+upload blobs, build commit/tree/ref objects, derive write keys.
- **Key exports:** `writeVaultFile(vault, filePath, content, options)`, `buildSubTrees(entries, keys)`, `deriveWriteKeys(passphrase, vaultId)`, `deriveWriteKeysFromSimpleToken(token)`, `encryptMetadata(plainObj, key)`, `decryptMetadata(encryptedBase64, key)`, plus `IV_LENGTH` constant.

### 1.3 `vault-cache` — Cache API read-through

- **Path:** `core/vault-cache/v1/v1.0/v1.0.0/sg-vault-cache.js`
- **Import:** `https://tools.sgraph.ai/core/vault-cache/v1/v1.0/v1.0.0/sg-vault-cache.js`
- **Purpose:** Thin wrapper over the browser Cache API for immutable (`obj-cas-imm-*`) objects. Cached entries are permanent until explicitly cleared.
- **Key exports:** `cachedFetch(apiBaseUrl, vaultId, objectId, readKey)`, `cachedFetchJson(...)`, `cachedFetchRaw(...)`, `fetchRef(...)`, `clearCache()`, `getCacheStats()`.

### 1.4 `vault-tree-model` — in-memory tree

- **Path:** `core/vault-tree-model/v1/v1.0/v1.0.0/sg-vault-tree-model.js`
- **Import:** `https://tools.sgraph.ai/core/vault-tree-model/v1/v1.0/v1.0.0/sg-vault-tree-model.js`
- **Purpose:** Mutable tree representation with STUB (folder summary only) and LOADED (children populated) node states. Underpins vault-session.
- **Key exports:** `createTreeModel()` → instance with `loadRoot(entries)`, `loadSubTree(path, entries)`, `getRoot()`, `getNode(path)`, `insertFile(folderPath, name, entry)`, `updateFile(...)`, `removeFile(...)`, `createFolder(folderPath, name)`, `buildTreeEntries(node)`.

### 1.5 `vault-session` — orchestrator

- **Path:** `core/vault-session/v1/v1.0/v1.0.0/sg-vault-session.js`
- **Import:** `https://tools.sgraph.ai/core/vault-session/v1/v1.0/v1.0.0/sg-vault-session.js`
- **Purpose:** Coordinates `vault-client`, `vault-cache`, `vault-tree-model`, and `vault-write` with a two-branch (Named HEAD / Clone HEAD) model.
- **Key exports:** `createSession(config)` → `VaultSession` with `open()`, `commit(message)`, `push()`, `pull()`, `uploadBlob(content)`, `.treeModel`.

### 1.6 `vault-mutations` — high-level ops

- **Path:** `core/vault-mutations/v1/v1.0/v1.0.0/sg-vault-mutations.js`
- **Import:** `https://tools.sgraph.ai/core/vault-mutations/v1/v1.0/v1.0.0/sg-vault-mutations.js`
- **Purpose:** Compose vault-session into nine ergonomic file/folder operations.
- **Key exports:** `addFile(session, folderPath, name, content, options)`, `updateFile(...)`, `removeFile(...)`, `renameFile(...)`, `createFolder(...)`, `moveFile(...)`, `copyFile(...)`, plus folder equivalents.

### 1.7 `vault-init` — bootstrap

- **Path:** `core/vault-init/v1/v1.0/v1.0.0/sg-vault-init.js`
- **Import:** `https://tools.sgraph.ai/core/vault-init/v1/v1.0/v1.0.0/sg-vault-init.js`
- **Purpose:** Create a brand-new vault and its first commit.
- **Key exports:** `createVault(config)` → `{ token, vaultId, keys, commitId, treeId }`, `generateToken()`, `generateMemorablePassphrase()`, `isFriendlyToken(token)`.

## 2. Read-only components (`components/vault-embed/`)

Read-only custom elements designed for embedding on third-party origins. They have **no globals**, do not touch `localStorage`, and require nothing more than a vault-id + read-key + object-id. Use these from any consumer agent.

### 2.1 `<sg-vault-key>`

- **Import:** `https://tools.sgraph.ai/components/vault-embed/sg-vault-key/v0/v0.1/v0.1.0/sg-vault-key.js`
- **Purpose:** Imports and holds an AES-GCM read key. Renders nothing.
- **Attrs:** `id`, `vault-id`, `read-key`, `endpoint?` (default `https://send.sgraph.ai`)
- **Events:** `sg-vault-key:key-ready` `{ vaultId, cryptoKey, endpoint, derivationMs }`, `sg-vault-key:key-error` `{ vaultId, error }`
- **Methods:** `getKey()`, `getEndpoint()`, `getVaultId()`

### 2.2 `<sg-vault-fetch>`

- **Import:** `https://tools.sgraph.ai/components/vault-embed/sg-vault-fetch/v0/v0.1/v0.1.0/sg-vault-fetch.js`
- **Purpose:** Fetches a vault object, verifies, decrypts. Renders nothing.
- **Attrs:** `key-source` (ID of an `<sg-vault-key>`), `object-id`, `auto?` (default on; `auto="false"` requires explicit `.fetch()`)
- **Events:** `sg-vault-fetch:fetch-started`, `…:fetch-completed`, `…:decrypt-started`, `…:decrypt-completed`, `…:content-ready` `{ objectId, bytes, contentType, text }`, `…:fetch-error` `{ stage, objectId, error }`. All events bubble and are composed.
- **Methods:** `fetch()`

### 2.3 `<sg-vault-content>`

- **Import:** `https://tools.sgraph.ai/components/vault-embed/sg-vault-content/v0/v0.1/v0.1.0/sg-vault-content.js`
- **Purpose:** All-in-one convenience wrapper. Internally inlines a `<sg-vault-key>`, a `<sg-vault-fetch>`, and the appropriate renderer.
- **Attrs:** `vault-id`, `read-key`, `object-id`, `render` (`markdown` | `image` | `json`), `endpoint?`, `inspect?`
- **Events:** none directly (delegates to internal fetch + renderer)

### 2.4 `<sg-vault-manifest>`

- **Import:** `https://tools.sgraph.ai/components/vault-embed/sg-vault-manifest/v0/v0.1/v0.1.0/sg-vault-manifest.js`
- **Purpose:** Loads a JSON manifest and expands `[data-vault-slot]` elements into `<sg-vault-content>` instances. Multi-slot pages with one declaration.
- **Attrs:** `src` (manifest URL), `vault-id?`, `read-key?` (used if not in the manifest body)
- **Events:** `sg-vault-manifest:manifest-loaded` `{ src, slotCount }`, `…:manifest-error` `{ src, error }`, `…:slot-ready` `{ slotName, objectId, render, vaultId, readKey }`
- **Hard rule:** rejects any manifest containing a `write_key` field. Manifests are public artefacts.

### 2.5 `<sg-vault-trace>`

- **Import:** `https://tools.sgraph.ai/components/vault-embed/sg-vault-trace/v0/v0.1/v0.1.0/sg-vault-trace.js`
- **Purpose:** Dev/debug panel that records every `sg-vault-*` event in document order.
- **Attrs:** `target?`, `format?` (`compact` | `detailed`)
- **Methods:** `getLog()`, `clearLog()`, `recordEvent(name, detail)` — sanitises non-serialisable values (e.g. `CryptoKey`).

## 4. Interactive components (`components/vault/`)

These elements implement the editor/manager experience. They share state via a `[data-vault-bus]` ancestor: any element marked with that attribute becomes the event bus for its descendants. If no ancestor is found, the components fall back to `document`. Most write-capable components require a write key (derived from a write token or passphrase via `vault-write.deriveWriteKeys`).

| Tag                     | Latest path                                       | Purpose                                          | Write key | Key events                                                                                                              |
|-------------------------|---------------------------------------------------|--------------------------------------------------|-----------|-------------------------------------------------------------------------------------------------------------------------|
| `<sg-vault-connect>`    | `components/vault/sg-vault-connect/v0/v0.1/v0.1.3/`    | Key-entry form; opens a session                  | no        | emits `vault:connected { session, vault, vaultId, apiBaseUrl, keys }`, `vault:disconnected {}`                          |
| `<sg-vault-tree>`       | `components/vault/sg-vault-tree/v0/v0.1/v0.1.3/`       | File/folder tree panel                           | no        | consumes `vault:connected`, `vault:disconnected`, `vault:tree-refresh`; emits `vault:file-select`, `vault:folder-select`, `vault:new-file-request` |
| `<sg-vault-viewer>`     | `components/vault/sg-vault-viewer/v0/v0.1/v0.1.3/`     | File-content viewer                              | no        | consumes `vault:file-select`                                                                                            |
| `<sg-vault-file-preview>` | `components/vault/sg-vault-file-preview/v0/v0.1/v0.1.0/` | Preview pane for selected file                | no        | consumes `vault:file-select`                                                                                            |
| `<sg-vault-file-ops>`   | `components/vault/sg-vault-file-ops/v0/v0.1/v0.1.0/`   | Upload / rename / delete UI                      | **yes**   | issues mutations via the session                                                                                        |
| `<sg-vault-commit-log>` | `components/vault/sg-vault-commit-log/v0/v0.1/v0.1.0/` | Commit history panel                             | no        | consumes `vault:connected`                                                                                              |
| `<sg-vault-sync-status>`| `components/vault/sg-vault-sync-status/v0/v0.1/v0.1.0/`| Push/pull/pending indicator                      | no        | consumes `vault:connected`                                                                                              |
| `<sg-vault-create>`     | `components/vault/sg-vault-create/v0/v0.1/v0.1.0/`     | Bootstrap form for a brand-new vault             | **yes**   | emits `vault:created { token, vaultId, … }`                                                                             |

Import URL pattern: prepend `https://tools.sgraph.ai/` to the latest path and append `<tag-name>.js`. Example: `https://tools.sgraph.ai/components/vault/sg-vault-manager/v0/v0.1/v0.1.2/sg-vault-manager.js`.

**Note on write-capable components:** these accept write tokens or passphrases as user input. Do not pre-populate them with secrets fetched from a remote origin — they are designed for human-driven sessions.

## 6. CORS, hostnames, version policy

- **Public CDN:** `https://tools.sgraph.ai/` — permissive CORS, designed for cross-origin ESM imports.
- **Default vault API:** `https://send.sgraph.ai` — overridable per component (`endpoint` attribute) or per session (`apiBaseUrl` config).
- **Version pinning:** every URL in this document is pinned to an immutable folder. Production consumers should always pin. Rolling paths (e.g. `v0/v0.1/latest/`) are not part of the contract.
- **Upgrade path:** the catalogue at `library/catalogue/v0.1.91__catalogue__index.md` (and successors) is the source of truth for "latest version per module". Re-pin in one place; do not chase versions manually across HTML files.
- **No CORS allowlist in the static assets themselves.** CORS is enforced server-side by the CDN config. If you operate a private deployment of `send.sgraph.ai`, configure its CORS policy to match your consumer origins.
