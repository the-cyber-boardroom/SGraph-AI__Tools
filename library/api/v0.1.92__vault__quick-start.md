# Vault Components — Quick Start for Consumer Agents

**Version:** v0.1.92
**Audience:** AI agents and developers embedding vault-stored content on pages hosted on a different origin, importing modules over CORS from `https://tools.sgraph.ai`.
**Companion doc:** `v0.1.92__vault__full-inventory.md` — exhaustive list of every vault module, component, and tool.
**Revised:** 24 Aug 2026 — pins updated for the sgit 0.16 interop fix (`vault-client` v1.2.3, `vault-cache` v1.0.1, `vault-write` v1.1.2, `vault-session` v1.0.1, `vault-init` v1.0.1, `sg-vault-connect` v0.1.4, `sg-vault-manager` v0.1.3, `sg-vault-key` / `sg-vault-fetch` / `sg-vault-create` / `sg-vault-commit-log` v0.1.1). The versions previously listed here cannot open a vault made by the sgit CLI — see `team/explorer/dev/reviews/v0.2.92__dev-review__sgit-0.16-browser-vault-interop.md`.

This document covers the **small, common subset** you actually need to display encrypted vault content in a browser. It mirrors the components used by the reference implementation `tools/vault-peek` (and adds a couple). Everything here is **read-only**: no write keys, no mutations, no `localStorage`.

---

## 1. What a vault is (30 seconds)

A vault is a server-side, content-addressed store at `https://send.sgraph.ai` (default endpoint). Each vault has:

- A **vault-id** — short identifier (4–24 chars, e.g. `abc12345`).
- A **read-key** — a 32-byte AES key, base64url-encoded or (since `vault-client` v1.2.3)
  64-char hex. Holders can decrypt, not write. A key copied straight out of sgit works as-is:
  the `sgit_public_read_` / `sgit_private_read_` prefix is stripped for you.
- **Objects** — immutable encrypted blobs identified by `obj-cas-imm-<hash>`.

To display a vault object on a page you need three things: the vault-id, the read-key, and the object-id. The components below handle fetching, AES-GCM decryption, and rendering for you.

## 2. The one-liner: `<sg-vault-content>`

The fastest path. Drops in a single element that fetches, decrypts, and renders.

```html
<script type="module"
  src="https://tools.sgraph.ai/components/vault-embed/sg-vault-content/v0/v0.1/v0.1.0/sg-vault-content.js"></script>

<sg-vault-content
  vault-id="abc12345"
  read-key="J3kRP7QyL_base64url_encoded_key"
  object-id="obj-cas-imm-xyz999"
  render="markdown">
</sg-vault-content>
```

**Attributes:**

| Attribute   | Required | Description                                                              |
|-------------|----------|--------------------------------------------------------------------------|
| `vault-id`  | yes      | Vault identifier                                                         |
| `read-key`  | yes      | 32-byte AES read key — base64url or 64-char hex, sgit prefix optional    |
| `object-id` | yes      | Object to fetch (`obj-cas-imm-…`)                                        |
| `render`    | yes      | One of `markdown`, `image`, `json`                                       |
| `endpoint`  | no       | Override API host (default `https://send.sgraph.ai`)                     |
| `inspect`   | no       | Boolean attribute — also render an inline trace panel for debugging      |

Use `<sg-vault-content>` when you have a single piece of content to show and don't need to react to events. For everything else, use the composition pattern below.

## 3. The composition pattern: key + fetch + renderer

When you need to listen to events, share one read-key across many fetches, or render multiple objects, hand-wire three elements.

```html
<script type="module" src="https://tools.sgraph.ai/components/vault-embed/sg-vault-key/v0/v0.1/v0.1.1/sg-vault-key.js"></script>
<script type="module" src="https://tools.sgraph.ai/components/vault-embed/sg-vault-fetch/v0/v0.1/v0.1.1/sg-vault-fetch.js"></script>
<script type="module" src="https://tools.sgraph.ai/components/content/sg-content-markdown/v0/v0.1/v0.1.0/sg-content-markdown.js"></script>

<!-- 1. Hold the read key (renders nothing) -->
<sg-vault-key
  id="my-key"
  vault-id="abc12345"
  read-key="J3kRP7QyL_base64url_encoded_key">
</sg-vault-key>

<!-- 2. Fetch + decrypt one object (renders nothing) -->
<sg-vault-fetch
  id="fetch-hero"
  key-source="my-key"
  object-id="obj-cas-imm-xyz999">
</sg-vault-fetch>

<!-- 3. Render the decrypted bytes -->
<sg-content-markdown content-source="fetch-hero"></sg-content-markdown>
```

The data flow is event-driven:

```
<sg-vault-key>  ──"sg-vault-key:key-ready"──▶  <sg-vault-fetch>
                                                     │
                                                     ├─ fetch-started
                                                     ├─ fetch-completed
                                                     ├─ decrypt-started
                                                     ├─ decrypt-completed
                                                     ▼
                                              "sg-vault-fetch:content-ready"
                                                     │
                                                     ▼
                                              <sg-content-markdown>
```

### Element reference (read-only)

#### `<sg-vault-key>`

Imports and holds an AES-GCM key. Renders nothing visible.

- **Attrs:** `id`, `vault-id`, `read-key`, `endpoint?`
- **Events:** `sg-vault-key:key-ready` (`{ vaultId, cryptoKey, endpoint, derivationMs }`), `sg-vault-key:key-error` (`{ vaultId, error }`)
- **Methods:** `getKey()`, `getEndpoint()`, `getVaultId()`

#### `<sg-vault-fetch>`

Fetches the ciphertext, verifies, decrypts. Renders nothing visible.

- **Attrs:** `key-source` (ID of a `<sg-vault-key>`), `object-id`, `auto?` (default on; set `auto="false"` to require a manual `.fetch()` call)
- **Events** (all bubble + composed):
  - `sg-vault-fetch:fetch-started` — `{ vaultId, objectId, url }`
  - `sg-vault-fetch:fetch-completed` — `{ vaultId, objectId, bytesReceived, fetchMs, cacheHit }`
  - `sg-vault-fetch:decrypt-started` — `{ objectId, ciphertextBytes }`
  - `sg-vault-fetch:decrypt-completed` — `{ objectId, plaintextBytes, decryptMs }`
  - `sg-vault-fetch:content-ready` — `{ objectId, bytes: ArrayBuffer, contentType, text: string|null }`
  - `sg-vault-fetch:fetch-error` — `{ stage: 'fetch'|'decrypt'|'no-key', objectId, error }`
- **Methods:** `fetch()` — manual trigger when `auto="false"`

#### Content renderers

All three accept `content-source` (the ID of a `<sg-vault-fetch>`) and listen for its `*:content-ready` event:

| Tag                      | Reads from `event.detail`            | Notes                                              |
|--------------------------|--------------------------------------|----------------------------------------------------|
| `<sg-content-markdown>`  | `text`                               | Renders Markdown → HTML.                           |
| `<sg-content-image>`     | `bytes`, `contentType`               | Creates a Blob URL; revokes on disconnect.         |
| `<sg-content-json>`      | `text`                               | `mode="render"` (default) or `mode="emit"` (fires `sg-content-json:json-parsed` with `{ objectId, data }` instead of rendering). |

Import paths:

```
https://tools.sgraph.ai/components/content/sg-content-markdown/v0/v0.1/v0.1.0/sg-content-markdown.js
https://tools.sgraph.ai/components/content/sg-content-image/v0/v0.1/v0.1.0/sg-content-image.js
https://tools.sgraph.ai/components/content/sg-content-json/v0/v0.1/v0.1.0/sg-content-json.js
```

## 4. Multi-slot pages: `<sg-vault-manifest>`

When a page has several slots (hero, body, sidebar image, etc.) backed by different vault objects, point one `<sg-vault-manifest>` at a JSON manifest and let it expand the page.

```html
<script type="module"
  src="https://tools.sgraph.ai/components/vault-embed/sg-vault-manifest/v0/v0.1/v0.1.0/sg-vault-manifest.js"></script>

<sg-vault-manifest src="https://example.com/home-page.manifest.json"></sg-vault-manifest>

<article>
  <header data-vault-slot="hero"></header>
  <section data-vault-slot="body"></section>
  <aside   data-vault-slot="side-image"></aside>
</article>
```

**Manifest schema** (JSON, served with permissive CORS):

```json
{
  "vault_id": "abc12345",
  "read_key": "J3kRP7QyL_base64url_encoded_key",
  "slots": {
    "hero":       { "object_id": "obj-cas-imm-aaa", "render": "markdown" },
    "body":       { "object_id": "obj-cas-imm-bbb", "render": "markdown" },
    "side-image": { "object_id": "obj-cas-imm-ccc", "render": "image"    }
  }
}
```

For each slot the manifest dispatches `sg-vault-manifest:slot-ready` with `{ slotName, objectId, render, vaultId, readKey }`, then replaces the matching `[data-vault-slot]` element with a `<sg-vault-content>`.

**Hard safety rule (enforced in code):** any manifest containing a `write_key` field is rejected outright. Manifests are public artefacts — never put write keys in them.

`vault_id` and `read_key` may also be supplied as attributes on the `<sg-vault-manifest>` element if you prefer to keep them out of the manifest body.

## 5. Debugging: `<sg-vault-trace>`

Drop in a trace panel and it will collect every `sg-vault-*` and `sg-vault-fetch:*` event in document order. Indispensable when wiring up a new page.

```html
<script type="module"
  src="https://tools.sgraph.ai/components/vault-embed/sg-vault-trace/v0/v0.1/v0.1.0/sg-vault-trace.js"></script>

<sg-vault-trace id="trace" format="compact"></sg-vault-trace>
```

- **Attrs:** `target?` (element ID to scope to; default: document-wide), `format?` — `compact` (default) or `detailed`
- **Methods:** `getLog()`, `clearLog()`, `recordEvent(name, detail)`

The trace panel sanitises `CryptoKey` and other non-serialisable values so you can safely export the log.

## 6. CORS, hostnames, version pinning

- **CDN:** All component and core URLs above are served from `https://tools.sgraph.ai` with permissive CORS. They can be imported as ES modules from any HTTPS origin.
- **API endpoint:** The default vault API is `https://send.sgraph.ai`. Override with the `endpoint` attribute on `<sg-vault-key>` or `<sg-vault-content>` if you run a private deployment.
- **Pin to exact versions in production.** All URLs in this guide are pinned (`v0/v0.1/v0.1.0`). Pinned content is immutable. Do not use rolling paths — a silent component update can break your page.
- **Upgrades:** When a new version ships (`v0.1.1`, `v0.2.0`, …) the catalogue at `library/catalogue/v0.1.91__catalogue__components-extended.md` (and successors) is the source of truth. Re-pin in one place.

## 7. End-to-end worked example

A complete page that shows a Markdown hero and a JPEG, with a trace panel underneath for debugging.

```html
<!doctype html>
<html lang="en-gb">
<head>
  <meta charset="utf-8">
  <title>Vault embed demo</title>
  <script type="module" src="https://tools.sgraph.ai/components/vault-embed/sg-vault-key/v0/v0.1/v0.1.1/sg-vault-key.js"></script>
  <script type="module" src="https://tools.sgraph.ai/components/vault-embed/sg-vault-fetch/v0/v0.1/v0.1.1/sg-vault-fetch.js"></script>
  <script type="module" src="https://tools.sgraph.ai/components/vault-embed/sg-vault-trace/v0/v0.1/v0.1.0/sg-vault-trace.js"></script>
  <script type="module" src="https://tools.sgraph.ai/components/content/sg-content-markdown/v0/v0.1/v0.1.0/sg-content-markdown.js"></script>
  <script type="module" src="https://tools.sgraph.ai/components/content/sg-content-image/v0/v0.1/v0.1.0/sg-content-image.js"></script>
</head>
<body>
  <sg-vault-key id="k" vault-id="abc12345" read-key="J3kRP7QyL..."></sg-vault-key>

  <sg-vault-fetch id="hero" key-source="k" object-id="obj-cas-imm-aaa"></sg-vault-fetch>
  <sg-content-markdown content-source="hero"></sg-content-markdown>

  <sg-vault-fetch id="banner" key-source="k" object-id="obj-cas-imm-bbb"></sg-vault-fetch>
  <sg-content-image content-source="banner"></sg-content-image>

  <sg-vault-trace format="detailed"></sg-vault-trace>
</body>
</html>
```
