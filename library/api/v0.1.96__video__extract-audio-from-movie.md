# Capability Debrief — Extracting Audio from a Movie/Video File (browser, client-side)

**From:** SGraph-AI__Tools — for the **voicedebrief.ai** tools section
**Date:** 17 Jun 2026 · code-verified against the tools repo, CORS confirmed live
**Pairs with:** your existing text-to-voice tool. This adds the *front* of the pipeline: **movie → audio track → (transcribe / voice)**.

---

## TL;DR

There is a **deployed, importable, browser-only** capability to pull the audio track out of a video file (`.mp4`/`.mov`/`.webm`/…): **`extractAudio()`** in `core/video/sg-video.js`, backed by **FFmpeg WASM**. It runs entirely client-side (no upload, no server), imports cross-origin from `tools.sgraph.ai` (**CORS `*`, confirmed live**), needs **no COOP/COEP** (single-threaded core), and the notorious cross-origin-Worker problem is **already solved** in the loader. Output is an **`.m4a`** (AAC) audio blob — ready to hand straight to a transcription/voice model.

```js
import { loadFFmpeg, extractAudio, isWasmSupported }
  from 'https://tools.sgraph.ai/core/video/v1/v1.0/v1.0.1/sg-video.js';

const ffmpeg = await loadFFmpeg(p => console.log(p));   // lazy-loads ~30 MB once
const { blob } = await extractAudio(ffmpeg, movieFile); // File/Blob → audio/mp4 (.m4a)
// → feed `blob` to transcription, or to your voice pipeline
```

## 2. The `extractAudio` capability, precisely

- **Signature:** `extractAudio(ffmpeg, file)` → `{ blob, /* + name/size */ }`. `ffmpeg` is the instance from `loadFFmpeg()`; `file` is a `File`/`Blob` (the movie).
- **What it does under the hood:** `ffmpeg -i input -vn -c:a copy output.m4a` — i.e. **drops the video stream (`-vn`) and *stream-copies* the audio (`-c:a copy`)**. No re-encode → **fast and lossless**, and it preserves the source audio codec (typically AAC) in an **`.m4a`** (MP4) container. Output MIME `audio/mp4`.
- **Errors clearly** if the file has no audio stream.
- **`getVideoInfo(file)`** probes duration/streams first if you want to check there's audio, or show duration.
- **Want just a slice?** `trimVideo()` / `splitVideo()` cut segments (also `-c copy`), then extract audio from the piece.
- **Guard:** `isWasmSupported()` before you start.

**Why `.m4a`/AAC is the right output here:** it's small, universally decodable, and is directly accepted by audio-input LLMs / STT — so it flows straight into a transcription or voice step with no conversion.

## 3. The two things that usually break FFmpeg-in-the-browser — both already handled

1. **Cross-origin Worker (the classic blocker).** FFmpeg WASM spins up a Web Worker internally, and a Worker script **must be same-origin**. Importing FFmpeg from a CDN (unpkg) makes `new Worker('https://unpkg.com/…/worker.js')` throw. **`sg-video.js` solves this** by building a **same-origin blob-URL class worker** and passing `{ classWorkerURL, coreURL, wasmURL }` to `ffmpeg.load()`. Because the blob URL is created in *your page's* context, it's same-origin to your page — so **it keeps working when you import `sg-video.js` into voicedebrief.ai**.
2. **SharedArrayBuffer / cross-origin isolation (COOP/COEP).** The multi-threaded FFmpeg core needs those headers (a deploy headache). **`sg-video.js` uses the single-threaded core (`@ffmpeg/core@0.12.6`), so no COOP/COEP is required** — which is exactly why it runs on a plain static CDN and will run on voicedebrief.ai as-is.

## 4. CORS / hosting

- **`tools.sgraph.ai` serves `Access-Control-Allow-Origin: *` — confirmed live** on the actual `sg-video.js` asset. So voicedebrief.ai can `import` it directly (ESM), no proxy, no build step.
- **FFmpeg core/wasm** are fetched from **unpkg** (`@ffmpeg/core@0.12.6`, `@ffmpeg/ffmpeg@0.12.10`, `@ffmpeg/util@0.12.1`) at first use (~30 MB) — public CDN with CORS. If you prefer to self-host or cache those bytes, the repo has `core/sg-wasm-cache` (Cache-API persistence) forward-designed for exactly this; it's an optional optimisation.

---

## 5. Cost / performance / limits

- **First `loadFFmpeg()`:** downloads ~30 MB of FFmpeg WASM (cached by the browser afterwards). Show a progress UI — `loadFFmpeg(onProgress)` and `extractAudio` accept/emit progress.
- **Extraction itself is cheap** because it's a stream copy (no transcode) — near-I/O-bound.
- **All client-side:** the movie never leaves the browser (privacy-preserving, matches the voicedebrief/whatsapp-transcribe ethos).
- **Edge cases:** if the container/codec combo can't be copied into `.m4a` (rare — e.g. Opus-in-WebM video), a re-encode variant would be needed (`-c:a aac`); today `extractAudio` does a copy. Flag it if you hit it and we can add a re-encode fallback.

## 6. The end-to-end recipe for voicedebrief.ai

```js
import { loadFFmpeg, extractAudio, getVideoInfo, isWasmSupported }
  from 'https://tools.sgraph.ai/core/video/v1/v1.0/v1.0.1/sg-video.js';

if (!isWasmSupported()) { /* fall back / warn */ }

const ffmpeg = await loadFFmpeg(({ stage, detail }) => showProgress(stage, detail));
const info   = await getVideoInfo(movieFile);         // optional: duration, has-audio
const { blob } = await extractAudio(ffmpeg, movieFile); // audio/mp4 (.m4a)

// hand off to your existing pipeline:
//   - transcription (audio LLM / STT) → text
//   - or your text-to-voice tool for a re-voiced version
```

Chained with your text-to-voice tool, that's the full loop: **drop a movie → extract audio → transcribe → (re)voice**, all in the browser.
