# Text-to-Speech (TTS) — Capabilities & Generating Voice Audio Files

**Version:** v0.1.94 (code-verified against the branch)
**Audience:** agents/devs generating **spoken audio from text** — e.g. a Journalist Agent turning `/updates/` entries into news-style voice files, or a chat UX speaking replies.
**What exists:** two TTS engines, both under `core/` (importable from `*.tools.sgraph.ai`).

> **TL;DR for the Journalist-Agent use case:** use **OpenRouter cloud TTS** (`core/sg-tts-openrouter`). It's a plain HTTPS call, so it runs **headless (Node/CI) or in a browser**, needs no model download, and gives broadcast-style voices. The agent writes a short news *script* per update; TTS reads it verbatim in the chosen voice. Local Kokoro TTS is free but browser-only + a ~90 MB download — better for interactive/in-browser use than a file-generation pipeline.

## 1. The two engines at a glance

| | **OpenRouter cloud** (`core/sg-tts-openrouter`) | **Local Kokoro** (`core/sg-tts`) |
|---|---|---|
| Import URL | `…/core/sg-tts-openrouter/v0/v0.1/v0.1.0/sg-tts-openrouter.js` | `…/core/sg-tts/v0/v0.1/v0.1.0/sg-tts.js` |
| Runs in | **Browser OR Node/headless** (just needs `fetch`) | **Browser only** (Web Workers + WASM; loads `kokoro-js` from a CDN) |
| Cost | OpenRouter tokens (BYOK) — cheap; a short update ≈ fractions of a penny | **Free** (on-device) |
| First-run download | none | **~90 MB** model (cached after) |
| Output | **WAV** Blob (24 kHz, mono, 16-bit) | Float32 PCM `{ data, sampleRate:24000, durationSecs }` |
| Voices | `alloy, echo, fable, onyx, nova, shimmer` (OpenAI voices) | Kokoro voices: `af_heart, af_bella, am_michael, bf_emma, bm_george, …` |
| Model | default `openai/gpt-audio` (any OpenRouter audio-output model) | Kokoro-82M ONNX |
| Best for | **automated/agent file generation**, servers, CI, chat voice-out | free interactive/offline synthesis in a live page |
| CORS | `*` (importable cross-origin, incl. a vault frame) | `*` |

Both are **client-side / BYOK** — no SGraph server; the caller supplies the OpenRouter key (cloud) or nothing (Kokoro).

## 2. OpenRouter cloud TTS — the API (`core/sg-tts-openrouter`)

```js
import {
  synthesizeOpenRouter, encodeWav, base64ToBytes, base64ToBlob, pcm16ToWav,
  TTS_OPENROUTER_VOICES, TTS_OPENROUTER_DEFAULT_MODEL, OPENROUTER_TTS_SAMPLE_RATE,
} from 'https://tools.sgraph.ai/core/sg-tts-openrouter/v0/v0.1/v0.1.0/sg-tts-openrouter.js';

const { blob, durationMs, generationId, transcript } =
  await synthesizeOpenRouter(text, { apiKey, voice: 'onyx', model, fetchImpl });
// blob = a ready-to-save WAV (audio/wav)
```

- **`synthesizeOpenRouter(text, opts)`** → `{ blob, durationMs, mode:'openrouter', generationId, transcript }`. Streams the model's `pcm16` audio (the only streamable format — `wav` 400s when `stream:true`) and wraps it to a WAV in-code.
- `opts`: `apiKey` (required), `voice` (default `alloy`), `model` (default `openai/gpt-audio`), `fetchImpl` (inject a fetch for testing / non-global-fetch environments).
- Errors are typed: `{code:'no-key'}`, `{code:'tts-http', ...}` (provider HTTP error, message included), `{code:'tts-no-audio'}`.
- **Node note:** works in Node 18+ (global `fetch`, `Blob`, `atob`). `blob.arrayBuffer()` → bytes → write to disk.
- Helpers exported for advanced use: `encodeWav(float32, rate)`, `pcm16ToWav(bytes, rate)`, `base64ToBytes/Blob`.

## 3. Recipe — news-style audio for each update (Journalist Agent)

The **news style comes from the script + the voice**, not a special mode: the agent writes a short spoken-word script for the update (a lead-in + the news), then TTS reads it verbatim in a broadcast voice (`onyx` / `echo` read well as an anchor).

```js
// Node/CI agent — turn one update into a voice file.
import { synthesizeOpenRouter } from 'https://tools.sgraph.ai/core/sg-tts-openrouter/v0/v0.1/v0.1.0/sg-tts-openrouter.js';
import { writeFile } from 'node:fs/promises';

const script = `Here's the latest from Voice Note Transcribe. ${update.title}. ${update.summary}`;
const { blob } = await synthesizeOpenRouter(script, { apiKey: process.env.OPENROUTER_KEY, voice: 'onyx' });
await writeFile(`updates/audio/${update.id}.wav`, Buffer.from(await blob.arrayBuffer()));
```

Wire it to your pipeline: read `updates.json`, diff against already-rendered audio, synthesize only new entries, and publish the `.wav` next to the update (link it from `updates.json` / the RSS enclosure so players can pick it up).

**Long updates → chunk + concatenate.** Audio-output models cap length, so split a long script into ~1–3-sentence chunks, synthesize each, and glue the PCM (you can't concat WAV *files* directly — headers get in the way). Minimal glue using the exported helpers:

```js
import { synthesizeOpenRouter, base64ToBytes /* … */ } from '…/sg-tts-openrouter.js';
// Simpler: strip each WAV's 44-byte header, concat the PCM, re-wrap once with pcm16ToWav.
async function pcmOf(wavBlob) { return new Uint8Array(await wavBlob.arrayBuffer()).slice(44); }
const parts = [];
for (const chunk of splitIntoChunks(script)) {
  const { blob } = await synthesizeOpenRouter(chunk, { apiKey, voice: 'onyx' });
  parts.push(await pcmOf(blob));
}
// concat parts → one Uint8Array → pcm16ToWav(all, 24000) → the full file.
```
*(If you'd rather not hand-roll that, ask us to add a `concatWavBlobs()` / a "synthesize long text" helper to the module — small, and it belongs in `sg-tts-openrouter`.)*

## 4. Local Kokoro TTS — the API (`core/sg-tts`), for the free/in-browser path

```js
import { loadTTS, generateAudio } from 'https://tools.sgraph.ai/core/sg-tts/v0/v0.1/v0.1.0/sg-tts.js';
await loadTTS({ voice: 'af_bella', poolSize: 1 });          // first run downloads ~90 MB (cached)
const { data, sampleRate, durationSecs } = await generateAudio(text, { voice: 'am_michael', speed: 1.0 });
// data = Float32 PCM @ 24 kHz. Wrap to WAV with encodeWav(data, sampleRate) from sg-tts-openrouter.
```
- `loadTTS({ voice, poolSize=4, cdnUrl })` — spins up a Web-Worker pool loading `kokoro-js` from a CDN. **Use `poolSize:1` for one short job** (the default 4 downloads the model 4×).
- `generateAudio(text, { voice, speed })` → `{ data:Float32Array, sampleRate:24000, durationSecs }` (splits into sentences, synthesises in parallel, concatenates).
- **Browser-only** (Web Workers + WASM). Not suitable for a headless file-generation agent unless you run a browser/worker runtime.

## 5. Practical notes for the audio files

- **Format:** both engines give WAV (24 kHz mono). WAV is large; for web delivery convert to **MP3/Opus** (ffmpeg in the pipeline, or a browser encoder) — that conversion is **not** in these modules. For an RSS/podcast enclosure, MP3 is safest; Opus/`.ogg` is smaller.
- **Voice choice (news):** `onyx` (deep, authoritative) or `echo` read like an anchor; `nova`/`shimmer` are lighter. Pick one per your brand and keep it consistent.
- **Tone/pacing:** `gpt-audio` reads the script's words; there's currently **no `instructions`/tone parameter** in `synthesizeOpenRouter` (it prompts "read verbatim"). Steer tone via the *script* (punctuation, sentence length, an explicit lead-in). If you need explicit tone control (e.g. "read as a calm news anchor"), that's a **small enhancement** we can add (an `instructions` passthrough) — flag it.
- **Cost/consistency:** each synthesis is a billed OpenRouter request (BYOK); a short update is a fraction of a penny. `generationId` is returned if you want to reconcile exact cost via `GET /api/v1/generation`.
- **Length:** keep a single call to a few paragraphs; chunk beyond that (§3).

## 6. What's clean vs what we'd add

- **Clean import today:** `synthesizeOpenRouter(text, {apiKey, voice})` → WAV. Works headless. This is all a file-generation agent needs for typical-length updates.
- **Small, well-scoped enhancements** (ask if the pipeline needs them): a `concatWavBlobs()` / `synthesizeLong(text)` helper (chunk + glue) in `sg-tts-openrouter`; an `instructions`/tone passthrough for news pacing; a WAV→MP3/Opus encode helper (or keep that in your pipeline via ffmpeg).
- **Interactive path:** the `audio-transcribe` tool's **🗣 Voice** tab (and its `synthesize({text, mode, voice, returnAudio})` action on `window.__tool`) is the UI/embed path — see the integration guide `v0.1.93` §5b. For automation, import the core module directly (above).
