# Architecture Guide — Three-Tier Model

**Version:** v0.1.68 | **Date:** 8 April 2026 | **Author:** Librarian

---

## Overview

tools.sgraph.ai is the **canonical component library** for the SGraph ecosystem. Strict three-tier architecture with one-way dependency flow: tools depend on components, components depend on core, nothing flows backward.

```
┌─────────────────────────────────────────────────────┐
│  TOOLS (24 standalone browser pages)                │
│  tools/v0/v0.1/{version}/en-gb/{tool}/index.html    │
│  Compose core + components into complete UIs         │
├─────────────────────────────────────────────────────┤
│  COMPONENTS (20 families, ~106 JS files)             │
│  components/{family}/{name}/v0/v0.1/{ver}/           │
│  JS + CSS + HTML. May import from core/.             │
├─────────────────────────────────────────────────────┤
│  CORE (15 module families, ~33 JS files)             │
│  core/{name}/v{M}/v{M}.{m}/v{M}.{m}.{p}/            │
│  Zero dependencies on components or tools.           │
└─────────────────────────────────────────────────────┘
```

---

## Dependency Rules (Non-Negotiable)

1. **Core MUST NOT import from components/ or tools/.** Pure logic only.
2. **Components MAY import from core/.** E.g. sg-send-drop → sg-send-crypto.
3. **Components MUST NOT import from tools/.**
4. **Tools MAY import from both core/ and components/.**
5. **External SGraph projects import FROM tools.sgraph.ai** via CDN URLs.

### Cross-Project Consumers

```
send.sgraph.ai ──imports──► tools.sgraph.ai/core/
vault.sgraph.ai ──imports──► tools.sgraph.ai/core/
workspace ──imports──► tools.sgraph.ai/core/ + components/
chrome ext ──imports──► tools.sgraph.ai/core/
```

## Versioning — IFD

Folder-based immutable versioning. Content at a pinned version URL never changes.

### The IFD Filename Collision Constraint

The IFD layering system (`build_ifd_latest.py`) copies files from each version into `_latest/`, later versions overwriting earlier ones **by filename**. For the surgical override pattern (sg-tree), **version-stamped filenames** are required: `sg-tree--v0.1.2.js` not `sg-tree.js`. See `library/development/ifd/v1.3.0__ifd__surgical-overrides-version-stamped-filenames.md`.

## Security Model

1. **Client-side only.** No server calls for processing.
2. **No data exfiltration.** Tools MUST NOT send user data anywhere except with explicit user action (sg-send-drop, vault write).
3. **Secure context required.** Crypto operations need HTTPS or localhost.
4. **No localStorage in core modules.** Use in-memory state. Exception: tools with explicit persistence needs.
