# SG Video Editor — Round History

_Per-round development history for `tools/v0/v0.1/v0.1.54/en-gb/sg-video-editor/`.
Append new rounds to this file as the tool moves through patch versions._

---

## Phase 1 (Initial)

**NEW** — Phase 1 multi-clip browser video editor. Manifest-driven (sg-tool-api + manifest-loader). Plain DOM orchestrator (`ui/ui-shell.js`) composes a top bar with Export controls, asset panel (left, drag source for `application/x-sg-asset`), `<sg-preview-canvas>` (preview + transport), and `<sg-timeline>` (single video lane, ruler, playhead). Project state container in `ui/state.js` (wrapped schema: `{schemaVersion, project, assets, tracks, operations}` + in-memory `assetRegistry: Map<assetId, Blob>`). 10 SgToolApi methods: `loadAsset` (probe via hidden `<video>`, register Blob), `addClip`, `trimClip`, `removeClip`, `moveClip`, `splitClip` (round-3 part A: split clip at timeline-time; both halves share assetId; non-destructive), `setClipColor` (round-5 part B), `getProject`, `setProject` (validate via composer-schema), `exportMp4` (canvas captureStream + MediaRecorder; WebM→MP4 fallback).

## Round-3 part A

Round-3 part A timeline UX: hover-× delete button → `sg-timeline:clip-deleted` (the Delete/Backspace keyboard shortcut originally shipped here was removed in Round-9-L per user feedback); S key splits selected clip at playhead → `sg-timeline:clip-split`; composer `play()` auto-advances playhead to the next clip when in dead space.

## Round-5 part B

Round-5 part B: clips render in 6 cycling distinct-hue shades (indigo / teal / amber / rose / purple / sky, `clip--shade-0..5`); optional per-clip `color` field overrides the auto-shade as inline style and is preserved across `splitClip`; new SgToolApi method `setClipColor({clipId, color})` (op: `setClipColor`, `color: null` removes override) wired through state-clip-ops.js + api-methods.js + manifest; timeline toolbar colour-picker control opens a swatch popover with 12 presets + native `<input type="color">` + "Use auto" reset. Single video track only (`t-video-1`); titles, crop, masks, transitions, multi-track audio deferred to Phases 2-4. Skills: `SKILL__{human,browser,api}.md`. `handoff/` directory reserved for Phase 4 cross-tool handoffs. No network, no localStorage. Image assets supported (PNG/JPEG/WebP/GIF), default 5-second display duration on drop.

## Round-6 part B

Round-6 part B: undo/redo via deep-clone snapshot stack (max 50 per side, oldest dropped on overflow) — every state mutation snapshots the pre-state into `state-history.js` (`createHistory({maxEntries})`); new SgToolApi methods `undo`/`redo`/`canUndo`/`canRedo`; new `Undo` / `Redo` toolbar buttons on `<sg-timeline>` (events `sg-timeline:undo-requested` + `sg-timeline:redo-requested`, enable-state plumbed via new `setHistoryFlags()` prop on the component); shell-level Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z (or Cmd/Ctrl+Y) global shortcuts via `ui-shortcuts.js`, skipped while focus is on INPUT/TEXTAREA/contenteditable. AssetRegistry blobs are shared across snapshots — undoing an `addAsset` leaves the blob inert in memory (cheap, harmless).

## Round-9-D

Round-9-D snap-abut: `state-overlap.js` exports a new `snapToClearSlot(track, start, end, excludeClipId)` helper that, on overlap, returns a flush-abut start (after-the-neighbour by default; before if more of the proposed range sits to the left of the neighbour mid-point; falls back to the other side; returns `null` if both sides still collide). `addClip` / `moveClip` / `addShapeClip` / `addTextClip` accept an opt-in `snap: true` param routed through `api-methods.js` → `state.js` → `state-clip-ops.js` (`addClipOp` / `moveClipOp` / `addShapeClipOp` / `addTextClipOp`); when `snap` is true and the proposed range overlaps a neighbour, the op snap-abuts via `snapToClearSlot`, otherwise falls back to the existing `Error{code:'overlap'}`. ## Round-9-G

Round-9-G (preview refresh + redraw button): (1) Bug fix — the preview no longer stays black after the user drops the first asset onto an empty timeline at time 0. Root cause was in `composer-playback.seek()`: when the freshly-created `<video>` was at `readyState=0`, the only paint trigger was a `seeked` listener — but assigning `currentTime = 0` on a not-yet-loaded video where the existing `currentTime` is also 0 isn't a real seek and doesn't fire `seeked`, so the canvas stayed black until the user pressed Space (which forces `v.play()` and a real load). Fix is the new `waitForVideoFrame(video, cb)` helper that races `seeked` + `loadeddata` + `canplay` and cleans up siblings on first fire. (2) New `composer.refresh()` method on the playback handle synchronously re-paints the current frame via `sched.paintAt(playhead)`. (3) New SgToolApi method `refreshPreview()` on the tool — registered through `api-methods.js` + `sg-video-editor-api.js` + manifest — calls `composer.refresh()`; returns `{ ok }` (false when no composer is attached). (4) `<sg-preview-canvas>` transport bar gains a fourth button (↻ "Redraw current frame") inserted after fast-forward via `preview-transport.buildTransport`; `wireTransport` wires its click to `composer.refresh()`; `setTransportEnabled(false)` leaves the redraw button enabled at all times.

## Round-9-J

Round-9-J (asset blobs in IndexedDB): asset bytes (videos / images) now persist to IndexedDB so a reload restores full pixels — Round-9-H only persisted project metadata to localStorage, leaving every clip as a `__missingBlob` placeholder after refresh. New module `ui/state-asset-storage.js` wraps the browser's IDB with a small async key→blob API: `saveAsset({id, blob, name, kind, mimeType, width, height, duration, bytes})`, `loadAsset(assetId)`, `deleteAsset(assetId)`, `listAssetIds()`, `pruneOrphanedAssets(usedIds)`, `computeAssetStorageUsage()`, `clearAllAssets()`. Database name `sgve`, object store `assets`, keyed by asset id. Pattern mirrors the wheel cache in `tools/.../sg-send-cli/index.html` rather than the heavier `core/sg-vfs/v0.1.0/sg-vfs-provider-indexeddb.js` (the VFS provider models hierarchical paths + folders, overkill for our flat key→blob map). `api/api-storage-methods.js` extended: `saveProject` / `loadProject` / `autosave` / `deleteSavedProject` are now ASYNC — they `await persistBlobsToIdb(state)` before localStorage writes (saves), `await hydrateBlobsFromIdb(state)` after restore (loads), and `await pruneOrphanedAssets(referencedIds)` after deletes (the GC sweep computes the union of asset ids across every saved project + autosave + the live project, never evicting a still-referenced blob). Two new SgToolApi methods: `hydrateAssets()` (used by the autosave-restore path after `setProject({project: slot.project})` since that path doesn't go through `loadProject`'s built-in hydration) and `getStorageUsage()` (returns `{totalBytes, assetBytes, assetCount, projectJsonBytes}` for the new "Storage" line in the Properties pane). State container (`ui/state.js`): `replaceProject(next)` now `assetRegistry.clear()`s before swapping (stale registry blobs from the previous project would mask the IDB hydration); new `attachAssetBlobs(blobsById)` method writes blobs into the registry, clears the `__missingBlob` flag on each matched asset, and emits a single `change`. UI: `ui/ui-save-load.js` and `ui/ui-autosave.js` rewritten to `await` every SgToolApi call (SgToolApi's `_invoke` is itself async-by-default, so even synchronous registered methods returned a Promise that the Round-9-H code wasn't awaiting — that bug silently hid the saved-projects list); `ui/ui-storage-usage.js` is a new ~50-LOC module mounted under Save/Load that polls `api.getStorageUsage()` and renders `"X.XX MB (N assets)"`. `ui/asset-row.js` adds a visible "missing — re-upload" hint and an `is-missing` CSS class with a striped thumb for assets still flagged `__missingBlob` after hydration (e.g. pre-Round-9-J saves where blobs were never written to IDB). `ui/state-storage.js`: soft byte limit dropped from 4 MB to 1 MB — the project JSON without blobs is small (a 100-clip project with 30-char names is ~10 KB); the cap now catches pathological growth before localStorage chokes rather than acting as the de-facto blob ceiling. `manifest.json` + `skills/SKILL__api.md` updated with async tags, IDB layout, and the two new methods. Backwards compatibility: pre-Round-9-J saved projects still load; their assets simply stay flagged `__missingBlob` (the user can re-upload a fresh file with the same id-shape and re-save to write into IDB). Verified via Node-only tests with a fake-IDB shim (30 assertions across `state-asset-storage` round-trips + `api-storage-methods` save→load roundtrip + `deleteSavedProject` orphan pruning + `getStorageUsage`); browser walk-through pending the user.
