# Design Review: Homepage Tool Organisation

**Date:** 8 Apr 2026 | **Reviewer:** Designer (Explorer) | **Page:** `tools/v0/v0.1/v0.1.22/en-gb/index.html`

---

## 1. Current State — Problems

- **"Utilities" is a dumping ground** (10 tools, from SSH keys to video editing to Python REPL)
- **No audience split** — developers and end-users see the same flat list
- **No entry point for newcomers** — 24 cards with equal visual weight; no guidance on where to start
- **Dev/experimental tools mixed in** — VFS Dev, SG Tree Demo, Send Simulator sit alongside production tools
- **Will not scale** — adding 5 more tools makes the page unusable

---

## 2. Proposed Category Structure (6 categories)

| # | Category | Tools | Count |
|---|----------|-------|-------|
| 1 | **Security & Crypto** | SSH Key Generator, File Encryptor, File Hasher, Key Generator | 4 |
| 2 | **AI / LLM** | Chat, One-Shot Chat, Infographic Generator, Multi-Agent Chat, Agentic Loop, Model Compatibility | 6 |
| 3 | **Media** | Image Tools, Video Tools | 2 |
| 4 | **Vault & Send** | Vault, Vault Browser, OpenRouter, SG/Send CLI | 4 |
| 5 | **Code & Runtime** | Python REPL, Folder Editor, LLM Dev Environment | 3 |
| 6 | **Developer Sandbox** *(collapsed by default)* | VFS Dev, VFS Tree Demo, SG Tree Demo, Send Simulator, Vault (Pyodide) | 5 |

**Key changes:**
- "Utilities" dissolved into purpose-driven groups
- OpenRouter moves to Vault & Send (it manages SGraph API spending, not LLM chat)
- LLM Dev Environment moves to Code & Runtime (it is a builder tool, not a chat tool)
- All `status--dev` and `status--exp` tools move to Developer Sandbox
- Developer Sandbox is a `<details>` element, closed by default

---

## 3. Featured / Hero Section

Add a **"Start Here"** row of 3-4 showcase cards between the hero text and the search bar. Larger cards, brief call-to-action.

| Slot | Tool | Why |
|------|------|-----|
| 1 | **Chat** | Most used; instant value; demonstrates LLM capability |
| 2 | **File Encryptor** | Showcases the privacy promise; tangible security tool |
| 3 | **Infographic Generator** | Visual wow factor; shows LLM + creative output |
| 4 | **Vault** | Gateway to the SGraph ecosystem |

**Card treatment:**
- 2x width of normal cards (span 2 grid columns on desktop)
- Accent-coloured left border (`var(--sg-accent)`)
- One-line tagline below the description (e.g. "No account needed — just paste your API key")

---

## 4. Key UX Improvements

### 4a. Progressive Disclosure
- Developer Sandbox collapsed by default (`<details closed>`)
- "Show all 24 tools" link at bottom of featured section for power users
- Search still indexes hidden/collapsed tools

### 4b. Audience Segmentation (no extra pages)
- Add two filter pills below search: **All** | **End User** | **Developer**
- End User = Security & Crypto, AI / LLM, Media, Vault & Send
- Developer = Code & Runtime, Developer Sandbox
- Filter is additive to search; stored in URL hash (`#audience=dev`)

### 4c. Status Badges — Tighten Rules
| Badge | Meaning | Show in |
|-------|---------|---------|
| `Live` | Production-ready | All views |
| `New` | Shipped in last 2 releases | All views |
| `Experimental` | Works but unstable | All views |
| `Dev` | Internal / demo only | Developer Sandbox only |

### 4d. Card Improvements
- Add **keyboard shortcut hint** on hover (stretch goal)
- Add **"Requires API key"** sub-badge to all LLM tools so users know before clicking
- Truncate descriptions to 2 lines with CSS `-webkit-line-clamp: 2`

### 4e. Scalability
- When tool count exceeds 30, switch categories to accordion (`<details>`) with open-first-two pattern
- Category counts already exist in `.count` spans — keep them
