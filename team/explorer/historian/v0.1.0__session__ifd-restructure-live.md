## What Happened

### Trigger: SG/Send Agentic Team Debrief

On 5 Mar 2026, the SG/Send agentic team (Librarian, Architect, Dev, DevOps) delivered a formal debrief to the Tools team at `team/explorer/librarian/reviews/v0.1.0__debrief__sg-send-team-to-tools-team.md`. The debrief was the result of a cross-project code review: the Send team inspected the Tools repo and compared it against the IFD methodology, SG/Send production patterns, and the original architecture brief.

The debrief identified **critical structural gaps** that would prevent the Tools project from deploying or integrating with the broader SGraph ecosystem.

### Key Issues Raised by SG/Send Team

1. **Missing `sgraph_ai__tools/` base folder.** Code sat directly in the repo root. Every SG project uses a `{package_name}/` base folder as the deployable root that gets synced to S3. Without this, CI/CD cannot cleanly separate deployable code from team docs, briefs, and config.

2. **Flat version folders instead of IFD nested paths.** The repo had `core/crypto/v1.0.0/` instead of the IFD convention `core/crypto/v1/v1.0/v1.0.0/`. Every SG project uses nested version paths, and the `deploy_static_site.py` script's `version_to_ifd_path()` function depends on this structure.

3. **No CI/CD pipeline.** No `.github/workflows/`, no deploy scripts, no version file. The architecture's value proposition (cross-project imports via CDN URLs) was blocked.

4. **No i18n support.** No locale structure, no translation files, no `data-i18n` attributes. Send's v0.2.0 layout with `_common/en-gb/i18n` was the reference pattern.

5. **No `manifest.json` for any module.** Send uses manifests to declare what gets deployed.

6. **No shared CSS extraction.** Styles were duplicated across HTML pages.

7. **Crypto and SSH code written from scratch.** The debrief advised using Send's proven, deployed code from `static.sgraph.ai` rather than new implementations. The existing code was flagged as unverified.

### Tools Team Response

The Tools team (Explorer team, all roles) responded in the same session:

1. **Architect** assessed the debrief against existing code and confirmed all gaps were valid.
2. **Dev** created a dev plan (`team/explorer/dev/reviews/v0.1.0__dev-plan__ifd-restructure.md`) with three phases: folder restructure, CI/CD infrastructure, and cleanup/documentation.
3. **All corrections were implemented in a single session.** No items were deferred or partially completed.

## Decisions Made

| Decision | Rationale | Source |
|----------|-----------|--------|
| Adopt `sgraph_ai__tools/` as deployable root | Matches all other SG project conventions; enables clean S3 sync | SG/Send debrief, section 1 |
| Use IFD nested version paths (`v1/v1.0/v1.0.0/`) | Required by `deploy_static_site.py`; groups related versions on disk and in S3 | SG/Send debrief, section 2 |
| Copy `deploy_static_site.py` from Send, not write new | Proven script, already handles content-type detection, cache headers, release versioning, latest alias, and CloudFront invalidation | SG/Send debrief, section 3 |
| Start with 5 locales, not 17 | Prove the i18n pipeline works before scaling | SG/Send debrief, section 9 |
| Keep existing crypto/SSH code but flag as unverified | Debrief advised using static.sgraph.ai imports for production; existing code retained for development/demo purposes | SG/Send debrief, section 6 |
| No `latest/` folders in git | `latest/` is a CI/deployment concept: CI copies versioned release to latest in S3 | SG/Send debrief, section 4 |
| Tools at v0.1.0, core/components at v1.0.0 | Tools are new (pre-1.0); core modules were already declared at v1.0.0 in initial bootstrap | Dev plan |

## Significance

This session marks the first time the Tools project has a live, accessible deployment. The restructure brings the repo into full alignment with the IFD methodology and SG/Send conventions that are already proven in production. The cross-team debrief model (Send team reviewing Tools, providing actionable guidance, Tools team implementing in one session) demonstrated an effective pattern for agentic team coordination.

The site at `dev.tools.sgraph.ai` is the foundation for the dependency inversion described in the architecture brief: tools.sgraph.ai as the canonical source, with send, vault, workspace, and the Chrome extension as consumers.
