## What Happened

### Trigger: SG/Send Agentic Team Debrief

On 5 Mar 2026, the SG/Send agentic team (Librarian, Architect, Dev, DevOps) delivered a formal debrief to the Tools team after reviewing the Tools repo against production SG/Send patterns and the IFD methodology. The debrief is recorded at:

`team/explorer/librarian/reviews/v0.1.0__debrief__sg-send-team-to-tools-team.md`

The debrief identified critical structural gaps between the Tools repo's initial bootstrap implementation and the conventions already shipping across send.sgraph.ai, vault.sgraph.ai, and static.sgraph.ai. The core message was: **reuse what we've already shipped; don't write new code where proven code exists.**

### What the SG/Send Team Identified

The debrief listed 12 sections of guidance. The critical findings were:

1. **Missing `sgraph_ai__tools/` base folder.** Every SG project uses a `{package_name}/` folder as the deployable root that gets synced to S3. The Tools repo had code at the repo root, making clean CI/CD impossible.

2. **Flat version folders instead of IFD nested paths.** The repo used `core/crypto/v1.0.0/` (flat) instead of the SG convention `core/crypto/v1/v1.0/v1.0.0/` (nested). This matters because S3 paths, `latest/` aliases, and the `deploy_static_site.py` script all depend on the nested IFD path convention.

3. **No CI/CD pipeline at all.** No `.github/workflows/`, no deploy scripts, no version file. The Send project has a mature pattern (path-scoped triggers, S3 path isolation by environment, Python deploy scripts) that should be reused directly.

4. **No i18n structure.** Send uses `_common/en-gb/i18n` with CI-generated locale folders. Tools had no locale support.

5. **No manifest.json files.** Send uses manifests to declare what each module contains. Tools had none.

6. **Tools pages not structured for multi-locale deployment.** No `_common/` shared assets folder, no locale redirect, no 404 page, no robots.txt/sitemap.xml.

### What the Tools Team Did

The Tools team (Dev role leading, with Architect and Librarian support) created a dev plan and executed all corrections in a single session:

`team/explorer/dev/reviews/v0.1.0__dev-plan__ifd-restructure.md`

**Phase 1 -- Folder Restructure:**
- Created `sgraph_ai__tools/` base folder as the deployable root
- Moved all core modules to IFD nested paths: `core/crypto/v1/v1.0/v1.0.0/`, `core/ssh/v1/v1.0/v1.0.0/`
- Moved all components to IFD nested paths: `components/header/v1/v1.0/v1.0.0/`, `components/footer/v1/v1.0/v1.0.0/`
- Restructured tools to `tools/v0/v0.1/v0.1.0/` with `_common/en-gb/i18n` pattern
- Created `manifest.json` for every module (5 total: crypto, ssh, header, footer, tools UI)
- Extracted shared CSS into `_common/css/tools.css` with design tokens
- Added `data-i18n` attributes to all translatable text (35 keys across landing page and SSH keygen)
- Created i18n JSON files for 5 starter locales (en-gb, en-us, fr-fr, de-de, es-es)
- Added locale redirect (`index.html`), 404 page, robots.txt, sitemap.xml
- Updated all import paths to use IFD nested version paths
- Removed old flat-version folders

**Phase 2 -- CI/CD Infrastructure:**
- Created `version` file at repo root containing `v0.1.0`
- Copied `scripts/deploy_static_site.py` from SG/Send repo
- Adapted `scripts/generate_tools_i18n_pages.py` from Send's i18n generator
- Adapted `scripts/inject_build_version.py` for Tools repo paths
- Created `.github/workflows/deploy-tools__dev.yml` (triggers on push to dev)
- Created `.github/workflows/deploy-tools__main.yml` (triggers on push to main)

**Phase 3 -- Cleanup:**
- Updated `.gitignore` for CI-generated locale folders
- Updated reality document to reflect all new paths and infrastructure

## Decisions Made

| # | Decision | Rationale | Source |
|---|----------|-----------|--------|
| 1 | Adopt IFD nested version paths (`v1/v1.0/v1.0.0/`) | Matches SG/Send production convention; required by `deploy_static_site.py` and S3 path structure | SG/Send debrief, section 2 |
| 2 | Create `sgraph_ai__tools/` as deployable root | Every SG project uses `{package_name}/` for S3 sync isolation; keeps team/, briefs/, .claude/ out of deployment | SG/Send debrief, section 1 |
| 3 | Reuse `deploy_static_site.py` from Send | Script is generic and already handles content-type detection, cache headers, release versioning, latest alias, and CloudFront invalidation | SG/Send debrief, section 3 |
| 4 | Start with 5 locales (en-gb + 4 generated) | SG/Send debrief recommends starting small; full 17-locale set deferred until pipeline is proven | SG/Send debrief, section 9 |
| 5 | No `latest/` folders in git | `latest/` is a CI/deployment concept only -- created in S3 by `aws s3 sync` from the release folder | SG/Send debrief, section 4 |
| 6 | Keep existing crypto and SSH code as-is for now | SG/Send debrief recommends eventually importing from static.sgraph.ai, but for MVP the existing code serves the SSH keygen tool | SG/Send debrief, section 6 |
| 7 | Tools get i18n; core modules do not | Pure JS libraries have no user-facing text; only HTML pages and components with visible text need i18n | SG/Send debrief, section 9 |

## Outcome

The Tools repo went from a flat-structured skeleton with no deployment infrastructure to a fully IFD-compliant, deployed static site in a single session. The site is live at `dev.tools.sgraph.ai` with the landing page and SSH keygen tool both accessible.

This is the first time tools.sgraph.ai has served live traffic. It validates the full pipeline: repo structure -> CI workflow -> S3 deployment -> CloudFront serving -> browser access.

---

## Known Issues

1. **Root URL returns 404.** `dev.tools.sgraph.ai/` does not resolve. A root-level redirect to `tools/v0/v0.1/v0.1.0/en-gb/index.html` (or to `latest/`) is needed.

2. **SGraph header not yet integrated.** The site uses the basic `sg-header` component, not the shared sgraph.ai navigation bar (Product, Pricing, Architecture, Team). Integrating the sgraph.ai header is the next task.

3. **AWS secrets not confirmed.** CI workflows exist but may not have GitHub Actions secrets configured yet. Deployment may have been done manually or via a pre-existing pipeline.

4. **Crypto module unverified.** `sg-crypto.js` has not been tested against Send's production crypto. The SG/Send team flagged this as a risk.

---

## What's Next

1. **Root redirect** -- Add an `index.html` at the site root (or S3 redirect rule) so `dev.tools.sgraph.ai/` resolves to the landing page.

2. **SGraph header integration** -- Replace or augment `sg-header` with the shared sgraph.ai navigation bar used across sgraph.ai, send.sgraph.ai, and vault.sgraph.ai.

3. **Promote to main** -- Once the dev deployment is validated, merge to `main` and deploy to `tools.sgraph.ai` (production).

4. **Verify crypto against Send production** -- Run cross-module compatibility tests between `sg-crypto.js` and Send's `sg-send-crypto.js`.

5. **Expand locale set** -- Once the 5-locale i18n pipeline is proven, expand to the full 17-locale list used by SG/Send.
