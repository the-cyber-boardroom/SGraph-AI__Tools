# Part 1 — How the CI pipeline builds a deploy today

**Version:** v0.2.92 · Part 1 of 3

Single workflow: `.github/workflows/deploy-tools.yml`. No other workflow exists.
No test job exists anywhere in CI.

## 1. Trigger and environment mapping

```
push → dev              ─┐
push → main             ─┼→ increment-tag (minor on dev, major on main) → deploy
workflow_dispatch       ─┘   (dispatch skips increment-tag)

environment    S3 prefix
dev         →  websites/sgraph-tools/dev/
main        →  websites/sgraph-tools/main/
production  →  websites/sgraph-tools/prod/      (manual dispatch only)
```

Path filter: only `sgraph_ai_tools__static/**`, `scripts/**`, the workflow itself, and
`sgraph_ai_tools/version` trigger a build.

## 2. The six deploy steps

### Step A — Resolve latest UI version

```bash
LATEST=$(ls -d sgraph_ai_tools__static/tools/v0/v0.1/v0.1.* | sort -V | tail -1 | xargs basename)
# → v0.1.67
APP_VERSION=$(cat sgraph_ai_tools/version)   # → v0.1.0
```

Note there are **three unrelated version numbers** in play:

| File / source | Value today | What it drives |
|---|---|---|
| `version` (repo root) | `v0.2.92` | Nothing in this pipeline |
| `sgraph_ai_tools/version` | `v0.1.0` | `appVersion` in `build-info.js` only |
| highest `tools/v0/v0.1/v0.1.*` dir | `v0.1.67` | **The S3 release path** |
| git tag from `increment-tag` | separate counter | Nothing in this pipeline |

The S3 release path is derived from a *directory listing*, not from any version file.

### Step B — Build layered IFD content

```bash
python scripts/build_ifd_latest.py \
  --source-dir sgraph_ai_tools__static \
  --ifd-base   tools/v0/v0.1 \
  --up-to      auto
```

`scripts/build_ifd_latest.py` is the heart of the current model:

1. `rmtree(_latest)` then `mkdir(_latest)` — always a clean rebuild.
2. Discover every `v0.1.N` dir, sort ascending by parsed `(major, minor, patch)` tuple.
3. For each version in order, `shutil.copy2` every file into `_latest/<same relative path>`.
   Later versions silently overwrite earlier ones.
4. Verify `_latest/en-gb/index.html` exists; fail the build if not.

Measured output on the current tree:

```
  + v0.1.0: 13 files
  + v0.1.1: 13 files
  ...
  + v0.1.53: 72 files      ← the last full re-lay of every tool
  ...
  + v0.1.67: 34 files
  = _latest: 556 total files       (from 904 input files across 68 folders)
  Tools: 50 tool directories under en-gb/
```

**There is no delete primitive.** The only `rmtree` in the script wipes `_latest` before the
rebuild. A file introduced in `v0.1.2` is served forever unless a later version writes to the
exact same path.

### Step C — Generate i18n locale pages

```bash
python scripts/generate_tools_i18n_pages.py \
  --source-dir sgraph_ai_tools__static/tools/v0/v0.1/_latest
```

Walks `_latest/en-gb/**/*.html` (53 files), and for each of 4 locales (`en-us`, `fr-fr`,
`de-de`, `es-es`) emits a translated copy into a sibling locale folder. **HTML only** — CSS/JS
stay shared via `../_common/`. Adds **212 generated HTML files**. Gitignored.

### Step D — Inject build version

```bash
python scripts/inject_build_version.py --version v0.1.67 \
  --source-dir …/_latest --commit $GITHUB_SHA
```

Writes `_latest/_common/js/build-info.js` exposing `window.SGRAPH_BUILD`. Gitignored.

### Step E — AWS credentials (soft-fail)

If `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` are unset the deploy steps are **skipped and
the job still goes green**. A credential misconfiguration produces a passing build that
deployed nothing.

### Step F — Deploy to S3

```bash
python scripts/deploy_static_site.py \
  --site sgraph-tools --version v0.1.67 \
  --source-dir sgraph_ai_tools__static \
  --deploy-env dev --skip-validation --clean-urls \
  --clean-urls-source-version tools/v0/v0.1/_latest
```

`--skip-validation` is passed unconditionally, so `validate_website_files`,
`validate_keys_json` and `check_broken_links` never run.

CloudFront invalidation is currently disabled — the workflow carries
`# TODO: add --cloudfront-distribution-id back once CF cache is restored`.

## 3. What `deploy_static_site.py --clean-urls` actually uploads

`version_to_ifd_path("v0.1.67")` → `v0/v0.1/v0.1.67`.

**Step 1 — full archive.** Syncs the *entire* `sgraph_ai_tools__static/` tree to
`releases/v0/v0.1/v0.1.67/`, split into six passes by file type so each gets its own
`Cache-Control` and `Content-Type`. This includes `core/`, `components/`, **all 68 tool
version folders**, and the freshly built `_latest/`.

**Step 2 — clean-URL overlay.** Copies `_latest`'s `_common/`, every locale folder, `i18n/`,
and root files (`index.html`, `404.html`, `robots.txt`, `sitemap.xml`, `manifest.json`) to the
**root of the same release prefix**, plus the locale-detector `index.html` from the source root.

CloudFront's origin points at `releases/{ifd_path}/`, which is why the flattened content must
be duplicated up to that level.

**Step 3 — `latest/` mirror.** Syncs `components/` and `core/` plus the same clean-URL overlay
to `websites/sgraph-tools/{env}/latest/`. Described in-code as "for future origin switch".

### `--delete` coverage

Only the **HTML** pass passes `--delete`. CSS, JS, JSON, images and fonts are synced without
it, so a removed `.js` or `.css` file is never deleted from S3 — it lingers at its old key
indefinitely.

## 6. How tools reference shared code

Confirmed by grepping the built `_latest`: tool code uses **root-absolute** paths.

```js
import { ... } from '/core/markdown/v1/v1.0/v1.0.0/sg-markdown.js'
import { ... } from '/core/sg-layout/v0.1.0/sg-layout-events.js'
import { ... } from '/core/sg-media-analysis/v0/v0.1/v0.1.0/align.js'
```

```html
<link href="/core/markdown/v1/v1.1/v1.1.0/sg-markdown.css">
<script src="https://dev.sgraph.ai/_common/js/components/sg-site-header/v1/v1.0/v1.0.6/sg-site-header.js">
```

Only 4 relative `../../…/core/…` references survive anywhere in the tree — deep, fragile, and
inconsistent (`../../../../../` in one file, `../../../../../../../` in another).

**This is the single most important constraint on the flattening plan.** Because `/core/…` and
`/components/…` are root-absolute and — per `.claude/CLAUDE.md` — are imported by
send.sgraph.ai, vault.sgraph.ai, the workspace and the Chrome extension, they **must stay at
those URLs**. They cannot be vendored inside a release folder without breaking every external
consumer. Part 3 builds on this.
