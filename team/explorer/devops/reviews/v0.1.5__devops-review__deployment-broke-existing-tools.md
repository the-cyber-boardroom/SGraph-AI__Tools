# DevOps Review: v0.1.5 Deployment Broke Existing Tools (404s)

**Version:** v0.1.5
**Date:** 28 March 2026
**Role:** DevOps (Explorer team)
**Session:** `claude/start-tools-explorer-session-WariD`
**Severity:** P0 — all existing tools returned 404 on dev.tools.sgraph.ai

---

## What Happened

When v0.1.5 was deployed to dev, all existing tools (vault-browser, file-encryptor, ssh-keygen, etc.) started returning 404. Only the 2 new tools (image-tools, video-tools) worked.

## Root Cause

The v0.1.5 `en-gb/` directory was created with only the 2 new tools. The deploy script's `--clean-urls-source-version tools/v0/v0.1/v0.1.5` extracts locale content from that folder and syncs it to the S3 clean URL root, **replacing** everything. Since v0.1.5 only had 2 tools, the other 8 were deleted from the clean URL root.

```
v0.1.4/en-gb/  (9 tools)    →  v0.1.5/en-gb/  (2 tools)  =  7 tools lost
```

## The IFD Rule (Violated)

From the SG/Send debrief (section 9):

> "Surgical minor versions = full previous version + deltas"

A minor version bump (v0.1.4 → v0.1.5) must be **additive**. The new version should contain everything from the previous version plus the new additions. It should never be a subset.

## Fix Applied

**Wrong approach (reverted):** Copying all v0.1.4 tools into v0.1.5. This violates IFD — each version should only contain its deltas.

**Correct approach (implemented):** Fixed the deployment infrastructure to LAYER all versions in order into a `_latest` directory, with later versions overwriting earlier ones.

### What Changed

1. **`scripts/build_ifd_latest.py`** (NEW) — Layers all version directories (`v0.1.0` → `v0.1.1` → ... → `v0.1.5`) into a `_latest/` directory inside the IFD base path. Later versions overwrite earlier ones. The deploy script then uses `_latest` as its clean-urls source.

2. **`scripts/run-locally.sh`** (UPDATED) — Local server now iterates all version directories in order (`sort -V`) and copies each into the serve directory, merging content. No more single `UI_VERSION` content source.

3. **CI workflows** (UPDATED) — Both dev and main workflows now:
   - Run `build_ifd_latest.py` before deploying
   - Use `--clean-urls-source-version tools/v0/v0.1/_latest` (the merged output)

4. **v0.1.5 cleaned up** — Removed the incorrectly copied v0.1.4 tools. v0.1.5 now correctly contains only its deltas: `image-tools/`, `video-tools/`, `index.html` (updated landing page).

### How IFD Layering Works

```
v0.1.0/en-gb/  →  ssh-keygen/     (base)
v0.1.1/en-gb/  →  (nothing new)   (frozen)
v0.1.2/en-gb/  →  file-hasher/, file-encryptor/, key-generator/,
                   vault-browser/, vault-pyodide/
v0.1.4/en-gb/  →  pyodide-repl/, sg-send-cli/, vault-browser/ (updated)
v0.1.5/en-gb/  →  image-tools/, video-tools/, index.html (updated landing)

_latest/en-gb/ =  ALL of the above merged (10 tools)
```

Each version only ships its deltas. The `build_ifd_latest.py` script merges them.

## IFD Rules (Corrected)

1. **Each version contains ONLY its deltas** — new or changed files
2. **Never copy previous version content into a new version** — that's the build system's job
3. **The `_latest` directory is built, not committed** — it's a CI artifact
4. **Overwrite is forward-only** — v0.1.5 files replace v0.1.4 files, never the reverse
5. **The landing page is an exception** — it lists ALL tools, so it gets updated in the latest version
