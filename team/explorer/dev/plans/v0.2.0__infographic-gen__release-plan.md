# v0.2.0 — Infographic Generator (IFD) Release Plan

**Goal.** Ship `sgraph_ai_tools__static/tools/v0/v0.2.0/en-gb/infographic-gen/` that is:

1. **Functionally equivalent** to the latest working IFD in the v0.1.x line.
2. **100% self-contained** under `tools/v0/v0.2.0/` — when deployed, no runtime path resolves into `tools/v0/v0.1/*`.
3. Tracked in the reality document in the same commit.

Versioned `core/` and `components/` modules (e.g. `/core/sg-tool-api/v0/v0.1/v0.1.0/…`, `/components/llm/sg-llm-request/v0/v0.1/v0.1.2/…`) are **out of scope** — they are independently versioned outside the tools tree and consumers (including v0.2.0) keep importing them at their pinned paths. "Self-contained" means **no v0.1.x tool-tree paths**, not "no shared libraries".

---

## 1. What the v0.1.x IFD line actually looks like

The reality document (`team/explorer/librarian/reality/v0.1.0__what-exists-today__2__tools.md`, lines 32–86) confirms IFD has been released in two modes:

- **Full snapshots** — v0.1.6, v0.1.8, v0.1.12, v0.1.24, v0.1.25, v0.1.26.
- **Delta-only commits** — every release from v0.1.27 onwards contains *only the files that changed* in that bump. The CDN serves them as overlays on top of the previous version.

The last v0.1.x release that touched IFD content was **v0.1.37**. There is no IFD entry for v0.1.38–v0.1.52 in the reality doc. `tools/v0/v0.1/v0.1.53/en-gb/infographic-gen/index.html` exists as an isolated stub that swaps `sg-site-header` for an external `https://dev.sgraph.ai/...` CDN import; it is **not** documented in the reality doc and references three local files (`infographic-gen.js`, `infographic-gen.css`, `../../_common/favicon.svg`) that do not exist in `v0.1.53/`. Treat v0.1.53 as a partial site-header experiment, not a working IFD release.

### Dependency classification

For the merged v0.1.37 IFD state, every runtime fetch falls into one of three buckets:

- **(a) v0.1.x tool-tree paths → MUST be relocated for v0.2.0:**
  `../../_common/css/tools.css`, `../../_common/favicon.svg`, all sibling JS/CSS in the tool folder. All of these live under `tools/v0/v0.1/…`; copy them under `tools/v0/v0.2.0/…`.
- **(b) `/core/…` and `/components/…` at pinned versions → KEEP AS-IS:**
  `sg-layout v0.1.0`, `sg-tool-api v0/v0.1/v0.1.0`, all `sg-llm-*`, `sg-openrouter-generation v0.1.1`, `sg-infographic-model-picker v0.1.0`, `sg-infographic-export v0.1.0`, `sg-tool-api-{explorer,console,manifest} v0.1.0`, `sg-site-header v1/v1.0/v1.0.2` (local path, not dev.sgraph.ai). These are independently versioned, exist in the repo at those pinned paths, and are explicitly allowed by the self-containment goal.
- **(c) External CDNs → MUST be removed:**
  `https://dev.sgraph.ai/_common/js/components/sg-site-header/v1/v1.0/v1.0.6/sg-site-header.js` (only appears in v0.1.53's stub; not in v0.1.37). Replace with the local `/components/site-header/v1/v1.0/v1.0.2/sg-site-header.js`.

There are no other external CDN dependencies in the v0.1.37 codebase.

## 3. Build sequence

1. **Create the directory skeleton.** `tools/v0/v0.2.0/_common/css/` and `tools/v0/v0.2.0/en-gb/infographic-gen/`.

2. **Copy `_common` assets.**
   - `tools/v0/v0.1/v0.1.53/_common/css/tools.css` → `tools/v0/v0.2.0/_common/css/tools.css`.
   - `tools/v0/v0.1/v0.1.22/_common/favicon.svg` → `tools/v0/v0.2.0/_common/favicon.svg`.

3. **Flatten the IFD deltas.** Copy each file in the source-of-truth map into `tools/v0/v0.2.0/en-gb/infographic-gen/` using the listed v0.1.x folder as the source. Run a grep on the resulting tree for `v0.1.` and `dev.sgraph.ai` — both should match **only** inside the pinned `/core/` and `/components/` import paths (those are correct; they are version numbers of independent modules, not v0.1.x tool paths).

4. **Rewrite `index.html`.** Start from `tools/v0/v0.1/v0.1.34/en-gb/infographic-gen/index.html` and apply:
   - Local script for site-header: `<script type="module" src="/components/site-header/v1/v1.0/v1.0.2/sg-site-header.js"></script>` (delete the `dev.sgraph.ai` variant if present).
   - Favicon: `<link rel="icon" type="image/svg+xml" href="../../_common/favicon.svg">`.
   - Stylesheet: `<link rel="stylesheet" href="../../_common/css/tools.css">`, `<link rel="stylesheet" href="/core/sg-layout/v0.1.0/sg-layout.css">`, `<link rel="stylesheet" href="infographic-gen.css">`.
   - Module loader: `<script type="module" src="infographic-gen.js"></script>`.

5. **Bump version strings.**
   - `manifest.json` → `"version": "0.2.0"`.
   - `infographic-gen.js` `SgToolApi({ version: { api: '0.2.0', ui: '0.2.0', content: '0.2.0' } })` (currently `0.1.37` / `0.1.0`).
   - `localStorage` key — keep `'sg-infographic-gen-prefs'` to preserve user prefs across the upgrade. (Changing it would silently strand v0.1 user state. If we ever want to deliberately reset prefs, do it in a follow-up.)

6. **Update the reality document.** Add a row to `team/explorer/librarian/reality/v0.1.0__what-exists-today__2__tools.md`:
   `| Infographic Generator | sgraph_ai_tools__static/tools/v0/v0.2.0/en-gb/infographic-gen/ | v0.2.0 | **NEW** — Self-contained re-release. Functionally equivalent to v0.1.37 (last v0.1.x IFD). Flattens deltas from v0.1.25 → v0.1.37 into one folder, drops the v0.1.53 dev.sgraph.ai site-header experiment, no v0.1.x runtime paths. |`
   Also add a `_common` row for the new `tools/v0/v0.2.0/_common/`.

7. **Sanity checks (manual).**
   - `grep -rE "v0\.1\.[0-9]+/en-gb|v0\.1\.[0-9]+/_common" tools/v0/v0.2.0/` returns nothing.
   - `grep -rE "dev\.sgraph\.ai" tools/v0/v0.2.0/` returns nothing.
   - All `import '/components/...'` and `import '/core/...'` paths resolve to files that exist on disk under the corresponding repo locations (the audit confirmed all v0.1.37 imports resolve today).
   - Open `tools/v0/v0.2.0/en-gb/infographic-gen/index.html` in a browser via a local static server: page renders, `window.__tool` is live, `window.__tool.meta.getMethods()` lists 13 actions, Skills tab renders all three SKILL files, dev-panel footer bar is clickable.

8. **Smoke test.** Re-point `sgraph_ai_tools__static/tests/playwright/infographic-gen-smoke.js` at the v0.2.0 URL and run. The test is version-agnostic on the API surface, so it should pass without code changes; the only edit is the page URL constant. (If the test hardcodes a `0.1.37` UI version assertion, update it to `0.2.0`.)

## 4. Open decisions to confirm with Dinis before implementing

1. **Source folder for `index.html`** — v0.1.34 (last working local-only) vs adapting v0.1.53 minus the CDN swap. Recommendation: v0.1.34 because it matches the `dev-panel.js` markup contract that ships in v0.1.37.
2. **Whether `_common/` lives at `tools/v0/v0.2.0/_common/` or whether v0.2.0 should pin to `tools/v0/v0.1/v0.1.53/_common/`.** The brief says no v0.1.x dependency, so the answer is the new path — but it means every other tool we re-release into v0.2.0 needs to follow the same pattern. This plan assumes IFD is the first.
3. **localStorage key** — keep (preserve user prefs) vs rename (clean slate). Recommendation: keep.
4. **Reality doc structure** — whether v0.2.0 gets its own reality cover sheet (`v0.2.0__what-exists-today.md`) or just new rows in the v0.1.0 reality doc. Default to "new rows in the existing doc" unless the librarian asks for a versioned cover sheet.

---

## 5. Out of scope (explicitly NOT in v0.2.0)

- Refactoring IFD architecture, splitting files further, or introducing new features.
- Migrating other tools to v0.2.0 (one at a time; IFD is first).
- Upgrading any `/core/` or `/components/` pinned dependency. Functional equivalence means same components, same pinned versions.
- Removing/renaming the localStorage key.
