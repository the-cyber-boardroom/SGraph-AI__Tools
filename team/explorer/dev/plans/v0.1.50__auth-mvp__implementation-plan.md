# Auth MVP — Implementation Plan (Phase 1: Building Blocks)

**Version:** v0.1.50 | **Date:** 19 April 2026 | **Role:** Dev
**Follows:** `team/humans/dinis_cruz/briefs/04/19/v0.21.2__architect-review__auth-mvp-revised-vault-key-as-credential.md`

## 1. Goal

Build and validate each auth building block independently before wiring them together. Each component is a standalone Web Component testable in isolation and combined in an MVP tool with a health-check style UI.

**No vault in Phase 1.** The vault integration is Phase 2 (separate plan). This phase proves the UX flows and browser APIs work correctly.

## 2. Component Catalog

### 2.1 `sg-auth-google` — Google OAuth

**Path:** `components/auth/sg-auth-google/v0/v0.1/v0.1.0/sg-auth-google.js`
**Purpose:** Google Identity Services wrapper — sign-in, sign-out, token parsing.

```
Attributes:
  client-id    string   Google OAuth Client ID
  auto-prompt  boolean  Call prompt() on connect

Methods:
  initialize(clientId)        → Promise<void>   load GIS + configure
  signIn()                    → void            show One Tap / button
  signOut()                   → void            revoke + clear localStorage
  getStatus()                 → AuthStatus      { signedIn, provider, claims, expiresAt, expired }
  parseToken(idToken)         → Claims          decode JWT payload (no verify needed client-side)

Events (on window):
  sg-auth:signed-in    { provider: 'google', claims, idToken }
  sg-auth:signed-out   { provider: 'google' }
  sg-auth:error        { provider: 'google', message }

localStorage key: 'sg-auth-token-google'
Token shape: { idToken, claims, expiresAt, provider, savedAt }
```

**Other OAuth providers:**

| Provider | Client-side PKCE? | CDN script? | Notes |
|---|---|---|---|
| Google | ✅ GIS implicit | `accounts.google.com/gsi/client` | Recommended — best UX |
| Microsoft | ✅ MSAL.js PKCE | `alcdn.msauth.net/lib/msal-browser` | ~3MB, full PKCE, easy to add |
| Apple Sign In | ✅ AppleID.js | `appleid.cdn-apple.com/appleauth/static/jsapi/appleid/1/en_US/appleid.auth.js` | Requires Apple Developer account |
| GitHub | ❌ server required | N/A | GitHub OAuth app can't do PKCE redirect client-side |
| Discord | ⚠️ CORS issues | N/A | PKCE works but their CORS policy blocks browser clients |

**MVP ships Google only.** Microsoft is the easiest next addition — `sg-auth-microsoft.js` would mirror this component's API exactly, replacing GIS with MSAL.js.

### 2.2 `sg-auth-tokens` — Token Storage (headless)

**Path:** `components/auth/sg-auth-tokens/v0/v0.1/v0.1.0/sg-auth-tokens.js`
**Purpose:** localStorage-based token store (MVP stand-in before vault storage).

```
Exports: SgAuthTokens (headless Web Component) + named functions

Methods (instance + static exports):
  saveToken(provider, data)    → void     persist token to localStorage
  getToken(provider)           → Token|null
  hasValidToken(provider)      → boolean   checks expiry
  removeToken(provider)        → void
  listTokens()                 → Token[]   all stored tokens (unexpired first)
  clearAll()                   → void      remove all sg-auth-token-* keys

Token shape:
  { idToken, accessToken?, claims, provider, expiresAt, savedAt }

localStorage key pattern: 'sg-auth-token-{provider}'
Events (on window): sg-auth:token-saved, sg-auth:token-removed, sg-auth:tokens-cleared
```

### 2.5 `sg-credential-store` — Browser Password Manager

**Path:** `components/auth/sg-credential-store/v0/v0.1/v0.1.0/sg-credential-store.js`
**Purpose:** Wrap the Credential Management API with a form-based fallback.

```
Methods:
  detect()                   → { supported, method: 'native'|'form'|'none', browser }
  store(name, secret)        → Promise<void>   save to password manager
  get(mediation?)            → Promise<{name, secret}|null>   retrieve (may show chooser)
  markRemoved(name)          → void   remove from local index (can't delete from PM)

Mediation values: 'silent' | 'optional' (default) | 'required'

Browser paths:
  Chromium (Chrome/Edge/Brave/Opera):
    store → new PasswordCredential({id: name, password: secret}) → navigator.credentials.store()
    get   → navigator.credentials.get({password: true, mediation})

  Safari / Firefox (PasswordCredential not supported):
    store → hidden <form autocomplete="new-password"> programmatically submitted
    get   → visible <form autocomplete="current-password"> shown to user

Note: No browser exposes a "list all stored passwords" API.
      sg-credential-store maintains a localStorage INDEX of names + timestamps.
      Secrets never stored in localStorage — only in the password manager.

localStorage key: 'sg-cred-index'  → [{ name, storedAt, method }]

Events (on window):
  sg-cred:stored     { name, method }
  sg-cred:retrieved  { name, method }
  sg-cred:unsupported { browser }
  sg-cred:error      { name, message }
```

**Important security note:** The browser password manager syncs across devices only when the user is signed into their sync account (Google account for Chrome, Apple ID for Safari, Firefox account, or a third-party manager like 1Password/Bitwarden). The sync requirement is a feature, not a bug — it ties the credential sync to the user's existing trusted identity infrastructure.

**Path:** `components/auth/sg-credential-list/v0/v0.1/v0.1.0/sg-credential-list.js`
**Purpose:** Show what credentials this app has stored (via local index).

```
Visual:

  • [Retrieve] button per entry — triggers credentials.get() chooser
  • [Add new] button — opens store flow (prompts for name + secret)
  • [Clear index] button — removes local metadata (does not affect PM entries)

Reads from: sg-credential-store's localStorage index
Methods:
  refresh()       → void    re-read index, re-render

```

### 2.7 `sg-vault-picker` — Vault Create / Open (Stage 1)

**Path:** `components/vault/sg-vault-picker/v0/v0.1/v0.1.0/sg-vault-picker.js`
**Purpose:** Create and open vaults. Stage 1 uses localStorage as the credential backend.

```
Attributes:
  mode    'create' | 'open' | 'auto'   default: 'auto'

Methods:
  createVault(name?)        → Promise<{ vaultKey, vaultId, name }>
  openVault()               → Promise<{ vaultKey, vaultId, name }|null>
  saveVault(name, vaultKey) → Promise<void>   persist vault credential
  listVaults()              → VaultEntry[]    from localStorage index

Stage 1 storage: localStorage key 'sg-vault-picker-vaults' → [{ name, vaultKey, vaultId, createdAt }]
Stage 2 storage: navigator.credentials (Credential Management API) — see Phase 2 plan

Events (on window):
  vault:opened    { vaultKey, vaultId, name, source: 'created'|'opened' }
  vault:created   { vaultKey, vaultId, name }
  vault:cancelled {}
  vault:error     { message }

Vault key format (Stage 1): random 24-char hex + ':' + random 8-char hex
  (mirrors real SG/Send vault key format for UX testing)
  e.g.  'a3f7c2d8e1b94f0256781abc:2d7e9a1f'

Note: Stage 1 vaults are local-only and not connected to SG/Send storage.
Stage 4 (Phase 2) wires real vault creation via sg-vault-write.
```

## 3. MVP Tool: `auth-mvp`

**Path:** `tools/v0/v0.1/v0.1.50/en-gb/auth-mvp/`
**Version:** 0.1.50

### Layout

```
sg-layout: left 38% (Setup + Checks) | right 62% (Output log)
Bottom dev panel: Skills / Explorer / Console / Manifest
```

### Left Panel — Check Sections

```
SETUP
  Google Client ID: [___________________________] [Save]
  Note: get yours at console.cloud.google.com

──────────────────────────────────────────────────
1. Auth Status Detection                  [Run] ⏳
2. Google OAuth Flow                      [Run] ⏳
   [Sign in with Google]  (rendered by GIS)
3. Token Storage (localStorage)           [Run] ⏳
4. User Info Display                      [Run] ⏳
5. Logout Workflow                        [Run] ⏳
6. Browser Credential Store               [Run] ⏳
7. Credential List (Password Manager)     [Run] ⏳
```

Each check section:
- Status icon: ⏳ pending / ✅ pass / ❌ fail / ⚠️ partial
- [Run] button triggers the check
- Output flows to right panel

### Right Panel — Output

```
Tabs:
  📋 Output   — structured result of the last-run check
  📡 Events   — live stream of all sg-auth:* and sg-cred:* window events
```

### Check Definitions

| # | Check | What it tests |
|---|-------|---------------|
| 1 | Auth Status Detection | Read localStorage, parse expiry, list providers, show state |
| 2 | Google OAuth Flow | Load GIS script, detect clientId, initialize, render button |
| 3 | Token Storage | save/get/expire/list/clearAll round-trip on localStorage |
| 4 | User Info Display | Render sg-auth-user from stored claims |
| 5 | Logout Workflow | Call signOut(), verify localStorage cleared, event fired |
| 6 | Browser Credential Store | detect() → report method; store test secret; get() round-trip |
| 7 | Credential List | Show index count; render sg-credential-list; retrieve flow |

## 4. Implementation Order

```
1. sg-auth-tokens       (no deps — pure storage)
2. sg-auth-google       (depends on: localStorage)
3. sg-auth-status       (depends on: sg-auth-tokens events)
4. sg-auth-user         (depends on: sg-auth-tokens, sg-auth-google, sg-auth-status)
5. sg-credential-store  (no auth deps)
6. sg-credential-list   (depends on: sg-credential-store index)
7. sg-vault-picker      (depends on: sg-credential-store Stage 2; standalone in Stage 1)
8. auth-mvp tool        (composes all the above)
```
