### PKI Key Requirements

The `pki.private_key_jwk` field is the user's **long-term Ed25519 identity key**. It is:

1. **Generated at vault creation** — using `window.crypto.subtle.generateKey({ name: 'Ed25519' }, true, ['sign'])` (Web Crypto API, non-extractable flag NOT set so it can be exported and stored)
2. **Stored encrypted** — inside the vault blob, under AES-256-GCM keyed by the vault key. Double-encrypted: vault layer AES-GCM wraps the entire blob including the private key JWK
3. **Never leaves the vault** — the private key JWK only exists in memory when the vault is open
4. **Used for:**
   - Signing SGraph documents (authorship attestation)
   - End-to-end encrypted messaging (recipient uses sender's public key)
   - Future PKI certificate requests (for code signing, email, etc.)
   - Agent identity — Claude agents can sign their outputs with the user's key

**PKI generation code (for sg-vault-picker Stage 3):**
```javascript
async function generateUserKeyPair() {
    const keyPair = await window.crypto.subtle.generateKey(
        { name: 'Ed25519' },
        true,  // extractable — needed to export + store in vault
        ['sign', 'verify']
    );
    const privateJwk = await window.crypto.subtle.exportKey('jwk', keyPair.privateKey);
    const publicJwk  = await window.crypto.subtle.exportKey('jwk', keyPair.publicKey);
    const pubKeyRaw  = await window.crypto.subtle.exportKey('raw', keyPair.publicKey);
    const fingerprint = await sha256Hex(pubKeyRaw);
    return { privateJwk, publicJwk, fingerprint };
}
```

**Public key distribution:** The public key JWK / fingerprint can be shared openly. Future tools (messaging, signing verification) read the public key from the vault's public profile.

## 5. Track C: Google Identity as Vault Personalisation

After vault is open and user clicks "Personalise with Google":

```javascript
// GIS One Tap returns response.credential (JWT)
const claims = parseJwt(response.credential);

// Write claims into vault
vault.oauth_tokens.google = {
    provider: 'google',
    id_token: response.credential,
    claims,
    expires_at: claims.exp * 1000,
    saved_at: Date.now(),
};
vault.identity.display_name = claims.name;
vault.identity.avatar_url   = claims.picture;

await saveVault(vault);  // re-encrypts entire blob, writes to SG/Send
```

The Google JWT never touches SG/Send's server — it lives in the encrypted vault blob.

2. **Shared vault auto-save** — suppress save prompt for one-time shared vaults?
3. **Vault name leakage** — vault name visible in password manager; document in UX copy
