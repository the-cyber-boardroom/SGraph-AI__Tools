## 2. Kokoro.js CDN Investigation

**This is the P0 blocker — must be validated before any `sg-tts.js` code is committed.**

### What the brief and Architect review say

The brief provides a CDN snippet:
```html
import { KokoroTTS } from "https://cdn.jsdelivr.net/npm/kokoro-js@latest";
```

The Architect review notes this is an **npm bare specifier** in a module context, which fails without import maps. The corrected form is a dynamic `import()` of a versioned full URL, following `sg-whisper.js` pattern:
```javascript
const { KokoroTTS } = await import(
  'https://cdn.jsdelivr.net/npm/kokoro-js@1.2.2/dist/kokoro.js'
);
```

### Findings

**jsDelivr:** `https://cdn.jsdelivr.net/npm/kokoro-js` resolves. The dist folder likely contains either `/dist/kokoro.js` (UMD/ESM hybrid) or `/dist/esm/index.js`. Based on the brief's own CDN snippet pointing to the package root, jsDelivr's auto-resolution of package `main`/`module` fields should serve an importable file. However the exact sub-path (`/dist/kokoro.js` vs `/dist/esm/index.js`) **must be manually verified** against the published package before coding.

**esm.sh:** `https://esm.sh/kokoro-js` wraps any npm package as a guaranteed ESM build. This is a reliable fallback if the jsDelivr path resolves to a CJS module. esm.sh rewrites `require()` calls and re-exports as ESM.

**Recommendation:** Prefer `esm.sh/kokoro-js@1.2.2` for the initial implementation — it guarantees ESM output with no dist-path guessing. Switch to a versioned jsDelivr path only after the exact dist path is confirmed. Either way, pin to an explicit semver (`@1.2.2` or current stable) — never `@latest` in a dynamic `import()`.

**Risk verdict: HIGH** — CDN ESM path is unconfirmed. Must be tested in a browser before `sg-tts.js` is written. If neither CDN serves a working ESM build, the entire TTS layer blocks.

## 3. Risk Assessment Table

| Layer | Risk | Reason |
|-------|------|--------|
| Kokoro.js CDN import | **HIGH** | ESM dist path unconfirmed; CJS build would break dynamic import() without esm.sh wrapper. Must verify before coding. |
| WASM vs WebGPU perf | **MED** | WebGPU unavailable on Firefox and older Safari — WASM fallback adds 5–10× latency. q8 WASM still ~1s per 10s audio on modern hardware, acceptable for MVP 1. |
| Canvas captureStream + MediaRecorder | **LOW** | Well-supported in all modern browsers. Chrome/Edge/Safari support VP8/VP9 with Opus. Firefox occasionally has MIME quirks — `getBestMimeType()` handles this. |
| FFmpeg convertToMp4 | **LOW** | `sg-video.js` v1.0.0 already lazy-loads FFmpeg from CDN and is verified. `convertToMp4()` is a straightforward additive export reusing the same loader. |
| 160MB model cold start UX | **MED** | First-load 160MB download is jarring without progress feedback. Must expose a `loadTTS()` progress event and show a spinner/progress bar in `ui-preview.js`. Cached on reload via browser cache. |

## 7. Open Questions / Blockers

- **Kokoro CDN path unconfirmed (P0 blocker):** `esm.sh/kokoro-js` must be tested in a real browser before `sg-tts.js` is written. If it fails, the TTS layer has no CDN path.
- **SharedArrayBuffer requirement:** Some ONNX WASM builds require `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp` headers. CloudFront must serve these headers for the video-creator origin or WASM will silently fall back to slower non-SAB mode.
- **Audio sync drift:** Canvas animation driven by `requestAnimationFrame` and TTS audio played via `AudioContext` may drift over long recordings (10+ min). Need to investigate clock-locking the animation loop to `AudioContext.currentTime`.
- **Safari MediaRecorder MIME support:** Safari supports `video/mp4` only (not webm). `getBestMimeType()` must handle this, and the output Blob will already be MP4 on Safari — `convertToMp4()` must skip the FFmpeg step if input is already MP4.
- **VFS memory ceiling:** Storing all slide PNGs + audio buffers in MemoryProvider is fine for small decks (≤30 slides at ~500KB each = ~15MB). For large decks or high-res slides, consider an IndexedDB provider tier from the start.
