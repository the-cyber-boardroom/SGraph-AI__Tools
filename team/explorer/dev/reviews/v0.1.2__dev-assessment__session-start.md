## Codebase Health

### Strengths

- **Consistent architecture** — all modules follow the IFD versioned path structure
- **Clean separation** — core (no UI) / components (reusable UI) / tools (standalone pages)
- **No framework dependencies** — vanilla JS, ES modules, deployable as-is
- **Wire compatibility** — crypto module verified against Send production
- **Cross-language proof** — Python and JS produce identical vault keys (test vectors exist)
- **Manifests everywhere** — every module has a `manifest.json`
- **sg-layout is a serious module** — ~2100 lines, Shadow DOM, drag-to-dock, fractal nesting, 23 test assertions. Well-documented with implementation guide.
- **Growing test suite** — vault-client (40+), sg-layout (23), pyodide tests. 5 test pages total.
- **Comprehensive debriefs** — every session produces detailed debriefs with decisions, bugs, and next steps

### Areas for Improvement

- **Test coverage gaps** — crypto and SSH still have zero browser tests despite being foundational
- **Input validation** — crypto module accepts any input without checking types/sizes
- **Superseded components** — sg-header and sg-footer are still in the repo but superseded by sg-site-header/footer
- **Locale gap** — UI supports 17 locales but CI only generates 5 locale page sets
- **No automated smoke tests** — all testing is manual browser-based
- **sg-layout file path vs version mismatch** — folder is `v0.1.0/` but features are at v0.1.4. Versioning strategy needs clarification.

### Code Patterns Observed

```
tools page → imports core modules + components
           → vanilla JS wiring in <script type="module">
           → CSS from _common/css/tools.css
           → i18n via data-i18n attributes + JSON files
           → Web Components for header/footer/locale picker

sg-layout  → single-file Web Component (~2100 lines)
           → Shadow DOM with embedded CSS template literal
           → plain JS object tree (not classes) for layout nodes
           → mutates tree directly, re-renders
           → event-based communication (16 event types)
```

Both patterns are clean and well-documented.
