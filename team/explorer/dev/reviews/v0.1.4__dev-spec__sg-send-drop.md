## What This Is

A reusable Web Component that provides a one-step "share via SG/Send" experience. Drop a file (or pass a blob programmatically) and it handles the full upload flow: encrypt → upload → display friendly token + copy button + link.

This component is the bridge between every tool on tools.sgraph.ai and the SG/Send product. It turns "Download your result" into "Download OR share securely in one click."

---

## Why a Component (Not Just a Link)

Every tool brief mentions "Share clips securely via SG/Send" as the conversion funnel. But a plain link to send.sgraph.ai means the user has to:
1. Download the file
2. Open send.sgraph.ai in a new tab
3. Upload the file again
4. Wait for encryption + upload
5. Copy the token

With `<sg-send-drop>`, the entire flow happens inline — no page change, no re-upload, no friction. The file is already in memory (as a Blob from the tool's output). The component encrypts and uploads it directly.

## Public API

### HTML Usage

```html
<sg-send-drop
    send-url="https://send.sgraph.ai"
    label="Share via SG/Send"
></sg-send-drop>
```

### Attributes

| Attribute | Type | Default | Description |
|---|---|---|---|
| `send-url` | string | `https://send.sgraph.ai` | SG/Send instance URL. Supports environment detection (dev/main/prod). |
| `label` | string | `"Share via SG/Send"` | Text shown in the drop zone |
| `auto-upload` | boolean | `false` | If true, upload starts immediately when a file is offered (no drop required) |
| `disabled` | boolean | `false` | Grey out the component |

### JavaScript API

```javascript
const sendDrop = document.querySelector('sg-send-drop');

/**
 * Programmatically offer a file for sharing. Shows the file in the
 * drop zone ready to upload. If auto-upload is set, starts immediately.
 * @param {Blob} blob - The file data
 * @param {string} filename - Display name for the file
 */
sendDrop.offerFile(blob, filename);

/**
 * Programmatically offer multiple files (will be zipped before upload).
 * @param {Array<{ blob: Blob, filename: string }>} files
 * @param {string} [zipName='files.zip'] - Name for the zip
 */
sendDrop.offerFiles(files, zipName);

/**
 * Reset the component to its initial state.
 */
sendDrop.reset();
```

### Events

| Event | Detail | When |
|---|---|---|
| `sg-send-start` | `{ filename, size }` | Upload begins |
| `sg-send-progress` | `{ percent, stage }` | During encrypt/upload. Stage: `'encrypting'` or `'uploading'` |
| `sg-send-complete` | `{ token, url, friendlyKey }` | Upload finished successfully |
| `sg-send-error` | `{ error, message }` | Upload failed |

## States and UI

The component transitions through 5 states:

### 1. Idle (no file offered)

```
┌───────────────────────────────────────────────┐
│                                               │
│     Drop a file here to share via SG/Send     │
│           or use the button below             │
│                                               │
│  ┌─────────────────────────────────────────┐  │
│  │  (dashed border drop zone)              │  │
│  └─────────────────────────────────────────┘  │
└───────────────────────────────────────────────┘
```

Accepts drag-and-drop of any file. Uses the same visual language as `sg-upload-dropzone` (dashed border, teal accent on hover).

### 2. File Ready (file offered, not yet uploading)

```
┌───────────────────────────────────────────────┐
│                                               │
│  📄 photo-edited.webp  ·  380 KB             │
│                                               │
│  [ Share via SG/Send ]                        │
│                                               │
└───────────────────────────────────────────────┘
```

Shows filename + size. Single button to start. If `auto-upload` is set, skips this state.

### 3. Processing (encrypting + uploading)

```
┌───────────────────────────────────────────────┐
│                                               │
│  Encrypting...   [▓▓▓▓▓▓▓▓░░░░░] 65%        │
│  Uploading...    [▓▓▓▓░░░░░░░░░] 35%        │
│                                               │
└───────────────────────────────────────────────┘
```

Two-phase progress: encryption (fast, client-side) then upload (network-bound).

### 4. Complete (shared successfully)

```
┌───────────────────────────────────────────────┐
│                                               │
│  ✓ Shared!                                    │
│                                               │
│  Token: purple-sunset-442                     │
│  ┌─────────────────────────────────────────┐  │
│  │ https://send.sgraph.ai/d/abc123        │  │
│  └─────────────────────────────────────────┘  │
│                                               │
│  [Copy Token] [Copy Link] [Open in SG/Send]  │
│                                               │
│  [Share Another]                              │
│                                               │
└───────────────────────────────────────────────┘
```

- **Copy Token** — copies just the friendly key to clipboard (e.g. `purple-sunset-442`)
- **Copy Link** — copies the full download URL
- **Open in SG/Send** — opens the download page in a new tab (`window.open()`)
- **Share Another** — resets to idle state

### 5. Error

```
┌───────────────────────────────────────────────┐
│                                               │
│  ✗ Upload failed                              │
│  Could not connect to send.sgraph.ai          │
│                                               │
│  [Retry] [Cancel]                             │
│                                               │
└───────────────────────────────────────────────┘
```

## Upload Flow (Internal)

```javascript
async function upload(blob, filename) {
    // 1. Generate encryption key
    const key = await generateKey();                    // sg-crypto.js
    const exportedKey = await exportKey(key);

    // 2. Encrypt the file
    dispatch('sg-send-start', { filename, size: blob.size });
    const encrypted = await encryptFile(blob, key);     // sg-crypto.js
    dispatch('sg-send-progress', { percent: 50, stage: 'encrypting' });

    // 3. Upload to SG/Send API
    const formData = new FormData();
    formData.append('file', new Blob([encrypted]), filename);

    const response = await fetch(`${sendUrl}/api/upload`, {
        method: 'POST',
        body: formData,
    });
    dispatch('sg-send-progress', { percent: 100, stage: 'uploading' });

    // 4. Get token and build share URL
    const { id, token } = await response.json();
    const friendlyKey = exportedKey;  // or derive friendly key
    const url = `${sendUrl}/d/${id}`;

    dispatch('sg-send-complete', { token, url, friendlyKey });
}
```

**Note:** The exact SG/Send upload API shape will need to be confirmed. The above is based on the expected pattern from the SG/Send architecture. The component should be designed to work with a configurable upload endpoint so it can target dev/main/prod environments.

## Environment Detection

The component uses `sg-nav.js`'s `getSgraphBaseUrl()` pattern to auto-detect the correct SG/Send instance:

| tools.sgraph.ai environment | SG/Send target |
|---|---|
| `dev.tools.sgraph.ai` | `dev.send.sgraph.ai` |
| `main.tools.sgraph.ai` | `main.send.sgraph.ai` |
| `tools.sgraph.ai` | `send.sgraph.ai` |
| `localhost` | `dev.send.sgraph.ai` (or configurable) |

The `send-url` attribute overrides auto-detection.

---

## Security Considerations

- Encryption happens **in the browser** before upload — the SG/Send server never sees plaintext
- The encryption key is **never sent to the server** — only the encrypted blob is uploaded
- The friendly key / token is displayed only to the user in the component UI
- The component does NOT store keys in localStorage or sessionStorage
- HTTPS required (Web Crypto API needs secure context)

## Where This Component Gets Used

| Tool | How |
|---|---|
| **Image Tools** | After export: `editor.addEventListener('sg-image-export', (e) => sendDrop.offerFile(e.detail.blob, e.detail.filename))` |
| **Video Splitter** | After split/trim/extract: offer individual clips or "Share All as ZIP" |
| **File Encryptor** | After encryption: offer the encrypted file (double encryption = extra secure, or skip) |
| **File Hasher** | Less relevant (hash is text, not a file) — but could share the hash report |
| **Key Generator** | Share generated key file |
| **Future tools** | Any tool that produces output files gets share-via-SG/Send for free |

The component is designed to be dropped into any tool page with zero configuration beyond the import.

## Open Questions

1. **SG/Send upload API shape** — need to confirm the exact endpoint, request format, and response format. Is it a simple `POST /api/upload` with FormData? Or does it require a two-step (create transfer → upload chunks)?
2. **Friendly key generation** — does the component generate the friendly key locally (using sg-pbkdf2 + sg-wordlist), or does SG/Send return one?
3. **File size limits** — what's the max file size SG/Send accepts via API? Do we need chunked upload for large files?
4. **Authentication** — does the upload API require any auth token, or is anonymous upload supported (with credit limits)?
5. **Expiry defaults** — what default expiry should be set for files shared from tools? 24 hours? 7 days?

These questions should be resolved with the SG/Send team before implementation. The component's internal architecture can accommodate any answer — the upload function is a single async method that can be swapped.
