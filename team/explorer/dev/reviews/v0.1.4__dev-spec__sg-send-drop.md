## What This Is

A reusable Web Component that provides a one-step "share via SG/Send" experience. Drop a file (or pass a blob programmatically) and it handles the full upload flow: generate simple token → SGMETA envelope → encrypt → 3-step API upload → display token + copy/link/open.

This component is the bridge between every tool on tools.sgraph.ai and the SG/Send product. It turns "Download your result" into "Download OR share securely in one click."

---

## Why a Component (Not Just a Link)

Every tool brief mentions "Share clips securely via SG/Send" as the conversion funnel. But a plain link to send.sgraph.ai means the user has to:
1. Download the file
2. Open send.sgraph.ai in a new tab
3. Upload the file again
4. Wait for encryption + upload
5. Copy the token

With `<sg-send-drop>`, the entire flow happens inline — no page change, no re-upload, no friction. The file is already in memory (as a Blob from the tool's output). The component encrypts and uploads it directly.

## Simple Tokens — How They Work

Simple tokens are **entirely client-side**. The server never sees the token — only the derived transfer ID.

### Token Format

```
word-word-NNNN
```

Two words from a 320-word wordlist + a 4-digit number. Examples: `royal-stamp-1474`, `coral-equal-1774`.

**Entropy:** 320 × 320 × 10,000 = ~1 billion combinations (~30 bits).

### Token → Transfer ID

```
transfer_id = SHA-256(token)[0:12]    // first 12 hex characters (6 bytes)
```

The server stores and looks up files by this 12-char hex ID. It has no idea a simple token exists.

### Token → Encryption Key

```
key = PBKDF2-SHA256(
    password:   token,
    salt:       "sgraph-send-v1",     // exact value
    iterations: 600_000,               // exact value
    keyLength:  32 bytes (256 bits)
)
```

### Token → URL

The token goes in the URL fragment (after `#`), which is never sent to the server:

```
https://send.sgraph.ai/en-gb/browse/#royal-stamp-1474
```

### Crypto Parameters (confirmed from `friendly-crypto.js` source)

| Parameter | Value |
|---|---|
| Token pattern | `word-word-NNNN` (regex: `/^[a-z]+-[a-z]+-\d{4}$/`) |
| Wordlist size | 320 words |
| Transfer ID | `SHA-256(token)` → first 6 bytes → 12 hex chars |
| Key derivation | `PBKDF2-HMAC-SHA256` |
| PBKDF2 salt | `sgraph-send-v1` (UTF-8 encoded) |
| PBKDF2 iterations | `600,000` |
| Key output | 256-bit (32 bytes) |
| Encryption | `AES-256-GCM` |

## Core Module: `sg-send-crypto.js` API

```javascript
// core/send-crypto/v1/v1.0/v1.0.0/sg-send-crypto.js

import { WORDLIST } from './wordlist.js';

const SALT = 'sgraph-send-v1';
const ITERATIONS = 600_000;
const SGMETA_MAGIC = new Uint8Array([0x53, 0x47, 0x4D, 0x45, 0x54, 0x41]); // "SGMETA"
const TOKEN_PATTERN = /^[a-z]+-[a-z]+-\d{4}$/;

/**
 * Check if a string is a valid simple token (word-word-NNNN).
 * @param {string} str
 * @returns {boolean}
 */
export function isFriendlyToken(str) {
    return TOKEN_PATTERN.test(str);
}

/**
 * Generate a random simple token: word-word-NNNN.
 * @returns {string}
 */
export function generateToken() {
    const arr = new Uint16Array(3);
    crypto.getRandomValues(arr);
    const w1 = WORDLIST[arr[0] % WORDLIST.length];
    const w2 = WORDLIST[arr[1] % WORDLIST.length];
    const num = arr[2] % 10000;
    return `${w1}-${w2}-${String(num).padStart(4, '0')}`;
}

/**
 * Derive a 12-char hex transfer ID from a simple token.
 * SHA-256(token) → first 6 bytes → 12 hex chars.
 * @param {string} token
 * @returns {Promise<string>}
 */
export async function deriveTransferId(token) {
    const hash = await crypto.subtle.digest(
        'SHA-256', new TextEncoder().encode(token)
    );
    const bytes = new Uint8Array(hash);
    let hex = '';
    for (let i = 0; i < 6; i++) {
        hex += bytes[i].toString(16).padStart(2, '0');
    }
    return hex;
}

/**
 * Derive an AES-256-GCM CryptoKey from a simple token via PBKDF2.
 * @param {string} token
 * @returns {Promise<CryptoKey>}
 */
export async function deriveKey(token) {
    const enc = new TextEncoder();
    const material = await crypto.subtle.importKey(
        'raw', enc.encode(token), 'PBKDF2', false, ['deriveKey']
    );
    return crypto.subtle.deriveKey(
        { name: 'PBKDF2', salt: enc.encode(SALT),
          iterations: ITERATIONS, hash: 'SHA-256' },
        material,
        { name: 'AES-GCM', length: 256 },
        true,
        ['encrypt', 'decrypt']
    );
}

/**
 * Build an SGMETA envelope: [magic 6B][metadata-len 4B][JSON metadata][file content].
 * This preserves the filename through encryption — the server never sees it.
 * @param {ArrayBuffer} content - The file content
 * @param {string} filename - The display filename
 * @returns {Uint8Array}
 */
export function buildSgmetaEnvelope(content, filename) {
    const metaBytes = new TextEncoder().encode(JSON.stringify({ filename }));
    const result = new Uint8Array(6 + 4 + metaBytes.length + content.byteLength);
    result.set(SGMETA_MAGIC, 0);
    // 4-byte big-endian metadata length
    result[6] = (metaBytes.length >> 24) & 0xFF;
    result[7] = (metaBytes.length >> 16) & 0xFF;
    result[8] = (metaBytes.length >> 8)  & 0xFF;
    result[9] =  metaBytes.length        & 0xFF;
    result.set(metaBytes, 10);
    result.set(new Uint8Array(content), 10 + metaBytes.length);
    return result;
}

/**
 * Encrypt plaintext with AES-256-GCM. Returns IV (12 bytes) || ciphertext.
 * @param {Uint8Array} plaintext
 * @param {CryptoKey} key
 * @returns {Promise<Uint8Array>}
 */
export async function encrypt(plaintext, key) {
    const iv = crypto.getRandomValues(new Uint8Array(12));
    const ciphertext = await crypto.subtle.encrypt(
        { name: 'AES-GCM', iv }, key, plaintext
    );
    const result = new Uint8Array(12 + ciphertext.byteLength);
    result.set(iv, 0);
    result.set(new Uint8Array(ciphertext), 12);
    return result;
}
```

## Core Module: `sg-send-upload.js` API

```javascript
// core/send-crypto/v1/v1.0/v1.0.0/sg-send-upload.js

import {
    generateToken, deriveTransferId, deriveKey,
    buildSgmetaEnvelope, encrypt
} from './sg-send-crypto.js';

const DIRECT_UPLOAD_LIMIT = 5 * 1024 * 1024; // 5 MB

/**
 * Complete upload flow: generate token → envelope → encrypt → 3-step API.
 *
 * @param {Blob} blob - The file to share
 * @param {string} filename - Display filename
 * @param {string} sendUrl - SG/Send base URL (e.g. "https://send.sgraph.ai")
 * @param {string} accessToken - x-sgraph-access-token value
 * @param {function} [onProgress] - callback({ percent, stage })
 * @returns {Promise<{ token: string, transferId: string, url: string }>}
 */
export async function uploadFile(blob, filename, sendUrl, accessToken, onProgress) {
    const report = (percent, stage) => onProgress?.({ percent, stage });

    // 1. Generate simple token and derive transfer ID + key
    const token = generateToken();
    const transferId = await deriveTransferId(token);
    const key = await deriveKey(token);
    report(5, 'generating');

    // 2. Build SGMETA envelope (preserves filename through encryption)
    const content = await blob.arrayBuffer();
    const plaintext = buildSgmetaEnvelope(content, filename);
    report(10, 'packaging');

    // 3. Encrypt with derived key (AES-256-GCM, IV prepended)
    const encrypted = await encrypt(plaintext, key);
    report(40, 'encrypting');

    // 4. API step 1: Create transfer
    const headers = {
        'Content-Type': 'application/json',
        'x-sgraph-access-token': accessToken,
    };
    const createRes = await fetch(`${sendUrl}/api/transfers/create`, {
        method: 'POST',
        headers,
        body: JSON.stringify({
            transfer_id: transferId,
            file_size_bytes: encrypted.byteLength,
            content_type_hint: blob.type || 'application/octet-stream',
        }),
    });
    if (!createRes.ok) throw new Error(`Create failed: ${createRes.status}`);
    report(50, 'uploading');

    // 5. API step 2: Upload encrypted payload
    if (encrypted.byteLength > DIRECT_UPLOAD_LIMIT) {
        await uploadMultipart(sendUrl, accessToken, transferId, encrypted, report);
    } else {
        await fetch(`${sendUrl}/api/transfers/upload/${transferId}`, {
            method: 'POST',
            headers: {
                'Content-Type': 'application/octet-stream',
                'x-sgraph-access-token': accessToken,
            },
            body: encrypted.buffer,
        });
    }
    report(90, 'uploading');

    // 6. API step 3: Complete transfer
    await fetch(`${sendUrl}/api/transfers/complete/${transferId}`, {
        method: 'POST',
        headers: { 'x-sgraph-access-token': accessToken },
    });
    report(100, 'complete');

    // 7. Build result
    const url = `${sendUrl}/en-gb/browse/#${token}`;
    return { token, transferId, url };
}

/**
 * Presigned multipart upload for files > 5 MB.
 * S3 presigned URLs, parallel part uploads (max 5 concurrent).
 */
async function uploadMultipart(sendUrl, accessToken, transferId, encrypted, report) {
    // Initiate multipart
    const initRes = await fetch(`${sendUrl}/api/presigned/initiate`, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'x-sgraph-access-token': accessToken,
        },
        body: JSON.stringify({ transfer_id: transferId, file_size: encrypted.byteLength }),
    });
    const { part_urls } = await initRes.json();

    // Upload parts in parallel (max 5 concurrent)
    const PART_SIZE = 10 * 1024 * 1024; // 10 MB
    const MAX_CONCURRENT = 5;
    const parts = [];

    for (let i = 0; i < part_urls.length; i += MAX_CONCURRENT) {
        const batch = part_urls.slice(i, i + MAX_CONCURRENT).map((url, j) => {
            const partIndex = i + j;
            const start = partIndex * PART_SIZE;
            const end = Math.min(start + PART_SIZE, encrypted.byteLength);
            const partData = encrypted.slice(start, end);
            return fetch(url, { method: 'PUT', body: partData })
                .then((res) => {
                    parts.push({ part_number: partIndex + 1, etag: res.headers.get('ETag') });
                    const pct = 50 + Math.round(40 * (partIndex + 1) / part_urls.length);
                    report(pct, 'uploading');
                });
        });
        await Promise.all(batch);
    }

    // Complete multipart
    await fetch(`${sendUrl}/api/presigned/complete`, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'x-sgraph-access-token': accessToken,
        },
        body: JSON.stringify({ transfer_id: transferId, parts }),
    });
}
```

## Authentication

The SG/Send API requires an `x-sgraph-access-token` header on every request.

### How the component gets the token

Three options, in priority order:

1. **`setAccessToken(token)` method** — set programmatically by the tool page
2. **`localStorage['sgraph-send-token']`** — same key used by send.sgraph.ai (only works same-origin)
3. **Prompt the user** — if no token is available, show a text input: "Enter your SG/Send access token" with a link to send.sgraph.ai to get one

**Cross-domain note:** tools.sgraph.ai and send.sgraph.ai are different origins, so localStorage won't be shared. The most likely flow for tools.sgraph.ai is option 3 (prompt), with the token cached in the component's memory for the session (NOT persisted to localStorage on the tools domain).

## File Size Routing

| Encrypted size | Upload path |
|---|---|
| ≤ 5 MB | Direct upload: `POST /api/transfers/upload/{id}` (raw binary) |
| > 5 MB | Presigned multipart: `POST /api/presigned/initiate` → parallel PUT to S3 → `POST /api/presigned/complete` |

| Limit | Value |
|---|---|
| Direct upload max | 5 MB |
| Presigned multipart max | 10 GB |
| Part size | 10 MB |
| Max concurrent part uploads | 5 |
| Max parts | 10,000 (S3 limit) |

The component should call `GET /api/presigned/capabilities` on init to confirm multipart availability.

## Security Considerations

- **Simple token is never sent to the server.** The server only sees the SHA-256-derived transfer ID.
- **Encryption key is derived client-side** via PBKDF2 and never leaves the browser.
- **SGMETA envelope** preserves the filename through encryption — the server never sees it.
- **IV is prepended** to ciphertext (12 bytes || encrypted data) — standard AES-GCM format.
- **Access token is stored in component memory only** — NOT persisted to localStorage on tools.sgraph.ai.
- **Token entropy is ~30 bits.** Designed for usability (speakable, typeable), not maximum security. The 600,000 PBKDF2 iterations make brute-force expensive. For high-security use cases, users should use SG/Send directly with full 256-bit keys or PKI.
- **HTTPS required** (Web Crypto API needs secure context).

## Interop Verification

The component's crypto MUST produce outputs identical to `friendly-crypto.js` in the SG/Send UI. Test with:

```
Token:       "test-token-1234"
Transfer ID: SHA-256("test-token-1234") → first 12 hex chars
AES Key:     PBKDF2("test-token-1234", "sgraph-send-v1", 600000, SHA-256) → 32 bytes
```

Run both the component's `sg-send-crypto.js` and the browser's `FriendlyCrypto` with the same token and verify:
1. Transfer IDs match
2. Derived key bytes match
3. A file encrypted by the component can be decrypted by the SG/Send browse page, and vice versa
