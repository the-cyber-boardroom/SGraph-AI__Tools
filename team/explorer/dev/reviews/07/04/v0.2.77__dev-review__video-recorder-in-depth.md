## 1. Verdict

The tool is well-architected and follows the repo's JS Tool API pattern faithfully
(state / events / pipeline / api split, SgToolApi activated before UI, three SKILL
files, manifest-loader driven). The recording pipeline's resilience design
(per-session isolation, `Promise.allSettled` stop, `onerror` + track-loss watchers,
guaranteed-safe `disposeAll()`) is genuinely good.

The one **critical defect** is that every canvas-composited output (Landscape PiP,
Vertical/Shorts, and viz overlays) is driven by a **main-thread `setInterval`**, which
Chrome throttles to ≤1 Hz the moment the recorder tab is hidden — which is the
*normal* state during a screen recording. See the companion root-cause doc.

Secondary issues are mostly hygiene: ~5 dead files, three files over the 500-line
hard ceiling, documentation drift (method counts, mode counts, dependency pins),
an API/UI mode-parity gap, and zero automated test coverage.

## 2. What exists and works (code-verified)

- **9 modes** via 3-column mode builder (Screen on/off × Audio none/mic/tab ×
  Camera-Viz none/camera/viz), derived in `ui-controls.js:_deriveMode()`.
- **Output streams**: `recordingMode` = `combined` (1 file) | `combined+separate` |
  `separate`. Independent MediaRecorders per track; composite recorder for
  camera+screen (`mergeAsPiP` landscape, `merge-vertical.js mergeAsShorts` 9:16 with
  branding/title/footer).
- **Pause/resume** with paused-time excluded from final duration.
- **Tab/screen audio** (`audioSource: 'mic'|'screen'|'none'`), mutually exclusive,
  UI auto-reverts Tab→Mic when Screen turns off.
- **Resilience**: `RecordingSession` per run; 10 s per-recorder stop timeouts;
  `MediaRecorder.onerror` → auto-stop; `_watchTracks` auto-stops on video track loss
  (e.g. user clicks Chrome's "Stop sharing"), warns on audio loss.
- **Codec choice**: prefers MP4/H.264, and rewrites `avc1→avc3` when supported so
  mid-recording window resizes don't kill the encoder (in-band SPS/PPS). Nice.
- **WebM duration patch**: EBML `Duration` element rewritten post-recording with the
  file's own TimecodeScale.
- **Post-recording tab** per recording (sg-layout stack): player, per-track
  downloads, SG/Send encrypted upload, **Send to YouTube Editor** handoff via
  `window.__sgYtHandoff` + `window.open('/en-gb/youtube-editor/')`.
- **Viz regeneration**: if `sg-audio-viz.wasHidden` during recording, user can
  re-render the viz from audio at 1×/2×/4×/8× (audio dropped above 1×).
- **JS API**: **15** registered methods (not 14 as previously documented):
  connect, setMode, startPreview, stopPreview, startRecording, pauseRecording,
  resumeRecording, stopRecording, newRecording, saveSendFile, saveFolder,
  getStatus, getConfig, setConfig, **setRecordingName**.

## 3. Findings

Severity: 🔴 defect · 🟠 gap/risk · 🟡 hygiene/doc drift

### 🔴 F1 — Composite video starves at ~0.5 fps when the recorder tab is hidden ✅ FIXED (v0.1.61 / sg-capture v0.1.1)
The reported bug. Root cause, evidence, and fix in the companion doc.
Was: `api/merge-vertical.js:196`, `core/sg-capture/v0.1.0/sg-capture.js:158`.
Fix: worker-driven ticker + `captureStream(0)`/`requestFrame()` in both compositors.
(`sg-audio-viz`'s own rAF loop is a separate, regen-mitigated issue, still open.)

### 🔴 F2 — On-screen timer undercounts for the same reason ✅ FIXED (v0.1.61)
`ui-controls.js:403` counts `elapsed++` per `setInterval` tick, so a hidden tab
freezes the counter (screenshot from the bug report: timer shows **119s** for a
**3m53s** recording — same ~0.5 Hz throttling). Recorded duration is correct
(computed from `Date.now()`); only the display lies. Fix: derive display from
`Date.now() - state.startedAt - pausedMs` on each tick.

### 🟠 F3 — API/UI mode parity gap: `setMode` rejects viz modes ✅ FIXED (v0.1.61)
`recorder-api.js:50` `VALID_MODES` lists 7 modes; the UI can produce 9
(`viz+audio`, `screen+viz+audio`). Agents driving `window.__tool` cannot select viz
modes through `setMode` (only via `setConfig` back door, skipping validation and
MODE_SET events). Either add the 2 modes or document the restriction.

### 🟠 F4 — "Three save targets" is aspirational; vault save is dead code
`api/save-vault.js` is imported by nothing and `saveVault` is not registered on the
API. `saveFolder` **is** registered but has no UI. Only SG/Send (+ downloads +
YouTube handoff) is a real user-facing save path. Reality doc corrected in this
commit; decide whether to wire vault/folder up or delete `save-vault.js`.

### 🟠 F5 — Zero automated test coverage
`sgraph_ai_tools__static/tests/` has suites for sg-audio-viz, sg-layout, YouTube
components, etc. — nothing for video-recorder or sg-capture. The tool has SKILL
files specifically to enable headless Playwright driving; a fake-media smoke test
(`--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`, camera+audio
mode: start → 3 s → stop → assert blob size > 0) would have caught regressions and
can also reproduce F1 headlessly (`page.evaluate` + a second tab to hide the page).

### 🟥 F6 — ~~Stray broken deploy at `tools/v0/v0.1/v0.1.53/en-gb/video-recorder/`~~ RETRACTED (false finding)
**Withdrawn.** This was based on reading the version folder in isolation. The deploy
is an **IFD layered build** (`scripts/build_ifd_latest.py`): each `vX` folder holds
only *deltas*, merged into `_latest/` (later layers override earlier). The
`index.html`-only v0.1.53 folder is a legitimate delta that swaps the site-header to
the `SG/Send` variant (the one in the bug-report screenshot); merged into `_latest`
its `./manifest.json`, `api/`, `ui/` all come from the v0.1.48 layer and resolve
correctly. Nothing broken — do **not** delete it. (Verified by running the IFD build
locally: `_latest/en-gb/video-recorder/` contains the full 24-file set.)

### 🟡 F7 — Dead files inside the tool (6 of 24)
Never imported by `index.html`, `manifest.json` loader phases, or any live module:
- `ui/ui-preview.js`, `ui/ui-export.js`, `ui/ui-api-pane.js` (superseded by
  ui-shell/ui-recording-tab/tool-api components)
- `api/save-vault.js` (see F4)
- `styles/api-pane.css`, `styles/export.css` (not in manifest loader CSS list)

Also dead inside live files: `recorder-pipeline.js:56 _withTimeout()` (unused —
`stopRecorder` implements its own timeout) and `RecordingState.mediaRecorder`
(only ever set to `null`; sg-recording-size consumes RECORD_PROGRESS events).

### 🟡 F8 — File-size ceiling breaches (repo rule: soft ~300 / hard ~500)
`recorder-pipeline.js` **704**, `ui-shell.js` **595**, `ui-controls.js` **557**.
Natural splits: pipeline → extract `_fixWebMDuration` (+ vint helpers) into
`api/webm-duration.js` and `RecordingSession` into `api/recorder-session.js`;
ui-shell → extract `_reRenderViz` into `ui/viz-regen.js` and the dev panel into
`ui/ui-dev-panel.js`; ui-controls → extract the HTML template.

### 🟡 F9 — Documentation drift (fix in the next tool version bump)
- `manifest.json`: says **"7 capture modes"** (9 exist); pins
  `sg-video-recorder` **v0.1.1** while code imports **v0.1.2**
  (`recorder-pipeline.js:22`); `api.events` list omits `tool:record:pause/resume`,
  `tool:record:progress`, `tool:track:lost`, `tool:mode:set`.
- `SKILL-api.md`: says 14 methods — omits `setRecordingName`; `RecordingMode` type
  and `RecordingConfig` omit viz modes / `recordingMode` / `recordingName` /
  `vizMode` / `layout`.
- `SKILL-browser.md`: `page.waitForEvent('tool:ready')` is not a Playwright API
  (that's for page-level events like `popup`); DOM CustomEvents need
  `page.evaluate`/`addInitScript` + `waitForFunction(() => window.__tool)`.
- `SKILL-human.md`: mostly accurate (9 modes ✓); button glyphs drifted
  ("▶ Preview" vs actual "👁 Preview"); no mention of Layout
  Landscape/Shorts option or Send-to-YouTube.
- Reality doc `…__2__tools.md`: said "14 methods" and "Three save targets" —
  **corrected in this commit**; `…__1__libraries.md` sg-capture row repeated the
  false "setInterval is background-safe" claim — **corrected in this commit**.

### 🟡 F10 — Minor code notes
- `startRecorder`'s RECORD_PROGRESS handler re-`reduce`s every chunk array on
  every 100 ms chunk → O(n²) over a long recording. Keep a running byte total.
- `getStatus().durationMs` is 0 while recording (only set at stop) — agents polling
  status can't see elapsed time; expose `Date.now() - startedAt - pausedMs`.
- `getConfig()` shallow-copies `config` including the non-serialisable
  `vizProvider` — noisy/broken JSON in the API console.
- ✅ FIXED (v0.1.61) Shorts footer clock kept counting through pauses; now driven
  by a paused-aware `getElapsedMs` callback from the pipeline.
- ✅ FIXED (v0.1.61) `mergeAsShorts` no longer attaches duplicate audio to its
  returned stream — it emits video only; the pipeline adds the raw audio.
- SG/Send token is pre-filled into a `value="…"` attribute of a password input
  from localStorage (`ui-recording-tab.js:88`) — fine for a client-side tool but
  worth remembering it lands in DOM snapshots.
