## 1. Three-Tier Placement

### Kokoro.js TTS Wrapper

**Decision: new `core/sg-tts/v0/v0.1/v0.1.0/sg-tts.js`**

Rationale: TTS generation is pure audio-data logic — no DOM, no UI. The pattern is identical to `sg-whisper.js` (lazy CDN ONNX load, health check, generate function). Multiple future tools (voice memo, video-creator, any narration feature) will want it. Inline in tool would duplicate the loading pattern.

Scope: wraps Kokoro only. No ElevenLabs, no OpenAI TTS. Those are API-based, not ONNX; they belong in `sg-llm.js` or a future `sg-tts-api.js` if needed.

### Canvas Video Recorder

**Decision: new `core/sg-video-recorder/v0/v0.1/v0.1.0/sg-video-recorder.js`**

`sg-audio.js` v0.1.0 is segment-based audio-only MediaRecorder. Extending it to combine a canvas video stream with an audio stream is a different abstraction — mixed-stream capture, not audio segments. Creating a new module keeps `sg-audio.js` clean.

`sg-video.js` v1.0.0 is FFmpeg-only (split, trim, extract). It is not a MediaRecorder wrapper. Do not extend it.

`sg-video-recorder.js` exports: `startRecording()`, `stopRecording()`, `isSupported()`, `getBestMimeType()`. It accepts a `canvas` element and an `AudioContext` destination stream, wires the `MediaStream` merge, and returns a `Blob` on stop.

### FFmpeg WebM → MP4

**Decision: add `convertToMp4()` as a new version `core/video/v1/v1.0/v1.0.1/sg-video.js`**

`sg-video.js` already lazy-loads FFmpeg from CDN. Adding one export to an existing module is lower cost than a new module path. The FFmpeg load/unload lifecycle is already managed there. Version bump from v1.0.0 → v1.0.1 is additive; existing consumers are unaffected.

New export signature:
```javascript
/** @param {Blob} webmBlob @returns {Promise<Blob>} mp4Blob */
export async function convertToMp4(webmBlob) { ... }
```

## 2. CDN Import Strategy

### Problem

`import { KokoroTTS } from "kokoro-js"` is an npm bare specifier — forbidden. No import maps, no build step.

### Pattern to Follow

`sg-whisper.js` loads HuggingFace transformers.js:
```javascript
const { pipeline, env } = await import(
  'https://cdn.jsdelivr.net/npm/@xenova/transformers@2.17.2/dist/transformers.min.js'
);
```
Full CDN URL, dynamic `import()`, version-pinned.

### Kokoro.js Verdict

The brief's own CDN links provide the answer:
```javascript
// inside sg-tts.js — loaded lazily on first generate() call
const { KokoroTTS } = await import(
  'https://cdn.jsdelivr.net/npm/kokoro-js@1.2.2/dist/kokoro.js'
);
```

**Condition:** Pin to an explicit version (`@1.2.2` or whatever is current stable at dev time). Never `@latest` in a CDN dynamic import — unpinned imports break silently on major bumps.

**Viability:** jsdelivr serves kokoro-js ESM builds. Confirmed viable by the brief's own CDN snippet. Dev role must verify the dist path (`/dist/kokoro.js` vs `/dist/esm/index.js`) before coding.

### TalkingHead (Three.js dep)

TalkingHead has no official CDN ESM build. Its Three.js transitive dependency makes this harder.

**MVP 1–3 verdict: do not use TalkingHead.** Use the audio-reactive 2D canvas avatar instead (no external dep, pure Canvas 2D). TalkingHead integration is deferred to MVP 4 and requires a separate CDN investigation at that point.

For MVP 4, approach: clone the TalkingHead dist, host it on the SGraph CDN (`tools.sgraph.ai/library/talkinghead/`), import from there. Never import from a third-party GitHub raw URL.

### FFmpeg.wasm

Already handled by `sg-video.js` v1.0.0 which lazy-loads it from CDN. `convertToMp4()` in v1.0.1 uses the same loader — no new CDN wiring required.

## 3. JS-API Surface (`window.__tool`)

### Registered Methods

| Method | Params | Returns | Notes |
|--------|--------|---------|-------|
| `connect` | `{ apiKey? }` | `void` | No API key needed for MVP 1 (all local). Reserved for future hybrid mode. |
| `loadSlides` | `{ files: File[] }` | `{ count: number, slides: SlideInfo[] }` | Accepts PNG/JPEG array. Stores in VFS memory layer. |
| `setNarration` | `{ slideIndex: number, text: string }` | `void` | Set or override narration text for one slide. |
| `generateAudio` | `{ voice?: string, speed?: number }` | `{ durations: number[] }` | Runs Kokoro TTS for all slides; returns per-slide audio duration in seconds. |
| `record` | `{ fps?: number, bitrateKbps?: number }` | `void` | Starts MediaRecorder pipeline. |
| `stopRecording` | `{}` | `{ webmBlob: Blob }` | Stops recording, returns raw WebM. |
| `convertToMp4` | `{ webmBlob: Blob }` | `{ mp4Blob: Blob }` | Delegates to `sg-video.js` v1.0.1 `convertToMp4()`. |
| `download` | `{ blob: Blob, filename: string }` | `void` | Triggers browser download. |
| `getStatus` | `{}` | `PipelineStatus` | Returns current pipeline state snapshot. |
| `getConfig` | `{}` | `VideoConfig` | Returns current voice, fps, bitrate, layout settings. |
| `setConfig` | `Partial<VideoConfig>` | `void` | Update voice/fps/bitrate/avatarMode/layout. |

### Window Events (namespaced `tool:`)

| Event | Detail | Fired when |
|-------|--------|-----------|
| `tool:ready` | `{ version }` | `activate()` called — API live |
| `tool:slides:loaded` | `{ count }` | `loadSlides()` complete |
| `tool:audio:progress` | `{ slideIndex, total }` | Each TTS chunk generated |
| `tool:audio:complete` | `{ durations[] }` | All TTS audio generated |
| `tool:record:start` | `{ fps }` | MediaRecorder started |
| `tool:record:stop` | `{ durationMs }` | MediaRecorder stopped |
| `tool:convert:start` | `{}` | FFmpeg conversion begins |
| `tool:convert:progress` | `{ ratio }` | FFmpeg progress (0.0–1.0) |
| `tool:convert:complete` | `{ mp4Blob }` | MP4 ready |
| `tool:error` | `{ step, message }` | Any pipeline error |

### `api/` Subfolder Breakdown

- `video-events.js` — event name constants (SGA_VIDEO frozen object)
- `video-state.js` — PipelineState: slides[], narrations[], audioDurations[], config, status
- `video-pipeline.js` — orchestration logic: TTS loop, record start/stop, convert
- `video-api.js` — SgToolApi registration + `activate()` + `init()` entry point

## 5. MVP Scope Recommendation

**MVP 1 boundary:** Slides + Kokoro TTS + MediaRecorder → WebM output. No avatar, no MP4 conversion, no text animation beyond a static caption bar. The deliverable is a working narrated slideshow as a downloadable WebM file.

**Out of scope for MVP 1:** Any avatar (2D or 3D), FFmpeg MP4 conversion, animated caption transitions, progress bar animation, GSAP, automated narration from articles. These are MVP 2–5 items. MP4 conversion can be added in MVP 2 since `convertToMp4()` is a one-call addition once `sg-video.js` v1.0.1 exists.

## Conditions on Approval

1. **CDN path verified before coding.** Dev role must confirm `kokoro-js` jsdelivr ESM path and pin to a semver before any `sg-tts.js` code is committed.
2. **No TalkingHead in MVP 1–3.** 3D avatar integration is deferred. The 2D audio-reactive canvas avatar is the MVP 3 ceiling.
3. **`activate()` before UI.** `video-api.js` must call `activate()` before calling `init()` to hand off to `ui-shell.js`. Non-negotiable per JS-API-first rule.
4. **Named exports only.** All three new core modules must use named exports exclusively. No default exports.
5. **No `@latest` in CDN imports.** All dynamic CDN imports must use a pinned version string.
