## 1. Three-Tier Placement Decision

All three are **components/** tier — they are reusable UI elements that compose a core module
(or browser APIs) and can be embedded in any tool. None belongs in core/ (no UI allowed there)
and none belongs in tools/ (they are shared primitives, not standalone pages).

| Component | Tier | Rationale |
|---|---|---|
| `sg-recording-size` | `components/` | Pure UI display; subscribes to a MediaRecorder event. Zero tool-specific logic. Reusable in any future recorder tool. |
| `sg-video-player` | `components/` | General-purpose player for Blob or URL. Already identified as shared between video-recorder and sg-send download views. |
| `sg-video-compressor` | `components/` | Wraps `sg-video.js` (core) with a progress UI. The FFmpeg logic stays in core; this is the UI layer only. |

**Versioned paths (final):**

```
components/sg-recording-size/v0/v0.1/v0.1.0/
components/sg-video-player/v0/v0.1/v0.1.0/
components/sg-video-compressor/v0/v0.1/v0.1.0/
```

Each folder contains: `{name}.js`, `{name}.css`, `{name}.html` (optional), `manifest.json`.

## 2. Component API Design

### Component A — `sg-recording-size`

**HTML usage:**
```html
<sg-recording-size
  threshold-mb="100"
  warn-at-percent="80">
</sg-recording-size>
```

**Observed attributes:**

| Attribute | Type | Default | Description |
|---|---|---|---|
| `threshold-mb` | number | `500` | Size at which warning state activates (MB) |
| `warn-at-percent` | number | `80` | Percent of threshold that triggers warning colour |
| `label` | string | `"Recording size"` | Display label prefix |

**JS property API:**

| Property / Method | Description |
|---|---|
| `attach(mediaRecorder)` | Subscribe to `ondataavailable`; accumulates chunk sizes. Replaces any prior attachment. |
| `reset()` | Zero the counter and clear warning state. |
| `readonly bytes` | Current total bytes accumulated. |
| `readonly formattedSize` | Current size as human string e.g. `"24.3 MB"`. |

**Events fired:**

| Event | Detail | When |
|---|---|---|
| `sg-recording-size:warn` | `{ bytes, mb, thresholdMb }` | Accumulated size crosses warn threshold |
| `sg-recording-size:limit` | `{ bytes, mb, thresholdMb }` | Accumulated size reaches 100 % of threshold |

**Exported JS functions:** None. API is purely via the element.

### Component B — `sg-video-player`

**HTML usage:**
```html
<!-- URL playback -->
<sg-video-player src="https://..." poster="https://.../thumb.jpg"></sg-video-player>

<!-- Blob set programmatically -->
<sg-video-player></sg-video-player>
```

**Observed attributes:**

| Attribute | Type | Default | Description |
|---|---|---|---|
| `src` | string | — | URL to play on mount |
| `poster` | string | — | Thumbnail image URL |
| `autoplay` | boolean | false | Begin playback when source is set |
| `loop` | boolean | false | Loop playback |
| `muted` | boolean | false | Start muted |
| `label` | string | — | ARIA label for the player region |

**JS property API:**

| Property / Method | Description |
|---|---|
| `setBlob(blob, mimeType?)` | Load a Blob as the source (creates an object URL internally; revokes previous). |
| `setUrl(url)` | Load a remote URL as the source. |
| `play()` | Start playback. Returns `Promise<void>`. |
| `pause()` | Pause playback. |
| `seek(seconds)` | Seek to timestamp. |
| `readonly duration` | Total duration in seconds (NaN until metadata loaded). |
| `readonly currentTime` | Current playback position in seconds. |
| `readonly paused` | Boolean. |
| `destroy()` | Revoke any object URL and disconnect. Call before removing the element. |

**Events fired:**

| Event | Detail | When |
|---|---|---|
| `sg-video-player:ready` | `{ duration }` | Metadata loaded |
| `sg-video-player:play` | `{}` | Playback starts |
| `sg-video-player:pause` | `{}` | Playback paused |
| `sg-video-player:ended` | `{}` | Playback reached end |
| `sg-video-player:error` | `{ message }` | Media error |
| `sg-video-player:timeupdate` | `{ currentTime, duration }` | Every ~250 ms during playback |

**Exported JS functions:** None. Blob lifecycle (URL.createObjectURL / revokeObjectURL) is
encapsulated inside the component to prevent leaks.

### Component C — `sg-video-compressor`

**HTML usage:**
```html
<sg-video-compressor
  resolution="720p"
  format="mp4"
  video-kbps="1500">
</sg-video-compressor>
```

**Observed attributes:**

| Attribute | Type | Default | Description |
|---|---|---|---|
| `resolution` | `"original"\|"1080p"\|"720p"\|"480p"\|"360p"` | `"720p"` | Target output resolution |
| `format` | `"mp4"\|"webm"\|"original"` | `"mp4"` | Output container/codec |
| `video-kbps` | number | `1500` | Target video bitrate in kbps |
| `audio-kbps` | number | `128` | Target audio bitrate in kbps |

**JS property API:**

| Property / Method | Description |
|---|---|
| `compress(blob)` | Start compression. Returns `Promise<Blob>`. Fires progress events during processing. Rejects if FFmpeg WASM unavailable. |
| `cancel()` | Abort in-flight compression (best-effort). |
| `readonly busy` | Boolean — true while FFmpeg is processing. |

**Events fired:**

| Event | Detail | When |
|---|---|---|
| `sg-video-compressor:start` | `{ inputBytes, resolution, format, videoKbps }` | FFmpeg begins |
| `sg-video-compressor:progress` | `{ percent, stage }` | FFmpeg `progress` callback; `stage` is `"transcoding"` |
| `sg-video-compressor:complete` | `{ outputBlob, inputBytes, outputBytes, durationMs }` | FFmpeg done; consumer receives the Blob via event AND via the `compress()` promise |
| `sg-video-compressor:error` | `{ message }` | FFmpeg error or WASM unavailable |
| `sg-video-compressor:cancelled` | `{}` | `cancel()` called mid-operation |

**Exported JS function:**

```js
/** Compress a video Blob without mounting the Web Component (headless pipeline use).
 * @param {Blob} blob
 * @param {{ resolution?: string, format?: string, videoKbps?: number, audioKbps?: number, onProgress?: (pct:number)=>void }} opts
 * @returns {Promise<Blob>} */
export async function compressVideo(blob, opts = {}) { ... }
```

Thin wrapper over `sg-video.js` v1.0.1 `loadFFmpeg()`. The Web Component calls it internally
and layers the progress UI on top.

## 3. CSS Strategy

All three components use **Shadow DOM** via `SgComponent` base class (the established pattern
in this codebase — see `sg-site-header`, `sg-locale-picker`). Each component:

- Loads its own sibling `.css` file via `SgComponentPaths.resolve(import.meta.url, name)`
- Loads `sg-tokens.css` as a shared style sheet via `sharedCssPaths` (design token cascade)
- No global style leakage — Shadow DOM ensures isolation

**`sg-recording-size`** has minimal CSS: a flex row with a label, a size value (mono font),
and a warning modifier class (`--warn`, `--limit`) that shifts the colour token to amber/red.

**`sg-video-player`** wraps a `<video>` element in Shadow DOM. The native browser controls
(`controls` attribute) handle the baseline UX. A thin overlay CSS layer adds the poster,
fullscreen button styling, and brand-consistent colours. Do NOT replicate all browser controls
from scratch — use `<video controls>` and augment with a custom control bar overlay if and
only if the design requires it. Keep v0.1.0 simple.

**`sg-video-compressor`** CSS covers: resolution/format dropdowns, a bitrate slider,
an `<sg-progress-bar>`-style animated bar (reuse `sg-transfer-progress` token conventions),
and disabled states while `busy`.

## 4. Inter-Component Dependencies

```
sg-video-compressor
  └─ imports sg-video.js  (core/video/v1/v1.0/v1.0.1)  [required]
  └─ does NOT depend on sg-video-player

sg-video-player
  └─ no component dependencies — wraps native <video>

sg-recording-size
  └─ no component dependencies — attaches to MediaRecorder passed by caller
```

**No circular dependencies.** The video-recorder tool may place all three side-by-side, but
the components themselves are unaware of each other. The tool's `ui-preview.js` is responsible
for wiring: passing the `mediaRecorder` to `sg-recording-size`, the recorded Blob to
`sg-video-player` (via `setBlob`), and the same Blob to `sg-video-compressor` (via `compress`)
when the user opts to compress before saving.

`sg-video-compressor` fires `sg-video-compressor:complete` with the output Blob in the event
detail so the tool can forward it to `sg-video-player` for preview of the compressed result —
no direct component coupling required.

## 5. Integration with Video Recorder Tool

**Tool path:** `tools/v0/v0.1/v0.1.48/en-gb/video-recorder/`

**Mounting points in the tool UI:**

| Component | Mounted in | Wiring |
|---|---|---|
| `sg-recording-size` | `ui/ui-controls.js` | `attach(mediaRecorder)` on start; `reset()` on stop |
| `sg-video-player` | `ui/ui-preview.js` | `setBlob(blob)` when stop resolves; also handles share-link playback |
| `sg-video-compressor` | `ui/ui-export.js` | Optional step before save; output Blob replaces original in save pipeline |

All three load at **phase 2** in `manifest.json` (ES module side-effects — registers custom
elements before Phase 3 tool entry runs). Matches `manifest-loader.js` v0.1.0 pattern.

All three extend `SgComponent` from `components/base/v1/v1.0/v1.0.0/sg-component.js`.
