## 1. Three-Tier Placement Decision

All three are **components/** tier — they are reusable UI elements that compose a core module
(or browser APIs) and can be embedded in any tool. None belongs in core/ (no UI allowed there)
and none belongs in tools/ (they are shared primitives, not standalone pages).

| Component | Tier | Rationale |
|---|---|---|
| `sg-recording-size` | `components/` | Pure UI display; subscribes to a MediaRecorder event. Zero tool-specific logic. Reusable in any future recorder tool. |
| `sg-video-player` | `components/` | General-purpose player for Blob or URL. Already identified as shared between video-recorder and sg-send download views. |
| `sg-video-compressor` | `components/` | Wraps `sg-video.js` (core) with a progress UI. The FFmpeg logic stays in core; this is the UI layer only. |

**Versioned paths (final):**

```
components/sg-recording-size/v0/v0.1/v0.1.0/
components/sg-video-player/v0/v0.1/v0.1.0/
components/sg-video-compressor/v0/v0.1/v0.1.0/
```

Each folder contains: `{name}.js`, `{name}.css`, `{name}.html` (optional), `manifest.json`.

## 2. Component API Design

### Component A — `sg-recording-size`

**HTML usage:**
```html
<sg-recording-size
  threshold-mb="100"
  warn-at-percent="80">
</sg-recording-size>
```

**Observed attributes:** `threshold-mb` (default `500`), `warn-at-percent` (default `80`), `label`.

**JS property API:** `attach(mediaRecorder)` — subscribe to `ondataavailable`, accumulate chunk sizes.
`reset()` — zero counter. `readonly bytes`, `readonly formattedSize` (`"24.3 MB"`).

**Events:** `sg-recording-size:warn` `{ bytes, mb, thresholdMb }` at warn %;
`sg-recording-size:limit` at 100 % of threshold.

**Exported functions:** None.

---

### Component B — `sg-video-player`

**HTML usage:**
```html
<!-- URL playback -->
<sg-video-player src="https://..." poster="https://.../thumb.jpg"></sg-video-player>

<!-- Blob set programmatically -->
<sg-video-player></sg-video-player>
```

**Observed attributes:** `src`, `poster`, `autoplay` (bool), `loop` (bool), `muted` (bool), `label`.

**JS property API:** `setBlob(blob, mimeType?)` — creates object URL internally, revokes previous.
`setUrl(url)`. `play()` → `Promise<void>`. `pause()`. `seek(seconds)`.
`readonly duration`, `readonly currentTime`, `readonly paused`. `destroy()` — revokes object URL.

**Events:** `sg-video-player:ready { duration }`, `:play`, `:pause`, `:ended`, `:error { message }`,
`:timeupdate { currentTime, duration }` (throttled ~250 ms).

**Exported functions:** None. Object URL lifecycle is encapsulated to prevent leaks.

---

### Component C — `sg-video-compressor`

**HTML usage:**
```html
<sg-video-compressor
  resolution="720p"
  format="mp4"
  video-kbps="1500">
</sg-video-compressor>
```

**Observed attributes:**

| Attribute | Type | Default | Description |
|---|---|---|---|
| `resolution` | `"original"\|"1080p"\|"720p"\|"480p"\|"360p"` | `"720p"` | Target output resolution |
| `format` | `"mp4"\|"webm"\|"original"` | `"mp4"` | Output container/codec |
| `video-kbps` | number | `1500` | Target video bitrate in kbps |
| `audio-kbps` | number | `128` | Target audio bitrate in kbps |

**JS property API:**

| Property / Method | Description |
|---|---|
| `compress(blob)` | Start compression. Returns `Promise<Blob>`. Fires progress events during processing. Rejects if FFmpeg WASM unavailable. |
| `cancel()` | Abort in-flight compression (best-effort). |
| `readonly busy` | Boolean — true while FFmpeg is processing. |

**Events fired:**

| Event | Detail | When |
|---|---|---|
| `sg-video-compressor:start` | `{ inputBytes, resolution, format, videoKbps }` | FFmpeg begins |
| `sg-video-compressor:progress` | `{ percent, stage }` | FFmpeg `progress` callback; `stage` is `"transcoding"` |
| `sg-video-compressor:complete` | `{ outputBlob, inputBytes, outputBytes, durationMs }` | FFmpeg done; consumer receives the Blob via event AND via the `compress()` promise |
| `sg-video-compressor:error` | `{ message }` | FFmpeg error or WASM unavailable |
| `sg-video-compressor:cancelled` | `{}` | `cancel()` called mid-operation |

**Exported JS function:**

```js
/** Compress a video Blob without mounting the Web Component (headless pipeline use).
 * @param {Blob} blob
 * @param {{ resolution?: string, format?: string, videoKbps?: number, audioKbps?: number, onProgress?: (pct:number)=>void }} opts
 * @returns {Promise<Blob>} */
export async function compressVideo(blob, opts = {}) { ... }
```

Thin wrapper over `sg-video.js` v1.0.1 `loadFFmpeg()`. The Web Component calls it internally
and layers the progress UI on top.

## 3. CSS Strategy

All three use **Shadow DOM** via `SgComponent` base class (same pattern as `sg-site-header`,
`sg-locale-picker`):

- Sibling `.css` file loaded via `SgComponentPaths.resolve(import.meta.url, name)`
- `sg-tokens.css` listed in `sharedCssPaths` for brand token cascade
- No global style leakage

**`sg-recording-size`** — flex row, monospace size value, `--warn` / `--limit` BEM modifiers
shift colour tokens to amber / red.

**`sg-video-player`** — Shadow DOM wraps native `<video controls>`. v0.1.0 augments with a
thin overlay for poster + brand colours only. Custom control bar deferred to v0.1.1.

**`sg-video-compressor`** — resolution/format selects, bitrate input, animated progress bar
using `sg-transfer-progress` token conventions, disabled state while `busy`.

## 4. Inter-Component Dependencies

```
sg-video-compressor  →  sg-video.js (core/video/v1/v1.0/v1.0.1)
sg-video-player      →  (no deps — wraps native <video>)
sg-recording-size    →  (no deps — caller passes MediaRecorder)
```

No circular dependencies. Components are unaware of each other. The tool's `ui-preview.js`
handles wiring: `attach(mediaRecorder)` → `sg-recording-size`; `setBlob(blob)` →
`sg-video-player`; `compress(blob)` → `sg-video-compressor`. The compressor's
`sg-video-compressor:complete` event carries the output Blob so the tool can forward it to
the player for compressed-result preview without any direct component coupling.

## 5. Integration with Video Recorder Tool

**Tool path:** `tools/v0/v0.1/v0.1.48/en-gb/video-recorder/`

**Mounting points in the tool UI:**

| Component | Mounted in | Wiring |
|---|---|---|
| `sg-recording-size` | `ui/ui-controls.js` | `attach(mediaRecorder)` on start; `reset()` on stop |
| `sg-video-player` | `ui/ui-preview.js` | `setBlob(blob)` when stop resolves; also handles share-link playback |
| `sg-video-compressor` | `ui/ui-export.js` | Optional step before save; output Blob replaces original in save pipeline |

All three load at **phase 2** in `manifest.json` (ES module side-effects — registers custom
elements before Phase 3 tool entry runs). Matches `manifest-loader.js` v0.1.0 pattern.
