**version** v0.2.63
**date** 13 Jun 2026
**from** Architect (Explorer team)
**to** Dev, Designer, Librarian
**type** Architecture / implementation brief
**status** PROPOSED — the tool described here does not exist yet. Cross-checked against the Reality Document (`team/explorer/librarian/reality/v0.1.0__what-exists-today*.md`).

> **v0.2.63 supersedes v0.2.62.** This revision folds in four new human requirements: (1) process WhatsApp **`.opus`** voice notes; (2) **batch** drag-drop of many files with a per-item queue; (3) group a session's outputs and **download as a single `.zip`** (audio + transcripts, user-selectable); (4) **send via sg/send** using the **embedded `<sg-send-drop>` component**. All four were investigated against the codebase; existing-vs-new building blocks are called out honestly in §3 and §11.

---

## 1. Summary

A new standalone browser tool — **`audio-transcribe`** — that lets a user (1) record from the microphone OR (2) **drag/drop/multi-select one or more local audio files (including WhatsApp `.opus` voice notes)**, then (3) transcribe **each** to text using a pre-selected list of **OpenRouter** audio-capable models, all client-side, then optionally (4) **bundle the session's audio + transcripts into a `.zip`** for download and/or (5) **send that bundle via sg/send (send.sgraph.ai)** as an encrypted share — all exposing the mandatory **`SgToolApi`** JS API.

**The 90/10 reuse thesis is VALIDATED, with one honest correction.** Recording, file-drop, the LLM fetch engine, OpenRouter wiring, the SgToolApi pattern, the api/+ui/ tool layout, the dev-panel components, the **multi-item queue/state model** (heic-converter's `state.getItems()`), the **JSZip CDN lazy-load pattern**, and the **`<sg-send-drop>` encrypted-send component** — plus the audio→`input_audio` wire-format translation — **all already exist and are code-verified**. The genuinely-new ~10% is:

- A thin **curated audio-model list + transcription glue** (a tool-local pipeline that builds the `binary_file`/`input_audio` message and reads back the text);
- **One audio-format concern that must be solved**: the existing recorder (`core/sg-audio`) emits **webm/opus**, and WhatsApp notes arrive as **Ogg/Opus `.opus`**. OpenRouter's audio input documents **wav/mp3/aac/ogg/flac/m4a/pcm** — bare **webm/opus is NOT a documented input format**, and `.opus` files need careful MIME sniffing + a decode→WAV fallback (see §3, §6, §7);
- The **batch queue** orchestration (sequential transcription with a small concurrency cap, per-item status/retry);
- A small **zip bundler** (audio + transcripts + manifest) — reusing the JSZip CDN lazy-load already used across the repo; and
- The **sg/send wiring** to the existing `<sg-send-drop>` component (the encrypted-upload primitive already exists; only the in-tool glue is new).

There is **no** existing "transcribe an arbitrary audio file via OpenRouter" tool. The closest tool, `voice-memo` (`tools/v0/v0.1/v0.1.53/en-gb/voice-memo/`), records audio but transcribes **locally via Whisper WASM** (`core/sg-whisper`), not via OpenRouter — so it solves a different problem and is reuse for the *recording* leg only.

## 2. Requirements (restated)

1. **Record audio** from the microphone (start / stop, with a visible timer / waveform).
2. **Select or drag-drop audio files** from local disk — including **batch / multiple files at once** (drag-drop or multi-select). *(extended in v0.2.63)*
3. **Transcribe audio → text** using a number of **pre-selected OpenRouter models** (list configurable/curated), **once per file** in the batch.
4. **Support the JS Tool API** (`SgToolApi`: `register()` + `activate()` + three SKILL files).
5. **Follow the patterns/standards of the most recent commits** (the `api/` + `ui/` split + manifest-loader bootstrap, as in `heic-converter`).
6. **Process WhatsApp `.opus` voice notes** (Ogg/Opus container) — recognise `.opus` in the `accept` filter and MIME sniffing, and route it through the format pipeline (pass-through as `ogg` where accepted, else decode→WAV). *(new in v0.2.63 — see §3 row 6 + §7)*
7. **Batch queue.** Accept many files at once; each is a **queue item** with its own status (`queued → transcribing → done → error`), transcript, model and metadata. Transcribe sequentially with a small concurrency cap; support per-item retry and per-item removal. *(new in v0.2.63 — see §3 row 7 + §5 + §8)*
8. **Session bundle → ZIP.** Accumulate processed items in a session and bundle them into one `.zip`. The bundle is **user-selectable** and may contain **both the audio files AND the transcripts** (`.txt`/`.md`) plus a **manifest** (`manifest.json` + `index.txt`) listing per item: original filename, model, duration, transcript filename. *(new in v0.2.63 — see §3 row 8 + §5)*
9. **Send via sg/send.** Send a single item's outputs OR the whole session bundle (same zip as req. 8) as an **encrypted share** using the **embedded `<sg-send-drop>` component** (in-page, not a deep-link hand-off); return the resulting **share URL**. *(new in v0.2.63 — see §3 row 9 + §5 + §11)*

† **Why JSZip CDN over a pure-JS store-only writer:** the no-build-step / no-dependency rules in CLAUDE.md are about *the repo*, not about runtime CDN modules — and **every existing zip consumer in the repo already lazy-loads JSZip from a CDN** (heic-converter, video-splitter, send-drop, playbooklm, send-receive). A pure-JS store-only writer is technically viable (and was the fallback the brief was asked to consider) but would be **net-new, untested, single-use code** for no benefit over the proven lazy-load. If the human later wants zero external CDN reliance, the store-only writer is the documented promote-to-core alternative (and would honour immutable versioning under `core/sg-zip/`).

New code is a small constants file, a small transcription pipeline, the **batch orchestrator**, the **zip bundler**, the **send glue**, the UI panels, the api registration, the manifest, and the SKILL files — none of which need to be large, and **the one substantive engineering problem remains audio format conversion (now including `.opus`).** No new `core/` module is required for v1.

Rationale: it names the verb (transcribe) and the medium (audio), is unambiguous against `voice-memo` (local Whisper, vault pipeline) and the `openrouter` key/usage tool, and reads clearly in the landing-page registry. `transcribe` alone is acceptable but less descriptive; prefer `audio-transcribe`.

**Path:** `tools/v0/v0.1/v0.1.60/en-gb/audio-transcribe/` (next free tool-version slot above the current max `v0.1.59`; Dev should bump to whatever is free at build time and reflect it in the registry).

## 5. JS Tool API surface (`api.register(...)`)

Registered on `SgToolApi({ name:'audio-transcribe', version:{api,ui,content}, panelId:'root', manifest:'./manifest.json', skills })`, then `activate()`.

The data model is a **queue of items** (not a single source). Each item: `{ id, name, sizeBytes, mimeType, durationMs, origin:'recording'|'file', model, status:'queued'|'transcribing'|'done'|'error', transcript, error }`. Item ids are returned by the ingest actions so callers can address rows headlessly.

**Source / queue ingest**

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `startRecording` | yes | `{ deviceId?, mimeType? }` | `{ recording:true, mimeType }` | Begins a single-take mic recording via `sg-audio`/`sg-audio-recorder`. Emits `AT_EVENTS.RECORDING_STARTED`. |
| `stopRecording` | yes | `{}` | `{ id, name, sizeBytes, mimeType, durationMs }` | Stops, assembles the blob, **adds it as one queue item**. Emits `RECORDING_STOPPED` + `ITEM_ADDED`. |
| `addFiles` | yes | `{ files }` (File[] / FileList) or via dropzone | `{ added:[{id,name,sizeBytes,mimeType}], rejected:[{name,code}] }` | **Batch ingest.** Adds every audio file (incl. `.opus`) as a queue item. Rejects non-audio per file with `{code:'not-audio'}`; rejects oversize with `{code:'too-large'}`. Emits `ITEM_ADDED` per accepted file. |
| `getItems` | no | `{}` | `[{ id, name, sizeBytes, mimeType, durationMs, origin, model, status, transcript? }]` | Serialisable (no Blob) snapshot of the whole queue. |
| `getItem` | no | `{ id }` | `{ …item }\|null` | One item (serialisable). |
| `removeItem` | no | `{ id }` | `{ removed:true }` | Drops one item. Emits `ITEM_REMOVED`. |
| `clearAll` | no | `{}` | `{}` | Clears the whole queue + session. Emits `RESET`. |

**Model + connect**

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `listModels` | no | `{}` | `[{ id, label, cost, speed, default }]` | The curated list from `audio-models.js`. |
| `setModel` | no | `{ model, id? }` | `{ model }` | Sets the active model for new items (or, with `id`, overrides one item's model). Validates against curated list (or allows passthrough id). Emits `MODEL_CHANGED`. |
| `connect` | yes | `{ apiKey, model? }` | `{ provider:'openrouter', model }` | Fires `llm:connected { provider:'openrouter', model, apiKey }`. `sanitiseParams` masks `apiKey`. |

**Transcription (per-item + batch)**

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `transcribeItem` | yes | `{ id, model?, language? }` | `{ id, text, model, latencyMs }` | Transcribe one queue item: blob → `audio-format` (incl. `.opus`) → `binary_file` message → `llm:send` → resolve. Sets item `status`/`transcript`. Emits `TRANSCRIBE_STARTED`/`TRANSCRIBE_COMPLETE`/`TRANSCRIBE_ERROR` (each carries `{ id }`). Used for **retry** too. |
| `transcribeAll` | yes | `{ model?, language?, concurrency? }` | `{ total, done, errors:[{id,code}] }` | Transcribe every `queued`/`error` item **sequentially with a small concurrency cap (default 2)** to respect OpenRouter rate limits. Emits `BATCH_STARTED`, `BATCH_PROGRESS {done,total}` per item, `BATCH_COMPLETE`. |
| `transcribe` | yes | `{ model?, language? }` | `{ total, done, errors }` | **Alias / convenience** = `transcribeAll`. Kept so single-file callers and the prior API name still work; if exactly one item exists it behaves like `transcribeItem` on that row. |
| `getTranscript` | no | `{ id? }` | `{ id, text, model }` \| `[{ id, text, model }]` | One item's transcript (with `id`) or all transcripts (without). |

**Bundle + send**

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `downloadZip` | yes | `{ include:{ audio?:boolean, transcripts?:boolean }, items?:string[] }` | `{ ok:true, count, zipSize, name }` | Builds a `.zip` from the session (or the `items` subset) per the `include` flags — audio files and/or `.txt`/`.md` transcripts — plus `manifest.json` + `index.txt` (per item: original filename, model, durationMs, transcript filename). Triggers a browser download. Defaults: `include:{audio:false,transcripts:true}`. Emits `BUNDLE_CREATED`. |
| `sendViaSgSend` | yes | `{ include?:{audio?,transcripts?}, items?:string[], accessToken? }` | `{ shareUrl, token }` | Builds the same bundle (zip) — or, for a single item with one output, the bare file — and hands it to the embedded `<sg-send-drop>` via `offerFile(blob, name)`. Resolves on the component's `sg-send-complete` `{url, token}`. If no token/auth, surfaces `{code:'send-auth-required'}` (the component shows its auth prompt). Emits `SEND_STARTED`/`SEND_COMPLETE`/`SEND_ERROR`. **Runtime dependency: a live send.sgraph.ai + access token (§11.4).** |

**Events** (`api/audio-transcribe-events.js`, frozen `AT_EVENTS`, all `at:*` namespaced):
`RECORDING_STARTED 'at:recording:started'`, `RECORDING_STOPPED 'at:recording:stopped'`, `ITEM_ADDED 'at:item:added'`, `ITEM_REMOVED 'at:item:removed'`, `MODEL_CHANGED 'at:model:changed'`, `TRANSCRIBE_STARTED 'at:transcribe:started'`, `TRANSCRIBE_PROGRESS 'at:transcribe:progress'`, `TRANSCRIBE_COMPLETE 'at:transcribe:complete'`, `TRANSCRIBE_ERROR 'at:transcribe:error'`, `BATCH_STARTED 'at:batch:started'`, `BATCH_PROGRESS 'at:batch:progress'`, `BATCH_COMPLETE 'at:batch:complete'`, `BUNDLE_CREATED 'at:bundle:created'`, `SEND_STARTED 'at:send:started'`, `SEND_COMPLETE 'at:send:complete'`, `SEND_ERROR 'at:send:error'`, `RESET 'at:reset'`. Plus the framework `tool:ready` from `activate()`.

All `TRANSCRIBE_*` and per-row events carry `detail.id` so a headless driver can correlate them with a queue row.

## 6. Core / module changes

**Phase 1: no new core module required** — *including* batch, zip, and sg/send. The transcription glue lives **tool-local** in `api/api-transcribe.js` + `api/audio-format.js`, reusing `sg-llm-request` v0.1.6 unchanged. The batch orchestrator (`api/api-batch.js`), the zip bundler (`api/audio-zip.js`), and the send glue (`api/api-send.js`) are also tool-local and reuse, respectively, the heic-converter queue model, the JSZip CDN lazy-load, and the existing `<sg-send-drop>` component. This respects "reuse first" and keeps the new surface small. **Promote-to-core candidates (only if a 2nd/3rd tool needs them):** `audio-format.js`→`core/sg-audio-convert`, `audio-zip.js`→`core/sg-zip`, and a future thin `core/sg-send-embed` wrapper around `<sg-send-drop>` — all under immutable versioning.

**The format-gap fix (`api/audio-format.js`) — the one piece of real engineering:**

```js
// audio-format.js (tool-local, ~160 lines)
// OpenRouter audio input accepts: wav, mp3, aiff, aac, ogg, flac, m4a, pcm16/24.
// webm/opus (what core/sg-audio records by default) is NOT documented as accepted.
// WhatsApp .opus = Ogg-Opus → maps to OpenRouter format 'ogg' (try pass-through first).

// Strategy order:
//   (1) already supported (mp4/m4a/mp3/wav/ogg/flac/aac)  → passthrough.
//   (2) .opus (Ogg-Opus)  → passthrough as { format:'ogg' } FIRST (no decode, cheapest);

//       NOTE: decodeAudioData of Opus is BROWSER-DEPENDENT (Chrome/Firefox yes,
```

The `.opus` strategy is **try-cheap-then-fallback**: pass through as `ogg` (no CPU), and only decode→WAV if the model errors. This keeps the common WhatsApp case (Chrome/Firefox, model accepts `ogg`) zero-cost, while giving a real fallback and an honest hard-stop on Safari+Opus rather than a silent failure.

A pure-JS **WAV encoder** (decode with `AudioContext` — already used by `sg-whisper.blobToFloat32Array` — then write a 16-bit PCM WAV header) avoids any CDN dependency and guarantees a model-accepted format. **Recommended default:** also try recording directly as `audio/mp4` where `MediaRecorder.isTypeSupported('audio/mp4')` (Safari/iOS), falling back to webm→WAV conversion elsewhere. **If `audio-format.js` grows past ~300 lines or is reused by a second tool, promote it to `core/sg-audio-convert/v0/v0.1/v0.1.0/`** (immutable-version rules; do not mutate `sg-audio` v0.1.0).

**Phase 2 (optional, future): `core/sg-or-transcribe/v0/v0.1/v0.1.0/sg-or-transcribe.js`** — a small pure-JS client for OpenRouter's dedicated `POST https://openrouter.ai/api/v1/audio/transcriptions` endpoint (`Authorization: Bearer`, JSON body `{ model, input_audio:{ data:<base64>, format }, language? }`, returns `{ text, usage }`). This endpoint returns word-accurate transcripts from true STT models (whisper-large-v3, gpt-4o-transcribe, gpt-4o-mini-transcribe, Google Chirp) and reports `usage.cost`/`seconds`. 2. **Queue panel (`ui-queue.js`)** — the heart of the batch UI. A **list/table with one row per item**: filename + size + duration, a per-row **status chip** (`queued`/`transcribing`/`done`/`error`), a per-row **model** (defaults to the active model, optionally overridable), the per-row **transcript** (expandable text + Copy + per-row Download `.txt`/`.md`), and per-row **Retry** (on error) + **Remove** controls. Header has a **"Transcribe all"** button (calls `transcribeAll`) and an **overall progress** bar (`BATCH_PROGRESS done/total`). Mirrors heic-converter's per-row + batch layout.
3. **Model panel (`ui-model.js`)** — the curated model selector (radio/select with cost + speed badges, from `listModels()`), plus **`components/openrouter/sg-openrouter-key-manager`** for key capture (persists to `localStorage` under `sg-openrouter-mgmt-key` — the persist-the-key decision, §11.1). `connect()` reads the persisted key and fires `llm:connected`.
4. **Bundle & Send panel (`ui-bundle.js`)** — appears once ≥1 item is `done`. Two **include** checkboxes — **Audio files** and **Transcripts** (`.txt`/`.md`) — that drive both the zip and the send (default: transcripts on, audio off). A **"Download .zip"** button (`downloadZip`) bundles the selected outputs + `manifest.json` + `index.txt`. A **"Send via SG/Send"** control mounting the embedded **`<sg-send-drop>`** component (`components/send-drop/v1/v1.0/v1.0.0/sg-send-drop.js`): on click, `api-send.js` builds the same bundle and calls `dropper.offerFile(zipBlob, name)`; the component handles the encrypted upload + auth prompt and emits `sg-send-complete` → the panel shows the **share URL** + Copy Link. 5. **Dev panel (`ui-dev-panel.js`)** — collapsible `<details>` mounting `sg-tool-api-explorer` + `-console` + `-manifest` (identical to heic-converter).

`ui/state.js` is the EventTarget store, now built around an **item list / queue** (mirroring heic-converter's `state.js`): `{ items:[{ id, blob, name, mime, durationMs, origin, model, status, transcript, error }], activeModel, apiKeyPresent }` with `addItem`/`getItem`/`getItems`/`updateItem`/`removeItem`/`clear`, emitting `change` events the panels subscribe to.

These questions were put to the human and answered. The Dev should build to these decisions; they are no longer open. Decisions 1–3 were resolved for v0.2.62 (13 Jun 2026); decisions 4–5 are the new ones resolved for v0.2.63 (13 Jun 2026).

1. **OpenRouter API-key handling → PERSIST via key-manager.** Reuse `components/openrouter/sg-openrouter-key-manager` (persists to `localStorage` under `sg-openrouter-mgmt-key`). This is the allowed exception under CLAUDE.md rule 7 (tools that need persistence). `ui/ui-model.js` mounts the key-manager component rather than a plain in-memory field; `connect()` reads the persisted key. Mask `apiKey` in `sanitiseParams` for the dev console.
2. **Transcription path → CHAT `input_audio` MVP.** Ship the chat-completions path through `sg-llm-request` v0.1.6 unchanged — **zero new core code** for transcription. The dedicated `/audio/transcriptions` STT core module (`core/sg-or-transcribe`) is deferred to the optional **Phase 2** (§6, §10 step 12). The two Whisper/transcribe models in §7 stay gated/"coming soon" until that module lands.
3. **Long-audio chunking → OUT OF SCOPE for v1.** No segment-split-and-stitch in the first release. Apply a soft **max-file-size cap per item** (suggest ~25 MB; large WAV base64 inflates the request ~33%) and reject/​warn above it with a clear message. Record as `audio/mp4` where `MediaRecorder.isTypeSupported('audio/mp4')`, otherwise re-encode webm→WAV via AudioContext (§6). Document the size/length limit in `SKILL__human.md`.
4. **sg/send mechanism → EMBEDDED send component.** Reuse the existing **`<sg-send-drop>`** component (`components/send-drop/v1/v1.0/v1.0.0/sg-send-drop.js`) in-page to perform the encrypted upload — NOT a deep-link hand-off. The send glue (`api/api-send.js`) builds the bundle and calls `dropper.offerFile(blob, name)`, resolving on `sg-send-complete` with the **share URL**. *Code-verified: the embed component EXISTS and already performs token → SGMETA → AES-256-GCM → 3-step upload via `core/send-crypto/.../sg-send-upload.js`, and is already embedded by infographic-gen / PlaybookLM / folder-editor.* **OPEN RUNTIME DEPENDENCY (not new code, flag for human):** the component needs (i) a **live send.sgraph.ai API** (auto-detected: `send.sgraph.ai` / `dev.` / `main.`) and (ii) an **access token** entered by the user (or in `localStorage['sgraph-send-token']`). This repo does not contain the send server/auth — by design send.sgraph.ai is a *consumer* of this repo. Dev must verify the send flow end-to-end against `dev.send.sgraph.ai` with a real token, and the SKILL/UX must make the "you need a SG/Send access token" requirement explicit.
5. **ZIP bundle contents → BOTH audio + transcripts, USER-SELECTABLE.** The session bundle (`downloadZip` / the same blob fed to `sendViaSgSend`) can contain **both the original audio files and the transcripts** (`.txt`/`.md`), chosen via two include-checkboxes in `ui-bundle.js` (default: transcripts on, audio off). Always include a **manifest** — both `manifest.json` (structured) and a human-readable `index.txt` — listing per item: original filename, model, durationMs, and transcript filename. **Implementation = JSZip CDN lazy-load** (the established repo pattern), copied from `heic-converter/api/api-output.js` into tool-local `api/audio-zip.js`; a pure-JS store-only writer is the documented fallback only (§3 row 8 / †). **No shared zip helper exists in core/ today** — promote `audio-zip.js`→`core/sg-zip` only if a 3rd tool needs the manifest-bundle shape.
