## Finding-by-finding (delta since v0.2.70)

### Finding 4 — Deploy-drift — ✅ tool/QA half done · 🔲 DevOps owns promotion
Agreed: the served `{}`/0-byte-TTS is a **stale CDN bundle**, not source. The Node
contract test can't see that, so per your ask I extended
`tests/playwright/audio-transcribe-live-smoke.js` (it drives the **real served
page**) with:
- `[9]` `getItems()` is a **non-empty array** after a take, and
- `[10]` OpenRouter TTS returns `blob.size > 0` (mocked stream).

Both **pass against the locally-served current build** — which confirms source is
correct and gives QA a served-page guard. **What's left is purely DevOps:** promote
the v0.1.20 bundle and bust the CDN cache so the page behind the version string is
actually that version. The tool can't self-enforce "deploy ≤ repo".

### Finding 7 — Typed key/quota errors — ✅ DONE (rev-3 matrix is stale here)
Shipped v0.1.18 (`api/llm-errors.js` `classifyLlmError`): 401→`key-invalid`,
402→`budget-exceeded`, 403→`key-exhausted`, 429→`rate-limited`, else `llm-error`,
preferring the provider message. `transcribeItem`/`ask` reject with `{code,status}`;
v0.1.19 added **friendly** UI messages (Queue rows + Live) and the Debug code chip.
The "blocked on `sg-llm-request` status" item can be **closed** — it already exposes
`status`. The only residual is the **finer expired-vs-exhausted-vs-revoked**
distinction (a 401 can't be split from the status alone), which stays with the
SG-API-secret minting layer.

### Finding 8 — Live in a vault — ◑ → cost ✅, mic graceful ✅, host-cooperation 🔲
- **8(a) cost:** done (per-segment cost on `at:live:segment` + running total). Your
  caution is right and now actionable: live re-sends the **growing take** per
  segment, so cost grows with duration. The new **session-total roll-up** (v0.1.20)
  and the Live panel's running total surface this **before/while** it runs on a
  shared key. A hard **session-length cap for a sponsored key** is a good next
  guard — but it belongs with the **key-budget/vault layer** (the tool doesn't know
  a key is sponsored or what its cap is); the tool already exposes the running cost
  for that layer to act on.
- **8(b) mic graceful:** done (v0.1.20). In a null-origin sandboxed frame
  `navigator.mediaDevices` is `undefined`; `live.js start()` now detects that and
  throws typed `{code:'mic-unavailable'}` with an actionable message, and
  `startLive()` emits `at:live:error`. No more bare throw.
- **8(c) host cooperation 🔲:** for embedded Live to actually capture audio, the
  **host** must put `allow="microphone"` on the tool iframe and serve it in a
  secure, gesture-permitted context. That is **host-cooperation-required**, not a
  tool fix — documented here and in the manifest note. Recommendation for embedders
  that can't grant mic: hide/disable Live and offer the **file-drop** path (which
  works in the null-origin frame), exactly as the new `live-transcribe` variation
  degrades.

## New work this round (product track)

- **#1 Live-first variation — `tools/…/en-gb/live-transcribe/` (v0.1.0).** A
  deliberately tiny "big button" page: the reused `ui-live` panel as the hero
  (transcript + per-segment cost), a key bar, an "or drop a file" zone, and a
  transcripts list. It **reuses** audio-transcribe's `api/` modules and the
  `ui-live` panel — **no engine duplication** (I extracted the isolated transport to
  a shared `api/llm-transport.js` so both entries use the exact same code). This is
  the strategy-brief's "max-simplicity" experiment, and it **degrades gracefully**:
  if the mic is unavailable (e.g. embedded), the file-drop path still works. Verified
  by a new Playwright smoke (8/8): boot, live round-trip, take saved, drop→transcribe.
- **#2 Voice cost in the session total.** `state.js` gained an `aux[]` cost
  accumulator; Create Voice (TTS) spend now folds into the "This session" line and
  `getCostSummary()` (`auxUsd`/`auxPending`).
