## 1. Summary

A new standalone browser tool — **`audio-transcribe`** — that lets a user (1) record from the microphone OR (2) drag/drop/pick a local audio file, then (3) transcribe it to text using a pre-selected list of **OpenRouter** audio-capable models, all client-side, exposing the mandatory **`SgToolApi`** JS API.

**The 90/10 reuse thesis is VALIDATED, with one honest correction.** Recording, file-drop, the LLM fetch engine, OpenRouter wiring, the SgToolApi pattern, the api/+ui/ tool layout, the dev-panel components, and even the audio→`input_audio` wire-format translation **all already exist and are code-verified**. The genuinely-new ~10% is:

- A thin **curated audio-model list + transcription glue** (a tool-local pipeline that builds the `binary_file`/`input_audio` message and reads back the text), and
- **One audio-format concern that must be solved**: the existing recorder (`core/sg-audio`) emits **webm/opus**, but OpenRouter's audio input documents **wav/mp3/aac/ogg/flac/m4a/pcm** — **webm/opus is not a documented input format**. This is the single biggest real gap (see §3 and §6).

There is **no** existing "transcribe an arbitrary audio file via OpenRouter" tool. The closest tool, `voice-memo` (`tools/v0/v0.1/v0.1.53/en-gb/voice-memo/`), records audio but transcribes **locally via Whisper WASM** (`core/sg-whisper`), not via OpenRouter — so it solves a different problem and is reuse for the *recording* leg only.

---

## 2. Requirements (restated)

1. **Record audio** from the microphone (start / stop, with a visible timer / waveform).
2. **Select or drag-drop an audio file** from local disk.
3. **Transcribe audio → text** using a number of **pre-selected OpenRouter models** (list configurable/curated).
4. **Support the JS Tool API** (`SgToolApi`: `register()` + `activate()` + three SKILL files).
5. **Follow the patterns/standards of the most recent commits** (the `api/` + `ui/` split + manifest-loader bootstrap, as in `heic-converter`).

**Path:** `tools/v0/v0.1/v0.1.60/en-gb/audio-transcribe/` (next free tool-version slot above the current max `v0.1.59`; Dev should bump to whatever is free at build time and reflect it in the registry).

## 5. JS Tool API surface (`api.register(...)`)

Registered on `SgToolApi({ name:'audio-transcribe', version:{api,ui,content}, panelId:'root', manifest:'./manifest.json', skills })`, then `activate()`.

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `startRecording` | yes | `{ deviceId?, mimeType? }` | `{ recording:true, mimeType }` | Begins a single-take mic recording via `sg-audio`/`sg-audio-recorder`. Emits `AT_EVENTS.RECORDING_STARTED`. |
| `stopRecording` | yes | `{}` | `{ name, sizeBytes, mimeType, durationMs }` | Stops, assembles the blob, sets it as the current source. Emits `RECORDING_STOPPED` + `SOURCE_SET`. |
| `loadFile` | yes | `{ file }` (File) or via dropzone | `{ name, sizeBytes, mimeType }` | Sets a dropped/picked audio file as the current source. Rejects non-audio with `{code:'not-audio'}`. Emits `SOURCE_SET`. |
| `getSource` | no | `{}` | `{ name, sizeBytes, mimeType, durationMs, origin:'recording'|'file' }|null` | Serialisable (no Blob). |
| `clearSource` | no | `{}` | `{}` | Clears source + transcript. Emits `RESET`. |
| `listModels` | no | `{}` | `[{ id, label, cost, speed, default }]` | The curated list from `audio-models.js`. |
| `setModel` | no | `{ model }` | `{ model }` | Validates against curated list (or allows passthrough id). Emits `MODEL_CHANGED`. |
| `connect` | yes | `{ apiKey, model? }` | `{ provider:'openrouter', model }` | Fires `llm:connected { provider:'openrouter', model, apiKey }`. `sanitiseParams` masks `apiKey`. |
| `transcribe` | yes | `{ model?, language? }` | `{ text, model, latencyMs }` | The core action: source blob → `audio-format` → `binary_file` message → `llm:send` → resolves with transcript. Emits `TRANSCRIBE_STARTED` + (`TRANSCRIBE_COMPLETE` \| `TRANSCRIBE_ERROR`). |
| `getTranscript` | no | `{}` | `{ text, model }` | Last transcript. |

**Events** (`api/audio-transcribe-events.js`, frozen `AT_EVENTS`, all `at:*` namespaced):
`RECORDING_STARTED 'at:recording:started'`, `RECORDING_STOPPED 'at:recording:stopped'`, `SOURCE_SET 'at:source:set'`, `MODEL_CHANGED 'at:model:changed'`, `TRANSCRIBE_STARTED 'at:transcribe:started'`, `TRANSCRIBE_PROGRESS 'at:transcribe:progress'`, `TRANSCRIBE_COMPLETE 'at:transcribe:complete'`, `TRANSCRIBE_ERROR 'at:transcribe:error'`, `RESET 'at:reset'`. Plus the framework `tool:ready` from `activate()`.

## 6. Core / module changes

**Phase 1: no new core module required.** The transcription glue lives **tool-local** in `api/api-transcribe.js` + `api/audio-format.js`, reusing `sg-llm-request` v0.1.6 unchanged. This respects "reuse first" and keeps the new surface small.

**The format-gap fix (`api/audio-format.js`) — the one piece of real engineering:**

```js
// audio-format.js (tool-local, ~120 lines)
// OpenRouter audio input accepts: wav, mp3, aiff, aac, ogg, flac, m4a, pcm16/24.
// webm/opus (what core/sg-audio records by default) is NOT documented as accepted.
export const OR_SUPPORTED = ['wav','mp3','aac','ogg','flac','m4a'];
export function isSupportedAudio(mimeOrName) { /* map + test */ }
// Convert an arbitrary recorded/loaded blob into a supported-format base64 data URL.
// Strategy order: (1) if already supported (mp4/m4a/mp3/wav/ogg/flac/aac) → passthrough;
//                 (2) else decode via AudioContext.decodeAudioData → re-encode to 16-bit PCM WAV (pure JS, no deps).
export async function toSupportedDataUrl(blob) { /* → { dataUrl, mime, format } */ }
```

A pure-JS **WAV encoder** (decode with `AudioContext` — already used by `sg-whisper.blobToFloat32Array` — then write a 16-bit PCM WAV header) avoids any CDN dependency and guarantees a model-accepted format. **Recommended default:** also try recording directly as `audio/mp4` where `MediaRecorder.isTypeSupported('audio/mp4')` (Safari/iOS), falling back to webm→WAV conversion elsewhere. **If `audio-format.js` grows past ~300 lines or is reused by a second tool, promote it to `core/sg-audio-convert/v0/v0.1/v0.1.0/`** (immutable-version rules; do not mutate `sg-audio` v0.1.0).

**Phase 2 (optional, future): `core/sg-or-transcribe/v0/v0.1/v0.1.0/sg-or-transcribe.js`** — a small pure-JS client for OpenRouter's dedicated `POST https://openrouter.ai/api/v1/audio/transcriptions` endpoint (`Authorization: Bearer`, JSON body `{ model, input_audio:{ data:<base64>, format }, language? }`, returns `{ text, usage }`). This endpoint returns word-accurate transcripts from true STT models (whisper-large-v3, gpt-4o-transcribe, gpt-4o-mini-transcribe, Google Chirp) and reports `usage.cost`/`seconds`. Proposed signature:

```js
export async function transcribeAudio({ apiKey, model, dataBase64, format, language, signal })
  // → { text, cost, seconds }
```

This is **not** required for the MVP because `sg-llm-request`'s chat path already reaches audio-capable chat models. It is the cleaner long-term home for "true STT" and would let the tool offer both an LLM-chat mode and a dedicated-STT mode. Flag for the human (§11).

## 7. Pre-selected OpenRouter models

Configured in **`api/audio-models.js`** (mirrors infographic-gen's `sg-infographic-model-picker.js` constants pattern: an array of IDs + a `MODEL_METADATA` map with `label`/`cost`/`speed`). Editing this file is the single point of model curation.

| Model id | Label | Path | Cost (approx) | Notes |
|---|---|---|---|---|
| `google/gemini-2.5-flash` | Gemini 2.5 Flash | chat `input_audio` | low | Fast, cheap, audio-in multimodal; good default. |
| `openai/gpt-4o-audio-preview` | GPT-4o Audio | chat `input_audio` | medium | Native audio-in chat model; strong quality. |
| `openai/gpt-4o-mini-audio-preview` | GPT-4o Mini Audio | chat `input_audio` | low | Cheaper audio chat tier. |
| `openai/whisper-large-v3` | Whisper Large v3 | dedicated `/audio/transcriptions` (Phase 2) | low | Pure STT; best raw transcription. Surface once Phase-2 module lands; until then, label "STT (coming soon)". |

**Default (MVP / chat path):** `google/gemini-2.5-flash`. Rationale: cheapest fast audio-capable chat model reachable through the **already-working** `sg-llm-request` path. The two Whisper/transcribe entries are listed but gated behind the Phase-2 dedicated-endpoint module (do not expose them as working until that module exists — Reality-Document rule).

> Model IDs and pricing drift; Dev should confirm each id is live on OpenRouter at build time (the `sg-openrouter-models` component fetches the live `/v1/models` catalogue and can be used to validate). Do **not** hardcode pricing as fact in user-facing copy — show it as "approx".

## 8. UI panels

Single-column linear shell (heic-converter style; sg-layout is optional and not needed for four panels). `ui/ui-shell.js` mounts:

1. **Source panel (`ui-source.js`)** — a Record button (mic) with a live timer + a small waveform (reuse `sg-audio-recorder`'s built-in waveform, or `components/sg-audio-viz` if a richer visual is wanted), **OR** an `<sg-upload-dropzone accept="audio/*">` + hidden `<input type=file accept="audio/*">`. Shows the current source name/size/duration and a Clear button. Record and file are mutually exclusive — picking one clears the other.
2. **Model panel (`ui-model.js`)** — the curated model selector (radio/select with cost + speed badges, from `listModels()`), plus **`components/openrouter/sg-openrouter-key-manager`** for key capture (persists to `localStorage` under `sg-openrouter-mgmt-key` — the persist-the-key decision, §11.1). `connect()` reads the persisted key and fires `llm:connected`.
3. **Transcript panel (`ui-transcript.js`)** — a Transcribe button (disabled until source + model + key present), a progress/spinner during the request, the transcript text area, and Copy + Download (.txt / .md) buttons.
4. **Dev panel (`ui-dev-panel.js`)** — collapsible `<details>` mounting `sg-tool-api-explorer` + `-console` + `-manifest` (identical to heic-converter).

`ui/state.js` is the EventTarget store: `{ source:{blob,name,mime,durationMs,origin}|null, model, apiKeyPresent, transcript, status }`, emitting `change` events the panels subscribe to.

## 9. SKILL files plan

Three files under `skills/` (heic-converter naming `SKILL__{human,browser,api}.md`), also declared in `manifest.json` `api.skills` + top-level `skills`.

- **`SKILL__human.md`** — what the tool does; record vs drop-a-file; choosing a model (cost/speed/quality trade-off); entering an OpenRouter key; privacy statement ("audio is sent to OpenRouter for transcription — unlike the local-only voice-memo tool"); supported formats + the conversion-on-the-fly note; limitations (file size, long-audio, language).
- **`SKILL__browser.md`** — DOM selectors (record button, dropzone, file input, model select, key field, transcribe button, transcript area, download buttons), how to inject a file via Playwright `setInputFiles`, how to drive transcription headless via `window.__tool.transcribe()`, what CSS/status classes to observe.
- **`SKILL__api.md`** — `window.__tool` lifecycle (`tool:ready`), every action from §5 with params/returns/events/errors, every `AT_EVENTS` window event, dependency list (incl. `sg-llm-request`, the lazy nothing-extra note), and 2-3 end-to-end example scripts (load file → connect → transcribe; record → stop → transcribe → download).

## 10. Implementation phases (small-file, incremental)

1. **Scaffold + bootstrap.** Create the tree (empty files), `index.html` manifest-loader bootstrap, `manifest.json` (dependencies + phased loader + `api:` stub), `styles/audio-transcribe.css`. Mirror heic-converter. Land an empty `ui-shell` that mounts a title — verify the page loads and dev-panel components register.
2. **Source leg.** `ui/state.js` + `api/api-source.js` + `ui/ui-source.js`: file drop/pick first (simplest), then mic record via `sg-audio-recorder`. Verify `getSource()` returns the blob metadata.
3. **Format helper.** `api/audio-format.js`: passthrough + AudioContext→WAV re-encode. Unit-verify in browser with a webm recording and an mp3 file.
4. **Model + connect.** `api/audio-models.js` + `ui/ui-model.js` + `connect()`. Wire `llm:connected`. Mount `sg-llm-request` (add to manifest deps).
5. **Transcribe pipeline.** `api/api-transcribe.js`: build the `binary_file` audio message, fire `llm:send`, resolve on `llm:request-complete`. Wire `ui/ui-transcript.js` (output + copy + download). End-to-end test with the default Gemini model.
6. **SgToolApi registration.** `api/audio-transcribe-api.js` + `api/audio-transcribe-events.js`: register all §5 actions, `activate()`, mount shell. Verify `window.__tool` + headless `transcribe()`.
7. **Dev panel + SKILL files + manifest `api:` section.** Fill `ui-dev-panel.js`, write the three SKILL files, complete the manifest `api.actions`/`api.events`.
8. **Registry + landing page.** Add `audio-transcribe` to the tool registry / `TOOL_SLUGS` (Media or AI category) so it appears on the landing page; bump the registry version. Add a Playwright/Node smoke test mirroring existing tool smoke tests.
9. **(Optional Phase 2)** `core/sg-or-transcribe` dedicated-endpoint module + expose the Whisper/transcribe models as a second "STT mode".

Each step is independently testable and produces a small diff. Prefer `Edit` over `Write` after a file first exists.

## 11. Decisions (RESOLVED by human — 13 Jun 2026)

These three open questions were put to the human and answered. The Dev should build to these decisions; they are no longer open.

1. **OpenRouter API-key handling → PERSIST via key-manager.** Reuse `components/openrouter/sg-openrouter-key-manager` (persists to `localStorage` under `sg-openrouter-mgmt-key`). This is the allowed exception under CLAUDE.md rule 7 (tools that need persistence). `ui/ui-model.js` mounts the key-manager component rather than a plain in-memory field; `connect()` reads the persisted key. Mask `apiKey` in `sanitiseParams` for the dev console.
2. **Transcription path → CHAT `input_audio` MVP.** Ship the chat-completions path through `sg-llm-request` v0.1.6 unchanged — **zero new core code** for transcription. The dedicated `/audio/transcriptions` STT core module (`core/sg-or-transcribe`) is deferred to the optional **Phase 2** (§6, §10 step 9). The two Whisper/transcribe models in §7 stay gated/"coming soon" until that module lands.
3. **Long-audio chunking → OUT OF SCOPE for v1.** No segment-split-and-stitch in the first release. Apply a soft **max-file-size cap** (suggest ~25 MB; large WAV base64 inflates the request ~33%) and reject/​warn above it with a clear message. Record as `audio/mp4` where `MediaRecorder.isTypeSupported('audio/mp4')`, otherwise re-encode webm→WAV via AudioContext (§6). Document the size/length limit in `SKILL__human.md`.
