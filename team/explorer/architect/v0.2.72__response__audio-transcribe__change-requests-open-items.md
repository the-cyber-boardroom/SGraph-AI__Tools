## Tool items (done)

### #3 — `getItems()` on the deployed build — ✅ investigated, no code change
I read `sg-tool-api._invoke` directly: it does `const result = await fn(params); …;
return result;` — the result is returned **verbatim**, with no spread, no
`{...result}`, no `JSON` round-trip (the log stores a reference but never mutates
it). So there is **no serialisation collapse at the public API boundary**. Combined
with the served-page `[9]` assertion (getItems is a non-empty array) passing against
the locally-served current build, the deployed `{}` is **stale-bundle deploy-drift**
(the old build where the getter differed), not a boundary bug. **Resolution: promote
(item #1).** The accept criterion ("live `getItems()` reflects state as an array")
will pass once the current bundle is served.

### #4 — Embedder can obtain the synthesised audio — ✅
`synthesize({ …, returnAudio: true })` now returns `{ …, audioDataUrl }` — the WAV
as a base64 data URL, a readable handle over the JS API. `synthesize` also now
honours an `{ apiKey }` override (it previously ignored it and used the connected
key). The manifest documents both, plus `addSynthesized` → queue as the alternate
retrieval path. (Accept: satisfied — a handle is returned **and** the queue path is
documented.)

### #5 — Versioned TTS component — ✅
The OpenRouter TTS engine + WAV/PCM helpers moved to **`core/sg-tts-openrouter`
/v0/v0.1/v0.1.0/** — a versioned `/core/` URL with the same `*`-CORS contract as
`sg-audio-decode`, importable by vault pages directly. The tool's `api/tts.js` is now
a thin mode-dispatch that **dynamically** imports it (deliberately dynamic, not
static, so `tts.js` stays importable under Node — the headless `mountShell` test
imports it transitively and Node can't resolve a static absolute `/core/`
specifier). Browser-verified: the live smoke's `[10]` TTS-bytes check now exercises
the extracted module end-to-end.

### #9 (tool-half) — Spend cap — ✅ enforcement done; cap value = vault
`setSpendCap({ usd })` sets (or clears with `null`) a session cap;
`transcribeItem` / `transcribeModels` / `transcribeBlob` (Live) halt with a typed
`{ code:'budget-cap' }` once known spend ≥ cap. It's a **soft** cap (deferred costs
lag a couple of seconds, so it can overshoot slightly) — documented. **Crucially**,
I closed the gap that made this (and the session total) under-count: **live-segment
costs are now recorded in `state` (`aux`, `kind:'live'`)**, so the cap and the Model
& Cost "This session" line both see live spend (previously live cost lived only in
the Live panel's local total). Browser-verified: after a live run, the cap halts the
next transcribe once the live cost resolves. **What stays with the vault/key-budget
layer:** *providing* the cap value (the tool can't know a key is sponsored or its
budget) and the key source itself.

### User-requested — Live "final pass" toggle — ✅
`stopLive({ finalPass })` + a "Clean up on stop" checkbox (default on). On = the
full-quality re-transcription for a clean saved transcript (~1× extra). Off = keep
the cheaper appended delta text (verified: saves the live text, no extra pass).
