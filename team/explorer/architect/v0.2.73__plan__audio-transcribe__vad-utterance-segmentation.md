# Plan — Live transcription: VAD / silence-boundary segmentation (replace time-based chunking)

**Version:** v0.2.73
**Type:** Architect plan (design only — no code yet, per request)
**Author:** claude-code-web session for dinis.cruz@owasp.org

**Status:** PROPOSED — does not exist yet. The current Live mode (v0.1.25) is time-based.

---

## 1. The problem (why the current approach is wrong, not just buggy)

Live mode currently cuts the audio on a **fixed clock** (every `intervalMs`) and sends each slice. Your screenshots show why that's the wrong foundation:

- **Cuts land mid-word.** A 1 s clock cut falls in the middle of a syllable. The audio model gets half a word and **confabulates** — "zero Cats Yes… Dritte Etappe zero upgrading… The pucker things crazy corrupt". Each run differs because the cut points differ.
- **Tiny/partial clips hallucinate.** Audio LLMs (Whisper-family included) are notorious for inventing confident text on <1 s or partial-word audio. The smaller the chunk, the worse.
- **No word-boundary alignment → concatenation mangles.** We glue per-segment transcripts; if word "identify" is split across two clips you get "iden" + "tify" → garbage.
- **The webm-fragment trick is fragile.** To keep a mid-stream slice decodable we prepend the init segment to a bare `Cluster`. It's *technically* decodable, but the cluster boundaries are arbitrary, and this is almost certainly why **segment playback didn't work** — `decodeAudioData` on these synthetic fragments is unreliable across browsers.

**Your proposal is correct and is the industry-standard fix:** don't cut on a clock — **cut at the silences**. Buffer audio while the user speaks; when the volume dips below a threshold for long enough, close that section, send it, and start a new one. Each sent clip is then a **complete utterance** (a phrase between pauses), which models transcribe cleanly, and gluing the clips reconstructs the original speech.

---

## 2. How others solve this (research)

The technique is **Voice Activity Detection (VAD) + endpointing**: detect speech-vs-silence and "endpoint" (finalize a segment) after a sustained pause.

**Two families of VAD:**
- **Energy/threshold VAD** (what you described): track short-frame RMS energy; speech = above threshold, silence = below. Cheap, zero-dependency, but sensitive to mic level / background noise → wants an *adaptive* threshold (track the noise floor) or a user control.
- **Neural VAD** — **Silero VAD** is the de-facto choice, runs in the browser via **`@ricky0123/vad-web`** (ONNX Runtime Web + an AudioWorklet). It resamples to 16 kHz, runs the model per frame, and emits a speech probability 0–1, with `onSpeechStart` / `onSpeechEnd` callbacks. Far more robust to noise; costs a ~1–2 MB model download + the ONNX runtime. (Picovoice's *Cobra* and the classic *WebRTC VAD* are alternatives; Silero is the common open default.)

**The endpointing parameters that make VAD usable** (these are exactly the `@ricky0123/vad-web` knobs, and they encode the engineering we must replicate even for energy VAD):
- `positiveSpeechThreshold` (≈0.3) — probability/energy above which we're "in speech".
- `negativeSpeechThreshold` — a *lower* threshold to exit speech → **hysteresis** (avoids flapping at the boundary).
- `redemptionFrames` — **hangover / grace**: wait N silent frames before declaring end-of-utterance, so a brief mid-phrase pause doesn't cut. This is the single most important parameter for natural cuts.
- `preSpeechPadFrames` — **pre-roll**: prepend a few hundred ms *before* the trigger so the word onset isn't clipped.
- `minSpeechFrames` — drop too-short blips (a cough, a click) so we don't send/charge for non-speech.

**Why this fits our constraint:** OpenRouter is **request/response** chat-completions — there is **no streaming STT endpoint** (unlike Deepgram / AssemblyAI / OpenAI Realtime, which do server-side VAD + incremental decode over a WebSocket). So the realtime intelligence has to live **client-side**: VAD segments the mic locally, and each finished utterance is one normal transcribe request. This is also how local **Whisper streaming** tools (whisper.cpp `stream`, faster-whisper) work — VAD + utterance windows, not blind fixed windows.

Sources: [@ricky0123/vad (npm)](https://www.npmjs.com/package/@ricky0123/vad) · [vad-web algorithm docs](https://docs.vad.ricky0123.com/user-guide/algorithm/) · [vad-web browser guide](https://docs.vad.ricky0123.com/user-guide/browser/) · [Picovoice — Best VAD 2026 (Cobra vs Silero vs WebRTC)](https://picovoice.ai/blog/best-voice-activity-detection-vad/) · [Picovoice — Complete VAD guide](https://picovoice.ai/blog/complete-guide-voice-activity-detection-vad/) · [Silero VAD guide](https://aiadoptionagency.com/silero-vad-voice-activity-detection/).

## 3. Proposed architecture

### 3.1 Capture PCM, not webm (the key enabler)
Switch the live capture source of truth from **MediaRecorder (webm)** to **raw PCM** via the Web Audio graph (an **AudioWorklet**, with a ScriptProcessor fallback for old Safari). Why:
- PCM is **sample-addressable** — we can cut at the *exact* silence sample and encode a clean WAV. No webm-fragment hacks, no init-segment surgery.
- We already run an `AnalyserNode` on the stream (added for the v0.1.25 silence gate) — extend that graph to also tap samples.
- We already have **`encodeWav()`** (in `core/sg-tts-openrouter`) → each utterance's Float32 PCM → a clean mono WAV.
- **This also fixes segment playback for free** — clean WAVs play in any `<audio>` element, no decode gymnastics.

Keep one **continuous PCM buffer** for the whole session → that *is* the saved take (gap-free, == original recording), used by the final full-quality pass on stop (unchanged).

### 3.2 The VAD state machine (energy VAD, Phase 1)
Run on ~20–30 ms frames of the PCM (RMS energy per frame):

```
state = SILENCE
ring-buffer the last ~300 ms of PCM (for pre-roll)

on each frame:
  e = rms(frame)
  if state == SILENCE:
     if e > speechThreshold for >= minOnsetFrames:
        state = SPEECH
        start utterance buffer  ← seeded with the pre-roll ring-buffer
  else (SPEECH):
     append frame to utterance buffer
     if e < silenceThreshold:
        silentRun += frameMs
        if silentRun >= endpointMs (e.g. 500–800 ms):
           close utterance  → encodeWav → send (if length >= minUtteranceMs)
           state = SILENCE; reset
     else:
        silentRun = 0
   # hard cap so a non-stop talker still gets cut:
   if utterance length >= maxUtteranceMs (e.g. 15 s): force-close + send + reopen
```

- **Hysteresis:** `speechThreshold > silenceThreshold` (two levels) so we don't flap.
- **Pre-roll:** seed each utterance with the buffered ~300 ms before onset (no clipped onsets).
- **Hangover (`endpointMs`):** the grace pause that defines a "phrase boundary"; the tuning that matters most.
- **min/max length:** drop blips; force-cut monologues.
- **Adaptive threshold (nice-to-have):** track a rolling noise floor during silence and set `speechThreshold = noiseFloor * k`, so it self-tunes to the mic/room.

### 3.3 Transcribe + reassemble (mostly reuse what exists)
- Each closed utterance → WAV → the **existing** transcribe path (`transcribeBlob`), **isolated transport**, **bounded concurrency**, **seq-ordered reassembly**, **per-segment cost**, **spend cap**, **typed errors** — all unchanged. Utterances are seq-numbered in capture order; reassembly stays contiguous-prefix.
- **Final full-quality pass on stop** stays exactly as is (operates on the continuous PCM → one clean WAV). Still the safety net / margin of error.
- On stop, flush any open utterance.

### 3.4 Net effect
- Clips align to phrase boundaries → each transcribes cleanly → concatenation ≈ the spoken text.
- Fewer, more-meaningful requests during natural speech (silence sends nothing) → usually **cheaper** than 1 s chunking, and **far** more accurate.
- Latency is "endpoint" latency (~0.5–0.8 s after you pause) — natural, like dictation.

## 4. The visual cue (viz)

You asked for a visual clue of *when* clips happen. Plan: a small **canvas "VAD timeline"** under the existing waveform (either a variation of `sg-audio-viz` or a tool-local `live-vad-viz` — I lean tool-local so we don't risk the shared component):

- **Scrolling energy/RMS trace** over time (we already sample RMS for the gate).
- A horizontal **threshold line** (the speech/silence level) so you *see* where the cut decision sits — and can tune it.
- **Speech regions shaded** vs silence; **alternating colour per utterance** so each sent clip is a distinct band.
- A **cut marker** (vertical tick) at each endpoint, optionally labelled `#seq`.
- Hovering/clicking a band → highlights/plays that segment (ties into the now-working WAV playback).

This makes the threshold tangible: the user watches their speech get bracketed into clips in real time, and sees immediately if the threshold is too hot/cold.

Recommendation: **tool-local viz** drawing from the same RMS samples the VAD uses (single source of truth), rather than overloading `sg-audio-viz`.

## 5. Phasing

- **Phase 1 — Energy VAD (no download).** PCM capture (AudioWorklet) + the energy state machine + clean-WAV utterances + the VAD timeline viz + a couple of controls (sensitivity, endpoint pause). Zero new dependencies; uses `encodeWav` + the existing transport. Replaces the time-based delta path. **This is the bulk of the win.**
- **Phase 2 — Optional Silero VAD ("smart mode").** Lazy-load `@ricky0123/vad-web` + the ONNX model, **cached via the existing `core/sg-wasm-cache`** (same pattern as the Opus decoder). A toggle: "Energy (fast) / Silero (robust)". Much better in noise. Note the known **Safari SIMD** caveat with vad-web → keep energy VAD as the always-available fallback.
- **Phase 3 — Refinements.** Adaptive noise-floor threshold; small inter-utterance **overlap + de-dup** for boundary words; optional "merge tiny utterances"; live re-punctuation.

---

## 6. Controls to expose (replacing "Chunk every")

- **Sensitivity** (speech threshold) — slider or presets (Quiet room / Normal / Noisy). Maps to the energy threshold (or Silero `positiveSpeechThreshold`).
- **Pause to split** (`endpointMs`) — e.g. 0.4 / 0.6 / 0.8 s. "How long a pause ends a clip."
- **Max clip length** (safety cap).
- **Engine** (Phase 2): Energy / Silero.
- Keep **Clean up on stop** and the **spend cap**. Drop the fixed "Chunk every" (superseded), or keep it only as the Phase-2 max-length cap.

JS API: `startLive({ vad: { mode, sensitivity, endpointMs, maxMs, minMs } })`; emit `at:live:segment` per utterance as today (now with a clean WAV blob).

## 7. Migration from the current code

- **Keep:** the isolated transport, seq reassembly, bounded concurrency, per-segment cost + spend-cap (aux), typed errors, the final full pass, `stopLive({finalPass})`, the segments strip + playback UI (playback starts *working* once clips are clean WAVs).
- **Replace:** `live.js`'s MediaRecorder time-loop (`tick` + delta-blob + `extractInitSegment`) with: AudioWorklet PCM capture + the VAD state machine + `encodeWav` per utterance. `extractInitSegment` / the webm-fragment path is **retired**.
- **Add:** the VAD timeline viz; the new controls.
- Net: `live.js` gets a bit bigger but conceptually simpler (no webm surgery). Could split into `live-capture.js` (PCM/worklet), `live-vad.js` (state machine), `live.js` (orchestration) to respect the file-size rule.

## 8. Risks & open questions

- **Endpoint latency** is inherent (must wait for the pause). It's natural, but set a sane default (~0.6 s) and let users shorten it.
- **Threshold tuning** for energy VAD across mics/rooms → adaptive noise floor and/or the visible threshold line + slider; Silero in Phase 2 sidesteps it.
- **Long monologue with no pauses** → the max-length cap forces a cut (back to a mid-word cut for that one boundary — acceptable, rare, and the final pass cleans the saved transcript).
- **AudioWorklet** needs a small worklet module served (one file, same-origin/CORS-ok) + a ScriptProcessor fallback for old Safari.
- **Silero on Safari** — the vad-web SIMD issue; keep energy VAD as fallback.
- **Open Q:** drop the inter-utterance silence from the *sent* clips (cheaper, recommended) while the *saved take* keeps everything (continuous PCM)? — Yes, recommend: send speech-only, save continuous.
- **Open Q:** do we still want a "send partial in-progress utterance" preview for very long utterances, or only on endpoint? Start with endpoint-only (simplest, cleanest); add partials later if the wait feels long.

---

## 9. Recommendation

Build **Phase 1 (energy VAD + PCM + clean-WAV utterances + VAD-timeline viz)** next. It directly fixes the garbled output and the dead play buttons, is dependency-free, and turns the existing transport/cost/cap machinery into a genuinely good realtime experience. Treat **Silero (Phase 2)** as the robustness upgrade once the shape is proven. Keep the final full-quality pass throughout as the accuracy backstop.
