# Architecture Brief: Audio Transcribe Tool (OpenRouter)

**version** v0.2.64
**date** 13 Jun 2026
**from** Architect (Explorer team)
**to** Dev, Designer, Librarian
**type** Architecture / implementation brief
**status** PROPOSED — the tool described here does not exist yet. Cross-checked against the Reality Document (`team/explorer/librarian/reality/v0.1.0__what-exists-today*.md`).

> **v0.2.64 supersedes v0.2.63.** This revision fixes the one critical flaw in v0.2.63: the `.opus` path previously **hard-stopped on Safari** with an `opus-decode-unsupported` error (Safari cannot `decodeAudioData` Opus). Processing WhatsApp `.opus` voice notes is the human's **#1 use case**, so a Safari hard-stop is unacceptable. The fix: a **reliable in-browser WASM Opus decoder** (`ogg-opus-decoder`, lazy-loaded from CDN as an ES module exactly like JSZip) converts Ogg/Opus → PCM Float32 → the existing WAV encoder, **on every browser including Safari, with NO hard-stop**. The decoder lives in a new reusable core module **`core/sg-audio-decode/v0/v0.1/v0.1.0/`** — the v1 tool's one new `core/` module (v0.2.63 wrongly claimed "no new core module in v1"; that claim is corrected here). All other v0.2.63 content (batch queue, zip bundle, embedded `<sg-send-drop>`) is unchanged.

> **v0.2.63 superseded v0.2.62**, folding in four human requirements: (1) process WhatsApp **`.opus`** voice notes; (2) **batch** drag-drop of many files with a per-item queue; (3) group a session's outputs and **download as a single `.zip`** (audio + transcripts, user-selectable); (4) **send via sg/send** using the **embedded `<sg-send-drop>` component**.

## 1. Summary

A new standalone browser tool — **`audio-transcribe`** — that lets a user (1) record from the microphone OR (2) **drag/drop/multi-select one or more local audio files (including WhatsApp `.opus` voice notes)**, then (3) transcribe **each** to text using a pre-selected list of **OpenRouter** audio-capable models, all client-side, then optionally (4) **bundle the session's audio + transcripts into a `.zip`** for download and/or (5) **send that bundle via sg/send (send.sgraph.ai)** as an encrypted share — all exposing the mandatory **`SgToolApi`** JS API.

**The 90/10 reuse thesis is VALIDATED, with one honest correction.** Recording, file-drop, the LLM fetch engine, OpenRouter wiring, the SgToolApi pattern, the api/+ui/ tool layout, the dev-panel components, the **multi-item queue/state model** (heic-converter's `state.getItems()`), the **JSZip CDN lazy-load pattern**, and the **`<sg-send-drop>` encrypted-send component** — plus the audio→`input_audio` wire-format translation — **all already exist and are code-verified**. The genuinely-new ~10% is:

- A thin **curated audio-model list + transcription glue** (a tool-local pipeline that builds the `binary_file`/`input_audio` message and reads back the text);
- **One audio-format concern that must be solved**: the existing recorder (`core/sg-audio`) emits **webm/opus**, and WhatsApp notes arrive as **Ogg/Opus `.opus`**. OpenRouter's audio input documents **wav/mp3/aac/ogg/flac/m4a/pcm** — bare **webm/opus is NOT a documented input format**. The `.opus` case is solved with a **three-tier format strategy** (pass-through → native `decodeAudioData` → **WASM Opus decode**) that NEVER hard-stops — a new `core/sg-audio-decode` module lazy-loads the `ogg-opus-decoder` WASM (single self-contained ES module from CDN) and decodes Ogg/Opus → PCM → WAV on **every** browser **including Safari** (see §3, §6, §7);
- The **batch queue** orchestration (sequential transcription with a small concurrency cap, per-item status/retry);
- A small **zip bundler** (audio + transcripts + manifest) — reusing the JSZip CDN lazy-load already used across the repo; and
- The **sg/send wiring** to the existing `<sg-send-drop>` component (the encrypted-upload primitive already exists; only the in-tool glue is new).

There is **no** existing "transcribe an arbitrary audio file via OpenRouter" tool. The closest tool, `voice-memo` (`tools/v0/v0.1/v0.1.53/en-gb/voice-memo/`), records audio but transcribes **locally via Whisper WASM** (`core/sg-whisper`), not via OpenRouter — so it solves a different problem and is reuse for the *recording* leg only.

## 2. Requirements (restated)

1. **Record audio** from the microphone (start / stop, with a visible timer / waveform).
2. **Select or drag-drop audio files** from local disk — including **batch / multiple files at once** (drag-drop or multi-select). *(extended in v0.2.63)*
3. **Transcribe audio → text** using a number of **pre-selected OpenRouter models** (list configurable/curated), **once per file** in the batch.
4. **Support the JS Tool API** (`SgToolApi`: `register()` + `activate()` + three SKILL files).
5. **Follow the patterns/standards of the most recent commits** (the `api/` + `ui/` split + manifest-loader bootstrap, as in `heic-converter`).
6. **Process WhatsApp `.opus` voice notes** (Ogg/Opus container) — **the #1 use case.** Recognise `.opus` in the `accept` filter and MIME sniffing, and route it through the three-tier format pipeline that **never hard-stops**: native decode where it works, else **WASM Opus decode (`core/sg-audio-decode`) → WAV** on every browser **including Safari**. *(strategy hardened in v0.2.64 — see §3 rows 6/6b + §6 + §7)*
7. **Batch queue.** Accept many files at once; each is a **queue item** with its own status (`queued → transcribing → done → error`), transcript, model and metadata. Transcribe sequentially with a small concurrency cap; support per-item retry and per-item removal. *(new in v0.2.63 — see §3 row 7 + §5 + §8)*
8. **Session bundle → ZIP.** Accumulate processed items in a session and bundle them into one `.zip`. The bundle is **user-selectable** and may contain **both the audio files AND the transcripts** (`.txt`/`.md`) plus a **manifest** (`manifest.json` + `index.txt`) listing per item: original filename, model, duration, transcript filename. *(new in v0.2.63 — see §3 row 8 + §5)*
9. **Send via sg/send.** Send a single item's outputs OR the whole session bundle (same zip as req. 8) as an **encrypted share** using the **embedded `<sg-send-drop>` component** (in-page, not a deep-link hand-off); return the resulting **share URL**. *(new in v0.2.63 — see §3 row 9 + §5 + §11)*

Everything else is reuse or small tool-local glue.

## 4. Proposed tool name + directory layout

**Name: `audio-transcribe`** (slug `audio-transcribe`). Rationale: it names the verb (transcribe) and the medium (audio), is unambiguous against `voice-memo` (local Whisper, vault pipeline) and the `openrouter` key/usage tool, and reads clearly in the landing-page registry. `transcribe` alone is acceptable but less descriptive; prefer `audio-transcribe`.

**Path:** `tools/v0/v0.1/v0.1.60/en-gb/audio-transcribe/` (next free tool-version slot above the current max `v0.1.59`; Dev should bump to whatever is free at build time and reflect it in the registry).

**New core module (the one new `core/` lib in v1) — `core/sg-audio-decode/`:**

```
core/sg-audio-decode/v0/v0.1/v0.1.0/
  sg-audio-decode.js       # public entry: decodeToPcm(blob,{hintName}) + blobToWav(blob) + needsDecode(file). Re-exports the helpers. (<150 lines)
  sg-opus-loader.js        # lazy CDN ESM import of ogg-opus-decoder (@1.7.3/+esm); cached singleton; decodeOggOpus(uint8) → {channelData,sampleRate} (<120 lines)
  sg-wav-encoder.js        # pure-JS: {channelData,sampleRate} → 16-bit PCM WAV Blob (RIFF header + interleave). No deps. (<150 lines)
```

Immutable-version rules apply: this is `v0.1.0` and must NOT be mutated once shipped; do **not** touch `core/sg-audio` v0.1.0 or `core/sg-whisper` v0.1.0. Public API signatures in §6.

## 5. JS Tool API surface (`api.register(...)`)

Registered on `SgToolApi({ name:'audio-transcribe', version:{api,ui,content}, panelId:'root', manifest:'./manifest.json', skills })`, then `activate()`.

The data model is a **queue of items** (not a single source). Each item: `{ id, name, sizeBytes, mimeType, durationMs, origin:'recording'|'file', model, status:'queued'|'transcribing'|'done'|'error', transcript, error }`. Item ids are returned by the ingest actions so callers can address rows headlessly.

**Source / queue ingest**

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `startRecording` | yes | `{ deviceId?, mimeType? }` | `{ recording:true, mimeType }` | Begins a single-take mic recording via `sg-audio`/`sg-audio-recorder`. Emits `AT_EVENTS.RECORDING_STARTED`. |
| `stopRecording` | yes | `{}` | `{ id, name, sizeBytes, mimeType, durationMs }` | Stops, assembles the blob, **adds it as one queue item**. Emits `RECORDING_STOPPED` + `ITEM_ADDED`. |
| `addFiles` | yes | `{ files }` (File[] / FileList) or via dropzone | `{ added:[{id,name,sizeBytes,mimeType}], rejected:[{name,code}] }` | **Batch ingest.** Adds every audio file (incl. `.opus`) as a queue item. Rejects non-audio per file with `{code:'not-audio'}`; rejects oversize with `{code:'too-large'}`. Emits `ITEM_ADDED` per accepted file. |
| `getItems` | no | `{}` | `[{ id, name, sizeBytes, mimeType, durationMs, origin, model, status, transcript? }]` | Serialisable (no Blob) snapshot of the whole queue. |
| `getItem` | no | `{ id }` | `{ …item }\|null` | One item (serialisable). |
| `removeItem` | no | `{ id }` | `{ removed:true }` | Drops one item. Emits `ITEM_REMOVED`. |
| `clearAll` | no | `{}` | `{}` | Clears the whole queue + session. Emits `RESET`. |

**Model + connect**

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `listModels` | no | `{}` | `[{ id, label, cost, speed, default }]` | The curated list from `audio-models.js`. |
| `setModel` | no | `{ model, id? }` | `{ model }` | Sets the active model for new items (or, with `id`, overrides one item's model). Validates against curated list (or allows passthrough id). Emits `MODEL_CHANGED`. |
| `connect` | yes | `{ apiKey, model? }` | `{ provider:'openrouter', model }` | Fires `llm:connected { provider:'openrouter', model, apiKey }`. `sanitiseParams` masks `apiKey`. |

**Transcription (per-item + batch)**

| Action | async | params | returns | notes |
|---|---|---|---|---|
| `transcribeItem` | yes | `{ id, model?, language? }` | `{ id, text, model, latencyMs }` | Transcribe one queue item: blob → `audio-format` (incl. `.opus`) → `binary_file` message → `llm:send` → resolve. ## 6. Core / module changes

**v1 adds exactly ONE new core module — `core/sg-audio-decode`** (the reliable WASM Opus decoder + WAV encoder; §3 row 6b, §4). Everything else — batch, zip, send, the transcription glue — stays **tool-local**: `api/api-transcribe.js` + `api/audio-format.js` reuse `sg-llm-request` v0.1.6 unchanged; the batch orchestrator (`api/api-batch.js`), zip bundler (`api/audio-zip.js`), and send glue (`api/api-send.js`) reuse, respectively, the heic-converter queue model, the JSZip CDN lazy-load, and the existing `<sg-send-drop>` component. **Promote-to-core candidates (only if a 2nd/3rd tool needs them):** `audio-zip.js`→`core/sg-zip` and a future thin `core/sg-send-embed` wrapper around `<sg-send-drop>` — both under immutable versioning. (`audio-format.js` is deliberately NOT promoted: the heavy, reusable work — the codec decode — already lives in `core/sg-audio-decode`; `audio-format.js` is the thin tool-local OpenRouter-format policy that calls into it.)

> **Why a new core module rather than tool-local?** The Opus→PCM→WAV decode is (a) non-trivial (WASM lazy-load + codec glue + WAV writer), (b) immediately reusable — `voice-memo` and any future audio tool hit the same Safari-Opus wall through `sg-whisper.blobToFloat32Array`, and (c) the thing that makes the #1 use case work on every browser. Per CLAUDE.md's "extract on the third repetition / lift reusable non-trivial work" guidance, this belongs in `core/` from the start, not buried in one tool. It does **not** mutate `sg-audio` or `sg-whisper` (immutable versioning).

**The format strategy (`api/audio-format.js` + `core/sg-audio-decode`) — the one piece of real engineering. NO hard-stop on any browser:**

```js
// audio-format.js (tool-local, ~140 lines) — OpenRouter-format POLICY only.
// OpenRouter audio input accepts: wav, mp3, aiff, aac, ogg, flac, m4a, pcm16/24.
// webm/opus (what core/sg-audio records by default) and bare .opus are NOT reliably accepted,
// so undecodable/unsupported inputs are converted to WAV before sending.
import { needsDecode, blobToWav } from '../../../../core/sg-audio-decode/v0/v0.1/v0.1.0/sg-audio-decode.js';
export const OR_SUPPORTED = ['wav','mp3','aac','ogg','flac','m4a'];

// .opus reports inconsistent MIME (audio/ogg | audio/opus | '' empty), so sniff on
// EXTENSION as well as MIME. accept attr must include the literal .opus extension.
export function isAudioFile(file) { /* MIME audio/* OR ext in [.opus,.ogg,.wav,.mp3,.m4a,.aac,.flac,.mp4,.webm] */ }
export function isSupportedAudio(mimeOrName) { /* true only for formats OpenRouter explicitly accepts */ }

// Convert an arbitrary recorded/loaded blob into a model-accepted base64 data URL.
// THREE-TIER, NEVER-FAIL strategy:
//   (1) already OpenRouter-accepted (m4a/mp3/wav/ogg/flac/aac) → pass through, no decode.
//   (2) else native AudioContext.decodeAudioData → WAV  (cheap; works on Chrome/FF
//       for webm/opus AND ogg/opus). Wrapped in try/catch.
//   (3) else (Safari+Opus, or ANY tier-2 failure) → core/sg-audio-decode.blobToWav():
//       lazy-loads the ogg-opus-decoder WASM (CDN ESM, WASM inlined → no .wasm fetch,
//       no Worker, no SAB/COOP-COEP) → Float32 PCM → 16-bit WAV. Works on EVERY browser.
//   There is NO tier that throws opus-decode-unsupported. .opus always becomes WAV.
export async function toSupportedDataUrl(blob, hintName) { /* → { dataUrl, mime:'audio/wav'|orig, format } */ }
```

```js
// core/sg-audio-decode/v0/v0.1/v0.1.0/sg-audio-decode.js — public API
//   needsDecode(file) → boolean   // true if not in OR_SUPPORTED (caller can pre-check)
//   decodeToPcm(blob, { hintName }) → Promise<{ channelData: Float32Array[], sampleRate:number }>
//        // tier-2 native decodeAudioData first; on failure or for .opus on Safari,
//        // falls through to the WASM Opus decoder (sg-opus-loader). Always resolves for Opus.
//   blobToWav(blob, { hintName }) → Promise<Blob>   // decodeToPcm → sg-wav-encoder → audio/wav Blob

// sg-opus-loader.js
//   loadOpusDecoder() → Promise<OggOpusDecoder>     // cached singleton; import('https://cdn.jsdelivr.net/npm/ogg-opus-decoder@1.7.3/+esm')
//   decodeOggOpus(uint8) → Promise<{ channelData: Float32Array[], sampleRate:number }>  // decoder.ready → decodeFile(uint8) → {channelData, sampleRate}

// sg-wav-encoder.js
//   encodeWav({ channelData, sampleRate }) → Blob   // pure-JS RIFF/16-bit PCM, no deps
```

**Why `ogg-opus-decoder` (eshaz `wasm-audio-decoders`) — recommended library:**
- **Safari coverage (the whole point).** Decodes Ogg/Opus → Float32 PCM purely in WASM, independent of the browser's media stack — so it works where `decodeAudioData` fails (Safari/iOS). This is what unblocks the #1 use case on every browser.
- **No-build-step fit.** Single self-contained minified JS file with the **WASM binary inlined** (yEnc-encoded + DEFLATE-compressed inside the JS) → loadable as-is via a plain dynamic `import()` from jsDelivr `/+esm`, **exactly the JSZip lazy-load pattern already in the repo**. Crucially this means **no separate `.wasm` fetch, no Web Worker, no SharedArrayBuffer, no COOP/COEP headers** — it decodes on the main thread. That sidesteps the entire class of bugs the team already hit with ffmpeg.wasm (the cross-origin-Worker failure documented in `…/03/28/v0.1.5__debrief__video-tools-ffmpeg-wasm-cross-origin-bug.md`).
- **Size/perf.** Hundreds of KB (single-purpose Opus decoder), vs ffmpeg.wasm's ~10–30 MB core. Lazy-loaded only when tier-3 is reached, so the common case (already-supported file, or Chrome/FF native decode) pays **zero** bytes.
- **License.** Wrapper is **MIT**; underlying decoder is libopus (**BSD-3-Clause**). Both permissive — fine for tools.sgraph.ai. Confirmed.
- **Output.** `decodeFile(uint8)` → `{ channelData:[Float32Array], samplesDecoded, sampleRate }` (48 kHz default) — feeds the existing WAV encoder directly. WAV is universally accepted by OpenRouter audio models, removing the per-model `ogg`-acceptance gamble.

**Options considered and rejected:**
- **ffmpeg.wasm** — universal ("convert anything") but ~10–30 MB, slow cold-start, needs a Worker + (for `-mt`) SharedArrayBuffer behind COOP/COEP headers — a real concern on S3+CloudFront, and the repo already has an **open, documented cross-origin-Worker bug** with it (`video-tools` debrief). Massive overkill for one codec. Keep as the future "convert truly-anything" path only.
- **Reuse `sg-whisper`'s loader** — it loads **transformers.js**, not an audio codec, and its `blobToFloat32Array` is the same Safari-blind `decodeAudioData`. Nothing reusable for Opus.
- **`decodeAudioData`-only fallback (v0.2.63's approach)** — fails on Safari for Opus → hard-stop. Rejected; that is the exact bug this revision fixes.

**Recording side (unchanged):** still record as `audio/mp4` where `MediaRecorder.isTypeSupported('audio/mp4')` (Safari/iOS, already a tier-1 supported format), else webm→WAV via the same `core/sg-audio-decode.blobToWav` path.

> **Open dependency for the human (D-6, §11):** `core/sg-audio-decode` lazy-loads the `ogg-opus-decoder` WASM from **jsDelivr CDN** (`@1.7.3/+esm`). This matches the established repo pattern (JSZip, ffmpeg, transformers.js all CDN-loaded) and keeps the binary out of the repo, but it is a **third-party CDN fetch at runtime** (a network/offline/supply-chain consideration). Because the WASM is inlined in the JS module, a self-hosted alternative is trivial: vendor the single `dist/ogg-opus-decoder.min.js` under `core/sg-audio-decode/v0/v0.1/v0.1.0/vendor/` (pinned, same-origin, immutable) and import it relatively. **No user audio is ever sent to the CDN — only the decoder code is fetched; all decoding is in-browser, so the no-data-exfiltration rule holds either way.** Human to confirm CDN-pinned vs vendored same-origin.

**Phase 2 (optional, future): `core/sg-or-transcribe/v0/v0.1/v0.1.0/sg-or-transcribe.js`** — a small pure-JS client for OpenRouter's dedicated `POST https://openrouter.ai/api/v1/audio/transcriptions` endpoint (`Authorization: Bearer`, JSON body `{ model, input_audio:{ data:<base64>, format }, language? }`, returns `{ text, usage }`). This endpoint returns word-accurate transcripts from true STT models (whisper-large-v3, gpt-4o-transcribe, gpt-4o-mini-transcribe, Google Chirp) and reports `usage.cost`/`seconds`. Proposed signature:

```js
export async function transcribeAudio({ apiKey, model, dataBase64, format, language, signal })
  // → { text, cost, seconds }
```

This is **not** required for the MVP because `sg-llm-request`'s chat path already reaches audio-capable chat models. It is the cleaner long-term home for "true STT" and would let the tool offer both an LLM-chat mode and a dedicated-STT mode. Flag for the human (§11).

The two Whisper/transcribe models in §7 stay gated/"coming soon" until that module lands.
3. **Long-audio chunking → OUT OF SCOPE for v1.** No segment-split-and-stitch in the first release. Apply a soft **max-file-size cap per item** (suggest ~25 MB; large WAV base64 inflates the request ~33%) and reject/​warn above it with a clear message. Record as `audio/mp4` where `MediaRecorder.isTypeSupported('audio/mp4')`, otherwise re-encode webm→WAV via AudioContext (§6). Document the size/length limit in `SKILL__human.md`.
4. **sg/send mechanism → EMBEDDED send component.** Reuse the existing **`<sg-send-drop>`** component (`components/send-drop/v1/v1.0/v1.0.0/sg-send-drop.js`) in-page to perform the encrypted upload — NOT a deep-link hand-off. The send glue (`api/api-send.js`) builds the bundle and calls `dropper.offerFile(blob, name)`, resolving on `sg-send-complete` with the **share URL**. *Code-verified: the embed component EXISTS and already performs token → SGMETA → AES-256-GCM → 3-step upload via `core/send-crypto/.../sg-send-upload.js`, and is already embedded by infographic-gen / PlaybookLM / folder-editor.* **OPEN RUNTIME DEPENDENCY (not new code, flag for human):** the component needs (i) a **live send.sgraph.ai API** (auto-detected: `send.sgraph.ai` / `dev.` / `main.`) and (ii) an **access token** entered by the user (or in `localStorage['sgraph-send-token']`). This repo does not contain the send server/auth — by design send.sgraph.ai is a *consumer* of this repo. Dev must verify the send flow end-to-end against `dev.send.sgraph.ai` with a real token, and the SKILL/UX must make the "you need a SG/Send access token" requirement explicit.
5. **ZIP bundle contents → BOTH audio + transcripts, USER-SELECTABLE.** The session bundle (`downloadZip` / the same blob fed to `sendViaSgSend`) can contain **both the original audio files and the transcripts** (`.txt`/`.md`), chosen via two include-checkboxes in `ui-bundle.js` (default: transcripts on, audio off). Always include a **manifest** — both `manifest.json` (structured) and a human-readable `index.txt` — listing per item: original filename, model, durationMs, and transcript filename. **Implementation = JSZip CDN lazy-load** (the established repo pattern), copied from `heic-converter/api/api-output.js` into tool-local `api/audio-zip.js`; a pure-JS store-only writer is the documented fallback only (§3 row 8 / †). **No shared zip helper exists in core/ today** — promote `audio-zip.js`→`core/sg-zip` only if a 3rd tool needs the manifest-bundle shape.

6. **`.opus` handling → IN-BROWSER WASM DECODE, NO HARD-STOP (human-directed, supersedes v0.2.63's Safari hard-stop).** `.opus` (and any browser-undecodable format) is converted client-side via a three-tier strategy (§6): (1) pass-through for OpenRouter-accepted formats; (2) native `decodeAudioData`→WAV (Chrome/FF); (3) **WASM Opus decode → WAV** for Safari/Opus or any tier-2 failure. The decoder is the new core module **`core/sg-audio-decode`**, which lazy-loads **`ogg-opus-decoder`** (eshaz `wasm-audio-decoders`, MIT wrapper over BSD libopus) from jsDelivr `/+esm`. The WASM is **inlined in the single JS module** → no separate `.wasm`, no Worker, no SharedArrayBuffer, no COOP/COEP headers (decodes main-thread) → it sidesteps the documented ffmpeg.wasm cross-origin-Worker bug and the COOP/COEP hosting concern on S3+CloudFront. ffmpeg.wasm was **rejected** for this (too heavy at ~10–30 MB, needs a Worker + SAB/headers, and the repo has an open bug with it). **The v0.2.63 `opus-decode-unsupported` Safari hard-stop is REMOVED.** *Sub-decision / open dependency → see (O-4): CDN-pinned WASM vs vendored same-origin binary.*
