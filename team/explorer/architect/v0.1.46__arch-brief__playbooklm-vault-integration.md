# Architecture Brief: PlaybookLM × Vault Integration

**Version:** v0.1.46
**Date:** 15 April 2026
**Role:** Architect (Explorer team)
**Type:** Architecture brief + implementation spec
**Status:** Pre-implementation — approved for build
**Follows:** PlaybookLM v0.1.46 (slide version history, deck view, session archive)

---

## 1. Goal

Make the vault the **primary session store** for PlaybookLM. Every pipeline step — source load, presentation strategy, slide briefs, each generated image, each regeneration — is committed to an encrypted vault on `send.sgraph.ai`. The browser's `PipelineState` remains the fast working cache; the vault is the durable, shareable, version-controlled record.

Users without a vault key skip all of this and get the current export-only behaviour unchanged.

---

## 2. New component: `sg-vault-manager`

The biggest architectural addition is not specific to PlaybookLM. The need to track multiple vaults, cache keys, and provide a consistent "connect to vault" UX is shared across all tools. This becomes a **platform component** others can reuse.

### Location

```
components/vault/sg-vault-manager/v0/v0.1/v0.1.0/sg-vault-manager.js
```

### Responsibility

- Maintains a **registry of known vaults** in `localStorage['sg-vault-registry']` as an array of `{vaultId, displayName, lastUsed, apiBaseUrl}`. Keys are **never** stored — only vault IDs and display names.
- Provides a compact "connect" UI: dropdown of known vaults + text input for new key + display name input.
- Caches the **derived key material** in `sessionStorage` keyed by vault ID (not the raw passphrase) so re-opening the same vault within a session skips the 150ms PBKDF2 derivation.
- Fires standard events on a `[data-vault-bus]` ancestor:
  - `vault:connected { vault, vaultId, displayName, apiBaseUrl, keys }`
  - `vault:disconnected { vaultId }`
- Handles first-time vault creation transparently: if the user enters a key and the vault's `refFileId` does not exist on the server, it creates the initial commit structure automatically via `vault-write`.

### DOM event bus

Follows the existing `sg-vault-connect` pattern — all events bubble on `[data-vault-bus]`, so the component is decoupled from the tool using it.

### localStorage schema (`sg-vault-registry`)

```json
[
  {
    "vaultId":     "a1b2c3d4",
    "displayName": "Personal Vault",
    "apiBaseUrl":  "https://send.sgraph.ai",
    "lastUsed":    1744900000000
  }
]
```

No passphrase ever stored. The user re-enters on each browser session; key material is cached in `sessionStorage` for the session duration.

## 3. Image compression: `optimizeSlide()` utility

### Location

```
tools/v0/v0.1/v0.1.47/en-gb/playbooklm/api/slide-optimizer.js
```

### What it does

Pure function. Takes a PNG data URL, returns three compressed variants using the Canvas API (no WASM, no libraries). Runs at generation time — immediately after the LLM returns the image.

### Three output variants

| Variant | Key | Max width | JPEG quality | Target size |
|---|---|---|---|---|
| Archive | `png` | original | — (PNG) | ~850 KB |
| Distribution | `dist` | 1200px | 0.82 | ~113 KB |
| Social | `li` | 800px | 0.70 | ~50 KB |

Numbers from the compression briefing (15 Apr 2026): 87% reduction PNG→JPEG q82; a 107-slide deck drops from 116 MB to 14.8 MB.

### Signature

```js
/**
 * @param {string} imageSrc - PNG data URL from LLM
 * @returns {Promise<{
 *   png: string,       // original data URL (kept for in-memory display)
 *   dist: Blob,        // JPEG 1200px q0.82 — vault + PDF
 *   li: Blob,          // JPEG 800px q0.70 — social sharing
 *   sizes: { png: number, dist: number, li: number }
 * }>}
 */
export async function optimizeSlide(imageSrc) { ... }
```

### Where it's called

In `pipeline-steps.js`, immediately after `_callImageLLM()` resolves and before `state.addSlideVersion()`. The `dist` blob is what gets written to vault and used in PDF export. The `png` data URL is kept in `PipelineState` for the fractal workspace display (full fidelity). The `li` blob is used for the SG/Send share.

## 4. `PipelineState` additions (v0.1.3)

### New top-level fields

```js
/** @type {object|null} Open vault object ({keys, apiBaseUrl, vaultId}) */
this._vault = null;

/** @type {string|null} Current deck's folder ID in vault */
this._vaultDeckId = null;

/** @type {string} Vault storage profile */
this._vaultProfile = 'full'; // 'full' | 'distribution' | 'minimal'

/** @type {number} Count of pipeline changes not yet committed to vault */
this._vaultPendingChanges = 0;

/** @type {string|null} Display name for current deck */
this._deckTitle = null;
```

### `SlideVersion` typedef additions

```js
/**
 * @typedef {object} SlideVersion
 * @property {string} imageSrc      - PNG data URL (in-memory display)
 * @property {Blob}   distBlob      - JPEG 1200px q82 (vault + PDF export)
 * @property {Blob}   liBlob        - JPEG 800px q70 (social)
 * @property {{png:number, dist:number, li:number}} sizes - bytes per variant
 * ... (existing fields unchanged)
 */
```

### New methods

```js
setVault(vault, deckId)           // stores vault + deck, resets pending count
get vault()                        // returns _vault
get vaultDeckId()                  // returns _vaultDeckId
get vaultConnected()               // boolean
get vaultPendingChanges()          // number

setDeckTitle(title)               // sets + notifies
get deckTitle()

incrementPending()                 // +1 pending (after each local write)
clearPending()                     // 0 (after vault commit succeeds)
get vaultProfile()
set vaultProfile(profile)
```

### What `addSlideVersion()` now stores

`addSlideVersion(index, versionData)` receives `distBlob` and `liBlob` alongside the existing fields. These are stored in `_slideVersions` and used by `vault-ops` for upload. They are NOT included in `getFullState()` (blobs aren't JSON-serialisable).

## 5. New module: `api/vault-ops.js`

### Location

```
tools/v0/v0.1/v0.1.47/en-gb/playbooklm/api/vault-ops.js
```

### Responsibility

All vault read/write logic isolated here. `pipeline-steps.js` and UI panels call into this; nothing else touches vault APIs directly.

### Vault folder structure it manages

```
playbooklm/
└── decks/
    └── {deck-id}/
        ├── deck.json
        ├── presentation-strategy.md
        ├── slide-briefs.json
        ├── sources/
        │   └── {filename}
        └── slides/
            └── {nn}-{slug}/
                ├── versions.json
                ├── selected.txt
                ├── v{n}.png          (if profile = 'full')
                ├── v{n}-dist.jpg     (always)
                └── v{n}-li.jpg       (always)
```

### `deck.json` schema

```json
{
  "schema":           "playbooklm-deck-v1",
  "id":               "a1b2c3d4",
  "title":            "Climate Tech Investment 2026",
  "createdAt":        "2026-04-15T11:30:00Z",
  "updatedAt":        "2026-04-15T14:05:00Z",
  "textModel":        "anthropic/claude-sonnet-4-6",
  "imageModel":       "google/gemini-3.1-flash-image-preview",
  "slideCount":       8,
  "sessionCost":      0.3225,
  "deckCost":         0.3919,
  "vaultProfile":     "full",
  "selectedVersions": { "0": 1, "1": 0 }
}
```

### Exported functions

```js
// Create a new deck folder in vault. Returns deckId.
export async function createDeck(vault, { title, state })

// Restore full PipelineState from vault. Returns { slideCount, versionCounts }.
export async function loadDeck(vault, deckId, state)

// List all PLM decks in vault. Returns [{id, title, updatedAt, slideCount, cost}].
export async function listDecks(vault)

// Write sources to vault + commit. Returns commitId.
export async function saveSources(vault, deckId, state, { message })

// Write presentation strategy + commit.
export async function savePresentation(vault, deckId, state, { message })

// Write slide briefs + commit.
export async function saveSlideBriefs(vault, deckId, state, { message })

// Write one slide's new version images + updated versions.json + commit.
// Respects vaultProfile for PNG inclusion.
export async function saveSlide(vault, deckId, state, slideIndex, { message })

// Update deck.json (cost, selectedVersions, title) + commit.
export async function saveDeckMeta(vault, deckId, state, { message })
```

### Commit message convention

```
PLM/{deck-title}/{step}: {description} (model, $cost, Xs)

Examples:
  PLM/Climate Tech/init: deck created
  PLM/Climate Tech/step2: presentation strategy (sonnet-4-6, $0.012, 8s)
  PLM/Climate Tech/step3: 8 slide briefs (haiku-4.5, $0.004, 3s)
  PLM/Climate Tech/slide3-v1: Capital Allocation (gemini-flash, $0.04, 22s)
  PLM/Climate Tech/slide3-v2: custom brief — EU taxonomy angle ($0.04, 19s)
```

## 6. `pipeline-steps.js` changes (v0.1.6)

### `generateSlide` additions

After `_callImageLLM` resolves:

1. Call `optimizeSlide(imageSrc)` → `{ png, dist, li, sizes }`
2. Pass `distBlob` and `liBlob` into `state.addSlideVersion()`
3. If `state.vaultConnected`, call `vaultOps.saveSlide(...)` with a built commit message
4. `state.incrementPending()` if vault write is skipped (vault not connected)

### `exportDeck` changes

- PDF export now uses `dist` JPEG blobs from `SlideVersion` instead of raw PNG data URLs
- Archive ZIP: writes `v{n}-dist.jpg` and `v{n}-li.jpg` alongside `v{n}.png`

A persistent status bar **above the stepper** (below the OpenRouter connect bar) showing:

```
🔒 Vault: Personal Vault  ·  Deck: "Climate Tech 2026"  ·  ● Saved  [⚙]
```

States:
- `● Saved` (green) — vault in sync
- `⚠ 3 unsaved changes` (amber) — pending commits; click to save now
- `✗ Vault sync failed` (red) — last commit failed; retry button
- `○ No vault` (grey) — running without vault

The `[⚙]` button opens a small deck config popover:
- Deck title (editable)
- Vault storage profile: Full archive / Distribution / Minimal
- "Disconnect vault"

## 12. Resolved design decisions

| Decision | Resolution |
|---|---|
| PNG save default | Yes — save PNG by default; opt-out in deck config (not a modal) |
| Auto-save triggers | After step 2, step 3, each slide generation. NOT on brief edits (local-only until next explicit save trigger) |
| Unsaved indicator | Amber "⚠ N unsaved changes" in vault status bar; click-to-save |
| Deck identity | Random 8-char hex (crypto.getRandomValues). User can set a display name, stored encrypted in vault tree. |
| Vault creation | If user provides a key and vault doesn't exist on server, create it automatically (first `writeVaultFile` call initialises the tree) |
| Multi-vault registry | `sg-vault-manager` component tracks known vaults in `localStorage['sg-vault-registry']` (vault IDs + display names only, no keys) |
| Key caching | Raw passphrase: never stored. Derived key bytes: `sessionStorage['sg-vault-keys-{vaultId}']` (cleared on tab close) |
| Offline fallback | Increment `_vaultPendingChanges`, show amber indicator, retry on next save trigger. No data lost — full state recoverable from PipelineState. |
| PDF images | Switch to `dist` JPEG blobs from generation time onward (87% smaller, visually indistinguishable for slides) |
| Archive ZIP images | Include all three variants (`v{n}.png`, `v{n}-dist.jpg`, `v{n}-li.jpg`) |

## 13. Out of scope for v0.1.47

- Vault branching (deck forks/variants on separate vault branches)
- Collaborative real-time sync (vault is append-only; no conflict resolution)
- Vault key rotation
- Simple Token sharing of deck snapshots (vault already supports this; surfacing it in PLM UI is a future step)
- Standalone compression tool (briefed separately in `briefing-image-pdf-compression.md`)
