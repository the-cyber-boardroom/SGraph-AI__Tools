## One-Line Summary

A full-screen browser tool that lets you enter a vault key (or simple token), browse its file tree, open files for decrypted preview, and trace every network event — all with zero server-side processing.

---

## What Exists After This Session

### Layout

The tool is a two-column full-height page using two `sg-layout` instances:

| Column | Content |
|--------|---------|
| Left (300px fixed, internally resizable) | Top: Credentials panel + setup form. Bottom: Vault file tree. |
| Right (flex) | Tab stack: Trace panel + one tab per opened file. |

Both columns are managed by `sg-layout`, giving resize handles and collapse buttons out of the box. Left column uses a `type: 'column'` layout with two stacked stacks; right uses a `type: 'stack'` where file tabs are added dynamically.

### Credential Entry

The setup form (left panel) accepts three input modes:

1. **Simple token** — `word-word-NNNN` (e.g. `dish-hold-5532`). The entire token is the secret. Vault ID is derived as `SHA-256(token)[:12 hex]`. Read key derived via `PBKDF2 → HKDF('vault-read-key')`.
2. **Full vault key** — `passphrase:vaultId`. Standard `parseVaultKey` + `deriveVaultKeys` from `sg-vault-client`.
3. **Manual** — separate Vault ID + Read Key (base64url) fields in an expandable `<details>` section. Endpoint field also here.

The primary Vault Key field is always visible. The Load Vault button is always visible immediately below it. Manual entry lives in a `<details>` that is collapsed by default.

### Vault History

After any successful vault load, the vault ID, read key, and endpoint are stored in `localStorage` under `sg-vault-embed-demo-v1__history`:

- Deduped by vault ID (latest entry wins)
- Capped at 10 entries
- Displayed at the top of the form as "Recent Vaults"
- Single-click: pre-fills manual fields and opens the `<details>`
- Double-click: activates the vault immediately, bypassing the form

A "Switch Vault" button appears in the credentials panel after a vault is loaded, returning to the setup form.

### Vault File Tree

`ved-vault-tree` is a shadow-DOM custom element that:
- Listens for `ved:vault-ready` → calls `openVaultTree()` from `sg-vault-client`
- Renders a collapsible tree with folder expand/collapse
- Highlights the active file
- On file click: dispatches `ved:file-open` with `{ entry, vault }`

### File Viewer

`ved-file-viewer` is a shadow-DOM custom element receiving `state: { entry, vault }` from `sg-layout` via `setLayoutState()`. It:

1. Shows a loading card (spinner + file name, guessed type, download method, blob_id)
2. Fetches via `readObject()` (direct API)
3. If that returns 502/413/504: falls back to presigned S3 URL
4. Decrypts (handled by `readObject` or locally via `decryptAesGcm` for presigned path)
5. Sniffs MIME type from magic bytes + extension
6. Renders with a metadata bar (blob_id, storage path, full API URL, MIME, size, load time, read-only badge)

### Supported File Types

| Type | Rendering |
|------|-----------|
| PDF (`application/pdf`) | Full-height `<iframe>` with blob URL |
| Images (PNG, JPEG, GIF, WebP) | `<img>` with blob URL |
| Markdown | Rendered via `sg-markdown.js` with styled `.md-body` |
| JSON / `_page.json` | Pretty-printed `<pre>`, or full `PageLayoutRenderer` for page schema |
| Text / JS / CSS / shell | `<pre>` with monospace styling |
| Binary | Size + MIME message |

### Trace Panel

`sg-vault-trace` (from the existing component library) is wired to receive `sg-vault-fetch:*` events dispatched on `document`:

- `fetch-started` — fired before the request, with URL
- `fetch-completed` — fired after, with bytes + timing
- `decrypt-completed` — fired after decryption
- `content-ready` — fired with final MIME type
- `fetch-error` — fired on failure

These are dispatched by both `ved-vault-tree` (on vault open) and `ved-file-viewer` (on each file load).
