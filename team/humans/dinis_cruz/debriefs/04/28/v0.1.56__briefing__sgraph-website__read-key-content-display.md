# Briefing: How to Display Vault Content on the sgraph.ai Website Using Read Keys

**Version:** v0.1.56
**Date:** 28 April 2026
**From:** Tools Team
**To:** sgraph.ai website team
**Type:** Technical briefing — integration pattern

## What This Document Covers

This document explains how to embed encrypted vault content on any sgraph.ai web page using only a read key. It covers the two key formats, the derivation chain, the API calls required, and the decryption + rendering steps — with working code snippets from the vault-embed-demo reference implementation.

---

## Background: What a Vault Is

A vault is a collection of encrypted files stored on `send.sgraph.ai`. All content is encrypted client-side before upload using AES-256-GCM. The server never sees plaintext. To read vault content, you need:

1. **Vault ID** — a 12-character hex string that identifies the vault on the server
2. **Read Key** — a 32-byte AES-256-GCM key (transported as base64url), used to decrypt content and derive file IDs via HMAC-SHA-256

You do **not** need a write key, passphrase, or server session to display content. The read key alone is sufficient.

## Part 1: Getting the Read Key

There are two vault key formats in use. Both produce a vault ID + read key pair — the only difference is how you compute them.

### Format A: Simple Token (`word-word-NNNN`)

Vaults created via send.sgraph.ai or `sg-key-generator` use a friendly token like `dish-hold-5532`. The token is the single secret.

**Derivation (runs in the browser, ~600ms for PBKDF2):**

```js
async function deriveReadKeyFromSimpleToken(token) {
    const enc      = new TextEncoder()
    const tokenLow = token.toLowerCase().trim()

    // Step 1: PBKDF2 → 256-bit intermediate
    const keyMat = await crypto.subtle.importKey(
        'raw', enc.encode(tokenLow), 'PBKDF2', false, ['deriveBits']
    )
    const aesKeyBits = await crypto.subtle.deriveBits(
        { name: 'PBKDF2', salt: enc.encode('sgraph-send-v1'), iterations: 600_000, hash: 'SHA-256' },
        keyMat, 256,
    )

    // Step 2: HKDF → read key bytes
    const hkdfKey = await crypto.subtle.importKey('raw', aesKeyBits, 'HKDF', false, ['deriveBits'])
    const readBits = await crypto.subtle.deriveBits(
        { name: 'HKDF', hash: 'SHA-256', salt: new Uint8Array(0), info: enc.encode('vault-read-key') },
        hkdfKey, 256,
    )

    // Step 3: Vault ID = SHA-256(token)[:12 hex chars]
    const hashBuf = await crypto.subtle.digest('SHA-256', enc.encode(tokenLow))
    const vaultId = Array.from(new Uint8Array(hashBuf))
        .map(b => b.toString(16).padStart(2, '0')).join('').slice(0, 12)

    return { vaultId, readKeyBytes: new Uint8Array(readBits) }
}
```

### Format B: Full Vault Key (`passphrase:vaultId`)

Some vaults use an explicit vault ID in the key string. Import from `sg-vault-client`:

```js
import { parseVaultKey, deriveVaultKeys }
    from 'https://tools.sgraph.ai/core/vault-client/v1/v1.2/v1.2.2/sg-vault-client.js'

const { passphrase, vaultId } = parseVaultKey('my-passphrase:abc12345')
const keys = await deriveVaultKeys(passphrase, vaultId)
// keys.vaultId, keys.readKeyBytes, keys.readKey (CryptoKey)
```

### Format C: Pre-computed Read Key (hardcoded for public content)

If you want to embed specific vault content publicly on the website, pre-derive the read key (offline, once) and hardcode it as a base64url string. The website user never sees the passphrase.

```js
// Hardcoded for the "Getting Started" vault
const VAULT_ID  = 'a1b2c3d4e5f6'
const READ_KEY  = 'base64url-encoded-32-byte-read-key-here'
```

## Part 2: Opening the Vault

Once you have `vaultId` and `readKeyBytes`, use `sg-vault-client` to build a vault handle and open the file tree:

```js
import {
    importReadKey, deriveFileIdHex, openVault, openVaultTree, SALT_PREFIX
} from 'https://tools.sgraph.ai/core/vault-client/v1/v1.2/v1.2.2/sg-vault-client.js'
import { formatFileId }
    from 'https://tools.sgraph.ai/core/vault-client/v1/v1.2/v1.2.2/vault-id-utils.js'

async function openVaultFromReadKey(vaultId, readKeyBytes, apiBaseUrl = 'https://send.sgraph.ai') {
    const readKey = await crypto.subtle.importKey(
        'raw', readKeyBytes, { name: 'AES-GCM' }, false, ['decrypt']
    )

    // Derive all HMAC-based file IDs
    const [refHex, indexHex, branchIndexHex, settingsHex] = await Promise.all([
        deriveFileIdHex(readKeyBytes, `${SALT_PREFIX}:file-id:ref:${vaultId}`),
        deriveFileIdHex(readKeyBytes, `${SALT_PREFIX}:file-id:index:${vaultId}`),
        deriveFileIdHex(readKeyBytes, `${SALT_PREFIX}:file-id:branch-index:${vaultId}`),
        deriveFileIdHex(readKeyBytes, `${SALT_PREFIX}:file-id:settings:${vaultId}`),
    ])

    const keys = {
        vaultId,
        readKey,
        readKeyBytes,
        refFileId:         formatFileId('ref', 'pid', 'muw', refHex),
        indexFileId:        formatFileId('idx', 'pid', 'muw', indexHex),
        branchIndexFileId: formatFileId('idx', 'pid', 'muw', branchIndexHex),
        settingsFileId:    formatFileId('idx', 'pid', 'muw', settingsHex),
    }

    return openVault(keys, { apiBaseUrl })
}

// Usage
const vault = await openVaultFromReadKey(vaultId, readKeyBytes)
const { entries } = await openVaultTree(vault)
// entries = [{ name: 'README.md', blob_id: 'obj-cas-imm-...', ... }, ...]
```

## Part 3: Reading a Specific File

To read a file by its `blob_id` from the tree:

```js
import { readObject }
    from 'https://tools.sgraph.ai/core/vault-client/v1/v1.2/v1.2.2/sg-vault-client.js'

// buf = ArrayBuffer of decrypted plaintext
const buf = await readObject(vault.apiBaseUrl, vault.keys.vaultId, blob_id, vault.keys.readKey)
const text = new TextDecoder().decode(buf)
```

`readObject` handles the fetch, IV extraction, and AES-256-GCM decryption internally. No extra steps.

### Large Files (> ~4MB)

For files that exceed API gateway limits, use the presigned S3 URL endpoint:

```js
async function readLargeFile(vault, blobId) {
    const { vaultId, readKey } = vault.keys
    const path = `bare/data/${blobId}`
    const presignedUrl = `${vault.apiBaseUrl}/api/vault/presigned/read-url/${vaultId}/${encodeURIComponent(path)}`

    const resp = await fetch(presignedUrl)   // no auth headers needed
    const { url } = await resp.json()

    const s3 = await fetch(url)              // plain GET to S3
    const encrypted = await s3.arrayBuffer()

    // S3 response is still AES-256-GCM encrypted (IV = first 12 bytes)
    const enc = new Uint8Array(encrypted)
    const iv  = enc.slice(0, 12)
    return crypto.subtle.decrypt({ name: 'AES-GCM', iv }, readKey, enc.slice(12))
}
```

## Part 4: Common Rendering Patterns for the Website

### Render Markdown

```js
import { renderMarkdown }
    from 'https://tools.sgraph.ai/core/markdown/v1/v1.0/v1.0.0/sg-markdown.js'

const buf  = await readObject(vault.apiBaseUrl, vaultId, blobId, vault.keys.readKey)
const text = new TextDecoder().decode(buf)
const html = renderMarkdown(text)

const container = document.getElementById('content')
container.innerHTML = html
```

### Render a _page.json Page

`_page.json` files follow the schema `{ theme: {...}, components: [...] }` and are rendered by `PageLayoutRenderer` served from send.sgraph.ai:

```js
// Load the renderer (once per page)
await new Promise((resolve, reject) => {
    const s = document.createElement('script')
    s.src = 'https://send.sgraph.ai/_common/js/page-layout-renderer.js'
    s.onload = resolve
    s.onerror = reject
    document.head.appendChild(s)
})

// Inject the CSS (required — PageLayoutRenderer needs its own stylesheet)
const cssResp = await fetch('https://send.sgraph.ai/_common/js/components/send-download/send-browse-v031--page-layout.css')
const style = document.createElement('style')
style.textContent = await cssResp.text()
document.head.appendChild(style)  // or into a shadow root if needed

// Fetch and render
const buf  = await readObject(vault.apiBaseUrl, vaultId, blobId, vault.keys.readKey)
const json = JSON.parse(new TextDecoder().decode(buf))

PageLayoutRenderer.render(
    document.getElementById('content'),   // container element
    json,                                 // parsed _page.json
    '',                                   // base URL (empty = no link rewriting)
    null,                                 // browseStub (null = no navigation)
    null,                                 // modal stub (null = no modals)
)
```

**Note on shadow DOM:** If your container is inside a shadow root, `document.head` CSS won't apply. Fetch the CSS text and inject it into the shadow root as a `<style>` element instead.

### Display an Image

```js
const buf  = await readObject(vault.apiBaseUrl, vaultId, blobId, vault.keys.readKey)
const blob = new Blob([buf], { type: 'image/png' })  // or sniff MIME from magic bytes
const url  = URL.createObjectURL(blob)

const img = document.createElement('img')
img.src = url
document.getElementById('content').appendChild(img)
// Call URL.revokeObjectURL(url) when done
```

### Display a PDF

```js
const buf  = await readObject(vault.apiBaseUrl, vaultId, blobId, vault.keys.readKey)
const blob = new Blob([buf], { type: 'application/pdf' })
const url  = URL.createObjectURL(blob)

const iframe = document.createElement('iframe')
iframe.src   = url
iframe.style.cssText = 'width:100%;height:600px;border:none;'
document.getElementById('content').appendChild(iframe)
```

## Part 5: Knowing Which File to Load

### Option A: Load by known blob_id

If you know the blob_id of the file you want (e.g. from a manifest or hardcoded), call `readObject` directly. No tree walk needed.

### Option B: Walk the tree and find by name

```js
const { entries } = await openVaultTree(vault)

function findFile(entries, name) {
    return entries.find(e => e.name === name && e.blob_id)
}

const readme = findFile(entries, 'README.md')
if (readme) {
    const buf = await readObject(vault.apiBaseUrl, vaultId, readme.blob_id, vault.keys.readKey)
    // ...
}
```

### Option C: Public manifest file

Keep a `_manifest.json` in the vault root that lists all intended public files with their names and blob IDs. Read the manifest first, then fetch whichever file the page needs. This avoids walking the full tree on every page load.

## Security Notes

| Concern | Answer |
|---------|--------|
| Does the server see plaintext? | No. All decryption is client-side, in the browser. |
| Is the read key in the page source? | Only if you hardcode it (Format C). For user-entered tokens, it lives only in memory. |
| Can a read key be used to write to the vault? | No. Read and write keys are derived independently via HKDF and are different keys. |
| What does a read key give access to? | All files in the vault — there is no per-file access control. |
| Is localStorage safe for read keys? | Acceptable for demo tools, not recommended for production. Use `sessionStorage` or re-derive on each load. |
| HTTPS required? | Yes. Web Crypto API requires a secure context. |
