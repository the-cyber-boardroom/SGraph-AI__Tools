## Immediate: Test the End-to-End Loop

The pipeline is wired but not yet tested with real tool execution. The first thing to verify at `http://localhost:10063/en-gb/agent-with-tools/`:

1. Bridge connects (green dot)
2. User asks "list the files in /workspace"
3. **Pipeline panel** cycles EXTRACT → VALIDATE → QUEUE → EXECUTE → DONE
4. **Queue panel** shows the `lb_list_folder` card (auto mode = instant, manual = awaiting approve)
5. **Tracer panel** shows the full event sequence
6. LLM receives the file list and gives a final text response

Likely blockers to investigate:

| Symptom | Likely cause |
|---|---|
| Queue shows card but execution hangs | `sg-tool-runner` not recognising `lb_*` tool names (it only has VFS builtins by default; `sg-local-bridge` registers lb_* on connect — check timing) |
| No tool calls generated at all | Qwen 2.5 Coder 7B may not reliably do native function calling; check model in Ollama (`qwen2.5-coder:7b` supports it but smaller context may confuse it) |
| Loop doesn't continue after tool result | `aw-loop-coordinator` not seeing `llm:tool-results-complete` — check it's inside `[data-llm-bus]` and its `_bus()` walks correctly |
| Duplicate tool execution | Both native `llm:tool-calls` from `sg-llm-request` and text-extracted ones from `aw-tool-extractor` fire — add dedup guard |

## Next Features (Priority Order)

### N1 — Manual mode UX hardening

`aw-execution-inspector` manual mode is built but needs real use-testing. Key gaps:
- The capture-phase interceptor for `llm:tool-calls` needs to not block `llm:tool-calls` events that have `_fromInspector = true` (already flagged, but verify)
- Should show a "⏸ Waiting for approval" badge in the Pipeline panel when manual mode holds a pack
- Consider a keyboard shortcut (Enter = Run All, Escape = Skip All)

### N2 — Tool result display in chat

Currently the LLM's final answer after tool use appears in chat, but the intermediate tool results don't. Options:
- Add a collapsible "tool results" section in the chat bubble after tool execution
- Or show results only in the Queue panel cards (already done) and keep chat clean

### N3 — Model compatibility layer

Qwen 2.5 Coder is the default. Some smaller Ollama models won't do native function calling. The `aw-tool-extractor` code-block fallback handles `lb_fn(args)` syntax but the system prompt needs to be model-aware:

- For native-capable models: use the `tool_calls` API (current)
- For text-only models: instruct them to output `lb_fn(args)` syntax and rely on the regex extractor

Add a "mode" attribute or auto-detect based on whether tool_calls come back empty after multiple tries.

### N4 — Error recovery

When a tool call fails (bridge offline, bad args, permission denied):
- `sg-local-bridge` fires `sg-local-bridge:error`
- The Queue card should show the error inline
- `aw-loop-coordinator` should re-send to LLM with the error context so it can retry or explain

### N5 — Multi-step task visibility

The loop coordinator handles multi-step correctly but there's no summary view. Consider:
- A "Session summary" at the end of an agentic run: N tool calls, M iterations, files touched, commands run
- The Tracer panel gives the raw data; a summary component would make it human-readable

### N6 — Agentic mode vs Chat mode toggle

Currently everything goes through `sg-llm-chat-history` → `llm:send`. For long agentic tasks the user may want to switch to a mode where:
- The chat input sends to `sg-agentic-loop.start()` directly (proper loop orchestration with human approval)
- Or keeps the current simple chat → tool → loop → response flow

The `sg-agentic-loop` component is already on the page (unused). Wiring it in as an optional mode would be straightforward.

### N7 — Reality doc update

`team/explorer/librarian/reality/` hasn't been updated for the new components. The Librarian should run a pass to add:
- `aw-tool-extractor`, `aw-execution-inspector`, `aw-step-tracer`, `aw-pipeline-view`, `aw-loop-coordinator` to the tools section
- Update the agent-with-tools entry to reflect the full pipeline

## Key Decisions Still Open

| Decision | Options | Recommendation |
|---|---|---|
| Default execute mode | Auto (current) vs Manual | Keep Auto default; document how to switch |
| Loop limit | 10 iterations (current default) | Fine for now; expose in UI later |
| Tool call format | Native function calling vs text | Native first; text extractor as fallback |
| System prompt editing | Applied per-session (current) | Consider saving to localStorage |
| Bridge auth | None (current, localhost only) | Add token auth before exposing on network |
