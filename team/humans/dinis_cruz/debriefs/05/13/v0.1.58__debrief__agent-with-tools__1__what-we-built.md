## One-Line Summary

A browser-based autonomous agent that chats with a local LLM (Ollama / OpenRouter), executes real file-system and bash tools via a Docker bridge, and shows the full extraction→validation→queue→execute→result pipeline with live visibility at every step.

---

## Starting Point

The tool existed as a skeleton: layout, chat UI, bridge connection, and headless engines (`sg-llm-request`, `sg-tool-runner`, `sg-local-bridge`, `sg-agentic-loop`) were all wired into the DOM. Nothing actually executed. Two bugs blocked progress:

1. **System prompt ignored** — The LLM responded as "Qwen" regardless of what the system prompt said.
2. **Tool calls never executed** — The LLM described tools as text (`lb_list_folder(".")` in a code block) instead of calling them, because `llm:send` never carried a `tools:[]` array.

---

## What Was Built This Session

### Bug Fix 1 — System Prompt (commit `93cec67`)

**Root cause:** `sg-llm-chat-history` owns the `llm:send` path and assembles the messages array (including the system turn). It reads `_systemPrompt` from its HTML attribute on connect — which is always empty. It never listened for `llm:system-prompt` bus events.

Additionally, `agent-with-tools-api.js` dispatches `llm:system-prompt` during `_loadSystemPrompt()`, which runs *before* `sg-layout` async-creates the panel tree containing `sg-llm-chat-history`. The event fired too early and was missed.

**Fix (2 additions to `api/agent-with-tools-api.js`):**
- A permanent `llm:system-prompt` bus listener that calls `bus.__sgLlmChatHistory?.setSystemPrompt(content)` — handles both boot and when the user clicks Apply.
- A one-time `aw-chat-pane:ready` listener that re-fires `_pushSystemTurn()` once `sg-layout` has mounted the panel tree and `sg-llm-chat-history` is connected.

### P1 — Tool Injection Middleware (commit `d4dea6a`)

**Root cause:** `sg-llm-chat-history` fires `llm:send` without a `tools:[]` field, so Ollama never enters function-calling mode.

**Fix:** A capture-phase `llm:send` interceptor in `api.js`:
- Stops the original event (before `sg-llm-request` sees it)
- Gets the active tool schemas from `sg-tool-definition.getActiveTools()`
- Re-fires `llm:send` with `tools:[]` and `tool_choice:'auto'`
- `_toolsInjected` flag prevents recursion

**Also:** `LB_TOOL_SCHEMAS` array defines JSON schemas for all 6 `lb_*` tools. Registered in `sg-tool-definition` via `addTool()` once the bridge connects — so they appear in the Tools panel with enable/disable checkboxes.

**Also removed:** The old inline JSON-in-content shim (replaced by `aw-tool-extractor`, P2).

### P2 — `aw-tool-extractor` (headless, commit `f5995c1`)

Multi-format tool call extraction with visibility events.

- **Native tool_calls** (from `sg-llm-request`): emits `llm:tool-calls-extracted { format:'native', confidence:1.0 }` for the Tracer/Pipeline — no re-dispatch needed.
- **JSON-in-content** `{"tool":"name","parameters":{}}`: emits `llm:tool-calls-extracted` + `llm:tool-calls` to trigger `sg-tool-runner`.
- **Code-block** `lb_fn(args)` regex: same as JSON path, `confidence:0.7`.

Lives in `index.html` as a headless element alongside `sg-agentic-loop`.

### P3 — `aw-execution-inspector` (Queue panel, commit `f5995c1`)

Visual panel showing pending tool calls as cards.

- **Auto mode** (default ON): captures `llm:tool-calls`, shows each call as a card for 4s, lets them pass through to `sg-tool-runner` automatically.
- **Manual mode**: stops `llm:tool-calls` (capture phase), holds packs, shows [Run] / [Skip] per card plus [Run All] / [Skip All]. On approval, re-fires `llm:tool-calls` with `_fromInspector` flag.
- Cards show: tool name, args (collapsed JSON, click to expand), status badge (pending → running → done/error).
- Listens for `sg-local-bridge:tool-call` to mark cards done with result preview.
- Clears on `llm:chat-message` (new user turn).

### P4 — `aw-step-tracer` (Tracer panel, commit `f5995c1`)

Timestamped event audit log.

- Traces 12 key bus events across three categories: LLM, Bridge, Tool.
- Each row: `[HH:MM:SS.ms]  event-name  [+]` — click to expand full JSON detail.
- Filter chips per category. Clear button. Auto-scrolls to bottom.
- `llm:request-chunk` (streaming) is throttled to every 10th chunk.

### P5 — `aw-pipeline-view` (Pipeline panel, commit `f5995c1`)

Stage progress indicator: **EXTRACT → VALIDATE → QUEUE → EXECUTE → DONE**

- Each circle lights up when its trigger event fires, dims after 3s.
- Event → stage: `llm:request-complete` / `llm:tool-calls-extracted` / `llm:tool-calls` / `sg-local-bridge:tool-call` / `llm:tool-results-complete`
- Status line below: `last: lb_list_folder · iter 1`

### P6 — `aw-loop-coordinator` (headless, commit `f5995c1`)

Closes the agentic loop without `sg-agentic-loop`.

- On `llm:tool-results-complete { messages }`: increments `_iter`, re-fires `llm:send { messages }` (P1 middleware adds tools again automatically).
- At `max-iterations` ceiling: emits `llm:loop-limit-reached` and stops.
- Resets `_iter` on `llm:chat-message`.
