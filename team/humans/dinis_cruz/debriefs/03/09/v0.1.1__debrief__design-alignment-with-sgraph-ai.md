## Executive Summary

This session delivered two things:

1. **Import path fix** — all 6 files that used relative paths for CSS and shared tokens were switched to absolute domain-root paths (`/components/...`, `/tools/...`). This was needed because CloudFront maps `/` to the S3 prefix, so relative paths break at different page depths.

2. **Design alignment with sgraph.ai** — a new site-header v1.0.1 and tools v0.1.1 that visually match the sgraph.ai website header (same SG/ logo, nav layout, teal accent line, locale picker). The locale picker component (v1.0.0) is now composed into the header via a `<slot name="locale">` — no changes needed to the picker itself.

The key architectural insight: the site-header Web Component now uses **slot composition** so that sgraph.ai, send.sgraph.ai, and tools.sgraph.ai can all share the same header but compose their own locale picker (or omit it). This sets up the path for sgraph.ai to replace its hand-coded header (~130 lines of CSS + the `renderLocaleSelector()` function in i18n.js) with two `<script>` tags.

**IFG versioning applied:** v0.1.0 is now frozen. All new work lives in v0.1.1.

## Key Decisions

| Decision | Why | Alternative Considered |
|----------|-----|------------------------|
| **Slot composition** for locale picker | Keeps header and picker as independent components that compose cleanly. sgraph.ai can use the same header with different nav items and its own picker instance. | Could have made the header internally instantiate the picker — rejected because it couples the two components and makes the header harder to reuse without a picker. |
| **Patch version** (v1.0.1 not v1.1.0) for header | The slot is additive and backward-compatible. Pages not using the slot see no difference. | v1.1.0 would signal a feature bump, but this is really just a non-breaking enhancement. |
| **IFG freeze** on v0.1.0 | Matches the pattern from SG/Send. Once a version ships, it's immutable. New work goes to next patch. | Could have edited v0.1.0 in place — rejected because it violates IFG and breaks pinned consumers. |
| **Absolute paths everywhere** | CloudFront + S3 makes relative paths fragile. `/components/...` always resolves correctly regardless of page depth. | Relative paths work in simple cases but break with nested tool pages (`/en-gb/ssh-keygen/index.html` is 2 levels deeper than landing). |

## sgraph.ai Reuse Plan

The shared components are now ready for sgraph.ai to consume. Here's what would change on the sgraph.ai website:

### Current (sgraph.ai hand-coded)
```html
<!-- 20 lines of header HTML -->
<header class="site-header">
    <div class="container">
        <a href="..." class="site-logo">SG/</a>
        <nav class="site-nav">...</nav>
        <div id="locale-picker"></div>
    </div>
</header>
<!-- ~130 lines of header + locale CSS in style.css -->
<!-- renderLocaleSelector() in i18n.js -->
```

### Proposed (shared components)
```html
<script type="module" src="https://tools.sgraph.ai/components/site-header/v1/v1.0/v1.0.1/sg-site-header.js"></script>
<script type="module" src="https://tools.sgraph.ai/components/locale-picker/v1/v1.0/v1.0.0/sg-locale-picker.js"></script>

<sg-site-header
    home-url="/en-gb/"
    nav-items='[{"label":"Product","href":"./product/"},{"label":"Pricing","href":"./pricing/"},{"label":"Architecture","href":"./architecture/"},{"label":"Team","href":"./agents/"},{"label":"Tools","href":"https://tools.sgraph.ai/tools/v0/v0.1/v0.1.1/en-gb/"}]'>
    <sg-locale-picker slot="locale" locale="en-gb" base-path="/"></sg-locale-picker>
</sg-site-header>
```

### Migration steps for sgraph.ai
1. Replace `<header class="site-header">` block with `<sg-site-header>` element
2. Remove `renderLocaleSelector()` call from `i18n.js` (component handles this)
3. Add "Tools" link to nav-items JSON
4. Remove header + locale CSS from `style.css` (~130 lines: sections 5 + 17)
5. Keep `SgI18n.init()` for translation key application (separate concern)
6. Add CORS headers on tools.sgraph.ai CloudFront for cross-origin module loading
