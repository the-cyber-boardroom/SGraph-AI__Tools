# Brief — LinkedIn Publisher · 4/5 JS API Surface

The contract the next session has to deliver. Every method here is callable both via the UI **and** via `window.__tool['linkedin-publisher'].method(...)` from a Claude Agent or Playwright test. Same SgToolApi pattern as youtube-editor.

---

## Methods

### Auth (3)

| Method | Returns | Notes |
|---|---|---|
| `setClientId({ clientId })` | `{ clientId }` | Persists to `localStorage['sg-linkedin-client-id']`. |
| `connect({ clientId?, silent? })` | `Promise<{ ok }>` | Cache → silent → interactive popup OAuth flow (see brief 2/5). Emits `tool:linkedin:connected`. |
| `disconnect()` | `{}` | Clears the cached token. Doesn't revoke at LinkedIn. |

### Identity + org (3)

| Method | Returns | Notes |
|---|---|---|
| `getMe()` | `Promise<{ id, firstName, lastName, headline, profilePictureUrl }>` | Viewer profile via `r_liteprofile`. |
| `getMyAdminOrganizations()` | `Promise<Array<{ urn, id, name, logoUrl, followerCount? }>>` | Calls LinkedIn's `organizationAcls` endpoint with `role=ADMINISTRATOR`. |
| `setCurrentOrg({ urn })` | `{ urn }` | Persists to `localStorage['sg-linkedin-current-org']`. All subsequent post operations target this org. |

### Posts (5)

| Method | Returns | LinkedIn endpoint | Cost (rate-limit units) |
|---|---|---|---|
| `createTextPost({ commentary, visibility?, isReshareDisabledByAuthor? })` | `Promise<{ urn }>` | `POST /rest/posts` with `lifecycleState: PUBLISHED` | 1 |
| `createArticlePost({ commentary, sourceUrl, title, description, thumbnailUrn? })` | `Promise<{ urn }>` | `POST /rest/posts` with `content.article` | 1 |
| `listOrgPosts({ pageSize?, pageToken? })` | `Promise<{ items, nextPageToken }>` | `GET /rest/posts?author=<urn>` | 1 / page |
| `getPost({ urn })` | `Promise<post>` | `GET /rest/posts/{encoded_urn}?viewContext=AUTHOR` | 1 |
| `uploadImage({ blob })` | `Promise<{ urn }>` | LinkedIn 2-step image upload (initialize → PUT bytes) | varies |

`createArticlePost` accepts `thumbnailUrn` — if absent, post will use whatever LinkedIn auto-generates from the URL. To use a custom image, call `uploadImage` first to get the URN, then pass it.

### Status / health (2)

| Method | Returns |
|---|---|
| `getStatus()` | `{ connected, currentOrgUrn, viewerName, postsLoaded, lastError, expiresInMs }` |
| `health()` | `{ ok, connected, hasCurrentOrg, clientIdSet, expiresInMs }` |

Plus `meta.*` inherited from SgToolApi.

## Window events

All namespaced `tool:linkedin:*` per the convention:

| Event | When | Detail |
|---|---|---|
| `tool:ready` | `activate()` called | `{ instanceId, tool, version }` |
| `tool:linkedin:connected` | OAuth grant or cache hit | `{ expiresAt, fromCache, scope }` |
| `tool:linkedin:disconnected` | `disconnect()` called | `{}` |
| `tool:linkedin:me-loaded` | `getMe()` returned | `{ profile }` |
| `tool:linkedin:orgs-loaded` | `getMyAdminOrganizations()` returned | `{ orgs }` |
| `tool:linkedin:org-changed` | `setCurrentOrg()` | `{ urn }` |
| `tool:linkedin:posts-loaded` | list page returned | `{ items, page }` |
| `tool:linkedin:post-selected` | UI row clicked | `{ urn, post }` |
| `tool:linkedin:post-published` | createText/Article succeeded | `{ urn, type }` |
| `tool:linkedin:image-uploaded` | uploadImage succeeded | `{ urn }` |
| `tool:linkedin:handoff-received` | YouTube hand-off arrived | `{ sourceTool, youtubeUrl, suggestedCommentary, suggestedTitle }` |
| `tool:error` | any pipeline error | `{ step, message }` |

## Storage keys

Per origin, all under `localStorage`:

| Key | Contents |
|---|---|
| `sg-linkedin-client-id` | LinkedIn app client ID |
| `sg-auth-token-linkedin-publisher` | `{ accessToken, expiresAt, scope, savedAt }` (via `sg-auth-tokens`) |
| `sg-linkedin-current-org` | URN of the currently-selected org |
| `sg-linkedin-pkce-verifier` | Transient PKCE verifier (deleted after token exchange) |

Token cache logic mirrors `youtube-token-cache.js` exactly — same 60 s expiry skew, same shape, just a different provider key. Vault migration path is identical (one-file swap).

---

## Error shape

Every thrown error from `LinkedInApi` follows the same format as `YouTubeApi`:

```
LinkedIn {status}: {body…}
```

The 401 → auto-disconnect pattern from `youtube-editor-pipeline._withAuth()` should be ported verbatim — wraps every API call so a stale/invalid token transparently triggers a re-auth on the next attempt.

## What an agent run looks like end-to-end

```js
const tool = () => window.__tool['linkedin-publisher'];

await page.evaluate(() => tool().connect());
await page.evaluate(() => tool().getMe());

const orgs = await page.evaluate(() => tool().getMyAdminOrganizations());
await page.evaluate(u => tool().setCurrentOrg({ urn: u }), orgs[0].urn);

// Pull recent activity to give the agent context
const recent = await page.evaluate(() => tool().listOrgPosts({ pageSize: 10 }));

// Publish the new post — text or article-link
const out = await page.evaluate(() => tool().createArticlePost({
    commentary:   'Just published a new demo of SG/Send + the SGraph YouTube tools.',
    sourceUrl:    'https://www.youtube.com/watch?v=GR6GyIxjhbg',
    title:        'Akeia VNC Browser',
    description:  'Browser-only screen recording + YouTube publishing pipeline.',
}));

// Confirm
const fresh = await page.evaluate(u => tool().getPost({ urn: u }), out.urn);
```

Same shape as the YouTube agent flow in `…__how-to-use__3__js-api-for-agents.md`. Anyone who learned that contract can drive this tool with no new mental model.
