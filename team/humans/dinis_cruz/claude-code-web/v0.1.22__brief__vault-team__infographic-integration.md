# Brief: Adding LLM Infographic Generation to the Vault UI

**To:** Vault Team  
**From:** Explorer Team (tools.sgraph.ai)  
**Date:** 2026-04-08  
**Version:** v0.1.22  
**Ref:** `tools/v0/v0.1/v0.1.12/en-gb/infographic-gen/` · `components/llm/sg-llm-infographic/v0/v0.1/v0.1.0/`

---

## 1. What This Brief Covers

The Explorer team has shipped a working infographic generator at `tools.sgraph.ai/en-gb/infographic-gen/` that takes a text description (or an uploaded document) and produces a live-rendered SVG via an LLM. This brief explains exactly how it works and how the Vault team can integrate the same capability directly into the vault UI — letting users select a vault file, generate an infographic or other LLM-derived document from its contents, and save the result back into the vault, all in the browser with no server involved.

---

## 2. The Infographic System — How It Works

### 2.1 Core Components

```
sg-llm-events         — shared event name constants (SGL_LLM.*)
sg-llm-request        — headless: sends requests to the LLM API, emits streaming events
sg-llm-infographic    — renders: listens for streaming chunks, extracts SVG, exports
sg-llm-model-picker   — optional: UI for picking provider + model
sg-llm-stats          — optional: token counts, cost, duration display
```

All are at `/components/llm/` on tools.sgraph.ai. Import them with versioned paths — no build step required.

### 2.2 The Event Bus Pattern

Every LLM component communicates via **custom events on a shared bus element**. The bus is any DOM element with a `data-llm-bus` attribute. Components walk their ancestor chain to find it:

```html
<div id="llm-bus" data-llm-bus>          <!-- the bus -->
    <sg-llm-request></sg-llm-request>    <!-- headless: sends requests -->
    <sg-layout id="layout"></sg-layout>  <!-- panels containing the other components -->
</div>
```

The critical detail: **`sg-layout` uses shadow DOM**, which breaks ancestor-chain walking. Components inside `sg-layout` panels cannot find `[data-llm-bus]` via `parentElement`. The fix is that `sg-llm-request` is placed **outside** `sg-layout` but **inside** the bus div. Components discover the bus by walking up from their position in the light DOM — `sg-layout` places panel content in light DOM slots, so this works as long as `sg-llm-request` shares the same bus ancestor.

### 2.3 The LLM Event Flow

```
1. Tool code dispatches: llm:send { messages, model, stream:true, tools? }
      on the bus div
2. sg-llm-request picks it up, calls the OpenRouter/Ollama/Anthropic API
3. As chunks arrive:
      llm:request-start    { model }
      llm:request-chunk    { chunk, accumulated }   (streaming)
      llm:request-complete { content, model, usage }
4. sg-llm-infographic listens for request-chunk and request-complete,
   extracts <svg>…</svg> from the accumulated text, renders it live
5. When SVG is extracted: llm:infographic-ready { svg, width, height }
```

### 2.4 The sg-llm-infographic Component

**File:** `components/llm/sg-llm-infographic/v0/v0.1/v0.1.0/sg-llm-infographic.js`

Key behaviours:

- Listens on its **bus** (walks ancestors to find `[data-llm-bus]`)
- Extracts the first `<svg>…</svg>` block from any LLM response — it doesn't care what else the LLM says
- Sanitises the SVG before injection (strips `<script>`, `on*` handlers)
- Live-renders during streaming (partial SVGs update as text arrives)
- Exports: SVG download or PNG (via Canvas `drawImage`)
- Emits `llm:infographic-ready { svg, width, height }` when complete

**Public API (call on the DOM element):**

```javascript
const inf = document.querySelector('sg-llm-infographic');

inf.getSystemPrompt()   // → the style-specific system prompt to inject
inf.getCurrentStyle()   // → 'executive' | 'technical' | 'playful' | 'minimal' | 'bold' | 'data'
inf.setStyle('data')    // programmatically change style
inf.getCurrentSvg()     // → SVG string or null
```

**Style presets** — each has a different system prompt baked in:

| Preset | Palette | Use case |
|---|---|---|
| `executive` | Dark navy, teal accents | Business summaries |
| `technical` | Dark bg, colour-coded nodes | Architecture diagrams |
| `playful` | White/cream, bright colours | Engaging visuals |
| `minimal` | White bg, single accent | Clean reports |
| `bold` | Black bg, neon accents | High-impact visuals |
| `data` | Light bg, chart-focused | Data tables, graphs |

**How the system prompt is used in the infographic tool:**

```javascript
// When the user clicks Send, the tool builds the messages array like this:
const inf = document.querySelector('sg-llm-infographic');
const systemPrompt = inf.getSystemPrompt();  // style-specific

busDiv.dispatchEvent(new CustomEvent('llm:send', {
    bubbles: true,
    detail: {
        model:    'google/gemini-2.0-flash-001',
        stream:   true,
        messages: [
            { role: 'system',    content: systemPrompt },
            { role: 'user',      content: userText },
            // OR for a file: { role: 'user', content: [{type:'text', text: fileContent}] }
        ],
    },
}));
```

The LLM is instructed to output ONLY raw SVG — no markdown fences, no prose — so extraction is reliable.

### 2.5 The Mini-Bus Pattern (Concurrent Multi-Model)

The infographic tool (v0.1.12) also demonstrates running multiple LLM requests concurrently with different models and displaying each result in its own panel. This uses a "mini-bus" pattern where each result tab contains its own isolated `data-llm-bus` div with its own `sg-llm-request`. A capture-phase event interceptor on the outer bus re-dispatches `llm:send` events into each mini-bus. This is more advanced — the Vault team probably doesn't need it initially, but it's there as a reference.

## 3. The Vault UI — Current Architecture

**File:** `tools/v0/v0.1/v0.1.16/en-gb/vault/index.html`  
**Components:** `sg-vault-connect`, `sg-vault-tree`, `sg-vault-viewer`

The vault uses a **`data-vault-bus`** pattern, analogous to the LLM bus:

```html
<div id="vault-bus" data-vault-bus>
    <sg-layout id="layout"></sg-layout>
</div>
```

**Vault event flow:**

```
vault:connected   { vault, keys }          — emitted by sg-vault-connect on success
vault:file-select { path, fileId, size }   — emitted by sg-vault-tree on click
vault:file-saved  { path }                 — emitted by sg-vault-viewer after write
vault:tree-refresh {}                      — trigger tree reload
vault:new-file-request {}                  — signal to create a new file
```

**sg-vault-viewer** already:
- Reads vault files via `readFile(vault, fileId)` — returns `Uint8Array`
- Writes via `writeVaultFile(vault, path, text)` — handles blob + tree + commit + ref update
- Exposes `this._vault` and `this._path` after `vault:connected` + `vault:file-select`

The vault/LLM buses are **completely independent** — they can coexist in the same page on different ancestor elements, which is the cleanest integration approach.

## 4. Integration Approach

### 4.1 Recommended Layout

Add a second bus div for LLM alongside the existing vault bus, or extend the sg-layout with a new panel column. The cleanest approach:

```html
<!-- Existing vault bus — unchanged -->
<div id="vault-bus" data-vault-bus>
    <sg-layout id="layout"></sg-layout>
</div>

<!-- New LLM bus — sits outside vault-bus so the two don't interfere -->
<div id="llm-bus" data-llm-bus style="display:none" id="generate-panel">
    <sg-llm-request></sg-llm-request>
    <!-- sg-llm-infographic rendered here via JS -->
</div>
```

Or more elegantly, extend the `sg-layout` to be a 3-column layout:

```
┌──────────────┬──────────────────────────┬──────────────────────────┐
│ Connect      │  File Viewer / Editor    │  Generate                │
│ File Tree    │                          │  (LLM + Infographic)     │
└──────────────┴──────────────────────────┴──────────────────────────┘
```

### 4.2 New Imports Needed

```javascript
import '/components/llm/sg-llm-events/v0/v0.1/v0.1.1/sg-llm-events.js';
import '/components/llm/sg-llm-request/v0/v0.1/v0.1.2/sg-llm-request.js';
import '/components/llm/sg-llm-infographic/v0/v0.1/v0.1.0/sg-llm-infographic.js';
import '/components/llm/sg-llm-model-picker/v0/v0.1/v0.1.0/sg-llm-model-picker.js';
// optional:
import '/components/llm/sg-llm-stats/v0/v0.1/v0.1.1/sg-llm-stats.js';
import { SGL_LLM } from '/components/llm/sg-llm-events/v0/v0.1/v0.1.1/sg-llm-events.js';
```

Use **v0.1.1** of `sg-llm-events` (latest) — it has additional agentic event constants.

### 4.3 Connection Flow

The LLM connection (API key) is separate from the vault connection. Add a compact API key input to the Generate panel header:

```javascript
// When user enters API key + clicks Connect in the Generate panel:
llmBusDiv.dispatchEvent(new CustomEvent(SGL_LLM.CONNECTED, {
    bubbles: true,
    detail: { provider: 'openrouter', apiKey: 'sk-or-v1-…' },
}));
// sg-llm-request picks this up and stores the key for subsequent llm:send events
```

Optionally, if the vault tool already loads credentials from the SG Vault (as the OpenRouter tool does), extend `openrouter/user/config.json` to include the API key and auto-connect both.

### 4.4 File → Infographic Flow

```javascript
// 1. Listen for vault:file-select on the vault bus
document.getElementById('vault-bus').addEventListener('vault:file-select', async (e) => {
    const { path, fileId } = e.detail;
    // Store for later use
    selectedPath   = path;
    selectedFileId = fileId;

    // Optionally auto-populate the prompt textarea
    promptArea.value = `Generate an infographic for the file: ${path}`;
});

// 2. When user clicks "Generate":
async function onGenerateClick() {
    const vault = currentVault;  // stored from vault:connected event

    // Read the vault file content
    const raw     = await readFile(vault, selectedFileId);  // Uint8Array
    const content = new TextDecoder().decode(raw);

    // Get the style-appropriate system prompt from the component
    const inf          = document.querySelector('sg-llm-infographic');
    const systemPrompt = inf.getSystemPrompt();

    // Dispatch the LLM request on the LLM bus
    llmBusDiv.dispatchEvent(new CustomEvent('llm:send', {
        bubbles: true,
        detail: {
            model:   selectedModel,  // from sg-llm-model-picker or hardcoded
            stream:  true,
            messages: [
                { role: 'system', content: systemPrompt },
                {
                    role: 'user',
                    content: `${promptArea.value}\n\n--- FILE CONTENT ---\n${content}`
                },
            ],
        },
    }));
}
```

### 4.5 Saving the Result Back to the Vault

```javascript
// Listen for llm:infographic-ready (emitted by sg-llm-infographic when SVG is complete)
llmBusDiv.addEventListener('llm:infographic-ready', async (e) => {
    saveBtn.disabled = false;  // enable "Save to Vault" button
    currentSvg = e.detail.svg;
});

// When user clicks "Save to Vault":
async function onSaveToVault() {
    const vault    = currentVault;
    const savePath = `${selectedPath}.infographic.svg`;  // or let user choose name

    await writeVaultFile(vault, savePath, currentSvg);

    // Refresh the tree so the new file appears
    document.getElementById('vault-bus').dispatchEvent(
        new CustomEvent('vault:tree-refresh', { bubbles: true })
    );
}
```

`writeVaultFile` is already exported from `core/vault-client/v1/v1.0/v1.0.0/sg-vault-client.js` — the same import the vault viewer uses.

## 5. Beyond Infographics — Other LLM-Generated File Types

The same pattern works for any LLM-generated content. The difference is only in the system prompt and what you extract from the response.

| Output type | System prompt instruction | Extraction | Save as |
|---|---|---|---|
| SVG infographic | "Output ONLY raw SVG" | First `<svg>…</svg>` block | `filename.svg` |
| Markdown report | "Output ONLY markdown" | Full response text | `filename.md` |
| JSON structured data | "Output ONLY valid JSON" | First `{…}` / `[…]` block | `filename.json` |
| HTML document | "Output ONLY raw HTML" | First `<!DOCTYPE…>` / `<html>…` block | `filename.html` |
| Python script | "Output ONLY Python code, no fences" | Full response | `filename.py` |

For non-SVG types, instead of `sg-llm-infographic`, listen directly for `llm:request-complete` on the bus and pull `e.detail.content`. `sg-llm-infographic` can still be used purely for its export capability if the output is SVG.

## 6. Gotchas and Known Issues

### Shadow DOM bus isolation
`sg-layout` places panels in shadow DOM. Components inside panels walk their `parentElement` chain looking for `[data-llm-bus]` or `[data-vault-bus]`. Since the shadow root breaks the chain, `sg-llm-request` **must** be placed in the light DOM directly inside the bus div, NOT inside an `sg-layout` panel. Same rule applies to `sg-vault-connect`.

### Two buses, not one
Do not try to combine the vault bus and the LLM bus into a single element. Keep them separate. The vault events (`vault:connected`, `vault:file-select`) and LLM events (`llm:connected`, `llm:send`) share no namespace conflicts, but mixing them on one element makes the architecture harder to reason about and debug.

### LLM key storage
The current vault viewer does not persist the LLM API key. Either:
- Store it in `localStorage` (same approach as the OpenRouter tool: `localStorage.setItem('or-user-api-key', key)`)
- Load it from the vault itself via a known path (e.g. `openrouter/user/config.json` contains `{ "apiKey": "…" }`)

### File size limits for context
Vault files can be large. Most LLMs have a 128k–200k token context window. For very large files, consider:
- Sending only the first N characters
- Letting the user select a range or section
- Summarising in a first pass, then generating from the summary

### SVG sanitisation
`sg-llm-infographic` already sanitises the SVG before rendering (strips `<script>`, `on*` attributes, `javascript:` hrefs). If you extract SVG yourself (for the save-to-vault flow), apply the same sanitisation before storage — or store the raw LLM output and sanitise on render.

## 7. Quick-Start Checklist

- [ ] Add `data-llm-bus` div with `sg-llm-request` to the vault page
- [ ] Import `sg-llm-events`, `sg-llm-request`, `sg-llm-infographic`, `sg-llm-model-picker`
- [ ] Add API key input + connect button → dispatch `llm:connected` on the LLM bus
- [ ] Listen for `vault:file-select` on the vault bus → store `path` + `fileId`
- [ ] Add "Generate" button → read file via `readFile()`, dispatch `llm:send` with file content as user message
- [ ] `sg-llm-infographic` auto-renders the SVG as it streams
- [ ] Listen for `llm:infographic-ready` → enable "Save to Vault" button
- [ ] "Save to Vault" → `writeVaultFile(vault, newPath, svg)` + dispatch `vault:tree-refresh`
