## Health-check tests

Each test is a self-contained HTML page that runs in a browser, stubs `window.fetch`, and prints PASS/FAIL rows. No Node.js, no real network.

| Test page | Assertions | What it covers |
|---|--:|---|
| `tests/sg-youtube-upload/v0.1.0.test.html` | ~17 | Scope const, `requestAccess` shape, `YouTubeUpload` guards, token cache round-trip + skew + clear, custom-element registration, public API surface. Live demo component embedded with the bundled client ID. |
| `tests/sg-youtube-api/v0.1.0.test.html` | 22 | All scope constants + ctor guards + the 11 method guard rails, plus stubbed-fetch round-trip for `getMyChannel`, `listMyUploads`, `getVideos`, `updateVideo`, `setThumbnail`, `deleteVideo`. |
| `tests/sg-youtube-videos/v0.1.0.test.html` | 11 | Element registration, public API, stubbed pagination across 2 pages, `videos-loaded` events fired, `video-selected` from row click. Live demo grid embedded with mock data. |
| `tests/sg-youtube-video-editor/v0.1.0.test.html` | 16 | Element registration, public API, form populated from `loadVideo`, tags joined into the input, privacy badge class, `save()` PUT body shape (snippet + categoryId + status), delete-confirm guard. Live demo editor embedded. |

**Total:** ~66 assertions across 4 pages, all green.

The 9 playlist + analytics methods added later don't have dedicated stubbed-fetch tests — they're thin wrappers around the same `_check`/`_json` helpers as the original methods. Tagged in `how-we-built-it.md` as a known follow-up rather than over-tested.

The `tests/index.html` master index has a new "sg-youtube — YouTube Tools" section linking to all four pages.
