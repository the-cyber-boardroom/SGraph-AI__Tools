## Pipeline state machine (`publisher-state.js`)

One `PublishJob` per video. A job starts from an in-tool recording *or* a loaded file:

```
idle → recording (armed/live/paused, driven by core/sg-recorder events) ─┐
idle → (drop / handoff) ─────────────────────────────────────────────────┤
                                                                         ▼
                     loaded → audio-ready → transcribing → transcribed
                            → generating-metadata → ready-to-publish → uploading → published
     (any step → error {code, step}; steps re-runnable individually)
```

On `stopRecording`, the engine's blobs land directly in the job (`blob` = combined/primary, `audioBlob` = the separate opus stream when present — Decision 2 route 1) and the job transitions to `loaded`.

Auto-advance through `audio-ready → transcribed → metadata` on load (configurable `autoRun: true`); the job **always pauses at `ready-to-publish`** — a human or agent must explicitly trigger `upload()`. Nothing is sent to YouTube without that explicit call.

## Refactors to existing tools (Phase R — land before publisher code)

All three are behaviour-identical releases, verified against each tool's existing health checks; event names and payload shapes are frozen (they're the public contract embedders and SKILL files depend on):

1. **video-recorder** — new overlay: `api/` engine files replaced by imports from `core/sg-recorder/v0/v0.1/v0.1.0/`; `ui-recording-tab.js` gains the **Publish** button; both handoff buttons switch to importing the shared `sg-publish-handoff.js` / `sg-youtube-handoff.js` helpers instead of inlining; `recorder-api.js` registers `sendToPublisher` and `sendToYouTubeEditor` as API actions. Handoff payload includes `audioBlob` when a separate audio stream exists.
2. **audio-transcribe + live-transcribe** — new versions re-pinning their engine imports to `core/sg-transcribe/v0/v0.1/v0.1.0/`. The v0.1.93 integration guide's "reuse-as-is vs tool-owned internals" table updates accordingly.
3. **`core/video` v1.0.2** — the Decision-3 merge (v1.0.1 exports + v1.0.0 WORKERFS), health-check suite green.

## Tool layout (sg-layout)

```
┌──────────────────────────────┬──────────────────────────────────────┐
│ LEFT (38%)                   │ RIGHT (62%)                          │
│ ┌──────────────────────────┐ │ ┌──────────────────────────────────┐ │
│ │ Record │ Import          │ │ │ Transcript │ Metadata │ Publish  │ │  ← tabs
│ │  ● Start / ■ Stop        │ │ │                                  │ │
│ │  preview · timer · size  │ │ │  (transcript text / editable     │ │
│ │  (advanced: mode/quality)│ │ │   title+description+tags+privacy │ │
│ ├──────────────────────────┤ │ │   form / connect+progress+URL)   │ │
│ │ Steps                    │ │ │                                  │ │
│ │  ① Audio    ✓ route 1    │ │ └──────────────────────────────────┘ │
│ │  ② Transcript ✓ $0.07    │ │                                      │
│ │  ③ Metadata  ● editing   │ │                                      │
│ │  ④ Publish   ○           │ │                                      │
│ ├──────────────────────────┤ │                                      │
│ │ Accounts (collapsed)     │ │                                      │
│ └──────────────────────────┘ │                                      │
└──────────────────────────────┴──────────────────────────────────────┘
```

The Record tab defaults to the publishing sweet spot — screen + mic + camera PiP, 2.5 Mbps, landscape, `combined+separate` streams (so route-1 audio is free) — with an "advanced" disclosure exposing the engine's other modes/layouts. Import is the sibling tab for drag-drop. After stop, the video preview replaces the live preview in place. The Steps panel is the spine: each row shows state, cost where applicable, and a re-run affordance; clicking a step focuses its tab on the right. Mobile: single stack in step order. Designer owns the final treatment; the constraint that matters is **one page, visible pipeline, one primary action per state**.

## Handoff mechanics (inherited contract)

Same-origin `window.opener` stash, consume-once, popup-blocker-sensitive (must be called from a click handler), payload lost if the producer tab closes before pickup — all documented in `sg-youtube-handoff.js:6-9`. `ui-shell.js` picks up after layout init and dispatches an internal event once the Source panel is mounted, exactly as youtube-editor's shell does (`ui-shell.js:79-95` there). If pickup yields nothing, the tool is simply in drag-drop mode.
