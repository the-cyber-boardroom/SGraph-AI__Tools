## Pipeline state machine (`publisher-state.js`)

One `PublishJob` per loaded video:

```
idle → loaded → audio-ready → transcribing → transcribed
     → generating-metadata → ready-to-publish → uploading → published
     (any step → error {code, step}; steps re-runnable individually)
```

Auto-advance through `audio-ready → transcribed → metadata` on load (configurable `autoRun: true`); the job **always pauses at `ready-to-publish`** — a human or agent must explicitly trigger `upload()`. Nothing is sent to YouTube without that explicit call.

The Steps panel is the spine: each row shows state, cost where applicable, and a re-run affordance. Clicking a step focuses its tab on the right. Mobile: single stack in step order. Designer owns the final treatment; the constraint that matters is **one page, visible pipeline, one primary action per state**.

## Handoff mechanics (inherited contract)

Same-origin `window.opener` stash, consume-once, popup-blocker-sensitive (must be called from a click handler), payload lost if the producer tab closes before pickup — all documented in `sg-youtube-handoff.js:6-9`. `ui-shell.js` picks up after layout init and dispatches an internal event once the Source panel is mounted, exactly as youtube-editor's shell does (`ui-shell.js:79-95` there). If pickup yields nothing, the tool is simply in drag-drop mode.
