# Brief — Video Publisher · 5/5 Phasing & Acceptance

Build incrementally — each phase lands a working, committed slice. Prefer `Edit` patches over big `Write`s; keep every file under ~300 lines.

---

## Phase 0 — Verification (½ day)

Three cheap probes before real code:

1. **Opus-in-m4a failure mode.** Feed a video-recorder WebM blob to `extractAudio()` (sg-video v1.0.0) and confirm it fails as the health check predicts; feed the same blob to `sg-audio-decode.decodeNative` and confirm a playable WAV comes out. This validates the route 2→3 fallback ordering.
2. **Engine extraction dry-run.** Confirm the six recorder engine files and six transcribe engine files have no hidden imports of tool-local UI/paths that would break a move to `core/` (grep their import graphs; the research says they're clean, verify it).
3. **Handoff payload with two blobs.** Stash `{blob, audioBlob}` on a `window.__sgYtHandoff`-style global, open a stub page, confirm both survive pickup.

## Phase R — Refactor existing tools (1–1.5 sessions, lands FIRST)

The consolidation-enabling refactors from part 3, each a behaviour-identical release with frozen event contracts:

- **R1:** extract `core/sg-recorder/v0/v0.1/v0.1.0/` from video-recorder's overlays; new video-recorder overlay imports from core; existing recorder walkthrough + health checks green.
- **R2:** extract `core/sg-transcribe/v0/v0.1/v0.1.0/` from audio-transcribe's `api/`; audio-transcribe and live-transcribe re-pin; their SKILL/manifest surfaces unchanged; v0.1.93 integration guide updated.
- **R3:** cut `core/video` v1.0.2 (v1.0.1 exports + v1.0.0 WORKERFS); health-check suite green.

**DoD:** all existing tools work exactly as before (verified against their own tests/SKILL walkthroughs), reality doc Part 1 gains the two new core modules, and nothing in this phase mentions the publisher — these refactors stand on their own merit.

## Phase 1 — Skeleton + record + source + audio (1 session)

Tool scaffold (manifest, state, events, shell, Steps panel), **Record panel over `core/sg-recorder`** (defaults per part 3, advanced disclosure), Import tab drag-drop, `audio-router.js` with the three routes. **Definition of done:** record in-tool → `audio-ready` via route 1; drop an MP4 and a WebM → `audio-ready` via routes 2 and 3 respectively, route reported.

## Phase 2 — Transcribe + metadata (1 session)

Wire `core/sg-transcribe`, Accounts panel chip for the OpenRouter key, `transcribe` + Transcript tab; `metadata-gen.js` with strict-JSON contract + Metadata form + regenerate-with-guidance. **DoD:** recorded or dropped video → transcript with cost shown → generated title/description/tags editable in the form.

## Phase 3 — YouTube connect + upload (1 session)

GIS connect (pipeline pattern from youtube-editor: cache/silent/popup, 60 s skew, 401 auto-disconnect, plus Decision 7's proactive refresh), Publish tab, `upload()` with progress, result URL, `publish({confirm:true})` one-shot. **DoD:** end-to-end record-to-real-unlisted-YouTube-URL in one page, agent-drivable via console.

## Phase 4 — Recorder handoff entry (½ session)

Shared `sg-publish-handoff.js` helper; video-recorder overlay: Publish button, both handoff buttons switch to the helper, `sendToPublisher` registered as an API action, `audioBlob` in the payload. **DoD:** stop a recording in the standalone recorder → Publish → publisher opens with route-1 audio (no extraction step run).

## Phase 5 — Skills + reality + tests (½ session)

Three SKILL files (SKILL-browser with stable DOM ids for Playwright), manifest `api` section authoritative, browser test page under `tests/`, reality document Part 2 entry + flip the Part 3 PROPOSED row, CHANGELOG.

**Total estimate: ~5–6 sessions** (~1.5 of which are the Phase R refactors, which pay for themselves — after them the publisher is thin UI over shared cores, and every future tool gets the same engines for free).

## Dependencies + risks

- **OpenRouter key required** for transcribe/metadata — without it the tool still functions as import → manual metadata → upload (steps 2–3 skippable).
- **Token lifetime vs upload time** (inherited): single-PUT + 1 h token; fine for target sizes, documented in SKILL-human. Chunked upload remains `core/youtube-upload` v0.2 territory.
- **Handoff fragility** (inherited): popup blockers, producer-tab lifetime. Drag-drop is always the fallback.
- **FFmpeg CDN** (~30 MB from unpkg on first route-2 use) — existing behaviour in video-tools; route 1/3 avoid it entirely.

## What's deliberately out of v0.1

Trim/edit before publish (sg-video-editor's lane), thumbnails, chapters/timestamps, playlists/analytics (youtube-editor), LinkedIn tail (existing brief — the natural v0.2: publisher output feeds an org post), segmented >25 MB-audio transcription, scheduled publishing.
