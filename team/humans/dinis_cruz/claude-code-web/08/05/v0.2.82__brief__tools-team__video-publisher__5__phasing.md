# Brief — Video Publisher · 5/5 Phasing & Acceptance

Build incrementally — each phase lands a working, committed slice. Prefer `Edit` patches over big `Write`s; keep every file under ~300 lines.

---

## Phase 0 — Verification (½ day)

Three cheap probes before real code:

1. **Opus-in-m4a failure mode.** Feed a video-recorder WebM blob to `extractAudio()` (sg-video v1.0.0) and confirm it fails as the health check predicts; feed the same blob to `sg-audio-decode.decodeNative` and confirm a playable WAV comes out. This validates the route 2→3 fallback ordering.
2. **`sg-video` v1.0.2 merge.** Copy v1.0.1, restore v1.0.0's `_mountInputFile` WORKERFS path, run the existing health-check suite against it.
3. **Handoff payload with two blobs.** Stash `{blob, audioBlob}` on `window.__sgYtHandoff`-style global, open a stub page, confirm both survive pickup.

## Phase 1 — Skeleton + source + audio (1 session)

Tool scaffold (manifest, state, events, shell, Source panel, Steps panel), drag-drop import, `audio-router.js` with the three routes, `extractAudio` action + events. **Definition of done:** drop an MP4 and a WebM; both reach `audio-ready` with the correct route reported.

## Phase 2 — Transcribe + metadata (1 session)

Wire the audio-transcribe `api/` modules (llm-transport, api-transcribe, audio-format, models, errors, cost), Accounts panel chip for the OpenRouter key, `transcribe` + Transcript tab; `metadata-gen.js` with strict-JSON contract + Metadata form + regenerate-with-guidance. **DoD:** dropped video → transcript with cost shown → generated title/description/tags editable in the form. (Architect decision from part 3 — import-in-place vs promote to `core/` — lands here.)

## Phase 3 — YouTube connect + upload (1 session)

GIS connect (pipeline pattern from youtube-editor: cache/silent/popup, 60 s skew, 401 auto-disconnect), Publish tab, `upload()` with progress, result URL, `publish({confirm:true})` one-shot. **DoD:** end-to-end from drop to a real unlisted YouTube URL, agent-drivable via console.

## Phase 4 — Recorder handoff (½ session)

Shared `sg-publish-handoff.js` helper; video-recorder overlay: Publish button, both handoff buttons switch to the helper, `sendToPublisher` registered as an API action, `audioBlob` included when a separate audio stream exists. **DoD:** stop a recording → Publish → publisher opens with route-1 audio (no extraction step run).

## Phase 5 — Skills + reality + tests (½ session)

Three SKILL files (SKILL-browser with stable DOM ids for Playwright), manifest `api` section authoritative, browser test page under `tests/`, reality document Part 2 entry + flip the Part 3 PROPOSED row, CHANGELOG.

**Total estimate: ~4 sessions** (mirrors the youtube-editor v0.1 effort; less unknown territory).

## Acceptance criteria for v0.1

| # | Criterion | Verification |
|---|---|---|
| 1 | Stop-to-URL in ≤5 interactions from video-recorder (Publish → [review] → Upload → copy) | manual walkthrough, screen-recorded |
| 2 | Same pipeline from a dropped MP4 (no recorder) | manual + Playwright |
| 3 | WebM/Opus input transcribes via route 3 when route 2 fails | Phase-0 probe promoted to test |
| 4 | No video bytes leave the browser except to `googleapis.com` (and OpenRouter receives audio only) | DevTools network audit |
| 5 | Nothing uploads without explicit `upload()`/`confirm:true` | code review + test |
| 6 | Credentials configured in audio-transcribe / youtube-editor are picked up with zero re-entry | manual |
| 7 | Full agent run headless via `window.__tool` (part 4 script) | Playwright |
| 8 | Costs (transcription + metadata) visible per step and rolled up | manual |
| 9 | SgToolApi + 3 SKILL files + manifest event catalogue complete | api-pane inspection |
| 10 | All new files ≤ ~300 lines; reality doc updated in the same commits | review |

## Dependencies + risks

- **OpenRouter key required** for transcribe/metadata — without it the tool still functions as import → manual metadata → upload (steps 2–3 skippable).
- **Token lifetime vs upload time** (inherited): single-PUT + 1 h token; fine for target sizes, documented in SKILL-human. Chunked upload remains `core/youtube-upload` v0.2 territory.
- **Handoff fragility** (inherited): popup blockers, producer-tab lifetime. Drag-drop is always the fallback.
- **FFmpeg CDN** (~30 MB from unpkg on first route-2 use) — existing behaviour in video-tools; route 1/3 avoid it entirely.

## What's deliberately out of v0.1

Trim/edit before publish (sg-video-editor's lane), thumbnails, chapters/timestamps, playlists/analytics (youtube-editor), LinkedIn tail (existing brief — the natural v0.2: publisher output feeds an org post), segmented >25 MB-audio transcription, scheduled publishing.
