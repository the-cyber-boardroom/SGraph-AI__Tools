Follows the mandated split (`api/{state,events,pipeline,api}.js` + one `ui/ui-*.js`
per panel), manifest-loader boot, sg-layout shell, every file under ~300 lines.

**Deliberately reused, not reimplemented:** `createVad`. The probe must replay the
*actual* state machine `narrated-review` runs — hysteresis, pre-roll, hangover,
`maxUtteranceMs` and all — otherwise the compare view is a fiction. Feed it the
recording's real RMS log with empty sample frames, exactly as `nr-video.js`
already does (pin: `api/nr-video.js` `segmentSpeech`).

## 3. The sampling pipeline

```
 file
  │
  ├─ AUDIO ────────────────────────────────────────────────────────────────
  │   decodeAudioData(file)            ← works directly on mp4/webm; FFmpeg
  │        │                             extractAudio only when it refuses
  │        ▼
  │   framewise 20 ms: rms, dBFS, spectralFlatness      → audio-metrics.js
  │        ▼
  │   percentile floor/speech + energy histogram        → distributions.js
  │        ▼
  │   gaps at N thresholds simultaneously  →  gap histogram
  │        ▼
  │   replay createVad at each candidate threshold  →  segment sets + capped counts
  │
  ├─ VIDEO ────────────────────────────────────────────────────────────────
  │   PASS 1 coarse (1 fps): signature per sample, 4 metrics
  │        ▼
  │   candidate regions = samples where ANY metric exceeds its own p95
  │        ▼
  │   PASS 2 fine (10 fps) inside candidate regions only     ← Decision 6
  │        ▼
  │   scene-change list, each with { at, metric, value, beforeThumb, afterThumb }
  │
  └─ ALIGN ────────────────────────────────────────────────────────────────
      for each scene change: nearest speech onset  →  Δ
      distribution of Δ  →  measured lead/lag, and a correlation score
```

**Signature raster:** 32×18 greyscale, matching `nr-frames.js` so the numbers are
directly comparable to what the tool actually does. `blockMax` uses an 8×8 grid
over the same raster (each tile 4×2 px) — coarse, but enough to catch a panel
opening. If Phase 2 shows it is too coarse, raise the raster; do not raise it
speculatively.

**Two-pass justification:** a screencast is static most of the time. Pass 1 at
1 fps over a 60-minute video is 3600 seeks; pass 2 at 10 fps over (say) 40 change
regions × 2 s is 800 more. Versus 36 000 for a naive 10 fps sweep.

## 4. The FFmpeg lane (optional, per-lane, lazy)

```js
// Scene scores at native frame rate.
ffmpeg -i in.mp4 -vf "select='gt(scene,0.05)',showinfo" -an -f null -
//   → stderr lines: [Parsed_showinfo] n:12 pts_time:41.2 ... scene:0.42
// Silence intervals on the full-rate signal.
ffmpeg -i in.mp4 -af silencedetect=n=-30dB:d=0.5 -vn -f null -
//   → stderr: [silencedetect] silence_start: 41.9 / silence_end: 43.1 | silence_duration: 1.2
// Loudness, properly.
ffmpeg -i in.mp4 -af ebur128 -vn -f null -
```

Both are **stderr log parsers**, which is fragile and must be treated as such:
parse defensively, and if a run yields zero rows say "FFmpeg produced no parsable
output" rather than "no scenes found". The two are not the same claim and
conflating them would repeat this pack's founding mistake at a different level.

Output goes onto the *same* timeline axis as the browser-native traces so the two
can be compared directly (Decision 5).

## 5. `plan()` — the recommender

```js
plan(metrics, opts) → {
  strategy: 'audio-led' | 'video-led' | 'hybrid' | 'none',
  reason:   'topic-gap population is empty (0 gaps > 1000 ms in 261 s)',
  cuts:  [{ tMs, source: 'silence'|'scene', evidence: { metric, value, gapMs } }],
  shots: [{ tMs, forCutIndex, evidence: { metric, value, settledAfterMs } }],
  estimate: { captures, transcribeUsd, cleanUsd, totalUsd },   // ← the cost case
  warnings: [{ code, message }],
}
```

Strategy selection, in order:

1. **audio-led** — there is a healthy topic-gap population (default: ≥ 3 gaps
   > 1000 ms per 5 minutes, and the energy histogram is bimodal). Cut at the
   gaps; shots from the scene list within the measured lead/lag window.
2. **video-led** — no usable topic gaps, but scene changes are present and their
   durations are plausible (default: median scene ≥ 4 s). Cut at scene changes;
   the words spoken between two changes belong to the first.
3. **hybrid** — both signals exist but disagree; take scene changes as the primary
   boundary and snap each to the nearest gap within ±2 s.
4. **none** — neither signal is usable. Return the reason. Do not invent
   boundaries (Decision 8).

`estimate` uses the measured per-capture costs from the real session
($0.0130 transcribe + $0.0343 cleanup per capture, cleanup being 72% of spend) so
the compare view can state the saving in money, not adjectives. Those constants
belong in one named place with the session they came from recorded beside them.

## 6. UI — the panels

**Timeline** (the centrepiece). One canvas, shared x-axis, stacked lanes:


Dragging the threshold line **re-runs `createVad` live** and redraws the `plan`
lane. That interaction is the whole tool: it turns an invisible constant into
something you can feel.

**Histograms** — energy (with floor/speech modes marked and both the calibrated
and old-fixed thresholds drawn) and gap length (with the word/sentence/topic
populations shaded).

**Strip** — every scene change as a before/after thumbnail pair with its metric
values, click to seek. This is where you see whether `blockMax` fired on a real
change or on a cursor.

**Compare** — a table: captures, forced cuts, mean segment length, sentences split
mid-clause (estimable from whether a cut lands inside a speech run), estimated
spend. Today's numbers against the plan's.

**Align** — the lead/lag histogram, with `narrated-review`'s current 2500/1200
window drawn over it so you can see whether the assumption holds.

## 7. What Media Probe deliberately does NOT do

- No model calls (Decision 2), so no key, no cost, no privacy surface.
- No editing of the video, no re-encode, no export of media — only of *numbers*
  (JSON/CSV) and the plan.
- It does not import into `narrated-review`. It hands over a `plan`, and
  `narrated-review` decides — a later, separate phase (part 5, Phase 6).
