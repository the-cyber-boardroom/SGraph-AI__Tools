## The shared extraction (Phase R, lands first)

**`core/sg-review-pairs` v0.1.0** — promoted from `narrated-review` v0.1.1,
behaviour-identical, contracts frozen. This is the two-thirds of the tool that
already exists and is live-verified.

```
core/sg-review-pairs/v0/v0.1/v0.1.0/
  pairs-state.js        # from nr-state.js  — session + ordered pairs + costs,
                        #   makePair/resequence/pairToJson/sessionToJson,
                        #   the raw|clean|notes three-text discipline
  pairs-edit.js         # from nr-edit.js   — setNotes, movePair, reorderPairs,
                        #   insertPair (author a capture with no audio)
  pairs-document.js     # from nr-document.js — ordered markdown assembler
  pairs-chat.js         # from nr-chat.js   — askPair (one capture) +
                        #   askSession (tool-calling over the whole review)
  pairs-llm.js          # from nr-llm.js    — isolated transport with tools/toolCalls
  pairs-pdf.js          # from nr-pdf.js    — paginated PDF of the artefact
  pairs-zip.js          # from nr-zip.js    — bundle shape over core/sg-zip
  pairs-vault.js        # from nr-vault.js  — vault write, audio opt-in
  pairs-events.js       # the shared `nr:*`-shaped event names, parameterised prefix
```

Two adjustments during the move, both small:

1. **Event prefix becomes a parameter.** `narrated-review` keeps emitting `nr:*`
   (its SKILL files and the manifest catalogue are a frozen contract);
   `video-review` emits `vr:*`. The module takes the prefix at construction.
2. **`tPress` becomes `tAnchor`.** In the sibling tool it is the moment a key was
   pressed; here it is the moment in the video the pair refers to. Same field,
   honest name; `narrated-review` keeps `tPress` as an alias in its own
   serialisation so nothing published changes.

**DoD for Phase R:** `narrated-review` behaves identically — its boot smoke
(37/37) and pipeline smoke (33/33) pass unchanged, its manifest and SKILL files
are untouched, and the reality doc gains the new core module. Nothing in Phase R
mentions `video-review`.

## Pipeline state machine (`vr-pipeline.js`)

```
idle → loaded (file probed: duration, size, has-audio, dimensions)
     → extracting-audio        (FFmpeg remux, or decode; typed no-audio-stream)
     → segmenting              (VAD cut — bounds are exact, no model involved)
     → transcribing            (parallel pool over clips; streams as they land)
     → framing                 (candidates sampled + scored per segment)
     → grouping                (adjacent same-frame segments merged)
     → pairs-ready ──────────► the shared review workspace
     → [optional] refining     (model picks among candidates)
     → [optional] cleaning     (screenshot-grounded cleanup, as the sibling tool)

  (any stage → error { code, stage }; every stage individually re-runnable)
```

Transcription and framing are **independent** and run concurrently: framing needs
only the segment bounds, not the words. On a long video that roughly halves the
wall-clock.

## Tool layout (sg-layout)

**Before processing** — one job, one button, and the cost stated up front:

```
┌────────────────────────────────────────────────────────────┐
│  ⬛ drop a video here, or choose a file                     │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  demo-walkthrough.mp4 · 18:42 · 412 MB · 1920×1080   │  │
│  │  audio: aac stereo ✓                                 │  │
│  └──────────────────────────────────────────────────────┘  │
│  transcribe  [openrouter ▾]   frames every [500ms ▾]       │
│  ☑ group segments that share a frame   ☐ model-refine      │
│  estimate: ~46 segments → ~18 pairs · ~$0.21   cap [$1.00] │
│                     [ ▶ Process ]                           │
└────────────────────────────────────────────────────────────┘
```

**After processing** — the sibling tool's workspace, plus the filmstrip:

```
┌──────────────────────────────┬──────────────────────────────────────┐
│ LEFT (36%)                   │ RIGHT (64%)                          │
│ ┌──────────────────────────┐ │ ┌──────────────────────────────────┐ │
│ │ Source                   │ │ │ Pairs │ Review │ Chat │ Doc │ 📦 │ │
│ │  ▶ video player          │ │ │ ┌──────────────┐                 │ │
│ │  18:42 · 18 pairs        │ │ │ │  chosen frame │  raw │ clean   │ │
│ ├──────────────────────────┤ │ │ └──────────────┘  notes          │ │
│ │ Steps                    │ │ │ ── filmstrip: other candidates ──│ │
│ │  ① Audio      ✓ remux    │ │ │ [▫][▫][■][▫][▫]  ← click to use  │ │
│ │  ② Segments   ✓ 46       │ │ │ 04:12.0  04:12.5  04:13.0 …      │ │
│ │  ③ Transcribe ✓ $0.09    │ │ │ ── segment bounds on the take ── │ │
│ │  ④ Frames     ✓          │ │ │  |───── 04:09 ─── 04:21 ─────|   │ │
│ │  ⑤ Group      ✓ 46→18    │ │ │  [↑ earlier] [↓ later] [+ split] │ │
│ │  ⑥ Document   ○          │ │ └──────────────────────────────────┘ │
│ └──────────────────────────┘ │                                      │
└──────────────────────────────┴──────────────────────────────────────┘
```

The **filmstrip is the new panel** and the one that earns its place: the most
common correction is "wrong frame", and because every candidate was already
decoded, fixing it is one click with no recomputation. Everything else on the
right is the sibling tool's workspace, unchanged. Designer owns the treatment;
the constraints that matter are **one primary action before processing, cost
shown before it starts, and the frame correctable in one click afterwards**.

## Flow trace (one pair, end to end)

```
drop demo.mp4 → getVideoInfo → 18:42, aac, 1920×1080 → estimate shown
[Process] → core/video extractAudio (FFmpeg remux) → .m4a
  → sg-audio-decode → PCM @16k
  → createVad(minSilence 700ms) → segment 12: tStart 04:09.4, tEnd 04:21.1 (EXACT)
  ├─ transcribe lane: slice → WAV → sg-transcribe → "and this is where the read key lives…"
  └─ frame lane:  window = [04:06.9 … 04:22.3]   (lead 2500ms, lag 1200ms)
        sample every 500ms → 31 candidates → greyscale diff →
        longest low-change run = 04:11.5–04:20.0 → pick 04:12.0, keep the rest
  → pair { tAnchor: 04:12.0, frame, candidates[31], raw, tStart, tEnd }
grouping: segment 13's frame ≈ segment 12's → merged, text concatenated
  → 46 segments → 18 pairs
→ shared workspace: review · filmstrip · notes · chat · document · PDF · vault
```
