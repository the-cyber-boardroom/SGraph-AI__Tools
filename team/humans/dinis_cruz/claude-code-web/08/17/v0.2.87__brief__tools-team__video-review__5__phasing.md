# Brief — Video Review · 5/5 Phasing & Acceptance

Build incrementally — each phase lands a working, committed slice. Prefer `Edit`
patches over big `Write`s; keep every file under ~300 lines.

---

## Phase 0 — Verification (½ day)

Five probes before real code. Two of them can invalidate a decision, which is the
point — the sibling tool's snap bug survived every synthetic test and only fell
to a real recording.

1. **Seek cost.** Seek one `<video>` element to 200 timestamps across a 20-minute
   1080p mp4, drawing each to a canvas. Measure. This decides whether
   `frameStepMs: 500` is affordable or has to be adaptive. If it is slow, fall
   back to sampling coarsely then refining around the winner.
2. **Settle detection against a real screencast.** Run Decision 4's metric over a
   genuine recording and eyeball whether the picked frames are the ones a human
   would have picked. **This is the probe that matters** — if the heuristic is
   wrong, model-refine becomes the default and the cost shape changes.
3. **The lead/lag window.** On the same recording, measure how far *before* each
   sentence the relevant screen change actually happened. Defaults of 2500/1200 ms
   are a guess; this replaces them with a number.
4. **Audio ladder on awkward inputs.** A screen-recorded WebM/Opus, an iPhone
   HEVC `.mov`, and a 1-hour mp4 — confirm the route ladder handles each and note
   the FFmpeg memory ceiling on the long one.
5. **Local Whisper timestamps.** `transcribeBuffer(model, audio, {timestamps:true})`
   on a 2-minute clip: confirm `chunks` come back with usable bounds, and time it.
   Decides whether the local lane is viable for the "no key at all" story.

Probe results are written back into part 2 as amendments.

## Phase 1 — Ingest → audio → segments (1 session)

Tool scaffold, dropzone + probe + `addVideo`, the audio route ladder, VAD
segmentation with exact bounds, `getSegments()`. No frames, no models yet.
**DoD:** drop a video, get a correct list of timed segments; a WebM and a `.mov`
both survive the ladder.

## Phase 2 — Transcription (½ session)

Parallel `core/sg-transcribe` over the clips, streaming into the segment list;
typed errors, cost roll-up, spend cap; the local-Whisper lane behind
`sttMode`. **DoD:** segments carry text with real timestamps; cost is visible;
one video transcribes with no key at all via local Whisper.

## Phase 3 — Frames + grouping → pairs (1 session) — **the milestone**

`vr-frames.js` (candidate sampling, settle scoring, keep-all-candidates),
`vr-group.js`, and the join into the shared pair model. At this point the tool
produces the artefact and the whole shared workspace lights up for free.
**DoD:** a real screencast in → an ordered document of frames and words out, with
no editing; the filmstrip lets a wrong frame be corrected in one click.

## Phase 4 — Review polish + refine (1 session)

Filmstrip panel, `setFrameAt` slider, split/merge, per-stage re-runs, and the
opt-in `refineFrames` model pass reporting how many frames it actually changed.
**DoD:** every automatic decision (frame, grouping, boundary) is correctable in
the UI, and refine's benefit is measurable rather than assumed.

## Phase 5 — Skills, registry, tests, reality (½ session)

Three SKILL files, manifest `api` section authoritative, registry overlay
(category **media**), Playwright boot smoke + a headless pipeline smoke over a
tiny generated test clip (`core/video generateTestClip` exists), reality doc
Part 2 + CHANGELOG, and an "As built" note appended to part 3.

**Total estimate: ~5 sessions**, of which one is Phase R — and that one pays for
itself immediately, because it is also the moment `narrated-review` stops being
the only owner of the review workspace.

## Acceptance criteria for v0.1

| # | Criterion | Verification |
|---|---|---|
| 1 | A 20-minute screencast becomes a sendable document with **no editing** | manual, measured against the sibling tool's own bar |
| 2 | Timestamps are exact, not model-claimed: every segment's bounds match the audio it was cut from | assert bounds against the VAD cut in the pipeline smoke |
| 3 | The chosen frame shows what is being discussed, on a real recording | Phase-0 probe 2 promoted to a scored check over a fixture clip |
| 4 | A wrong frame is corrected in **one click**, with no recomputation | Playwright: `setFrame` then assert no new decode |
| 5 | Grouping collapses repeated screens (46 → ~18 on the fixture) and is reversible | pipeline smoke: group, then `splitPair`, then compare |
| 6 | The video never leaves the browser; only audio clips and chosen frames go to OpenRouter | DevTools network audit |
| 7 | Cost is shown **before** processing and the spend cap halts mid-run | test |
| 8 | A one-hour video completes without exhausting memory | manual, with the Phase-0 probe-4 numbers |
| 9 | Full headless run via `window.__tool`; the post-pairs half of the script is **identical** to narrated-review's | Playwright |
| 10 | `narrated-review` is unchanged by Phase R | its own smokes, unmodified |
| 11 | SgToolApi + 3 SKILL files + manifest + registry complete; all files ≤ ~300 lines; reality doc updated in the same commits | review |

## Dependencies + risks

- **The settle heuristic is the risk that matters.** If Phase-0 probe 2 shows it
  picking poorly, the fallback is model-refine by default — which works, but
  changes the cost story from "pennies" to "cents per pair". Decide with the
  probe, not in the abstract.
- **FFmpeg on long files** — ~30 MB CDN fetch on first use, and memory pressure on
  hour-long inputs. `core/video` v1.0.2 has the WORKERFS build (multi-GB safe);
  route 2 (decode-to-WAV) avoids FFmpeg entirely for smaller files.
- **Silent or music-only video** → `no-audio-stream`; the tool should offer
  frame-only mode (sample scenes, no text) rather than failing flat. Parked, but
  the error code exists so the affordance can be added later.
- **Cost on long videos** — the honest ceiling. Grouping on by default, refine off,
  estimate first, cap offered.
- **Browser seek behaviour varies** — some codecs never fire `seeked`;
  `sg-video-frames` already falls back to FFmpeg for exactly this.

## What's deliberately out of v0.1 (ranked v0.2 queue)

1. **Short video clips in the artefact** — some moments are a motion, not a still.
2. **Speaker diarisation** — turns a call recording into an attributed document.
3. **Frame-only mode** for silent video (scene detection without a transcript).
4. **URL ingest** (YouTube etc.) and, with it, the fetch/CORS question.
5. **OCR-anchored frame choice** (Decision 4d) if the settle metric proves weak.
6. **Cross-session vault memory** — the same catalogue question the sibling tool parked.
