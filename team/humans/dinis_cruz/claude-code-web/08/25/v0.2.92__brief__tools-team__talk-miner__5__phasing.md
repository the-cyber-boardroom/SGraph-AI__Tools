# Brief — Talk Miner · 5/5 Phasing & Acceptance

Build incrementally — each phase lands a working, committed slice. Prefer `Edit`
patches over big `Write`s; keep every file under ~300 lines.
**PROPOSED — does not exist yet.**

## Phase 0 — Two checks and a real talk, before writing anything (½ day)

**This phase can cancel or redirect the whole project, so it comes first.**

### 0a · The fifteen-minute API check

With an OAuth token for your own channel, and `curl`:

1. `captions.list` for one of your talks. Is there a track at all? Is it
   `trackKind: 'ASR'`?
2. `captions.download` on that track. **Does the API hand back an auto-generated
   track to a third-party client, or refuse it?**

**This single answer decides the tool's shape** (Decision 2):

| Outcome | Consequence |
|---|---|
| ASR downloads work | Route B is primary. Cheap, fast, no VAD anywhere. Build as written. |
| ASR downloads refused | Route B only works on manually-uploaded tracks — probably none of yours. The corpus runs on route A/C + real transcription, and **Phase 2 becomes optional** |

Do not design around the outcome you would prefer. Fifteen minutes now saves a
fortnight of building the wrong primary path.

### 0b · One real talk through the tool that already exists

Download one talk from Studio, run it through `narrated-review` `importVideo()`
today, and look at the result honestly:

- How many captures, and how many were **force-cut** (`capped`) rather than cut at
  a pause? A conference talk is continuous speech with an audience — this is
  exactly the condition that produced nine identical 30-second captures on a
  screencast.
- Do the **chosen frames** show slides, or do they show you? Run it through
  `media-probe` and look at the filmstrip and the scene list.
- Does `blockMax` fire on your hands?

**Acceptance:** you can state, from measurements rather than expectation, whether a
region mask is necessary. If the frame heuristics already work on talk footage,
Decision 3 evaporates and Phase 3 shrinks to nothing. **Nobody knows yet**, and the
whole of part 2 Decision 3 is reasoning from the shape of the problem, not from a
measurement.

### 0c · The honest exit

If routes A + `importVideo` handle three talks well enough by hand, **stop and say
so**. Fifteen videos is not obviously past the threshold where a corpus tool pays
for itself, and the strongest outcome of Phase 0 may be "the tool we have is
enough, here are the fifteen documents".

## Phase 1 — Captions into `core/youtube-api` (1 day)

- `core/youtube-api` **v0.2.0**: `listCaptions`, `downloadCaption`, and
  `captions-parse.js` (SRT/VTT/SBV → cues). Scope escalation to `force-ssl` only on
  demand.
- `listCaptions` surfaces `trackKind` so the UI can distinguish ASR from an edited
  track before anyone relies on it.

**Acceptance:** cues parse for a real talk, byte-exact against the downloaded file;
`asr-download-refused` is a distinct, catchable error from `no-captions`; unit tests
over captured SRT/VTT text with no browser (the `sg-markdown` node-test pattern —
`tests/node/`). `youtube-editor` still boots on the new module version.

## Phase 2 — `importYouTube` as the fourth ingest (1½ days)

*Skip or reduce if Phase 0a said ASR downloads are refused.*

- `api/nr-youtube.js` in a new `narrated-review` overlay: cues → grouped captures
  against slide boundaries (Decision 6), `words: 'captions'` on every capture.
- Captions-only mode (no frame source) produces captures with words and no images —
  and reports that in `gaps_in_analysis`, not silently.

**Acceptance:** a real talk becomes captures whose text matches the caption file
verbatim before cleanup; grounded cleanup demonstrably corrects at least one
technical term against the slide (the `acme-vault-archive` effect); the boot smoke
still passes untouched, and a new smoke covers the captions path with the API
mocked.

## Phase 3 — The region mask (1½ days)

*Only if Phase 0b showed it is needed.*

- `core/sg-media-analysis` **v0.2.0**: `mask` on `signatureFrom()`, threaded
  through the sampler. Everything downstream unchanged.
- `mask-suggest.js` — per-pixel variance across ~40 frames proposes the rectangle.
- `media-probe` gains a draggable mask over the filmstrip, metrics recomputing live.
- `mask-unusable` when the masked region has no separable classes.

**Acceptance:** on the real talk from Phase 0b, masking raises the scene count to
roughly the slide count and drops the false detections on speaker movement — stated
as before/after numbers, not as an impression. On deliberately intercut footage the
tool **refuses with `mask-unusable`** rather than emitting a scene list.

## Phase 4 — The corpus (2 days)

- `talk-miner`: store, `addTalk`/`listTalks`, `groupSlides` (free, no model),
  `estimateCorpus`, the library and slides panels.
- Concept layer: `proposeConcepts` over the agentic-chat plumbing, every concept
  carrying `mentions`; `setConcept` for human curation; `buildConceptDoc`.

**Acceptance:** three real talks in one corpus; slide dedupe finds a genuinely
reused diagram and reports first/last use; **no concept without citations exists in
the store** (asserted, not merely intended); `estimateCorpus` states the spend
before `proposeConcepts` runs; base64 image overhead measured against the VFS text
limit rather than assumed.

## Phase 5 — Tab capture (1 day)

- `importTab()` — the live path with a shared tab as source. Real-time warning, tab
  audio support stated up front, cancellable.

**Acceptance:** a 5-minute video captured end to end produces captures; the panel
says "this runs in real time" before the picker opens, not after.

## Definition of done

- Every file under ~300 lines; `api/`+`ui/` split as mandated.
- SgToolApi with `activate()` before UI; three SKILL files; manifest with the full
  action and event catalogue; registry entry.
- Boot smoke asserting the action surface and the documented DOM ids.
- **Node tests for the caption parsers** (no browser, no network — the
  `tests/node/sg-markdown.test.mjs` pattern), and a Playwright smoke with the
  YouTube API mocked at `fetch`.
- **A test over talk-shaped footage, not screencast-shaped.** Synthetic clips have
  now hidden two defects in this project — digital silence hid the threshold bug,
  and a static frame hid the colour-blindness bug. The corresponding trap here is a
  synthetic "talk" with a still speaker. Generate one with a *moving* element
  outside the slide region, or the mask tests prove nothing.
- Reality document and CHANGELOG updated in the same commit as the code.

## Risks, and what we do about them

| Risk | Mitigation |
|---|---|
| **ASR captions cannot be downloaded** — the pack's cheapest path evaporates | Phase 0a, before any design. Routes A and C still work; the corpus layer is unaffected |
| **The mask is not enough** for intercut footage | Detect and refuse (`mask-unusable`), fall back to captions-only. Do not emit boundaries built on noise |
| Auto-caption quality is poor on technical vocabulary | That is what grounded cleanup is for, and it is the *reason* to keep the expensive lane. Measured in Phase 2's acceptance |
| **Concepts drift into plausible fiction** | `mentions` is required and enforced at the store, not by convention (Decision 8). A concept is a view over captures, never a copy |
| Corpus-scale spend surprises | `estimateCorpus` before the run; every generation lands in the existing billing ledger with its receipt |
| Base64 images blow past the VFS | Measured in Phase 4. A Blob-native provider is the fix if needed — one place, `nr-store.js`'s two helpers |
| **Building a second narrated-review** | Decision 9. Ingest is a mode; only the cross-talk index is a tool. This is the v0.2.87 lesson, already paid for once |

## What this pack does not claim

The mask, the variance-based suggestion, the grouping rule, the slide-dedupe
threshold and every cost figure beyond `COST_BASIS` are **starting points, not
findings**. The measured facts are: $0.0130 transcription and $0.0343 cleanup per
capture with cleanup at 73% of spend; `core/youtube-api` v0.1.0 exists with no
caption support; OAuth and token caching already work in `youtube-editor`; nothing
in the repo touches `timedtext`.

Everything else — most importantly *whether talk footage needs a mask at all* — is
a hypothesis Phase 0 exists to test. **Half a day with one real talk is worth more
than this entire document.**
