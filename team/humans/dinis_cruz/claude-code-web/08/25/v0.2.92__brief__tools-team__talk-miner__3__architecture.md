# Brief — Talk Miner · 3/5 Architecture

Follows the mandated split (`api/{state,events,pipeline,api}.js` + one `ui/ui-*.js`
per panel), manifest-loader boot, sg-layout shell, every file under ~300 lines.
**PROPOSED — does not exist yet.**

## 1. Layout, and who owns what

The work splits three ways, and the split is Decision 9: a **mode** where it is
another door into the capture list, a **core module change** where it is a
measurement improvement, a **tool** only where it is genuinely above a session.

```

  sg-youtube-api.js       + listCaptions(videoId), downloadCaption(id, fmt)
  captions-parse.js       NEW — SRT/VTT/SBV cues → [{ tMs, endMs, text }]

core/sg-media-analysis/v0/v0.2/v0.2.0/      ← EXTEND (v0.1.0 exists and works)
  frame-metrics.js        + region mask on signatureFrom()

  api/nr-tabcapture.js    NEW — thin: route C is the LIVE path with a tab as source
```

## 3. The three routes, end to end

```
 ROUTE A — Studio download                                   WORKS TODAY
   Studio → original.mp4 → narrated-review importVideo()
   ▸ nothing to build. Use it in Phase 0 to answer the open questions.

 ROUTE B — captions + masked frames                          THE NEW PATH
   sign in ─► listMine() ─► pick a talk
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
    listCaptions(videoId)            frame source (A's file, or C's tab)
    downloadCaption(id,'vtt')                 │
    parse → cues[{tMs,endMs,text}]     set/suggest MASK  ◄── Decision 3
              │                               │
              │                        masked frame sweep
              │                        → slide-change boundaries
              └───────────────┬───────────────┘
                              ▼
              group cues between boundaries        ◄── Decision 6
                              ▼
                    captures: slide + words
                              ▼
              grounded cleanup (fixes ASR vs slide text)
                              ▼
                   narrated-review's whole back half

 ROUTE C — tab capture                                       FALLBACK
   play in a tab → getDisplayMedia({video,audio}) → the LIVE path, unchanged
   ▸ real time. 45-minute talk = 45 minutes.
```

**Note what route B does not need:** no VAD, no silence threshold, no calibration.
The timings come from the caption file. The entire class of defect that has bitten
this project twice cannot arise on this path — which is worth more than the 27%
cost saving.

## 4. The region mask

One change, at the bottom, and everything above it is untouched:

```js
// core/sg-media-analysis v0.2.0 — frame-metrics.js
signatureFrom(rgba, { mask })   // mask = { x, y, w, h } in 0..1 of the frame
```

The signature is built from the masked rectangle only. `diff()`, `otsuSplit()`,
`findScenes()`, `compareMetrics()` and the whole of `plan()` are unchanged, because
they never see pixels — they see signatures.

**`mask-suggest.js` proposes a starting rectangle** rather than making the user
guess: sample ~40 frames, compute per-pixel variance across them, and the region
that changes *rarely but completely* is the slide, while the region that changes
*constantly and slightly* is the speaker. Present it as a suggestion on a thumbnail
with handles, never as a silent decision — the same discipline as the frame
candidates in `narrated-review` and the threshold slider in `media-probe`. When the
operator drags it, the metrics recompute and the scene count updates live.

**When it cannot work,** say so (Decision 3): if the masked region's own
distribution has no separable classes, report intercut footage and offer
captions-only with no images, rather than emitting a scene list built on noise.

## 5. Cost model, extended

`COST_BASIS` in `core/sg-media-analysis/.../plan.js` already carries the measured
per-capture figures from the real session, and `estimateCost()` already reports
in dollars. Route B changes one term:

```js
// talk-miner adds no new constants — it reuses the measured ones and drops a lane
estimateCorpus(talks, { captionsAvailable }) →
   captions ? captures * CLEAN_ONLY        // $0.0343
            : captures * (TRANSCRIBE+CLEAN) // $0.0473
```

Show the corpus total **before** the run, per talk and in aggregate, the way
`media-probe` shows the sweep estimate before committing. Fifteen talks is the
first time in this project's history that a wrong default costs real money.

## 6. The corpus store

One VFS folder per talk, plus one index — the same shape `nr-store.js` already
uses, one level up:

```
/talk-miner/index.json                     talks[], concepts[], slideGroups[]
/talk-miner/<talkId>/session.json          a narrated-review session, unchanged
/talk-miner/<talkId>/images/…              base64 (see the caveat)
/talk-miner/<talkId>/captions.vtt          the source cues, kept verbatim
```

**Two things carried over from what already exists, deliberately:**

- **`core/sg-vfs` is text-only.** Its provider stores `String(content)`, so images
  are base64 (~33% larger). Already true of `nr-store.js`, already documented, and
  fine — but fifteen talks × 40 slides is thousands of images and it is the first
  time the overhead will actually be felt. Measure it in Phase 4 before assuming.
- **The captions file is kept verbatim.** Same rule as `raw` transcripts: the
  source ships with the derived, and cleanup never overwrites it.

`index.json` holds **references**, never copies (Decision 7). Edit a capture in the
per-talk document and every concept citing it is correct immediately, because there
is only one copy of the text.

## 7. Slide dedupe across talks

Falls out of code that exists. `frame-metrics.signatureFrom()` already produces a
per-frame fingerprint and `diff()` already compares two; the same slide reused in
three talks yields three near-identical signatures. Store the signature with each
capture, compare across talks, group below a distance threshold — the threshold
chosen by `otsuSplit()` over the observed distances, **not** a constant, for the
reason this project keeps relearning.

Output: *"this diagram appears in four talks, first in Mar 2024, last in Aug 2026"* —
a genuinely new fact about the corpus, from a few dozen lines and no model call.

## 8. What Talk Miner deliberately does NOT do

- No downloading by any route YouTube does not provide, and no proxy.
- No arbitrary-URL ingest for the caption/metadata routes (Decision 1).
- No re-upload, no editing back on YouTube — `youtube-editor` already owns that.
- No video clipping: stills only, as in every tool in this family.
- No concept without citations (Decision 8).
