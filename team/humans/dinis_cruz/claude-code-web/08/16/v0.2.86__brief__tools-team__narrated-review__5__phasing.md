# Brief — Narrated Review · 5/5 Phasing & Acceptance

Build incrementally — each phase lands a working, committed slice. Prefer `Edit` patches over big `Write`s; keep every file under ~300 lines. The build order tracks the source brief's own (its step 3, the plain document, is the milestone).

---

## Phase 0 — Verification (½ day)

Five cheap probes before real code:

1. **Frame-grab fidelity.** `getScreenStream` → `<video>` → `drawImage` → PNG on a keydown in a narrow focused window. Confirm the PNG is full track resolution and the text on it is model-readable. (No background-throttling risk expected — the tool window is focused at press time — but verify.)
2. **Ring-slice round trip.** audio-transcribe v0.1.60's `live-capture.js` PCM ring → slice an arbitrary `[tStart, tEnd]` → `encodeWav` → `sg-transcribe.transcribeItem` → text. This validates the whole Decision-2 mechanism with zero new engine code.
3. **The speak-before-press test.** Say a sentence, press mid-sentence, confirm the VAD snap recovers the sentence start from the lookback window. This is the source brief's catch, promoted to a probe.
4. **Cleanup effectiveness.** Hand a garbled transcript ("Eskit", "Skid" for the product name) + a screenshot showing the correct spelling + an empty summary to the Decision-6 prompt via `sg-llm-request` v0.1.6. Confirm the multimodal model (default `audio-models.js` pick) fixes the name and emits valid strict JSON with `marks`. Run once text-only for the before/after — this reproduces the corpus's 6 Aug evidence on our own pipeline.
5. **Document PiP probe (Chrome).** Can a `documentPictureInPicture` window host a MARK button that calls back into the session? Ten-line probe; result decides whether Decision 3's option B ships in v0.1 or waits.

Probe results are written back into part 2 as amendments.

## Phase R — Extractions (½–1 session, lands FIRST)

- **R1:** `core/sg-zip` v0.1.0 from audio-transcribe v0.1.60 `api/audio-zip.js` (the reality doc's own flagged gap); audio-transcribe re-pins in its next overlay.
- **R2:** `core/sg-live-capture` v0.1.0 from `api/live-capture.js` + `api/live-vad.js` (already dependency-injected; the v0.1.93 guide invites exactly this); audio-transcribe + live-transcribe re-pin.

**DoD:** both are behaviour-identical releases — existing audio-transcribe/live-transcribe Playwright smokes green, `at:*` contract untouched, reality doc Part 1 gains the two modules, and nothing in this phase mentions narrated-review.

## Phase 1 — Capture loop + pairs (1 session)

Tool scaffold (manifest, state, events, shell, capture panel), screen share + continuous PCM ring + take recorder, `markMoment()` with screenshot grab + VAD snap, pair list filling live, VAD suggestion ticks collected. **Definition of done:** narrate over a real screen in the narrow-window layout, press 5 times, get 5 pairs each holding a full-res PNG and correct `[tStart, tEnd)` bounds (verified against the take), session take saved.

## Phase 2 — Transcription (½ session)

Wire `core/sg-transcribe`: slice → WAV → parallel transcribe as bounds close, per-pair cost, spend cap, typed errors; key chip + `sg-openrouter-key-stats`. **DoD:** pairs reach `raw` while the session is still being captured; costs visible per pair.

## Phase 3 — Assembler + export (1 session) — **the milestone**

`nr-document.js` (pure), Document preview via `core/markdown`, `core/sg-zip` bundle (review.md + images/ + audio/ + raw/ + session.json), `send-drop` link, copy-markdown. **DoD:** capture → Finish → export in ≤3 interactions with **no editing step**; the zip's `review.md` hands to any assistant and reads as an ordered walkthrough. This is the acceptance bar's first measurement — a plain document of screenshots + raw transcripts already beats a video.

## Phase 4 — Screenshot-grounded cleanup + rolling summary (1 session)

`nr-cleanup.js`: sequential lane, strict-JSON `{cleanText, marks, summary}`, `[unsure]` marks rendered, summary persisted, `text-only`/`off` modes, raw untouched everywhere. **DoD:** the Phase-0 name-correction probe passes end-to-end inside the tool; a session with a term established in pair 2 has it spelled correctly in pair 9; `review.md` shows clean text with raw in the appendix.

## Phase 5 — Review pass + skills + reality (1 session)

Boundary drag on the take timeline, editable clean text, per-pair re-transcribe/re-clean, VAD-tick promotion; full SgToolApi surface incl. the headless import path; 3 SKILL files; registry overlay (`TOOL_SLUGS` + header changelog, category **media**); Playwright smokes — boot smoke + a headless `addRecording → markAt → transcribeAll → cleanAll → buildDocument` run with mocked OpenRouter; reality doc Part 2 entry + CHANGELOG.

**Total estimate: ~4½–5½ sessions** (~1 of which is Phase R, which pays for itself — every media tool gets `sg-zip` and `sg-live-capture` for free afterwards).

## Acceptance criteria for v0.1

| # | Criterion | Verification |
|---|---|---|
| 1 | **Press send and not worry about it:** capture → export with zero edits produces a usable document | first real session, measured literally (the source brief's own test) |
| 2 | **No lost first seconds:** a sentence begun before the press appears whole in its segment | Phase-0 probe 3 promoted to a scripted test |
| 3 | Each pair = image + the words about it, in press order, in one markdown file | inspect `review.md` |
| 4 | A term misheard by the recogniser but visible on screen is corrected by grounded cleanup, and uncertain spans carry `[unsure]` marks — never silent resolution | Phase-0 probe 4 promoted to a mocked Playwright test |
| 5 | Raw transcript survives every operation (clean, edit, re-clean, export) | code review + test |
| 6 | Nothing leaves the browser except audio segments and (grounded mode only) screenshots, both to OpenRouter under the user's key; `off` mode sends nothing after transcription | DevTools network audit |
| 7 | Cleanup cost is ~constant per segment (screenshot + summary only — no history growth) | inspect request payloads across a 20-pair session |
| 8 | Full headless run via `window.__tool` (part 4 script) with no gestures | Playwright, mocked OpenRouter |
| 9 | Spend cap halts both lanes; typed error codes surface | test |
| 10 | SgToolApi + 3 SKILL files + manifest event catalogue + registry entry complete; all files ≤ ~300 lines; reality doc updated in the same commits | api-pane inspection + review |

## Dependencies + risks

- **OpenRouter key required** for transcription and cleanup — without it the tool still captures pairs and exports a document of images + untranscribed audio (degraded but not dead).
- **Multimodal model availability** — cleanup needs image+text in one call; the curated `audio-models.js` default handles both, but the cleanup model list must be its own curated set (probe 4 informs it).
- **Marker ergonomics** — the narrow-window rhythm is unproven; the PiP probe is the hedge, and VAD suggestions catch unmarked moments. First real session feedback drives v0.2 here.
- **Screenshot privacy** — screens carry secrets; grounded mode is prominent + toggleable (Decision 9), and the redact affordance (`core/image`) is queued for v0.2.
- **Memory** — 16 kHz mono Int16 ≈ 2 MB/min PCM + the webm take; fine for sub-hour sessions, `sg-recording-size` watches the take; document the practical ceiling in SKILL-human.

## What's deliberately out of v0.1 (ranked v0.2 queue)

1. **Vault as home** — sessions written via `core/vault-write` v1.1.1, memory across reviews, session index (the catalogue question); brings "chat with this review" via the chat components.
2. **Annotation** — vector overlay kept (`core/image` ops as the base), flattened composite shipped per pair.
3. **Screenshot-only mode** — same pipeline, capture front end without audio.
4. **Document PiP marker** (if probe 5 says no for v0.1) and same-tab `preferCurrentTab` mode.
5. **Redact-before-share** pass; pause-suggested auto-pairs; local `sg-whisper` STT fallback.
