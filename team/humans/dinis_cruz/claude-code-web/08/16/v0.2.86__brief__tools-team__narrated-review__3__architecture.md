## The pair structure (`nr-state.js`)

The unit is the pair; everything downstream operates on the ordered list:

```js
pair = {
  id, seq,                    // seq = press order, the document order
  tPress,                     // ms on the session timeline (the take's clock)
  tStart, tEnd,               // segment bounds — VAD-snapped, user-adjustable, may overlap
  screenshot,                 // PNG Blob grabbed at tPress (full track resolution)
  raw:   { text, model, generationId, costUsd },          // immutable once set
  clean: { text, marks:[{span,note}], model, generationId, costUsd } | null,
  status: 'marked'|'transcribing'|'raw'|'cleaning'|'clean'|'error',
  error: { code, step } | null,
}
session = { id, startedAt, status, pairs: [], suggestions: [],   // VAD ticks (t only)
            take: Blob|null, rollingSummary: '', config, costs }
```

## Session state machine

```
idle → capturing (screen picked + PCM ring live + take recording)
         markMoment() ×N ── pair 'marked' → slice → 'transcribing' → 'raw'   (parallel lane)
endSession() → take finalised ─► cleanup queue in seq order:
                                 'raw' → 'cleaning' → 'clean'                (sequential lane)
              → reviewing (edits, boundary drags, re-runs — every step re-runnable per pair)
              → buildDocument() → exported (zip / send / copy)
  (any step → error {code, step}; a failed clean leaves raw standing — never blocks the doc)
```

Transcription starts the moment a pair's bounds close (the *next* press or session end) — pairs stream to 'raw' while the narrator is still talking. Cleanup waits for session end because the rolling summary is order-dependent (Decision 7); a `cleanEarly` config can relax this later.

## Flow trace (one pair, end to end)

```
keydown in tool window → nr-marker.markMoment()
  → screenshot: drawImage(screenVideo) → canvas.toBlob('image/png')
  → boundary: live-vad nearest-silence snap in [tPress−4000, tPress]
  → pair {seq, tPress, tStart, screenshot} added → nr:mark + nr:pair:added
next keydown closes tEnd → nr-pipeline: PCM ring slice → encodeWav
  → sg-transcribe.transcribeItem (isolated transport, parallel) → raw.text + costUsd
     → nr:transcribe:complete → ui-pairs row fills in while capture continues
Finish → take finalised → cleanup queue (seq order):
  sg-llm-request ← [screenshot, raw.text, rollingSummary]
  → {cleanText, marks, summary} → pair.clean + session.rollingSummary
     → nr:clean:complete → nr:summary:updated
buildDocument() → review.md (per pair: ## heading · image ref · clean text
  · [unsure] footnotes · raw appendix) + images/ manifest → nr:document:built
downloadZip() / send-drop offerFile() / copy markdown
```

## As built (same day — v0.1.66)

The implementation followed this part closely. Six things worth recording:

1. **No `core/sg-live-capture` VAD session was needed.** The plan implied reusing
   the utterance-emitting VAD; in practice narrated-review needs the *energy /
   threshold* model for **boundary snapping**, not utterance emission. So
   `live-vad.js` is promoted and pinned, but `nr-capture.js` keeps its own RMS
   log and `snapBoundary()` walks it. `createVad()` remains available for the
   pause-suggestion work in v0.2.
2. **PCM is stored Int16 for the whole session** (~1.9 MB/min at 16 kHz) rather
   than a rolling ring. Keeping every frame is what makes `setBoundary` able to
   re-slice *any* pair at any time — the pack's "boundaries stay adjustable"
   promise is otherwise only true for recent audio.
3. **The session clock is the audio clock** (frames seen × frameMs), not
   wall-clock, so slices stay sample-accurate under main-thread jitter.
4. **`transcribeAll` awaits in-flight streaming work.** Pairs start transcribing
   the moment their bounds close mid-capture, so the first implementation
   reported `done: 0` while three transcriptions were in flight. The lane now
   tracks in-flight promises and awaits them, making the action idempotent and
   *complete on return* — the contract an agent expects.
5. **`core/sg-zip` is generic.** The plan said "extract audio-zip.js"; what was
   actually extracted is the reusable half (`loadJSZip` + `zipEntries` over a
   flat path list). The bundle *shape* stayed tool-side in `nr-zip.js`, which is
   the right seam — audio-transcribe's shape (manifest.json + index.txt) and
   narrated-review's (review.md + images/ + audio/ + raw/) are genuinely
   different documents.
6. **Boundary editing is numeric (ms) in v0.1**, not a draggable timeline. The
   data model supports dragging fully (`setBoundary` re-slices); only the
   affordance is deferred.

Deferred from this part as planned: the Document-PiP probe (needs a real
gesture), and the audio-transcribe / live-transcribe re-pin onto
`core/sg-live-capture` (additive extraction — nothing existing was changed).
