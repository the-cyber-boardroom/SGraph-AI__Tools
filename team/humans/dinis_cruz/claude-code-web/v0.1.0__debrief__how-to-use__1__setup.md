# Debrief 3a — How to Use · Setup Checklist

**Date:** 25 April 2026

The youtube-editor needs an OAuth Web Client ID from a Google Cloud project that owns the channel you'll be working with. This is a one-time setup. The tools.sgraph.ai default client ID is bundled, but you'll typically use your own.

---

## Step 1 — Pick or create a Google Cloud project

[https://console.cloud.google.com/](https://console.cloud.google.com/) → top bar → New Project (or select an existing one).

The project's quota is what gets consumed by uploads + edits.

---

## Step 2 — Enable the APIs

**APIs & Services → Library** → enable these two:

- **YouTube Data API v3** (covers channels/videos/playlists/uploads/thumbnails)
- **YouTube Analytics API** (covers channel + per-video analytics — only needed if you want the 📈 Analytics features)

---

## Step 3 — Configure the OAuth consent screen

**APIs & Services → OAuth consent screen.**

| Field | Value |
|---|---|
| User type | **External** (Workspace orgs may pick Internal) |
| App name, support email, dev contact | Fill in |
| **Scopes** | Add **two**: `https://www.googleapis.com/auth/youtube` and `https://www.googleapis.com/auth/yt-analytics.readonly` |
| **Test users** | Add your Google account email — required while the app is in Testing mode (max 100) |

Both scopes are "sensitive" and would normally trigger Google's verification process for production. While **in Testing mode** with you as a test user, no verification is needed.

If you only add the `youtube` scope (not analytics), the tool still works — you'll just get an inline notice in the Account panel telling you to add the second scope and reconnect.

---

## Step 4 — Create the OAuth Client ID

**APIs & Services → Credentials → Create credentials → OAuth client ID.**

| Field | Value |
|---|---|
| Application type | **Web application** |
| Name | e.g. "tools.sgraph.ai — YouTube Editor" |
| **Authorised JavaScript origins** | Every origin you'll load the tool from. Examples: `https://tools.sgraph.ai`, `https://dev.tools.sgraph.ai`, `http://localhost:8000`, `http://localhost:10063`. Add all of them. |
| Authorised redirect URIs | **Leave blank** (GIS token client doesn't use redirect URIs) |

Copy the resulting client ID — looks like `123456789-abcdef.apps.googleusercontent.com`.

---

## Step 5 — Open the tool

Visit `/en-gb/youtube-editor/` (under `tools.sgraph.ai` or your local origin).

In the left **🔑 Account** panel:

1. Paste your client ID into the **Google OAuth Client ID** field (or leave the bundled tools.sgraph.ai one if you want to use that).
2. Click **Connect to YouTube**.
3. Google's consent popup appears. Approve. The popup closes.
4. The channel card populates — banner image, avatar, handle, joined date, stats.
5. The **📈 Last 28 days** card populates a moment later (one extra Analytics API call).

You're connected. The token is cached in `localStorage['sg-auth-token-youtube-editor']` and will silently refresh on next visits while still valid.

---

## Quota awareness

YouTube Data API v3 default quota is **10 000 units / day**.

| Operation | Units | Notes |
|---:|---:|---|
| List a page of uploads | 1 | 50 videos per page |
| Enrich a page with stats | 1 | Single `videos.list?id=...` for the whole page |
| Edit a video | 50 | snippet/status/title/desc/tags/privacy |
| Set a thumbnail | 50 | image upload |
| Add to / remove from playlist | 50 each | per playlist toggle |
| Find which playlists a video is in | 1 / playlist | fan-out (no native endpoint) |
| **Upload a video** | **1 600** | dominant cost |
| Delete a video | 50 | not exposed in UI |

Analytics API has its **own quota**, separate from this — generous (~1 q/s/user), no daily unit cap.

To raise the Data API quota: **APIs & Services → YouTube Data API v3 → Quotas → Edit Quotas → submit the audit form**. Takes Google a few weeks to review.

## Storage created on your browser

Two `localStorage` keys, both per-origin:

| Key | Contents | When set |
|---|---|---|
| `sg-youtube-client-id` | Your OAuth client ID | When you change the input field |
| `sg-auth-token-youtube-editor` | `{ accessToken, expiresAt, scope, savedAt }` | After OAuth grant; cleared on Sign-out |

Both will be migrated to the SGraph vault in a future minor version. The cache adapter (`youtube-token-cache.js`) is one file, so the swap is contained.

Nothing else is stored locally. **No video bytes ever transit an SGraph server** — all uploads/downloads/API calls go directly browser → Google.

## When something doesn't work

| Symptom | Most likely cause | Fix |
|---|---|---|
| "Access blocked: Authorisation error · The OAuth client was not found" | Client ID typo | Double-check the ID; trailing whitespace is a common gotcha |
| "Origin mismatch" / "redirect_uri_mismatch" | Your current origin isn't in the Authorised JavaScript origins list | Add it in the Cloud Console; takes a couple of minutes to propagate |
| "Access blocked: This app's request is invalid" | App is in Testing mode and you're not a test user | Add yourself under OAuth consent screen → Test users |
| Avatar shows as broken image | Google's avatar host needs `referrerpolicy="no-referrer"` (already set in our code) — if you still see this, check browser extensions blocking it |
| Channel card empty after sign-in | Cached token has only `youtube` scope, not analytics | Sign out + reconnect to get fresh consent |
| 403 on analytics calls | Analytics API not enabled on the project | Enable it (Step 2) |
| 403 on upload | Quota exhausted (1 600 units = ~6 uploads/day default) | Wait until midnight Pacific, or raise the quota |
