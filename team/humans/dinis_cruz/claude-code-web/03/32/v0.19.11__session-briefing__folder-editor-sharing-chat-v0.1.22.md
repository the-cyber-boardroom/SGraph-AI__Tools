### 5. Folder Editor v0.1.23 — SG/Send Sharing

Based on v0.1.21. Adds full SG/Send sharing:

**New helpers:**
- `contentToBlob(content, mimeType)` — converts VFS content (text string or `data:` dataURL) to `Blob`

- `shareSelected()` — gets selected tree IDs, calls above helpers, then calls `sendDropEl.offerFiles(files, zipName)` on the `sg-send-drop` element

**Layout changes:**
- Bottom-right panel is now a **tab stack**: "Seed Data" (`sg-vfs-seeder`) + "Share ↗" (`sg-send-drop`)
- Added "Share ↗" button to tree toolbar

**Sharing behaviour:**
- Single file → `offerFile(blob, filename)` (no zip)
- Folder or multi-select → `offerFiles(files, name.zip)` — sg-send-drop lazy-loads JSZip, zips with full directory tree preserved, then does token generation + AES-256-GCM encrypt + 3-step upload
- Uses `sg-send-drop v1.0.0` from `components/send-drop/v1/v1.0/v1.0.0/`

## Critical Technical Reminders

- **sg-layout LAYOUT_READY** fires through custom `_events` emitter, NOT DOM `dispatchEvent`. Use `layoutEl.events.on(SGL_EVENTS.LAYOUT_READY, resolve)` — not `addEventListener`.
- **`[hidden]` override** — any element with explicit `display:flex` CSS needs `[hidden] { display: none !important }` in the tool's `<style>` block.
- **sg-tree private methods** — `_createFolder`, `_deleteNode`, `_startRename` all have underscore prefix.
- **sg-vfs-seeder event protocol** — uses `vfs:write-request` / `vfs:write-response` with matching `requestId`. Walks `parentElement` up DOM to find `[data-vfs-bus]`.
- **Named exports only** — no default exports anywhere in this codebase.
- **No build step** — every file must be deployable as-is. No webpack, no bundler.
- **VFS content storage** — text files stored as strings, binary files as `data:mime;base64,...` dataURLs. `contentToBlob()` in folder-editor v0.1.23 handles both.
