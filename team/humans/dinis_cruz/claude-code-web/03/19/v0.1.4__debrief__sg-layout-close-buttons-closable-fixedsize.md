## What Was Done

### 1. Close Button on Single-Tab Headers

**Problem:** When a stack has only one tab, sg-layout renders a title bar (not a tab bar). The title bar had a collapse `—` button but no close `×`. Users of SG/Vault couldn't close single-tab panels without first dragging another tab in to create a multi-tab stack.

**Fix:** Added a close button in the header actions area for single-tab stacks. Reuses the same `_closeTab()` method as multi-tab close buttons. Respects `locked: true` — no close button rendered for locked panels.

**CSS class:** `.sgl-header-close-btn` — styled consistently with `.sgl-collapse-btn`.

### 2. Close Button Position Bug

**Problem:** The first implementation placed the `×` in `.sgl-header-actions` (far right of the header), next to the `—` collapse button. This created a large gap between the title text (left) and the close button (far right). Worse, when switching between single-tab and multi-tab mode, the close button jumped position — jarring UX.

**Fix:** Introduced a `.sgl-title-group` wrapper that holds both the title span and the close button together. The title group sits on the left; the header actions (just collapse `—`) stay on the far right via `margin-left: auto`.

**Layout structure (single-tab):**
```
[title-group: title × ] .............. [actions: — ]
```

**Layout structure (multi-tab):**
```
[tab-bar: tab1 × | tab2 × | tab3 × ] [actions: — ]
```

The `×` is now consistently adjacent to the label in both modes.

### 3. `closable` Property

**Problem:** `locked: true` hides the close button but also blocks drag and drop. Users wanted a way to make tabs persistent (no close) while still allowing rearrangement.

**Solution:** New `closable` property on tab nodes. Default is `true` (closable). Set `closable: false` to hide the close button without affecting drag.

| Property | Drag | Drop onto | Close | Use case |
|----------|------|-----------|-------|----------|
| (default) | Yes | Yes | Yes | Normal tab |
| `closable: false` | Yes | Yes | No | Persistent, rearrangeable |
| `locked: true` | No | No | No | Pinned in place |

**Implementation:**
- `_renderTabElement()` checks `tab.closable !== false` before creating the close button DOM element
- `_closeTab()` returns early if `tab.closable === false`
- CSS class `.sgl-tab--no-close` hides close button (same rule as `.sgl-tab--locked`)
- Serialized in `_serializeNode()` — only written when `false` (opt-out)

### 4. `fixedSize` Property

**Problem:** All panel sizes are proportional (`fr` units). Users wanted fixed-width sidebars (e.g., 250px) that don't resize when the window changes.

**Solution:** New `fixedSize` property on any row/column child (stack, row, or column node). Accepts any CSS length string.

```javascript
{ type: 'stack', id: 's-sidebar', fixedSize: '250px', ... }
```

**Implementation:**
- `_applyGridSizes()` uses the `fixedSize` value directly in the CSS grid template instead of `fr`
- Fixed children are excluded from the `frTotal` normalisation calculation
- `_makeResizeHandle()` disables pointer events on handles adjacent to fixed children
- Serialized in `_serializeNode()` for both stack and container node types

## Key Decisions

| Decision | Why | Alternative |
|----------|-----|------------|
| `closable` as opt-out (default `true`) | Backwards compatible — existing layouts unchanged | Opt-in would break existing close buttons |
| `fixedSize` as CSS string, not number | Supports `px`, `%`, `rem` etc. without conversion | Number-only would limit to pixels |
| Disable resize handle via `pointerEvents: 'none'` | Simple, no new state tracking needed | Could remove handle entirely but that changes visual spacing |
| Close button in title-group, not header-actions | Keeps `×` adjacent to the label regardless of single/multi mode | Could duplicate position logic but adds complexity |

### Architecture Notes
- The entire component is a single `sg-layout.js` file (~2100 lines) containing:
  - Shadow DOM styles as a template literal (`SHADOW_STYLES`)
  - `SgLayout` class extending `HTMLElement`
  - Tree rendering (`_renderNode`, `_renderContainer`, `_renderStack`, `_renderTabElement`)
  - Drag system (`_onTabPointerDown`, `_onDragMove`, `_onDragEnd`, dock overlay)
  - Resize handles (`_makeResizeHandle`, `_applyGridSizes`)
  - Serialization (`_serializeNode`, `getLayout`, `setLayout`)
  - Fractal nesting (`getChildLayouts`, `getParentLayout`, `walkLayouts`)

- The CSS is embedded in the JS as a template literal, injected into Shadow DOM. There is also a standalone `sg-layout.css` but it only contains CSS custom property defaults — it's optional.

- Layout tree is a plain JS object tree (not a class). Nodes are `{ type: 'row'|'column'|'stack'|'tab', ... }`. The component mutates the tree directly and re-renders.
