# demo-reel — 3 · Architecture

*All PROPOSED. Existing modules are marked **shipped**.*

## Shape

```
narrated-review session.json ─┐
sg-page-recorder bundle ──────┤
loose screenshots ────────────┴──▶  reel.json  ──▶  compose  ──▶  landscape.webm
                                       ▲               │             shorts.webm
                                       │               └──▶ frames/ (PNG, for review)
                                  UI or agent
```

`reel.json` is the whole state. Everything else reads it or writes it.

## The document

```jsonc
{
  "schema": { "name": "demo-reel/reel", "version": 1 },
  "title": "SGit vaults — what they are",
  "theme": "sgraph-dark",
  "formats": ["landscape", "shorts"],
  "voice": { "id": "af_bella", "speed": 1.0 },
  "scenes": [
    {
      "id": "s01",
      "narration": "A vault is a folder that encrypts itself before it leaves your machine.",
      "caption": "Encrypted before it leaves",
      "shots": [
        {
          "image": "images/shot-01.png",
          "focus": [0.24, 0.08, 0.52, 0.70],
          "weight": 1,
          "annotations": [
            { "type": "box",     "at": [0.30, 0.42, 0.36, 0.08], "label": "the vault key", "in": 0.4 },
            { "type": "arrow",   "from": [0.12, 0.20], "to": [0.30, 0.44] },
            { "type": "blur",    "at": [0.62, 0.11, 0.30, 0.05], "reason": "customer name" },
            { "type": "tagline", "at": "bottom", "text": "one key, no password reset" }
          ]
        }
      ]
    }
  ]
}
```

**Coordinates are normalised to the SOURCE IMAGE** (0–1), never to the output
frame. The same annotation then renders correctly at 1920×1080, at 1080×1920, and
in a thumbnail, with no second set of numbers to keep in step.

`in` is an optional reveal time in seconds from the start of the shot — enough for
"the box appears as the voice mentions it" without a synchronisation engine.

## Modules

Small files, one job each, matching the house pattern
(`api/{tool}-state|events|pipeline|api.js`, one `ui/ui-*.js` per panel).

| Module | Job |
|---|---|
| `api/dr-state.js` | The reel document + config. No DOM. |
| `api/dr-events.js` | Frozen `dr:*` event names. |
| `api/dr-schema.js` | Validate a reel; return **typed, positional errors** ("scene 3, shot 2: focus rect is wider than 9:16 allows"). An agent writing JSON needs to be told exactly what is wrong. |
| `api/dr-annotate.js` | Pure renderer: `drawAnnotations(ctx, shot, geom)`. One function per primitive. No state, fully unit-testable against a canvas. |
| `api/dr-layout.js` | Geometry: source rect → output rect for each format, honouring `focus`. The only place that knows about aspect ratios. |
| `api/dr-caption.js` | Text layout — wrapping, sizing to fit, safe margins, background plate for contrast. |
| `api/dr-timing.js` | Audio duration → per-shot durations (weighted, floor-clamped). Pure. |
| `api/dr-compose.js` | The frame renderer: `renderFrame(t, format) → void` onto a canvas. **Deterministic: a given `t` always produces the same frame.** |
| `api/dr-record.js` | Drives `dr-compose` against a clock and `core/sg-video-recorder`. |
| `api/dr-import.js` | `session.json` / handover zip / loose images → `reel.json`. |
| `api/dr-api.js` | `SgToolApi` registration, `activate()` before UI. |
| `ui/ui-scenes.js` | The scene list — reorder, split, merge. |
| `ui/ui-canvas.js` | Preview with draggable annotation handles. |
| `ui/ui-inspector.js` | Narration, caption, voice, per-shot weights. |
| `ui/ui-export.js` | Format pick, render, download, publish. |

`dr-compose.renderFrame(t)` being pure and deterministic is what makes the whole
thing testable: a test can ask for the frame at t=4.2s and compare pixels, with no
recording, no audio and no timing.

## Reuse — what we do NOT write

| Need | Use (shipped) |
|---|---|
| Text → audio | `core/sg-tts` v0.1.0 (Kokoro, 8-worker pool) |
| Canvas + audio → file | `core/sg-video-recorder` v0.1.1 |
| Zip in/out | `core/sg-zip` |
| Session storage | `core/sg-vfs` (IndexedDB) |
| Panels | `core/sg-layout` |
| JS API + console/explorer | `core/sg-tool-api` + `components/tool-api/*` |
| Publishing | `youtube-upload`, `video-publisher` |
| Title-card imagery | `infographic-gen` |

`video-creator`'s `generateAllAudio` and `recordSlideshow` are the reference
implementation for the audio and recording lanes and should be read before either
is rewritten.

## The pacing question (unresolved, Phase 0)

`video-creator` today:

```js
await _drawSlide(recCtx, slide, …);
source.start();                                   // audio plays in real time
await new Promise(r => setTimeout(r, duration * 1000));   // ← the clock
```

Three risks, **none of them measured**:

1. **Drift.** `setTimeout` is a floor, not a promise. Twenty scenes of drift is
   audible against the audio.
2. **Throttling.** A backgrounded tab slows timers; the video silently gets longer
   while the audio does not.
3. **Frame pacing.** MediaRecorder samples the canvas as it paints. A slow first
   frame after a large PNG decode becomes a visible stutter.

Three candidate answers, in increasing order of cost:

- **A. Keep it**, add a monotonic clock (`performance.now()` deadline per shot
  rather than cumulative `setTimeout`) and pre-decode every image before recording
  starts. Cheapest; may well be enough.
- **B. Frame-clocked rendering.** Drive `renderFrame(n / fps)` from
  `requestAnimationFrame`, and record with a fixed `captureStream(fps)`. Correct
  pacing, still real-time, still MediaRecorder.
- **C. WebCodecs `VideoEncoder`.** Encode frame by frame, faster than real time,
  exact durations, and mux with the audio. Best output and the only path to
  "render a 90-second video in 15 seconds". Highest cost, and support varies.

**Phase 0 decides between them with numbers**, using the same discipline as
`media-probe`: render a known reel, compare intended and actual duration, plot the
inter-frame intervals. Do not pick from this list by argument.

## Two formats, one pass or two?

Two passes. A single pass rendering both would need two canvases and two
recorders competing for the same main thread, and MediaRecorder is real-time —
so one pass costs the length of the video, and two cost twice that, which is
still only a couple of minutes. If Phase 0 lands on WebCodecs (option C), both
formats can be encoded from the same source frames much faster, but that is a
consequence of the choice, not a reason to make it.

## Where files live

```
demo-reel/
  reel.json
  images/shot-01.png …
  audio/scene-01.wav …     (cached TTS — regenerating is slow and deterministic)
  out/landscape.webm
  out/shorts.webm
```

Same folder shape as a narrated-review export and a vault, so the three are
interchangeable in a zip, in `sg-vfs`, or in an sgit vault.

**Cache the TTS audio.** Kokoro is fast but not free, and re-rendering a reel
after moving one annotation should not re-speak twenty scenes. Key the cache on
`hash(narration + voice + speed)` so an edited sentence invalidates exactly one
file.
