# Debrief 2a — What We Built · Core Modules

**Date:** 25 April 2026 · **Branch:** `claude/new-tool-component-EzK43`

Three new pure-JS modules under `core/`. No DOM, no localStorage, no UI dependencies. Each is a thin, composable wrapper around a YouTube API surface.

---

## `core/youtube-upload/v0/v0.1/v0.1.0/sg-youtube-upload.js`

Resumable video upload + GIS scope-request helper.

**Exports:**
- `YOUTUBE_UPLOAD_SCOPE` — `https://www.googleapis.com/auth/youtube.upload`
- `requestAccess(clientId, { hint?, prompt?, scope? })` → `{ accessToken, expiresAt, scope }`
  - GIS-backed token request. Retries every 200 ms × 15 for the GIS library to load.
  - `scope` is opt-in (defaults to upload-only). The youtube-editor passes the broader `youtube` scope here.
- `class YouTubeUpload(accessToken)`
  - `uploadVideo(file, metadata, { onProgress, signal })` → `{ id, url, snippet, status }`
  - Resumable single-PUT: POST `/upload/youtube/v3/videos?uploadType=resumable` to initiate, PUT bytes via XHR for progress events.

**Quota:** 1 600 units per upload (the dominant cost in the toolchain).

---

## `core/youtube-api/v0/v0.1/v0.1.0/sg-youtube-api.js`

Read + edit + playlists. Pairs with `youtube-upload` for the resumable insert path.

**Exports:**
- `YOUTUBE_FULL_SCOPE`, `YOUTUBE_READONLY_SCOPE`
- `class YouTubeApi(accessToken)` with **11 methods**:

| Method | Quota | Purpose |
|---|---:|---|
| `getMyChannel()` | 1 | Channel info — banner, handle, joined date, description, topic categories, statistics, custom URL, Studio URL, hidden-subs flag, made-for-kids |
| `listMyUploads({pageToken, pageSize})` | 1/page | Uploads via uploads-playlist. Returns `{ items, nextPageToken, totalResults, uploadsPlaylistId }` |
| `getVideos(ids, parts?)` | 1 | Bulk fetch up to 50. Default parts: `snippet,status,statistics`. Used by the grid to enrich rows with privacy + views + duration. |
| `updateVideo(id, patch)` | 50 | Auto-fills required `categoryId` if omitted (YouTube rejects partial snippets without it) |
| `setThumbnail(id, blob)` | 50 | Image ≤ 2 MB, JPG/PNG |
| `deleteVideo(id)` | 50 | Irreversible. UI-disabled in the editor; SDK-callable. |
| `listMyPlaylists({pageSize, pageToken})` | 1/page | Playlists with itemCount + medium thumbnail |
| `listPlaylistItems(playlistId, ...)` | 1/page | Returns `{playlistItemId, videoId, ...}` — `playlistItemId` is needed for removal |
| `findVideoPlaylists(videoId, playlistIds)` | 1/playlist | Fans out per-playlist queries with `videoId` filter (no native "playlists for video" endpoint exists) |
| `addToPlaylist(playlistId, videoId, {position})` | 50 | Returns `{playlistItemId}` for later removal |
| `removeFromPlaylist(playlistItemId)` | 50 | Removal needs the playlistItemId, not the videoId |

All errors throw with `YouTube {status}: {body…}`.

## `core/youtube-analytics/v0/v0.1/v0.1.0/sg-youtube-analytics.js`

YouTube Analytics API v2 — separate scope, separate quota (~1 q/s/user, no daily unit cap).

**Exports:**
- `YOUTUBE_ANALYTICS_SCOPE` — `https://www.googleapis.com/auth/yt-analytics.readonly`
- `class YouTubeAnalytics(accessToken)` with **4 methods**:

| Method | Returns |
|---|---|
| `getChannelSummary({days})` | `{views, estimatedMinutesWatched, subscribersGained/Lost, likes, comments, averageViewDuration, averageViewPercentage, startDate, endDate}` — defaults to last 28 days ending yesterday (analytics lags ~1 day) |
| `getVideoSummary(id, {days})` | Same metrics, scoped via `filters=video==<id>` |
| `getDailyTrend(id, {days})` | `[{day, views, estimatedMinutesWatched}, …]` ascending — drives sparklines |
| `getRetentionCurve(id)` | `[{elapsedVideoTimeRatio, audienceWatchRatio}, …]` ~100 points 0.0→1.0; uses `audienceType==ORGANIC` filter |

**Internal:** the v2 reports endpoint returns `{columnHeaders, rows}` with parallel arrays. `_rowsToObjects(j)` normalises to `[{col: value}]`. Quoted error format: `YouTube Analytics {status}: {body…}`.
