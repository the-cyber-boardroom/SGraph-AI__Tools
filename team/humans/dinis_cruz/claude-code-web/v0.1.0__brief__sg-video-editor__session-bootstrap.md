## Known architectural issues (not fixed)

1. **Composer is destroyed and recreated on EVERY non-transient state mutation** — even a colour pick triggers `rebuild()` in `ui-shell.js` `handleChange` (line ~139). The new composer creates a fresh `<video>` and a fresh `URL.createObjectURL(blob)` for each unique asset, while the old composer's decoded buffers may not yet be GC'd. With a 4K video this stacks GBs of decode buffers transiently. **Fix shape**: lift the asset→`<video>` Map out of the composer so it lives at the same scope as `assetRegistry` and persists across rebuilds. Multi-file refactor; public composer API may shift. Out of scope for a single-session bug fix; needs explicit user call-out.
2. **No max output resolution clamp.** Project `width`/`height` is settable arbitrarily via `setProject`. Add a "max output dimension" clamp (e.g. 1920×1080) at the composer level.
3. **WebCodecs migration** would let us decode to fixed-size frames without holding decoded buffers. Months-of-work rewrite. Don't propose unless explicitly asked.
