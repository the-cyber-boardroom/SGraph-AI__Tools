# Brief — LinkedIn Publisher · 5/5 Phasing & Acceptance

Order matters here because of the dependencies (CORS verification → auth flow → core module → UI). Don't be tempted to start with the visible UI parts.

---

## Phase 0 — Verification (½ day)

**Done when:**
1. CORS behaviour of `api.linkedin.com` is documented (verified in DevTools).
2. CORS behaviour of `linkedin.com/oauth/v2/{authorization,accessToken}` is documented.
3. PKCE support for the LinkedIn app type is confirmed.
4. The proxy decision is recorded (Option A managed proxy, Option B user-deployed, or D direct).
5. A reality-doc-style note is committed to `team/explorer/architect/` capturing the findings.

**No code yet.** This phase exists to prevent the wrong architecture going in.

---

## Phase 1 — Core module + auth (1 session)

- `core/linkedin-api/v0/v0.1/v0.1.0/sg-linkedin-api.js` — pure JS, all 13 methods stubbed, real network for the auth-related ones (`getMe`, `getMyAdminOrganizations`, `listOrgPosts`).
- OAuth popup flow with `oauth-callback.html` postMessage bridge.
- Token cache adapter (`linkedin-token-cache.js`).
- Optional proxy passthrough flag in the constructor.
- Stubbed-fetch test page at `tests/sg-linkedin-api/v0.1.0.test.html`.

**Done when:** an agent can run `connect()` → `getMe()` → `getMyAdminOrganizations()` end-to-end against real LinkedIn (or against a route-stubbed test page), and the token survives a page reload.

---

## Phase 2 — Compose + Publish (1 session)

- `tools/.../en-gb/linkedin-publisher/` skeleton (manifest-driven, sg-layout, dev pane, skills) — copy `youtube-editor` and search-and-replace.
- `<sg-linkedin-org-picker>` component.
- `<sg-linkedin-post-editor>` component (text mode only at first, then article mode).
- Compose tab in the right stack.
- `createTextPost` + `createArticlePost` working end-to-end.

**Done when:**
1. Open the tool, connect, pick an org, type a message, publish — and it lands on the org page.
2. Same for an article-link post with a YouTube URL.
3. The auth panel shows the viewer's profile + the org banner/avatar/name on the picker.

---

## Phase 3 — List + read (½ session)

- `<sg-linkedin-post-list>` component with the same defer-and-replay race protection as `<sg-youtube-videos>`.
- Recent Posts tab.
- Per-post tab opens on click.

**Done when:** clicking a row in Recent Posts opens a read-only detail tab showing the post's content + a "View on LinkedIn" link.

---

## Phase 4 — YouTube hand-off + image upload (½ session)

- `handoff/sg-linkedin-handoff.js` mirroring `sg-youtube-handoff.js`.
- "▶ Share on LinkedIn" button in the youtube-editor's per-video tab.
- `uploadImage()` core method (LinkedIn's 2-step upload: initialize asset registration → PUT bytes → reference URN in post).
- Thumbnail picker in the article-post compose mode.

**Done when:** from the YouTube editor, click "Share on LinkedIn" → publisher tab opens with the article-link post pre-filled → user adjusts commentary → publishes. Loop closed.

---

## Phase 5 — Skills + reality doc + tests (½ session)

- `SKILL-human.md` (LinkedIn Developer Portal setup walkthrough, scope verification dependency).
- `SKILL-browser.md` (route stubs for the LinkedIn endpoints; how to prime the token cache).
- `SKILL-api.md` (the contract from brief 4/5).
- Reality doc updated with all artifacts.
- Health-check tests for the new components (~25 assertions across the 3 components).

**Done when:** a fresh agent can read the SKILL files + reality doc and drive the tool against a route-stubbed Playwright test without needing this brief.

| # | Criterion | How verified |
|--:|---|---|
| 1 | OAuth connect to LinkedIn works for an org admin | Live test |

| 5 | List recent posts for the org page | Live test |
| 6 | View a single post's detail | Live test |
| 7 | Hand-off from YouTube Editor pre-fills compose tab | Live test (record → upload → share) |
| 8 | All API calls go directly browser → LinkedIn (or browser → managed proxy → LinkedIn) | Network tab inspection |
| 9 | Token cached in localStorage; survives reload; auto-refresh on 401 | Live test |

| 12 | Skills + reality doc + tests committed | Repo inspection |

## Dependencies + risks

| Item | Risk | Mitigation |
|---|---|---|
| LinkedIn app verification approval | Days–weeks; tool can't ship to non-test users until approved | Apply for approval **on day 1** of the next session in parallel with code work |
| CORS = blocked | Forces proxy infra | Phase 0 verification gates this; if confirmed, ship Option A (Cloudflare Worker) before Phase 1 |
| LinkedIn rotates `LinkedIn-Version` and breaks the pinned version | Tool stops working until version bumped | Manifest pins the version; bump twice a year via a one-line PR |
| LinkedIn deprecates an endpoint | One method breaks at a time | Health check runs the endpoints; manifest events surface the failure to agents |

## What's deliberately out of v0.1

| Out | Why |
|---|---|
| Personal-profile posts | LinkedIn restricts to first-party apps; not viable for tools.sgraph.ai |
| Video / document posts | Need different upload protocols; defer to v0.2 |
| Edit existing post | `PARTIAL_UPDATE` semantics; rare use case; defer |
| Schedule posts | API doesn't support directly; would need local IndexedDB queue + cron |
| Engagement analytics (impressions, likes, click-throughs) | Different scope (`r_organization_social_feed`); defer to a future analytics phase |
| Comment moderation | Different scope, different endpoints; defer |
| Multi-language post variants | Possible via `localizations`, but rare; defer |

Each of these is a candidate for a v0.2/v0.3 follow-up brief. They're all additive — none change the v0.1 architecture.
