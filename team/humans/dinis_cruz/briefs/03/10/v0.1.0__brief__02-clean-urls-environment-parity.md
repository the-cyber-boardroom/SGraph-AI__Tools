## Problem Statement

The current tools site has two URL issues that need to be resolved before the site can be linked from the main sgraph.ai nav:

1. **Root `/` does not redirect to the correct locale** — it hardcodes `meta http-equiv=refresh` to a versioned path (`tools/v0/v0.1/v0.1.0/`). Users arriving at `tools.sgraph.ai` or `dev.tools.sgraph.ai` get no locale detection.

2. **User-facing URLs expose internal versioning** — `https://dev.tools.sgraph.ai/tools/v0/v0.1/v0.1.1/en-gb/` is the URL a user sees. The versioned path is an implementation detail, not a user-facing address. Users should see `https://dev.tools.sgraph.ai/en-gb/`.

Both must be resolved for the tools site to feel like a first-class part of the SG/Send ecosystem.

## Part 1: Root Redirect — Auto-Detect Locale

### Target behaviour

| User arrives at | Detected language | Redirected to |
|---|---|---|
| `tools.sgraph.ai/` | Browser = `de-DE` | `tools.sgraph.ai/de-de/` |
| `tools.sgraph.ai/` | Browser = `en-US` | `tools.sgraph.ai/en-us/` |
| `tools.sgraph.ai/` | Browser = unknown | `tools.sgraph.ai/en-gb/` (default) |
| `dev.tools.sgraph.ai/` | Browser = `fr-FR` | `dev.tools.sgraph.ai/fr-fr/` |

### Implementation: update `index.html` at root

Replace the current `<meta http-equiv="refresh">` approach with JS locale detection:

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>SG/Tools — Redirecting...</title>
    <!-- Instant JS redirect with locale detection -->
    <script>
    (function() {
        const supported = [
            'en-gb','en-us','de-de','de-ch',
            'es-es','es-ar','es-mx',
            'fr-fr','fr-ca',
            'hr-hr','it-it','nl-nl','pl-pl',
            'pt-br','pt-pt','ro-ro','tlh'
        ]
        // Check for a previously chosen locale stored in sessionStorage
        const stored = sessionStorage.getItem('sg-locale')
        if (stored && supported.includes(stored)) {
            window.location.replace('/' + stored + '/')
            return
        }
        // Detect from browser language
        const langs = navigator.languages || [navigator.language || 'en']
        for (const lang of langs) {
            const code = lang.toLowerCase().replace('_', '-')
            // Try exact match first (en-gb)
            if (supported.includes(code)) {
                window.location.replace('/' + code + '/')
                return
            }
            // Try language-only match (en → en-gb)
            const base = code.split('-')[0]
            const match = supported.find(s => s.startsWith(base + '-'))
            if (match) {
                window.location.replace('/' + match + '/')
                return
            }
        }
        // Default
        window.location.replace('/en-gb/')
    })()
    </script>
    <!-- Fallback for no-JS -->
    <noscript><meta http-equiv="refresh" content="0;url=/en-gb/"></noscript>
</head>
<body></body>
</html>
```

**Notes:**
- `sessionStorage` stores the user's last chosen locale so repeat visits skip detection
- The `sg-locale-picker` component should write to `sessionStorage` on locale change (add to `_navigateToLocale()`)
- No dependency on external JS — works before any component loads
- The `replace()` (not `href`) means the redirect does not appear in browser history

### Files to change

- `sgraph_ai_tools__static/index.html` — replace with locale-detecting version above
- `components/locale-picker/v1/v1.0/v1.0.1/sg-locale-picker.js` — add `sessionStorage.setItem('sg-locale', code)` in `_navigateToLocale()`

## Part 2: Clean URLs — `/en-gb/` Not `/tools/v0/v0.1/v0.1.1/en-gb/`

### Target URL structure

```
tools.sgraph.ai/               → redirects to /en-gb/ (Part 1)
tools.sgraph.ai/en-gb/         → tools landing page
tools.sgraph.ai/en-gb/ssh-keygen/  → SSH keygen tool
tools.sgraph.ai/de-de/         → German tools landing page
tools.sgraph.ai/fr-fr/ssh-keygen/  → French SSH keygen
```

The versioned path (`/tools/v0/v0.1/v0.1.1/`) becomes a **deployment implementation detail only** — it lives in S3 but is never the canonical URL a user sees.

### How this works with the current deploy model

The `deploy_static_site.py` script deploys to:
```
S3: websites/tools-sgraph-ai/{env}/releases/v0.1.1/
S3: websites/tools-sgraph-ai/{env}/latest/
```

CloudFront serves from the `latest/` path. The current `latest/` contains the versioned subfolder structure (`tools/v0/v0.1/v0.1.1/`), so the user URL includes the version.

**The change:** Deploy the locale folders directly to `latest/`, not nested under the version path.

```
CURRENT S3 structure:
  websites/tools-sgraph-ai/dev/latest/tools/v0/v0.1/v0.1.1/en-gb/index.html
  websites/tools-sgraph-ai/dev/latest/index.html  ← root redirect

TARGET S3 structure:
  websites/tools-sgraph-ai/dev/latest/en-gb/index.html      ← clean
  websites/tools-sgraph-ai/dev/latest/en-gb/ssh-keygen/index.html
  websites/tools-sgraph-ai/dev/latest/de-de/index.html
  websites/tools-sgraph-ai/dev/latest/index.html            ← locale detector
  websites/tools-sgraph-ai/dev/latest/_common/css/tools.css
  websites/tools-sgraph-ai/dev/latest/components/...        ← shared components
```

The versioned archive remains in `releases/v0.1.1/` for rollback capability. `latest/` is the clean-URL snapshot.

### Changes to `deploy_static_site.py`

The deploy script currently syncs `SOURCE_DIR` (`sgraph_ai_tools__static/`) to `latest/`. This means the versioned tool folders go up as-is.

Add a `--clean-urls` flag (or make it the default for this site) that copies the **locale output** (generated by `generate_tools_i18n_pages.py`) directly to the `latest/` root, not under the version path.

The `generate_tools_i18n_pages.py` script already generates locale folders (`en-gb/`, `de-de/`, etc.) alongside the source. These should be synced to `latest/` directly.

**Concrete deploy steps (updated):**

```
1. generate_tools_i18n_pages.py  → produces en-gb/, de-de/, fr-fr/, es-es/ alongside source
2. deploy_static_site.py:
   a. Sync sgraph_ai_tools__static/_common/        → latest/_common/
   b. Sync sgraph_ai_tools__static/components/     → latest/components/
   c. Sync sgraph_ai_tools__static/en-gb/          → latest/en-gb/
   d. Sync generated de-de/, fr-fr/, es-es/        → latest/de-de/, latest/fr-fr/, etc.
   e. Sync root files (index.html, 404.html, ...)  → latest/
   f. Also archive to releases/v{version}/         → for rollback
```

### Asset path fix

Current tool pages reference `_common/` assets with paths like `../_common/css/tools.css` (from within `tools/v0/v0.1/v0.1.1/en-gb/`). At the new clean URL (`/en-gb/`), the correct path is `../_common/css/tools.css` — which is the same relative depth. ✅ No path changes needed in the HTML files.

Component imports use absolute paths (`/components/site-header/...`). These resolve from the domain root regardless of depth. ✅ No changes needed.

### CloudFront URL rewrite

The existing `url-rewrite.js` CloudFront Function handles:
- `/` + trailing slash → append `index.html`
- bare path (no extension) → 302 redirect to add trailing slash

This is sufficient for the clean URL structure. No changes needed to the CloudFront Function.

## Part 3: Three-Environment Parity

### Required environments

| Environment | tools domain | sgraph domain | Deploys from |
|---|---|---|---|
| **dev** | `dev.tools.sgraph.ai` | `dev.sgraph.ai` | `dev` branch (automatic) |
| **main** | `main.tools.sgraph.ai` | `main.sgraph.ai` | `main` branch (automatic) |
| **prod** | `tools.sgraph.ai` | `sgraph.ai` | `main` branch + manual dispatch |

Both `dev` and `main` environments are served from the same CloudFront distribution (using different S3 path prefixes and CloudFront behaviours). Production uses a separate distribution.

### What "parity" means

- All three environments serve the same codebase, same URL structure
- `dev.tools.sgraph.ai/en-gb/` works identically to `tools.sgraph.ai/en-gb/`
- Cross-site links in the banner resolve to the matching environment (see Brief 01)
- The `index.html` locale detector works on all three

### CI workflow changes

The existing `deploy-tools.yml` workflow already handles three environments via the `deploy_env` variable. The changes required:

1. **Update `UI_VERSION` env var** when IFD version advances — this is already tracked in the workflow. The clean-URL change may make this variable less relevant (since version is no longer in the user-facing URL), but keep it for S3 archive path.

2. **Update the deploy step** to sync locale folders to the root of `latest/` rather than under the versioned subfolder. This is a change to `deploy_static_site.py` arguments or logic.

3. **Confirm `SGRAPH_TOOLS__DEV__CLOUDFRONT_DISTRIBUTION_ID`** is correctly configured for both `dev` and `main` environments — the current workflow uses the same secret for both, which is correct only if they share a distribution with path-based routing.

### Manifest update

Add environment context to `manifest.json`:

```json
{
    "deploy": {
        "url_structure": "clean",
        "root_redirect": "locale-detect",
        "environments": {
            "dev":  "https://dev.tools.sgraph.ai",
            "main": "https://main.tools.sgraph.ai",
            "prod": "https://tools.sgraph.ai"
        },
        "sgraph_environments": {
            "dev":  "https://dev.sgraph.ai",
            "main": "https://main.sgraph.ai",
            "prod": "https://sgraph.ai"
        }
    }
}
```

This makes the environment mapping explicit and machine-readable. The `sg-nav.js` module can potentially load this at build time rather than hardcoding the detection logic.
