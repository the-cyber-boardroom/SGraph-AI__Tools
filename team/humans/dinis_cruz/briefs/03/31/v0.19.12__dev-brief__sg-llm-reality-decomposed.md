# Dev Brief: sg-llm-reality — Decomposed into Buildable Pieces

**Version:** v0.19.12
**Date:** 31 March 2026
**From:** Dev (Explorer team)
**Type:** Implementation brief — decomposition of a too-large component
**Supersedes:** Phase 5 of `v0.19.11__architect-review__sg-llm-reality-constructor.md`
**Status:** Ready to implement

---

## Why This Brief Exists

Two separate Claude Code Web sessions have failed to build `sg-llm-reality` as a single file. The component as originally specified is doing too many things simultaneously:

1. Block data model + messages array assembly (pure logic)
2. Five different block editors, each with different UI
3. List container management (add/remove/reorder/drag)
4. Attachment event handling (text → Context blocks, images → multimodal)
5. Two send modes (Build vs Memory-update)
6. Cost estimation + token counting
7. Bundle restore
8. Template system

A single file containing all of this hits the LLM context limit during generation. The solution is to split along natural seams: **data logic**, **single block rendering**, and **orchestration** are three separate concerns that can be built and tested independently.

---

## The Decomposition

```
sg-llm-reality-core.js          ← Pure module. No DOM, no events.
                                   Block schemas, factory, token count,
                                   messages array assembly.

sg-llm-block.js                 ← Web Component for ONE block.
                                   Renders system/context/history/memory/question.
                                   Emits block-change, block-remove, block-toggle.
                                   No awareness of the list.

sg-llm-reality.js               ← Slim orchestrator Web Component.
                                   Manages the list of sg-llm-block elements.
                                   Listens to SGL_LLM events.
                                   Calls core.js to assemble messages array.
                                   Emits REALITY_CHANGED, SEND.
```

All three files live in the same folder:
`components/llm/sg-llm-reality/v0/v0.1/v0.1.0/`

Build order: **core → block → reality**. Each is independently testable before the next is started.

```js
export function createBlock(type, overrides = {}) {
    const id = `block-${Date.now()}-${Math.random().toString(16).slice(2, 6)}`;
    const base = {
        id,
        type,
        enabled: true,
        // type-specific defaults:
        ..._typeDefaults(type),
        ...overrides,
    };
    return base;
}

// Type-specific data shapes:
// system:   { content: '' }
// context:  { label: '', content: '' }
// history:  { pairs: [{ user: '', assistant: '' }] }
// memory:   { content: '' }
// question: { content: '' }
```

### `assembleMessages(blocks, imageAttachments)`

This is the most important function. Takes the blocks array (filtered to `enabled === true`) and `imageAttachments` (array of `{ dataUrl }` objects) and returns the messages array for the API.

```js
export function assembleMessages(blocks, imageAttachments = []) {
    const messages = [];

    for (const block of blocks) {
        if (!block.enabled) continue;

        if (block.type === 'system') {
            messages.push({ role: 'system', content: block.content });

        } else if (block.type === 'context') {
            const content = `--- CONTEXT: ${block.label} ---\n${block.content}`;
            messages.push({ role: 'user', content });

        } else if (block.type === 'history') {
            for (const pair of block.pairs) {
                if (pair.user)      messages.push({ role: 'user',      content: pair.user });
                if (pair.assistant) messages.push({ role: 'assistant', content: pair.assistant });
            }

        } else if (block.type === 'memory') {
            const content = `--- SESSION MEMORY ---\n${block.content}`;
            messages.push({ role: 'user', content });

        } else if (block.type === 'question') {
            if (imageAttachments.length > 0) {
                // Multimodal content array
                const parts = [{ type: 'text', text: block.content }];
                for (const img of imageAttachments) {
                    parts.push({ type: 'image_url', image_url: { url: img.dataUrl } });
                }
                messages.push({ role: 'user', content: parts });
            } else {
                messages.push({ role: 'user', content: block.content });
            }
        }
    }

    return messages;
}
```

### `assembleMemoryUpdateMessages(memoryBlock, lastQuestion, lastResponse)`

Builds the messages array for Mode 2 (Update Memory):

```js
export function assembleMemoryUpdateMessages(memoryBlock, lastQuestion, lastResponse) {

            content: `CURRENT MEMORY:\n${memoryBlock?.content || '(empty)'}\n\nLATEST QUESTION:\n${lastQuestion}\n\nLATEST RESPONSE:\n${lastResponse}`
        }

}
```

### `estimateTokens(text)`

```js

```

## File 2: `sg-llm-block.js` (~200 lines)

**What:** A Web Component for a SINGLE block. Knows nothing about the list. Receives its data as a property, renders the appropriate editor, and emits DOM events when the user changes it.

**Tag:** `<sg-llm-block>`

**No SGL_LLM events** — this component uses plain DOM events that bubble. The parent (`sg-llm-reality`) listens to these.

### Public API

```js
// Set the block data (object matching createBlock output)
blockEl.setData(block)

// Read back current data after edits
blockEl.getData()  // → block object with current content

// Events emitted (bubbling CustomEvents, detail = { blockId })
'block-change'   // user edited something — parent should re-assemble
'block-remove'   // user clicked remove — parent should delete this block
'block-toggle'   // user toggled enabled/disabled — detail: { blockId, enabled }
```

### Rendering per type

Each type has a specific editor. The component renders the right one based on `block.type`:

**system:** Single `<textarea>` with placeholder "Define the agent's role and constraints..."

**context:** `<input>` for label + `<textarea>` for content. Collapsible (collapsed by default). Header shows label when collapsed.

**history:** List of pair rows. Each row has two textareas side-by-side (👤 User / 🤖 Assistant). "+ Add pair" button appends a new empty pair. Each pair has an ✕ remove button.

**memory:** Single `<textarea>`. No "Update Memory" button here — that lives in sg-llm-reality's footer. Just the editable content.

**question:** Single `<textarea>`. If `block._imageCount > 0`, shows a static badge: `📷 {n} images attached`.

### Header (all block types share this)

```
[icon] [type label] [label if context] ─────── [token count] [toggle ●] [✕]
```

- Toggle: click to enable/disable block (grayed out when disabled)
- ✕: remove block (emits `block-remove`)
- Token count: `estimateTokens(allText)` from core.js, recalculated on every input event

### Implementation notes

- Use Shadow DOM with inline styles (no fetch needed)
- Import `{ estimateTokens, BLOCK_TYPES }` from `sg-llm-reality-core.js`
- On any `input` event in any textarea/input: recalculate token count, emit `block-change`
- Keep a copy of the block data internally; `getData()` reads current values from the DOM

### Test page: `tests/sg-llm/reality-block.test.html`

Tests:
- Custom element registered
- `setData` + `getData` round-trip for each of 5 block types
- `block-change` fires on textarea input

- `block-toggle` fires on toggle click, detail has `{ enabled: false }`
- History block: "+ Add pair" increases pairs count
- History block: pair ✕ decreases pairs count

## File 3: `sg-llm-reality.js` (~220 lines)

**What:** The slim orchestrator. Manages a list of `<sg-llm-block>` elements. Handles all the SGL_LLM events. Calls `assembleMessages()` from core.js whenever anything changes. Emits `REALITY_CHANGED` and `SEND`.

**No block rendering logic here** — all delegated to `<sg-llm-block>`.

### Internal state

```js
this._blocks         = []          // array of block data objects (source of truth)
this._imageAttachments = []        // image attachments tracked from ATTACHMENT_ADDED
this._currentModel   = null        // for cost display
this._lastResponse   = ''          // for Mode 2 memory update
this._lastQuestion   = ''          // for Mode 2 memory update
this._busy           = false       // true while request in flight
```

### DOM structure

```html
<div class="reality-root">
    <div class="reality-blocks" id="blocks-container">
        <!-- <sg-llm-block> elements inserted here -->
    </div>
    <div class="reality-toolbar">
        [+ System] [+ Context] [+ History] [+ Memory] [+ Question]
    </div>
    <div class="reality-footer">
        <span class="reality-token-count">0 tokens</span>
        <span class="reality-cost">≈ $0.000</span>
        <button id="send-btn">▶ Send</button>
        <button id="memory-btn">↻ Update Memory</button>
    </div>
</div>
```

### Key methods

```js
_addBlock(type)          // createBlock(type), push to this._blocks, render
_removeBlock(blockId)    // splice from this._blocks, remove DOM element
_updateBlock(blockId)    // call blockEl.getData(), update this._blocks entry
_rebuildDom()            // re-render all blocks from this._blocks (used for bundle restore)
_onChange()              // called after any change: assembleMessages → emit REALITY_CHANGED
_onSend(mode)            // assemble + emit SGL_LLM.SEND
```

### SGL_LLM events consumed (listen on parentElement)

| Event | Handler |
|---|---|
| `CONNECTED` | store `_currentModel`, update cost display |
| `MODEL_CHANGED` | store `_currentModel`, update cost display |
| `REQUEST_START` | disable send button (`_busy = true`) |
| `REQUEST_COMPLETE` | enable send button; store `_lastQuestion`, `_lastResponse` |
| `REQUEST_ERROR` | enable send button |
| `ATTACHMENT_ADDED` | if text → `_addBlock('context', { label: attachment.name, content: attachment.textContent })`; if image → push to `_imageAttachments`, update Question badge |
| `ATTACHMENT_REMOVED` | if text → remove corresponding context block; if image → remove from `_imageAttachments` |
| `ATTACHMENTS_CLEARED` | remove all attachment-sourced context blocks; clear `_imageAttachments` |
| `BUNDLE_LOADED` | call `_restoreFromBundle(bundle.reality.blocks)` |
| `MEMORY_UPDATED` | replace memory block content with `e.detail.content` |

### DOM events consumed (listen on blocks-container)

| Event | Handler |
|---|---|
| `block-change` | `_updateBlock(e.detail.blockId)`, then `_onChange()` |
| `block-remove` | `_removeBlock(e.detail.blockId)` |
| `block-toggle` | `_updateBlock(...)` then `_onChange()` |

### Mode 2 — Update Memory

```js
_onMemoryUpdate() {
    const memoryBlock = this._blocks.find(b => b.type === 'memory');
    if (!memoryBlock) return;
    const messages = assembleMemoryUpdateMessages(
        memoryBlock, this._lastQuestion, this._lastResponse
    );
    this._emit(SGL_LLM.SEND, { messages, mode: 'memory-update' });
}
```

The response comes back as a `REQUEST_COMPLETE` event. If `mode === 'memory-update'`, `sg-llm-reality` should update the memory block content. But `sg-llm-request` doesn't tag `REQUEST_COMPLETE` with mode — so `sg-llm-reality` tracks whether it sent a memory-update and applies the response to the memory block when the next `REQUEST_COMPLETE` arrives.

```js
// track pending mode:
this._pendingMode = null;

_onSend(mode) {
    this._pendingMode = mode;
    // ... assemble and emit
}

_onRequestComplete(e) {
    this._busy = false;
    this._lastResponse = e.detail.content;
    if (this._pendingMode === 'memory-update') {
        this._applyMemoryUpdate(e.detail.content);
    }
    this._pendingMode = null;
}
```

## What NOT to put in sg-llm-reality.js

To keep each file under the buildable size limit:

| Feature | Where it belongs |
|---|---|
| Block data schemas | `sg-llm-reality-core.js` |
| Messages array assembly | `sg-llm-reality-core.js` |
| Token estimation | `sg-llm-reality-core.js` |
| Per-block editor UI | `sg-llm-block.js` |
| Drag-to-reorder | **Defer to v0.1.1** — add as surgical override `sg-llm-reality--v0.1.1.js` |
| Template presets | **Defer to v0.1.1** — add as surgical override |
| Cost estimation (model pricing) | Use `core/sg-llm-pricing/` when built. For now, `estimatedCost: 0` |
| Tiktoken accurate counts | **Defer to v0.1.1** — `estimateTokens = text.length / 4` for now |

Deferring drag-to-reorder and templates to surgical overrides is the right call for v0.1.0. Users can manually remove and re-add blocks to reorder. The core value (build a reality, send it, see the response) works without drag.
