**Status:** Ready to implement

## Why This Exists

`sg-llm-connection` has model loading built in, but it's a full settings panel.
There is no standalone, reusable model picker that can be dropped into test pages,
tool pages, or composed inside other components.

The problem surfaced in `request.test.html`: users had to manually type Ollama model
names into a free-text input, causing HTTP 400 errors from wrong/mistyped model names.
We patched the test page with inline JS — this brief extracts that into a proper component.

---

## What It Does

`<sg-llm-model-picker>` is a compact dropdown that:

1. Shows a list of models for the active provider
2. Has a **↻ refresh** button that fetches live model lists (Ollama `/api/tags`,
   OpenRouter `/v1/models`, OpenAI `/v1/models`; Anthropic uses a builtin static list)
3. Emits `llm:model-changed` when the user picks a model
4. Listens to `llm:connected` to auto-populate itself when a connection is established

It is **not** a full connection manager — it only handles model selection.
It composes alongside `sg-llm-connection` or can be used standalone in test pages.

## Component Contract

**Tag:** `<sg-llm-model-picker>`

**Path:** `components/llm/sg-llm-model-picker/v0/v0.1/v0.1.0/sg-llm-model-picker.js`

**Attributes:**
- `provider` — current provider id (`openrouter` | `ollama` | `anthropic` | `openai`)
- `base-url` — optional base URL override (for custom Ollama endpoints)

**Emits (on parentElement, bubbling + composed):**
- `llm:model-changed` — `{ model: string }` — when user selects a model

**Consumes (from parentElement):**
- `llm:connected` — `{ provider, model, baseUrl, apiKey }` — auto-loads models for the provider, pre-selects the model

**Public JS API:**
```js
picker.setProvider(provider, apiKey, baseUrl)  // load models for a provider
picker.setModel(model)                          // pre-select a specific model
picker.getModel()                               // returns currently selected model string
```

## Provider Model Sources

Reuse the same definitions already in `sg-llm-connection.js`:

| Provider | Source | Format |
|---|---|---|
| `openrouter` | `GET https://openrouter.ai/api/v1/models` (Bearer auth) | `{ data: [{ id }] }` → sort by id |
| `ollama` | `GET {baseUrl}/api/tags` (no auth) | `{ models: [{ name }] }` → sort by name |
| `anthropic` | Static builtin list | `['claude-opus-4-6', 'claude-sonnet-4-6', 'claude-haiku-4-5-20251001', 'claude-3-5-haiku-20241022']` |
| `openai` | `GET https://api.openai.com/v1/models` (Bearer auth) | `{ data: [{ id }] }` → filter to `gpt-*` and `o*`, sort |

## UI

Compact — designed to fit in toolbars, test pages, and alongside other inputs:

```
[  anthropic/claude-haiku-4-5         ▾  ] [↻]
```

- A `<select>` for model choices + a `<button>` to refresh
- While loading: button shows spinner, select shows "Loading…"
- On error: select shows "Failed to load" with last known models still selectable
- If provider has no API models (anthropic): no refresh button shown

Full width of its container by default. Inline-block when `compact` attribute set.

---

## Implementation Notes

- **No SgComponent base** — inline Shadow DOM styles like `sg-llm-connection`
- **No separate CSS file** — styles inline in the JS
- **Expose on window:** `window.SgLlmModelPicker = SgLlmModelPicker`
- **Store last known models** so refresh failures don't clear the list
- **`apiKey` handling:** stored internally from `llm:connected`; used for auth on refresh; never logged
