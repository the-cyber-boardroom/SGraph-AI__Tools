## What We Have Today (Code-Verified Baseline)

The Video Tools page (`tools.sgraph.ai/en-gb/video-tools/`) shipped in v0.1.5 with three operations:

| Operation | FFmpeg flags | What it does |
|---|---|---|
| **Split** (fixed / custom) | `-ss {start} -to {end} -c copy` | Divide into multiple clips, no re-encoding |
| **Trim** | `-ss {start} -to {end} -c copy` | Cut both ends, keep middle |
| **Extract** | `-vn -c:a copy` / `-an -c:v copy` | Separate audio and video streams |

Architecture is three layers — all verified working, cross-origin Worker bug fixed:

```
Tool page (index.html)              — ~150 lines, orchestrator
  ├─ <sg-upload-dropzone>           — file selection
  ├─ <sg-video-splitter>            — UI (Shadow DOM, 1260 lines)
  │    └─ sg-video.js               — core module (838 lines, pure functions)
  │         └─ FFmpeg WASM          — @ffmpeg/ffmpeg@0.12.10 + core@0.12.6
  ├─ <sg-send-drop>                 — share via SG/Send
  └─ Setup Environment              — 8-step health check
```

All operations use `-c copy` (stream copy). Fast. No quality loss. But keyframe-accuracy only — not frame-accurate.

## Tier 1 — Core New Operations (extend `sg-video.js`)

### 1.1 Video Compression

Reduce file size by re-encoding with a lower bitrate. This is the single most-requested capability after splitting — users trim a clip and want to shrink it before sharing.

**FFmpeg commands:**

```bash
# Quality-based (CRF — constant rate factor)
-i input.mp4 -c:v libx264 -crf 28 -preset fast -c:a aac -b:a 128k output.mp4

# Target file size (2-pass or constrained quality)
-i input.mp4 -c:v libx264 -crf 28 -maxrate 1M -bufsize 2M -c:a aac -b:a 128k output.mp4
```

**Core module addition** — `sg-video.js`:

```javascript
export async function compressVideo(ffmpeg, file, options = {}) {
    // options: { quality: 'high'|'medium'|'low', maxSizeMB: null }
    // Returns: { blob, filename, originalSize, compressedSize, ratio }
}
```

**Quality presets** (user-facing):

| Preset | CRF | Typical reduction | Use case |
|---|---|---|---|
| High quality | 23 | ~30-50% smaller | Preserve most detail |
| Medium quality | 28 | ~50-70% smaller | Good balance (default) |
| Low quality / small file | 33 | ~70-85% smaller | Email, messaging |

**Note:** This is the first operation that **re-encodes** — it will be significantly slower than `-c copy` operations (minutes, not seconds). The UI must set expectations. FFmpeg WASM's `libx264` encoder runs entirely in WASM — no hardware acceleration. Progress reporting via FFmpeg's progress callback is essential.

**Performance estimate:** A 1-minute 1080p video at Medium quality takes ~30-90 seconds in FFmpeg WASM depending on device. The 500MB input limit still applies.

### 1.2 Video Concatenation (Stitch)

Join multiple clips into a single video. This is the foundation for the "highlights reel" concept from the gallery briefs.

**FFmpeg commands:**

```bash
# Concat demuxer (same codec — stream copy, fast)
-f concat -safe 0 -i filelist.txt -c copy output.mp4

# Concat filter (different codecs/resolutions — re-encodes)
-i clip1.mp4 -i clip2.mp4 -filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1" output.mp4
```

**Core module addition** — `sg-video.js`:

```javascript
export async function concatVideos(ffmpeg, files, options = {}) {
    // options: { mode: 'copy'|'reencode' }
    // 'copy' = fast, requires same codec/resolution
    // 'reencode' = slow, handles mismatched inputs
    // Returns: { blob, filename, duration, inputCount }
}
```

**Two modes in the UI:**

- **Quick join** (`-c copy`) — same format clips, instant. Works when splitting then reassembling.
- **Full merge** (re-encode) — different formats, resolutions, codecs. Slower. Normalises everything.

The UI should auto-detect whether quick join is possible (same codec + resolution across all inputs) and default to it.

### 1.3 Audio Format Conversion

Convert extracted audio between formats. Extends the existing `extractAudio()` which outputs `.m4a` only.

**FFmpeg commands:**

```bash
# AAC → MP3
-i input.m4a -c:a libmp3lame -b:a 192k output.mp3

# Any → WAV (lossless)
-i input.mp4 -vn -c:a pcm_s16le output.wav

# Any → OGG
-i input.mp4 -vn -c:a libvorbis -b:a 192k output.ogg
```

### 1.4 Frame-Accurate Trim

The current trim uses `-c copy` which cuts at keyframe boundaries — the actual cut point may be ~0.5-2 seconds off from what the user specified. For precise editing, offer a re-encode option.

**FFmpeg commands:**

```bash
# Frame-accurate (re-encodes the boundary GOPs, copies the rest)
-ss {start} -to {end} -i input.mp4 -c:v libx264 -crf 18 -c:a aac output.mp4
```

**Not a new function** — this is a parameter on the existing `trimVideo()`:

```javascript
export async function trimVideo(ffmpeg, file, start, end, options = {}) {
    // options: { accurate: false }
    // When accurate=true, uses re-encoding instead of -c copy
}
```

**UI change:** A toggle in the trim panel — "Frame-accurate (slower)" — defaulting to off.

## Tier 2 — Visual Timeline & Thumbnails (extend `<sg-video-splitter>`)

These are UI enhancements to the existing component, delivered as IFD surgical overrides.

### 2.1 Visual Timeline with Draggable Markers

A Canvas-based timeline bar showing the video duration, with draggable handles for trim points and split markers. This replaces (or augments) the text-only time inputs.

**Architecture:**

New component: `<sg-video-timeline>` — a standalone Web Component that renders a horizontal timeline bar with:

- Full-width progress representation of the video duration
- Draggable start/end handles for trim mode
- Draggable segment markers for split mode
- Current playhead position (synced with `<video>` element)
- Hover preview (thumbnail on hover — see 2.2)
- Shaded regions showing the selected/excluded portions

```
core/video-timeline/v1/v1.0/v1.0.0/
  sg-video-timeline.js       — Canvas rendering, pointer event handling
  sg-video-timeline.css      — positioning, cursors
```

**Integration with `<sg-video-splitter>`:**

The splitter component gains a timeline via IFD surgical override:

```
components/video-splitter/v1/v1.0/
  v1.0.0/sg-video-splitter.js          ← existing base (unchanged)
  v1.0.1/sg-video-splitter--v1.0.1.js  ← surgical: injects <sg-video-timeline>
```

The override patches `_renderPreview()` to insert the timeline below the `<video>` element and wires bidirectional sync: dragging a handle updates the time inputs, editing a time input updates the handle position.

**Events emitted by `<sg-video-timeline>`:**

| Event | Detail | When |
|---|---|---|
| `timeline-trim-change` | `{ start, end }` | User drags trim handles |
| `timeline-split-change` | `{ markers: [seconds...] }` | User drags split markers |
| `timeline-seek` | `{ time }` | User clicks on timeline |
| `timeline-hover` | `{ time, x }` | Mouse moves over timeline |

**Canvas rendering approach:**

```

│  0:15                                    2:10           │

  ▓▓ = trimmed (dark/shaded)    ░░ = kept (accent colour)
```

For split mode, vertical markers divide the bar into segments, each draggable:

```

│  0:00     │  0:30          │  1:15                 2:34 │
└───────────┴────────────────┴────────────────────────────┘
            ▲                ▲
```

**Interaction details:**

- Handles: 20px wide hit target, 4px visible, accent colour
- Drag: pointer events (not mouse events — touch compatible)
- Snap: optional snap to second boundaries
- Shading: trimmed regions use `rgba(0,0,0,0.5)` overlay
- Playhead: thin vertical line, synced to `<video>.currentTime`
- Hover thumbnail: positioned above cursor, 160×90 frame capture, debounced to ~200ms

## Limits and Constraints

| Constraint | Value | Reason |
|---|---|---|
| Input file size | 500 MB hard limit | Browser memory |
| FFmpeg WASM initial load | ~30 MB | CDN-cached after first use |
| Re-encoding speed | ~30-90s per minute of 1080p | No hardware acceleration in WASM |
| Concat (quick join) | Same codec + resolution required | `-c copy` limitation |
| Concat (re-encode) | Any format mix | Slower, but always works |
| Thumbnail capture | Browser-decodable formats only | Uses native `<video>` element |
| Output format | MP4 (H.264/AAC) for video, MP3/M4A/WAV/OGG for audio | FFmpeg WASM codec support |
