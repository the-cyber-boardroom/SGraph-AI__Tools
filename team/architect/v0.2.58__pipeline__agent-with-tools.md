# Pipeline Design — agent-with-tools v0.2.58

## Problem

Tool calls are never executed. `sg-llm-chat-history` fires `llm:send` without a `tools:[]` array, so Ollama never enters function-calling mode. There is also no visibility into extraction/validation/execution steps.

---

## Pipeline Stages

```
User input
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  sg-llm-chat-history  →  llm:send (no tools)                    │
│                  ↓ CAPTURE intercept (api.js P1)                │
│         llm:send + tools:[] + tool_choice:'auto'                │
│                  ↓                                              │
│           sg-llm-request → Ollama / OpenRouter                  │
│                  ↓                                              │
│         llm:request-complete { content, toolCalls }             │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼ EXTRACT (aw-tool-extractor P2)
    │  • Native tool_calls → visibility event only (sg-llm-request already fires llm:tool-calls)
    │  • JSON-in-content   → llm:tool-calls-extracted + llm:tool-calls
    │  • Code-block        → llm:tool-calls-extracted + llm:tool-calls
    │
    ▼ VALIDATE / QUEUE (aw-execution-inspector P3)
    │  • Auto mode: show cards briefly, pass through
    │  • Manual mode: hold llm:tool-calls, show [Run]/[Skip] UI
    │
    ▼ EXECUTE (sg-tool-runner + sg-local-bridge)
    │  • sg-tool-runner dispatches to lb_* functions
    │  • sg-local-bridge:tool-call { name, args, result, ms }
    │  • llm:tool-results-complete { results, messages }
    │
    ▼ LOOP (aw-loop-coordinator P6)
    │  • Appends tool result messages, re-fires llm:send
    │  • Tracks iteration count vs max-iterations cap
    │  • llm:loop-limit-reached when ceiling hit
    │
    ▼ Back to sg-llm-request (next iteration or final answer)
```

## Component Table

| Component | Type | Phase | Purpose |
|---|---|---|---|
| `agent-with-tools-api.js` | Logic | P1 | LB_TOOL_SCHEMAS, tool injection middleware |
| `aw-tool-extractor.js` | Headless CE | P2 | Extract tool calls from all formats |
| `aw-execution-inspector.js` | Visual CE | P3 | Show + approve/skip pending tool calls |
| `aw-step-tracer.js` | Visual CE | P4 | Event audit log with expand/filter |
| `aw-pipeline-view.js` | Visual CE | P5 | Pipeline stage indicators |
| `aw-loop-coordinator.js` | Headless + status | P6 | Loop back to LLM with iteration cap |

---

## Event Map

| Event | From | To | Detail |
|---|---|---|---|
| `llm:send` | sg-llm-chat-history | CAPTURE → api.js | `{ messages, tools, tool_choice }` |
| `llm:request-complete` | sg-llm-request | aw-tool-extractor | `{ content, toolCalls }` |
| `llm:tool-calls` | sg-llm-request / aw-tool-extractor | aw-execution-inspector → sg-tool-runner | `{ toolCalls, messages }` |
| `llm:tool-calls-extracted` | aw-tool-extractor | aw-step-tracer, aw-pipeline-view | `{ calls, format, confidence }` |
| `sg-local-bridge:tool-call` | sg-local-bridge | aw-execution-inspector, aw-step-tracer | `{ name, args, result, ms }` |
| `llm:tool-results-complete` | sg-tool-runner | aw-loop-coordinator | `{ results, messages }` |
| `llm:loop-limit-reached` | aw-loop-coordinator | (user) | `{ iterations }` |
| `sg-local-bridge:status` | sg-local-bridge | api.js (register lb_* schemas once) | `{ ok, latency_ms }` |

---

## Implementation Order

1. **P1** — api.js: LB_TOOL_SCHEMAS, bridge listener, tool injection middleware, remove old shim (already implemented)
2. **P2** — aw-tool-extractor.js: JSON/code-block fallback extraction
3. **P3** — aw-execution-inspector.js: card UI, auto/manual toggle
4. **P4** — aw-step-tracer.js: event audit log
5. **P5** — aw-pipeline-view.js: pipeline stage indicators
6. **P6** — aw-loop-coordinator.js: iteration-limited loop back
7. **manifest.json** — add phase-2 entries for P2-P6
8. **aw-layout.js** — add Pipeline, Queue, Tracer panels to right column
9. **index.html** — add headless `<aw-tool-extractor>` and `<aw-loop-coordinator>` to DOM
